# Mac 재개 문서·작업지시문과 전달 자료

기준일: 2026-11-16. 사용자는 다음 작업을 Mac에서 이어가므로 읽을 문서와 작업지시문을 작성하고
개발 branch에 commit/push하도록 지시했다. 실제 Mac은 아직 연결하지 않았으며 두 실기 행은 `NOT_RUN`이다.

## 이번 산출물

- [Mac 재개 문서](../MAC_HANDOFF.md): 읽기 순서, Windows 자료 전달·원본 복구, writer 인수, 실제 Mac 준비와 단계별 명령.
- [복사용 작업지시문](../MAC_START_PROMPT.txt): 새 Mac 작업에 전달할 지시문.
- [기계 판독 인계](../mac-handoff.json): source·kit hash·실행 범위·전달 경로·인수 조건.
- Windows의 `D:/w06/mac-transfer/NU54DK-Mac-handoff-20261116.zip`: 원본 kit·필요한 근거·최종 writer 해제 receipt.
  문서 CI 완료 뒤 최종 작성하며 binary를 Git에 넣거나 공개 Release로 게시하지 않는다.

현재 인계의 부모는 `09da4d740fb751904e939ca0f1ef944cdf1b720b`, 제품 C11은
`d304f369c0d3ebbac35c3bf0ef3b7b2887f40dfa`다. 이전 W08 문서 CI
[43813362106/attempt1](https://github.com/EIDOSDATA/NU54DK_Arduino_Core/actions/runs/43813362106)은8PASS·범위SKIP1이었다.
이번 문서의 commit·push·CI는 새 exact SHA와 별도 receipt로 확인한다.

## 변경 경계

AGENTS·HANDOFF의 D드라이브·Windows continuation·COM·임시 경로 요구를 Windows 보존 환경으로 한정했다.
Mac은 실제 checkout과 새 control/work root를 사용한다. 이전 문서·검증 원형의 D경로는 수정하지 않았다.
RC1 절차에서 이전 H12 후보가 모든 kit의 필수 입력처럼 읽히던 문장을 고쳤다.
C11의 이전/현재 version fixture는 같은 C11 source이며 공개판 갱신 실적이 아니다.

기존 PASS·FAIL, C5/C10/C11 원장, W06 실제46PASS와 수락3개, strict M33 생성 원장은 보존한다.
Host6/8·지원 목표 검증3/5·M33 수락6/8/기술5/8과 Mac NOT_RUN을 올리지 않는다.
새 SDK·firmware·실행기 변경, 전체204·HIL 반복, #29 분석은 없다.

## 인계 확인

원본 kit의201857017bytes·SHA-256과 tar 구조·222개 파일을 기존 감사와 대조한다.
전달 묶음은 파일별 SHA·source/run/attempt·원본 경로 대응을 기록하며 기존 CI state를 현재 Mac 실행 상태로 복원하지 않는다.
Markdown link/UTF-8·작업지시문 UTF-8·명령 인자·원장 보존·독립 검토와 exact 문서 CI를 확인한다.
최종 CI 결과와 Windows process/WSL 종료·writer 해제는 전달 묶음의 `windows-writer-release.json`이 소유한다.
문서가 있다는 사실만으로 이전 writer가 해제됐다고 추정하지 않는다.

Windows 원본 검토·commit/push·CI·전달 감사는 `D:/w06/h8mac`에 남긴다.
자동점검 w06은 PAUSED, 예약작업 없음, 공개 tag·Release·index 승인은 없다.
