# v0.5.0-rc.1 공개와 다운로드 smoke

## 1. 판정

프로젝트 소유자의 명시적 공개 지시에 따라 exact source
`7786984a186980f6220271cd506636e4564bc55d`에 annotated tag `v0.5.0-rc.1`을 만들고
[GitHub Pre-release](https://github.com/EIDOSDATA/NU54DK_Arduino_Core/releases/tag/v0.5.0-rc.1)로
공개했다. 결과는 **PASS**다.

비공개 Actions RC에서 검증한 ZIP·checksum·manifest·SBOM·license inventory·third-party notices와
RC Boards Manager index 7개를 그대로 게시했다. 인증 없는 공개 URL로 모두 다시 내려받아 크기와
SHA-256이 게시 전 byte와 같은지 확인했다.

## 2. 공개 설치 smoke

Windows의 새 Arduino CLI 1.5.1 data/downloads/sketchbook에서 공개 RC index를 추가하고
`nucode:zephyr@0.5.0-rc.1`을 설치했다.

| 항목 | 결과 |
| --- | --- |
| 공개 자산 다운로드와 hash | **PASS**, 7/7 일치 |
| 설치 version과 source | **PASS**, `0.5.0-rc.1` / `7786984a...` |
| 설치 예제 발견 | **PASS**, 113개 |
| 대표 clean compile | **PASS**, `NUCODE_BLE_DirectionFinding/CteBeacon`, `ble` profile |
| 대표 FLASH / RAM | 156,700 B / 51,405 B |
| uninstall / reinstall | **PASS** / **PASS** |
| 재설치 뒤 예제 발견 | **PASS**, 113개 |
| Nordic prerequisite marker 보존 | **PASS** |

첫 대표 compile은 `ready.json`에 고정된 사용자 Nordic root 대신 `C:\ncs`를 지정해
fail-closed 경로 검사에서 실패했다. 고정 marker의 `C:\Users\eidos\ncs`를 사용한 재실행은
PASS했다. 이어 PowerShell Core의 built-in module 경로 충돌 1회는 실제 uninstall 전에 중단됐고,
Windows PowerShell 5.1의 새 `-NoProfile` 프로세스로 같은 검사를 PASS했다. 두 실패는 숨기지 않으며
package 결함으로 계산하지 않는다.

## 3. 공개 경계

- 이 결과는 **공개 RC** 완료다. 정식 stable `v0.5.0` 공개 완료가 아니다.
- 현재 stable·공식 지원 버전과 root Boards Manager index는 계속 `v0.4.1`이다.
- `main`은 변경하지 않았고 tag는 검증한 exact RC source를 가리킨다.
- stable 승격에는 RC 사용 결과 검토, stable exact 자산 재현, 별도 승인, stable tag/Release/index와
  공개 설치 smoke가 필요하다.
- M32/M33, HOST-W04~W08과 Ubuntu/macOS 지원은 자동 착수하거나 완료 처리하지 않는다.
