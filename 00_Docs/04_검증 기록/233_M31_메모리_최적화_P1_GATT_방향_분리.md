# 233 — M31 메모리 최적화 P1 GATT 방향 분리

## 1. 판정

2026-09-23 generic GATT의 server와 client를 하나의 `ble-gatt-nus-dual-role`로만
공급하던 구조를 방향별 adaptive role로 분리했다.

- `ble-gatt-server-peripheral`: local dynamic database, characteristic server, advertising
- `ble-gatt-client-central`: scan/connect, remote discovery/read/write/subscribe, robust cache
- `ble-gatt-nus-dual-role`: server/client/NUS를 함께 쓰는 기존 full 호환 경로

`CONFIG_NUCODE_BLE_GATT_SERVER` 또는 `CONFIG_NUCODE_BLE_GATT_CLIENT`가 켜진 방향만
session callback과 event record 필드를 활성화한다. role은 반대 방향 translation unit과
Zephyr Kconfig를 source graph에서 제외한다. 폴더가 include search path에 남았다는
이유로 제외를 주장하지 않고 final `.config`, Ninja source graph, ELF symbol을 모두 대조했다.

## 2. 방향별 제외 경계

| image | 포함 | 제외 |
| --- | --- | --- |
| server Peripheral | `GattDatabase.cpp`, `GattServer.cpp`, `GattCache.cpp`, dynamic DB | `GattClient.cpp`, Zephyr GATT client, NUS facade/client, 1,576 B client state |
| client Central | `GattClient.cpp`, `GattCache.cpp`, Zephyr GATT client | `GattDatabase.cpp`, `GattServer.cpp`, dynamic DB, NUS facade/client, 572 B service slot |
| dual compatibility | server/client/NUS 기존 구성 | 없음 |

`NUCODE_BLE_GATT` Kconfig는 GATT client 또는 dynamic DB 중 선택된 방향 하나에 의존하도록
완화했다. 기존 Zephyr test와 `standard`/`ble` profile은 두 선택지의 default `y`로
양방향 호환을 유지한다. 공개 `CustomGattPeripheral`/`CustomGattCentral` 예제와 P0 server
fixture는 각각 방향 role을 선언하며 저수준 `prj.conf`에 의존하지 않는다.

## 3. ELF/map 비교

| 대상 | 분리 전 RAM | 분리 후 RAM | RAM 절감 | 분리 전 FLASH | 분리 후 FLASH | FLASH 절감 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P0 1×1/1-link/64 B server fixture | 59,338 B | 48,653 B | 10,685 B | 192,228 B | 131,048 B | 61,180 B |
| `CustomGattPeripheral` | 59,519 B | 48,835 B | 10,684 B | 198,628 B | 137,672 B | 60,956 B |
| `CustomGattCentral` | 59,214 B | 53,478 B | 5,736 B | 199,100 B | 150,036 B | 49,064 B |

server fixture의 `slots` 572 B와 16-depth event queue 1,664 B는 유지되지만 client `states`는
ELF에 없다. Central은 `states` 1,576 B를 유지하고 `slots`는 없으며, server-only event
필드가 사라진 queue는 1,536 B다. P0 GATT server RAM 상한은 60,000 B에서
50,000 B로 낮춰다.

## 4. 호환·실패 경계

- 역할 선언이 없는 `NUCODE_BLE` adaptive build는 기존처럼 fail-closed로 거부한다.
- server/client 방향 role은 서로와 다른 독립 firmware role과의 동시 선택을 거부한다.
- server-only image에서 `BLEClient` API를, client-only image에서 local service API를 사용하면
  반대 방향 source가 없으므로 link가 성공으로 위장되지 않는다.
- server/client/NUS 동시 사용자는 `ble-gatt-nus-dual-role`을 계속 사용한다.
- 이 단계는 compile-time source/static storage 분리이며 실물 BLE 상호운용 PASS로
  확대하지 않는다.

## 6. 남은 P1 경계

server service slot은 characteristic마다 notification과 indication snapshot을 각각 보존한다.
다음 P1은 bounded shared TX pool로 통합할 수 있는지 callback 완료·취소·disconnect,
stale completion, cross-link 거부, pool 고갈/backpressure와 해제 후 재시도 수명을 먼저 검증한다.
