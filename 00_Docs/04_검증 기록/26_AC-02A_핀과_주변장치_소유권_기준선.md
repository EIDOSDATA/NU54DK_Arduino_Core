## 1. 판정 요약

AC-02A는 GPIO와 주변장치가 같은 물리 pad 또는 peripheral block을 동시에 소유하지 못하게 하는
내부 기반을 구현하고 자동 시험을 통과했다.

- 동적 할당 없는 고정 슬롯 `IoResourceManager`
- GPIO pad와 serial/PWM/ADC/power block을 표현하는 정규화된 resource key
- `gpio`, `adc`, `pwm`, `wire`, `spi`, `serial`, `system` owner와 instance 구분
- 최대 8개 자원의 원자적 `reserve → commit`, 실패 시 `rollback`, 확정 lease의 `release`
- 64-bit generation·동일-owner 예약 token·manager epoch에 의한 stale lease 거부
- 중복 resource, 잘못된 phase, slot 부족과 경쟁 요청의 fail-closed 처리
- ISR의 소유권 변경과 snapshot 조회 거부
- 부팅 시 UART20·I2C22·PWM20 pinctrl pad와 block의 고정 owner 등록
- DTS에서 SPI00이 활성화된 경우에만 해당 pad와 block 등록
- `pinMode()`의 reserve/driver/commit 또는 rollback 연결
- `digitalRead()`/`digitalWrite()`의 active GPIO ownership 검사
- GPIOTE가 없는 P2의 LED0·LED2·connector 역할에서 interrupt capability 제거

NU54DK target ztest 8/8과 전체 host 회귀 408개 중 406 PASS·2 skipped를 통과했다. M3·M6·AC-01·M14와
AC-02A target application도 순차 direct build로 통과했다. 따라서 **내부 소유권 기반**은 완료로
판정한다.

이 판정은 AC-02 전체 완료가 아니다. 실제 runtime pinctrl 또는 driver 상태를 전환하지 않으며,
Wire/SPI/Serial/ADC/PWM의 `begin()`/`end()`와 소유권 manager가 아직 handover 수명주기를 공유하지
않는다. 공개 pin claim/remap API와 해당 물리 HIL도 제공하지 않는다.

## 2. 구현 계약

### 2.1 자원과 owner

GPIO 자원은 `controller device + controller 내부 pin`으로 식별한다. Arduino 논리 ID 또는 별칭이
달라도 같은 물리 pad를 가리키면 같은 key이므로 충돌한다. Peripheral 자원은 종류, 선택적 domain과
instance를 결합한다.

Manager 표와 lease는 고정 크기이며 heap을 사용하지 않는다. 하나의 lease는 최대 8개 자원을
다루며 batch 안에 중복 key가 있거나 하나라도 다른 owner와 충돌하면 아무 자원도 예약하지 않는다.
같은 owner가 이미 active인 자원을 다시 요청한 경우 기존 ownership을 새 lease의 `release`가
해제하지 않는다. 진행 중인 동일-owner 예약은 64-bit 일회용 token으로 직렬화하므로, 복사된 이전
예약 lease가 다음 예약을 commit 또는 rollback할 수도 없다.

### 2.2 트랜잭션과 수명 보호

호출자는 hardware 또는 pinctrl 변경 전에 자원을 reserve한다. Driver 작업이 성공하면 commit하고
실패하면 rollback한다. Manager는 lease phase, 각 slot의 generation과 manager epoch를 검사해 복사된
오래된 lease가 현재 ownership을 commit, rollback 또는 release하지 못하게 한다. 부팅 registry는
중간 자원 등록이 실패하면 앞서 등록한 자원을 역순으로 해제하며, production 부팅에서 복구까지
실패하면 조용히 불완전한 표를 사용하지 않고 panic한다.

소유권 표를 바꾸거나 조회하는 API는 thread 문맥 전용이다. ISR 요청은 mutex에 진입하지 않고
`invalid_context`로 거부한다.

### 2.3 NU54DK 부팅 registry

`variants/nu54dk/io_resource_registry.cpp`는 APPLICATION init에서 보드 DTS pinctrl을 읽고 다음
고정 owner를 active로 등록한다.

| 자원 | owner | 등록 범위 |
| --- | --- | --- |
| UART20 | `serial:20` | TX/RX/RTS/CTS pad와 serial block 20 |
| I2C22 | `wire:22` | SDA/SCL pad와 serial block 22 |
| PWM20 | `pwm:20` | 출력 pad와 PWM block 20 |
| SPI00 | `spi:0` | DTS에서 활성화된 경우 SCK/MOSI/MISO pad와 serial block 0 |

Registry는 실제 pinctrl, device 전원 또는 driver state를 변경하지 않는다. AC-02A의 역할은 현재
DTS가 이미 배정한 자원을 ownership 표에 반영해 다른 Core 경로가 덮어쓰지 못하게 하는 것이다.

### 2.4 GPIO 연결

`pinMode()`는 pad ownership을 reserve한 뒤 Zephyr GPIO 구성을 수행한다. 구성이 성공하면 lease를
commit하고 mode state를 기록하며, 실패하면 rollback한다. `digitalRead()`와 `digitalWrite()`는
해당 pad가 active GPIO owner인지 확인한 후에만 driver를 호출한다. 충돌은 공개 GPIO 진단의
`ownership-conflict`로 projection하고 hardware를 바꾸지 않는다.

GPIO mode 변경과 attach/detach 및 전체 callback mask는 하나의 전환 mutex를 공유한다. 잠금 순서는
전환 mutex, ownership snapshot, interrupt 설정 mutex 순서로 고정한다. Interrupt 해제 또는 GPIO
재구성이 실패하면 ownership 예약을 rollback하고 runtime mode를 `unconfigured`로 정리해, 이전
input mode가 남아 있는 것처럼 보이면서 callback만 유실되는 상태를 허용하지 않는다.

Variant interrupt capability는 DTS controller를 함께 확인한다. nRF54L15 CPUAPP의 GPIOTE20/30이
P1/P0만 처리하므로 P2의 `PIN_LED0`, `PIN_LED2`, `PIN_GPIO0/D10`, `PIN_GPIO1/D11`은 digital
input/output이어도 `digitalPinToInterrupt()`에서 `NOT_AN_INTERRUPT`를 반환한다.


## 4. 도구 제한 기록

여러 sysbuild case를 한 번에 병렬 실행한 Windows Twister에서는 NCS toolchain의 ccache archive
object 누락으로 build worker가 실패했다. 같은 M14와 AC-02A application의 순차 direct build가
통과했고 AC-02A image가 실제 NU54DK에서 8/8을 통과했으므로 제품 source 실패로 판정하지 않았다.
이 기록은 병렬 Twister 환경 자체의 안정성을 PASS로 주장하지 않는다.

## 5. AC-02B로 남긴 범위

다음 항목은 AC-02A 판정에 포함하지 않는다.

- runtime pinctrl apply/recover와 PM suspend/resume lifecycle
- GPIO와 Wire/SPI/Serial/ADC/PWM 사이의 실제 driver handover
- 각 peripheral `begin()`/`end()`와 acquire/release의 연결
- 추가 instance, ADC/PWM resolution·frequency, `tone()`/Servo 공개 API
- 공개 pin claim/remap 또는 사용자 설정 API
- handover, detach/reclaim와 저전력 전후의 실제 NU54DK HIL

AC-02 전체 완료와 `v0.3.0` stable 지원 선언은 위 AC-02B 범위, AC-03과 M22 gate를 모두 통과한
뒤에만 가능하다.
