# 220 — M31 릴리스 전환과 문서 전수 정비

## 1. 사용자 결정과 이번 작업 범위

2026-09-21 사용자 결정에 따라 **v0.5.0 릴리스 시점을 M33에서 M31 완료 후로 앞당긴다.**
배포 대상은 **Windows 10/11 x64**, 기능 범위는 검증된 **M28~M31**이다. M32/M33의 추가
기능·전체 NCS 예제 catalog와 Ubuntu/macOS 지원은 후속 버전(미정)으로 유지한다.

이번 요청은 **문서 검토·수정 → main 반영 → `M31-MEM-OPT` 브랜치 생성·푸시**까지다.
메모리 최적화 코드, 새 firmware build·물리 HIL, HOST-W04~W08, tag/Release/catalog 공개는
수행하지 않는다. 이전 squash를 반복하거나 branch/worktree를 정리하지 않는다.

다음 구현 순서는 [219번 최적화 계약](219_M31_W06_메모리_점유_감사와_최적화_계약.md)의
**P0~P2 메모리 최적화 → W04·W05 잔여·영향 재검증 → W06 자원·수명주기·회귀 →
W07 설치 예제·세 보드 역할 → W08 기능 마감·Windows 릴리스 준비**다.
W04·W05를 먼저 완료한 뒤 최적화하는 옛 순서는 대체한다.

## 2. 릴리스 gate와 보존 경계

M31 기능 8/8과 실제 공개는 별도 판정이다. M31-W08이 준비를 소유하고
[v0.5.0 TODO §6](../TODO_v0.5.0.md#6-결과공개-규칙)의 패키지·manifest/hash·clean Windows 설치·
전체 채택 예제·대표 upload/runtime·serial/debug·수명주기·RC·별도 공개 승인 gate를 충족해야 한다.
M32/M33을 기다리지 않는 결정은 배포 검증을 생략한다는 뜻이 아니다.

- 현재 설치·지원 버전 **v0.4.1**, source **0.4.1-dev**는 바꾸지 않았다.
- M31 **3/8**, W03 **11/11**, W04·W05 미완료, W06~W08 미착수다.
  메모리 감사 완료는 최적화 구현이나 W06 완료가 아니다.
- M32 **0/12**, M33 **0/8**, Host **3/8**을 유지한다. HOST-W04~W08은 사용자 보류다.
- W06은 독립 role image별 자원·수명주기·M19~M30 회귀다. ISO·Audio·DF·CS 네 기능을
  하나의 MCU image에서 동시에 실행하는 것은 완료 조건이 아니다.
- 외장 PDM/I2S·mic/speaker/codec·상용 peer 실물은 사용자 후속 **NOT RUN**·비차단이다.
  채택 기능의 구현·예제·자동 검사 의무는 유지한다. Apple/Google 신규 기능은 후속 M33 소유다.
- readiness의 Ubuntu/macOS `final_release`·`release_blocker=true`는 해당 OS를 지원하는
  후속 릴리스 gate로 유지한다. 문서 정리로 schema·판정 값을 바꾸거나 미검증 OS를 PASS로
  승격하지 않았다. Windows-only v0.5.0 공개 시에는 이 후속 OS 범위를 구분해야 한다.
- 과거 릴리스·시험·PASS/FAIL/HOLD/NOT RUN 원본, SDK lock과 board submodule은 보존한다.

## 3. 문서 검토와 정리 방식

검토 대상은 추적 Markdown 373개와 board submodule 6개다. 신규 이 기록을 포함한 최종
목록·파일별 유지/수정 사유·UTF-8 LF 정규화 SHA-256은 [문서 감사 원장](../document-review.json)에
기록한다. 현행 안내는 release 소유권·실행 순서·현재 상태·링크를 대조했고, 과거 기록은
작성 시점의 계획을 현행 지시로 읽지 않도록 색인에서 구분했다.

| 문서군 | 정리 내용 |
| --- | --- |
| README·AGENTS·HANDOFF·TODO | M31 Windows 릴리스, 정확한 `M31-MEM-OPT` 이름, 최적화 우선, 이번 종료 범위 |
| 로드맵·M31/M32/M33 계약 | v0.5.0과 후속 기능/Host 분리, M31-W08 배포 준비와 기능 완료의 별도 집계 |
| 빌드·배포·도구·시험 안내 | 지원 중인 v0.4.1과 예정 Windows 패키지 분리, 후속 OS gate 유지 |
| Audio 공개 예제 안내 | exact revision 없는 RAM 백분율 반복을 제거하고 `.config`·ELF/map·공통 Core 비용 설명으로 통합 |
| 219 메모리 계약 | 실행 순서 교정, 정적 합계와 linker region 구분, local static만으로 RAM 감소를 단정하지 않음 |
| 역사·공개 버전·third-party·board | 고유 원본 보존. 현재 계획은 TODO/HANDOFF에서 찾도록 색인 정리 |

본문 해시가 동일한 중복 문서는 발견하지 못했다. 고유 결정·검증 근거를 지울 이유가 없어
**문서 파일 삭제는 0개**다. 반복·오래된 현행 안내는 문단 단위로 정리했다. 기존 링크를 위해
다중 Host 계약 파일명은 유지하되 제목·적용 제품선은 후속으로 바꿨다.
이전 감사의 분모·검사 결과는 [215번](215_M31_W03_이력과_문서_정비.md)과 당시 commit에 남기며
이번 감사 결과로 복사하지 않는다.

## 4. 기존 W04 실패 원본의 추가 보존

이번 문서 작업 전에 수행됐지만 아직 추적되지 않았던
[connected-raw-iq.json](evidence/m31-w04-connected-rx-22ff349c/connected-raw-iq.json)을
수정 없이 보존한다. 이번에 새 보드 시험을 실행한 것이 아니다.

| 내부 진단 HCI | `RAW_RX_PARAM=0`, `RAW_REQUEST=0`; Host RX state 동기화 |

| 미실행 | connectionless RX·안테나 전환·각도 계산·외장 RF **NOT RUN** |

UART에는 ANT_INFO/SCANNING/연결 시작의 반복, `Failed LE Set PHY (-13)`, 최종 disconnect
reason 62가 남아 있다. 재부팅/세션 재시작의 원인과 PHY 오류의 인과관계는 **미확정**이다.
RSSI·IQ가 출력됐다는 이유로 각도·거리 정확도나 공개 Arduino RX 완료로 확대하지 않는다.
과거 [216번](216_M31_W04_연결_AoA_Controller_IQ_Event_진단.md)의 102 controller event·
Host gate 폐기·sample 0은 별도 source/attempt의 원본으로 유지한다.

cleanup은 RX STOPPED·Host disarm·상대 disconnect만 확인됐고 request/sampling disable,
disconnect request와 TX STOPPED는 확인되지 않았다. **다음 실기 전에 양쪽 STOP·clock 해제·
GPIO 반환을 직접 확인해야 한다.** 문서 정리 중 보드에 명령을 보내거나 상태를 추정하지 않았다.
원본 COM/probe hash는 당시 역할 증거일 뿐 현재 또는 다른 PC의 mapping으로 재사용하지 않는다.

W05의 동일 ACL read·flash 직후 복구 결과는 [217번](217_M31_W05_비암호화_RAS_ATT_오류_진단.md)·
[218번](218_M31_W05_flash_직후_RAS_복구_재검증.md)을 유지한다. wrong-key fixture/runner 준비는
실기 PASS가 아니며 실제 검증은 **NOT RUN**이다. 비보정 RTT는 정밀 거리 정확도 PASS가 아니다.
