| 항목 | 결과 |
| --- | --- |

| M30 물리 HIL | **NOT RUN — M30-CAP-01부터 후속 실행** |

M30의 실제 OOB carrier는 wired USB/DAPLink VCOM으로 고정했다. NFC는 canonical OOB record의
NDEF adapter를 구현·build하되 안테나/RF pairing은 실행하지 않고 `supported=false`로 유지한다.
기본 loaderless profile은 보존하며 별도의 secure BLE DFU profile만 Nordic 고정 62 KiB boot,
712 KiB dual-slot, 36 KiB storage layout을 사용한다. 실제 전원 차단은 `M30-POWER-01`의 네 주입
지점 × 3회이며 reset으로 대체하지 않는다.

## 구현

- `host-portability-inventory.json`은 launcher, executable, path, lock, prerequisite, CI와 HIL의
  Windows 전용 가정 12개를 `resolved` 5, `retained` 3, `deferred` 4로 분류한다.
- 공통 Host descriptor는 Windows 10/11 x86-64, Ubuntu 24.04+ AMD64, macOS 26+ Apple Silicon
  native만 승인하고 미지원 OS·architecture·emulation을 fail-closed 처리한다.
- Toolchain executable 후보는 OS별 table 한 곳에서 해석한다. POSIX에서는 실행 권한도 검사한다.
- Cache/application-data root는 LOCALAPPDATA, XDG 또는 macOS Library 규칙으로 분리한다.
- Arduino platform recipe는 Windows `.cmd`와 POSIX `.sh`를 선택하지만 두 launcher 모두 격리된
  `src/nu54_builder.py` backend에 argv를 그대로 넘긴다. Shell `eval`은 사용하지 않는다.

clean prerequisite, target build, package와 USB upload는 실행하지 않았으므로 HOST-W04~W07의
`NOT RUN`을 승격하지 않는다. 다음 작업은 M30-W01 capability target/1보드 HIL과 M30-W02 link별
security 수명주기다.
