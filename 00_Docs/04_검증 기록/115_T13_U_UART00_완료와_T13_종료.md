> T01~T25와 정식 공개 완료는 [125번](125_v0.4.0_정식_릴리스_공개와_T24_T25_마감.md)에 있습니다.

## 결론

2026-09-10, UARTE00에 필요한 네 신호와 공통 GND만 연결한 U 하네스에서 다음 범위를
모두 완료했다.

| 시험 | 결과 |
| --- | --- |
| U 결선 검사 | **PASS** — net 11·13·15·16, 양방향 3회와 pulse/lease 자동 해제 |
| 정상 사전시험 | **PASS** |
| 1 Mbit/s 8N1 full-duplex | **PASS** — 요청 180초, Host 연속 180.289622초 |
| RTS/CTS 정지·재개 | **PASS** — role1 100/100, role2 100/100 |
| TX DMA 취소·STOP·fresh restart | **PASS** — role1 100/100, role2 100/100 |
| RX DMA 취소·STOP·fresh restart | **PASS** — role1 100/100, role2 100/100 |
| 실행별 최종 핀·리스 반환 | **PASS** — 두 역할 모두 idle |

이 결과로 합의한 T13 U 물리 범위는 완료했다. 선행 S의 **정식 PASS 56 + System OFF 추가
결합 시험 제외 2**, QDEC·시리얼 handover 제외와 함께 T13은 사용자 합의 범위에서 종료한다.
제외 항목을 PASS 수에 넣지 않으며 완료한 U 결과를 다른 인스턴스·SPI personality·전체 충돌
요구의 증거로 확대하지 않는다.

## 정상 연속 전송

180초 측정의 종료 drain 기준은 다음과 같다.

| 역할 | TX | RX | 최대 TX/RX gap |
| --- | ---: | ---: | ---: |
| role1 | 9,029 frames / 9,245,696 bytes | 9,030 frames / 9,246,720 bytes | 20 / 21 ms |
| role2 | 9,030 frames / 9,246,720 bytes | 9,029 frames / 9,245,696 bytes | 20 / 20 ms |

양쪽 송신 결과가 상대 수신 결과와 교차 일치했고 sequence·payload hash·guard·연속 전진·
의도하지 않은 reset·STOP·clock/pin 반환 조건을 모두 통과했다. 180초 결과를 더 긴 시간이나
다른 하네스의 안정성 PASS로 재분류하지 않는다.

## 흐름제어와 DMA 취소 복구

RTS/CTS 시험은 선택한 송신 역할의 CTS 입력을 peer가 100ms 동안 실제 HIGH로 만들었을 때
송신 진행이 멈추고, 해제 뒤 같은 전송이 이어지는지 양방향으로 100회씩 판정했다. 각 반복은
활성 PSEL/HWFC, peer GPIO 구간, 배경 수신 전진과 최종 GPIO 정책 반환을 포함했다.

TX/RX 취소는 각 역할·방향에 대해 먼저 1회 preflight를 통과한 뒤 100회씩 실행했다. 진행 중
DMA의 terminal event와 실제 부분 길이, buffer 주소·guard, STOP과 자원 반환을 확인하고 다른
seed/nonce로 같은 UARTE00을 다시 열어 정상 양방향 전송되는 경우만 성공으로 셌다. 정식 취소
반복은 총 400/400회다.

## 최초 플래시 타임아웃의 원인 분리

첫 정상 preflight는 role1 재플래시의 erase 진행 중 CMSIS-DAP read timeout으로 종료됐다.
이 원본은 `external_wiring_executed=false`, 결과 행 0이므로 UART 트래픽이나 결선 실패가 아니다.

직후 두 probe를 10MHz read-only attach해 양쪽 Cortex-M33 CPUID `0x411fd210`과 SWD 응답을
확인했다. P2 OUT/IN/DIR와 P2.00/.02/.04/.05 `PIN_CNF`는 유휴였고, role1은 실패한 flash가
남긴 halt, role2는 sleep 상태였다. `cmsis_dap.limit_packets=true`로 같은 source·image를 다시
플래시하자 정상 preflight가 통과했고 이후 모든 물리 캠페인도 같은 설정에서 통과했다.

따라서 이 사건은 **재플래시 중 Host↔CMSIS-DAP 전송 타임아웃**으로 분류한다. 결선·UARTE
코어 결함으로 등록하지 않으며, 실패 원본과 성공 원본을 모두 보존한다. mass erase·unlock·
recover는 사용하지 않았다.
