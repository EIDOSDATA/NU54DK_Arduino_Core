# M31-W02 격리 설치본 ISO 11예제·실기 완료

clean Core `b47aaf40df6fd5f73d132508e06b2bf7da9364f6`과 고정 board
`fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3`에서 Arduino Sketchbook의
`hardware/nucode/zephyr`에 **독립된 로컬 개발 package**를 만들었다. 이는
저장소 junction이나 공개 v0.4.1 Boards Manager 배포판이 아니다.
[manifest](evidence/m31-w02-installed-examples-b47aaf40/manifest.json)는 staging,
선행조건, 11개 빌드, 다섯 무선 실기 원본과 각 도구의 SHA-256을 묶는다.

[staging 원본](evidence/m31-w02-installed-examples-b47aaf40/staging.json)은
clean checkout의 배포 대상 **485개 파일**과 고정 board gitlink를 기록한다.
[무결성 재검사](evidence/m31-w02-installed-examples-b47aaf40/integrity.json)에서
485개 hash 불일치가 0이고, 설치된 `NUCODE_BLE_ISO` 32개 파일은 저장소
원본과 동일하다. 별도 상태 디렉터리에서 공식 prerequisite 설치기의 완료
marker를 만들고 [고정 입력을 재검증](evidence/m31-w02-installed-examples-b47aaf40/prerequisite-verified.json)했다.
NCS v3.4.0, Zephyr revision, toolchain bundle 및 nRF Util 8.2.1의 고정
SHA-256이 모두 일치했다. 사용자 전역 prerequisite 완료 marker는 수정하지 않았다.

Arduino CLI의 `lib examples`에서 ISO 역할 **11/11개**를 발견했고,
[설치본 전수 빌드 원본](evidence/m31-w02-installed-examples-b47aaf40/installed-examples-11-build.json)에서
각 sketch의 HEX 생성·FLASH/RAM 수치와 source clean 상태를 확인해 **11/11
PASS**했다. 같은 revision의 설치본 HEX를 실제 보드에 올린 결과는 다음과 같다.

| 공개 역할 묶음 | clean package image 실기 |
| --- | --- |
| [CIS 중앙·주변](evidence/m31-w02-installed-examples-b47aaf40/package-cis.json) | 양쪽 20/20회, 2,000/2,000 SDU, 오류 0 |
| [일반 BIS](evidence/m31-w02-installed-examples-b47aaf40/package-bis-plain.json) | 양쪽 20/20회, 2,000 송신·1,998 수신·누락 2/허용 20, 오류 0 |
| [암호화 BIS](evidence/m31-w02-installed-examples-b47aaf40/package-bis-encrypted.json) | 양쪽 20/20회, 2,000 송신·1,998 수신·누락 2/허용 20, 오류 0 |
| [시각 동기 BIS](evidence/m31-w02-installed-examples-b47aaf40/package-bis-time.json) | 양쪽 20/20회, 2,000/2,000 SDU, HCI timestamp 유효, 오류 0 |
| [CIS→BIS 세 보드](evidence/m31-w02-installed-examples-b47aaf40/package-cis-to-bis.json) | peer·bridge·receiver 각 20/20회·2,000/2,000 SDU, 세 역할 종료 20/20, 오류 0 |

암호화 MIC 오류 뒤 같은 image의 올바른 Code 복구는 [197번](197_M31_W02_공개_API_암호화_BIS_오류_후_복구.md),
강제 sync loss 뒤 새 session 복구는 [198번](198_M31_W02_공개_BIS_sync_loss_재시작_복구.md)의
clean 실기다. 그 이후 ISO library·core·builder runtime source 변경은 0이다.
공개 예제 전수 감사는 82개 중 문제 0건이다. 앞선 고정 시험 backend의
[W02 audit](evidence/m31-w02-arduino-e6ae812e/closure-audit.json)도 별도 근거로 보존한다.

초기 검사에서 Arduino CLI 사용자 경로가 저장소 junction임을 확인하고
독립 package로 바꿨다. 첫 [진단](evidence/m31-w02-installed-examples-b47aaf40/diagnostic-missing-manifest.json)은
개발 staging에 runtime manifest가 없어 실패했고, 다음
[진단](evidence/m31-w02-installed-examples-b47aaf40/diagnostic-prerequisite-mismatch.json)은
사용자 전역 완료 marker의 pins hash가 달라 실패했다. 둘 다 최종 PASS에
합산하지 않았다. 독립 manifest와 격리된 공식 prerequisite 절차를 적용한
뒤 전체 빌드·실기를 재실행했다.

[완료 audit](evidence/m31-w02-installed-examples-b47aaf40/closure-audit.json)에 따라
**M31-W02 raw ISO 작업 묶음을 완료**한다. M31 전체는 W03~W08이 남아 있다.
