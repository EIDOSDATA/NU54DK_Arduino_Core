## 1. 목적

이 문서는 Loader/LLEXT 없는 Native Full Zephyr 기반 NU54DK Arduino Core의
v0.1.0-rc.1 고정 artifact에 대해 다음 항목을 검증한 실행 기준선이다.

1. RC archive, index, SBOM, license inventory, notice와 checksum의 byte identity
2. 고정 Core·board·NCS·Zephyr·Toolchain provenance
3. host 전체 회귀와 고정 Arduino package compile
4. M10 clean-Windows 기준 대상의 retained-prerequisite Zephyr Twister target build
5. exact RC HEX의 온보드 CMSIS-DAP V2/pyOCD Upload 1회와 UART READY
6. M10 clean Windows lifecycle evidence와 RC runtime payload의 동일성
7. 필수 문서의 exact Git blob

설치·패키징 구조는
[Boards Manager 설치와 패키징](<../02_빌드 설계/06_Boards_Manager_설치와_패키징.md>),
사용자 변경사항은 [RC 릴리스 노트](../05_릴리스/03_v0.1.0_rc1_릴리스_노트.md)를 따른다.
이 문서는 설계 초안이 아니라 실제 실행 결과와 출시 경계를 소유한다.

## 6. M10 evidence 계승 범위

M10 고정 run m10-20260828-045655는 clean Windows에서 preview 0.0.96→0.0.97의 최초 설치,
cold/warm compile, pyOCD 10회, upgrade, downgrade, uninstall·prerequisite 보존과 reinstall을
포함한 11/11 단계를 통과했다.

M11 importer는 M10 source가 RC의 ancestor이고 후속 변경이 문서·시험·릴리스 자동화 범위에
한정되며, 두 preview와 RC의 runtime payload SHA-256이 같은지 검증했다.

- **통과:** 동일 runtime payload의 clean Windows lifecycle과 pyOCD 10회 계승
- **통과:** exact RC ZIP 고정 package compile과 pyOCD 1회+UART READY
- **미실행:** exact RC version의 upgrade·downgrade·uninstall·reinstall 전체 lifecycle
- **독립 미실행:** Arduino IDE GUI 조작 자체

## 7. 원격 오케스트레이터 마감 수정

최종 원격 run은 세 gate PASS, 로컬 evidence 검증과 RC 디렉터리의 byte 동일 복사까지
완료했다. 그 뒤 Windows PowerShell 5.1이 generic List[object]를 object[] parameter로
변환하는 마지막 orchestrator receipt 단계에서 Argument types do not match를 발생시켰다.

이 오류는 원격 gate·evidence·artifact 결과를 바꾸지 않았다. 이미 회수된 여덟 필수
evidence를 repo-owned finalize가 다시 검증해 ready-for-human-approval을 생성했다.
원격 실행기는 generic list 대신 PowerShell 5.1 object[]를 사용하도록 수정했고 전용 host
회귀시험으로 동일 퇴행을 차단했다.

## 8. Evidence 보관과 공개 경계

원본 evidence와 로그는 로컬 build/m11 아래에 보관하며 Git source history에 넣지 않는다.
host, endpoint, serial port와 probe UID는 공개 기록에서 제거한다.

프로젝트 소유자가 RC prerelease 공개를 승인할 때의 허용 asset은 다음 9개에 한정한다.

1. RC ZIP
2. release manifest
3. SPDX SBOM
4. license inventory
5. third-party notices
6. checksum file
7. RC package index
8. m11-rc-plan.json
9. m11-rc-evidence-manifest.json

승인 후 생성하는 `v0.1.0-rc.1` tag는 반드시 실제 검증 RC Core
`4a4b1ece622b155ff7300a46bca304df9adfc797`을 직접 가리켜야 한다. 이 기준선 문서와
원격 오케스트레이터 수정이 들어간 후속 마감 commit 또는 당시의 `HEAD`를 암묵적으로
tagging하면 artifact 내부 `core_revision`과 불일치하므로 허용하지 않는다. 게시 전에 다음
검사를 통과해야 한다.

```powershell
$expectedRcCommit = '4a4b1ece622b155ff7300a46bca304df9adfc797'
$taggedRcCommit = (git rev-parse 'v0.1.0-rc.1^{commit}').Trim()
if ($taggedRcCommit -ne $expectedRcCommit) {
    throw "RC tag target mismatch: $taggedRcCommit"
}
```

M10 raw source JSON, gate별 raw evidence/log, SSH orchestrator 결과, preview index와 stable index는
RC Release asset으로 공개하지 않는다.

## 9. 선택 gate와 미실행 범위

hil_jlink는 M11의 선택 gate이며 이 RC run에서는 실행하지 않았다. 외장 J-Link
upload/debug 경로는 [M8 기준선](08_M8_업로드와_디버그_기준선.md)의 이전 실기 검증을
참조하며, M11 선택 gate PASS를 새로 주장하지 않는다.

로직 애널라이저·오실로스코프 계측, 실제 장기 rollover, PM/idle 전후 시간 연속성,
Linux/macOS와 BLE Arduino API도 이 RC 완료 판정에 포함하지 않는다.
