## 1. 준비와 실기 상태의 분리

[시험 목록](<../01_아두이노 코어 설계/12_v0.4.0_기능_시험_목록.md>)은 75개 identity와 19개
시험 family를 연결한다. JSON의 숫자는 초기 engineering 기준이며 기존 실측값이나 최고 속도
보증이 아니다. API/clock/배선 성립 조건을 대조하고 executable vector로 고정하기 전까지 T01은
부분 준비다. `verify_v04_test_plan.py` 성공은 대상 누락·문서 drift 검사이며 물리 PASS가 아니다.

초기 source/build/semantic 표시는 inventory의 이전 근거를 인용한다. 이후 T09에서 clean
`696defb`의 exact role image를 다시 빌드해 두 보드 무배선 primitives를 검증했으며, [41번](41_M24_M26_온보드_protocol_교정과_실기_재검증.md)의
`51c1986` 결과는 이전 제한 범위의 역사적 근거로 유지한다.
새 계획의 1MHz UART, flow/error, 100회 반복, 600초/7,200초 soak는 아직 수행하지 않았다.

## 4. 보드와 회로도 대조

읽기 전용 조회에서 기존 DUT UID 끝 `fd7d106d`는 COM5/COM6, peer 끝 `c887aaf1`은 COM7/COM8로
동시에 열거됐다. COM 번호 자체를 역할의 영구 ID로 사용하지 않는다. 이 조회는 SWD 응답·flash·시험 PASS가 아니다.

회로도 9페이지 전체를 PNG로 렌더해 읽었다. Page 1/2의 모듈 pin과 공유선, 3의 전원/PMIC,
6의 UART/SWD enable, 7의 I2C pull-up, 8의 button/LED, 9의 header를 대조했다.
원본 PDF에 이미 일부 `Cannot open file` 그림 placeholder가 있고 Poppler가 Symbol/ArialUnicode
대체 font 경고를 냈다. 중요한 연결선·pin 표·스위치 회로는 판독되며 PDF 자체는 수정하지 않았다.

- 두 보드는 각자 USB 전원 사용. 공통 GND와 승인 signal만 연결하고 VBUS/VEXT/VBAT/3.3V/VDD_MOD끼리 연결하지 않는다.
- P2.6~P2.10의 금지 dedicated bank, PMIC 제어선, LFXO pad를 임의 구동하지 않는다.
- `DISABLE_SWD`는 UART 차단과 별개다. 스위치 silk의 ON/OFF 추정 대신 회로의 SWD 연결 유지/필요 UART 분리 조건을 안내한다.
- **이 문서는 아직 최종 T10 결선표가 아니다.** T04~T08에서 실제 시험 firmware의 pin·role·전압 조건을 고정한 뒤 연결표를 제공한다.

### 첫 통합 검사 실패와 수정

`866852f`의 첫 target 검사(`C:/nb/06`)는 기존 18개 build-only 성공, 새 pair 2개는
SPIS compatible node 부재로 Kconfig 단계에서 실패했다(408.70초). 기존 M24 SPI overlay와
같이 disabled SPIS node를 명시했다. Driver를 켜거나 warning 전체를 무시하지 않는다.
Host 전체 검사에서는 v0.4.0 suite 수의 옛 기대값 18과 새 실제값 20이 달라 실패했다.
기대값을 20으로 갱신하고 재검사한다. 실패한 image의 flash는 수행하지 않았다.

추가로 controlled reset 직후 SRAM의 identity/request/response marker를 HALTED 상태에서
지워 이전 boot의 ready 값이 새 시작 확인으로 오인되지 않도록 했다.

### 두 보드 진단 — 단독 PASS와 통합 실패를 분리

`34475a0`은 Host 전체, 문서 142개, inventory와 target 20/20 build-only를 통과했다
(451.47초, `C:/nb/07`). Pair preflight에서 두 exact UID·role·HEX/ELF/source를 확인했다.
첫 통합 HIL은 DUT ping 뒤 PMIC 100kHz 첫 전송에서 `stop_timeout`으로 중단됐다.
SWD와 CPU는 응답했고 CFSR/HFSR는 0이었다. 동일 source의 기존 단독 TWIM20/21/22
400kHz 시험은 다시 3/3 PASS다. 따라서 USB 인식 실패나 보드 고장으로 확정하지 않는다.

별도 진단에서 두 보드 모두 TIMER00은 10,000us에 약 80,024 ticks, TIMER10은 약
20,005 ticks, TIMER20은 약 10,003 ticks를 반환했다. 분주 계산이 모든 instance에
16MHz base를 가정한 결함을 확인해 실제 HAL base clock으로 계산하도록 수정했다.
128/32/16MHz와 범위·2의 거듭제곱 분주 경계는 production helper를 Host C++로 검사한다.

내부 VDD 단발은 두 보드 모두 4092 raw와 정상 STOP을 반환했다. 뒤이어 VSS 시작은
실패했다. nrfx의 공통 enum 전체가 nRF54L15 입력은 아니며, pinned SDK의 이 칩 mapping은
VDD·AVDD 및 제공되는 DVDD다. 불가능한 입력은 configure 단계에서 거부하고 무배선
ADC 시험은 VDD/AVDD로 교정했다. 이는 VSS를 구현했다고 보고하는 변경이 아니다.

통합 I2C 실패 원인은 계속 분리 시험한다. 새 통합 image의 400/100kHz와 반환 코드를

두 role만 선택할 수 있으나 evidence gate를 `m12-zephyr-build-subset`으로 구분하며
최종 전체 group 회귀를 대체하지 않는다.

### NFC pad 설정 누락 분리와 온보드 UART 통합 준비

`01fc2d7`의 pair 2/2 build-only와 Host 전체는 통과했으나 PMIC는 100/400kHz,
SWD 유지/명령 중 분리 네 조합 모두 같은 timeout이었다. 속도·SWD polling만의 문제는 아니다.
기존 단독 image와 overlay를 직접 대조하니 새 pair에 `&uicr { nfct-pins-as-gpios; };`가
빠져 있었다. PMIC의 P1.2/P1.3은 NFC pad라 해당 선언을 추가하고 누락 회귀 검사를 넣었다.
실기 재시험 전에는 원인 해결 PASS로 승격하지 않는다.

같은 pair image에 온보드 UARTE20/21/22/30 arm/status/stop 명령을 준비했다.
독립 TX/RX pattern, 1~1024 byte 단일/이중 buffer, 16-byte guard와 사용하지 않은
padding, parity/flow control을 판정할 기반이다. UART payload 전송·실기 판정은 다음 검사다.

첫 UART 통합 build(`0143ddc`, `C:/nb/09`)는 Zephyr minimal C++ 환경에 `<cstring>`이 없어
2개 role 모두 compile 실패했다. 기존 C library의 `<string.h>`/`memset`으로 교정했다.
실패 image는 flash하지 않았다.

`6a45403` pair 2/2 build PASS(60.18초) 뒤 DUT의 PMIC 3 instance × 100/400kHz와
44개 TIMER capture는 통과했다. 이로써 NFC pad 설정 누락이 통합 PMIC 실패의 원인이었음을
재현/교정했다. ADC AVDD 판정은 4092 raw 포화로 실패했고 peer에는 아직 진행하지 않았다.
Pinned nrfx default는 gain=1/internal 0.9 V로 VDD와 AVDD 둘 다 포화될 수 있다.
후보 channel 설정에 nRF54L15의 8개 gain을 추가하되 기존 기본값 1은 유지하며,
내부 rail 시험은 gain=1/4(3.6 V full scale)로 바꾼다. 외부 reference pin 지원은 추가하지 않는다.
기존 포화 PASS는 변환/STOP의 증거이지 rail 전압 정확도 또는 full-range ADC 검증이 아니다.

### 격리 checkout과 반복 UART 진단

사용자가 원본 checkout에서 코드 정렬만 수행 중임을 확인했다. 정렬 변경은 보존하고
`C:/nb/s04` / `codex/v04-prep-20260905`에서 exact source 검사와 구현을 이어간다.
`e4b70ab`의 `C:/nb/11` build는 끝났지만 원본 dirty 검사로 flash 전에 거부됐다.
격리 checkout의 같은 source를 `C:/nb/12`에서 새로 2/2 build-only(67.96초)했다.

DUT의 내부 rail은 gain=1/4에서 VDD 3740~3756, AVDD 1008~1064 raw로 구분됐다.
MDK는 AVDD를 내부 **0.9 V rail**로 정의한다. AVDD 판정은 이상적 1024 code의 ±25%
(768~1280)로 명시하고, VDD 2500~4000과 겹치지 않게 한다. 이는 정밀 교정 검사가 아니다.

같은 실행에서 PMIC 사용 후 UARTE20 activate가 실패했다. Fresh boot UART sweep는 진행돼
약 50개 조합 뒤 1Mbps/flow/1024에서 수신 timeout이 났지만 그 조합의 별도 fresh 실행은
DUT에서 통과했다. Peer는 첫 port discovery 때 다른 VCOM의 잔류 109 byte 때문에 중단됐다.
두 보드 전체 UART PASS로 세지 않는다.

이를 분리하기 위해 UART discovery를 **firmware TX challenge → 유일 VCOM 선택**으로 바꿨다.
두 COM에 무작정 payload를 보내지 않고, port를 유지하며 설정 변경 뒤 pre-arm 100ms quiet를
확인한다. 그 이전 폐기 bytes는 기록하고, arm 이후 noisy/truncated/다른 port 응답은 계속 거부한다.
64 vectors × 4 onboard instances, DMA buffer state, 무수신 cancel과 TWIM↔UART handover를
공통 runner에 연결했다. 흐름 제어를 켠 데이터 통과와 강제 CTS backpressure 검증은 구분한다.

UARTE adapter는 disabled block의 공유 DMA READY(RXSTARTED)와 SHORTS를 초기화한 뒤
nrfx를 시작한다. 실제 ENABLE이 남아 있으면 소유권을 우회하지 않고 거부한다. nrfx가
부분 초기화 후 실패하면 uninit하며 새 activation에서 이전 이벤트 큐를 분리한다.
이 수정의 target/물리 회귀는 다음 실행에서 확인한다.

`e61594a` Host 전체와 pair 2/2 build(69.77초)는 통과했다. DUT UARTE20은 64개 vector와
cancel·TWIM↔UART handover까지 통과했고 UARTE21의 1Mbps/no-flow/1024×2에서 중단됐다.
중단 후 SWD 조회는 첫 buffer complete, 두 번째 DMA-owned, 오류 0으로 반환했다.
Pinned nrfx 문서에 따르면 `RX_ENABLE_CONT` 없이 다음 buffer를 시작하면 ISR에서 START하므로
무흐름제어 고속 전송에서 gap 동안 FIFO가 넘칠 수 있다. API에 기본 false의 명시적
`continuous_receive`를 추가하고, 32 byte 이상 이중 buffer에서만 허용한다. ISR 지연은
한 buffer 소비 시간보다 짧아야 하며 무한 queue/무제한 지연 보증이 아니다. HIL은 해당
경로를 선택하고 단일/1-byte buffer는 기존 interrupt-linked 방식으로 구분한다.
모든 timeout은 실패로 남기며 재시도 성공으로 앞선 실패를 덮어쓰지 않는다.

### DMA MAXCNT의 단위 교정 준비

Pinned NCS `v3.4.0`의 `nrf54l15_types.h`와 실제 HAL 대입식을 대조했다. PWM은
15-bit **byte count**라 uint16 값 최대 16383개(개별/파형 load는 4의 배수 16380),
SAADC는 15-bit **sample count** 최대 32767, I2S는 14-bit **word count** 최대 16383이다.
이들을 일괄 UINT16_MAX로 허용하던 후보 검사를 실제 단위로 교정한다. 나눗셈으로 먼저
상한을 계산해 크기 곱셈 overflow도 막으며 경계/경계+1/0/SIZE_MAX를 native Host로 검사한다.
이는 MAXCNT 조기 거부 보완이다. 전체 RAM 적합성·alignment·동적 queue 소유권·실물 overflow
시험까지 끝났다는 뜻이 아니다. T07에 계속 추적한다.

### T06 QDEC sampling 선행 보완

Pinned nrfx `NRFX_QDEC_DEFAULT_CONFIG`는 sample period 16384us, LEDPRE 500us,
10 sample마다 report/자동 누산기 초기화를 사용한다. 2ms·10ms 상태 간격의 기존 준비 계획을
그대로 넣으면 샘플링 누락이 가능하므로, `QdecConfiguration` 끝에 `sample_period_us`,
`led_pre_us`, `report_events`를 추가한다. 기본 16384/500/true는 보존하며 128~131072us
2배 단계·LEDPRE 9비트 및 period 미만 조건을 사전 검사하고 실제 nrfx 설정에 전달한다.

Host oracle은 Nordic의 [Sampling and decoding](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-concept_gfd_jzd_4r)

### T04 외부 UART·동기/이중 buffer와 T07 DMA 범위 보완

재개 승인 뒤 UART fixture 101/102/103을 추가했다. P2 전용 bank↔P1, P0↔P1, P1↔P1의
TXD/RXD·RTS/CTS 교차 연결을 회로도 커넥터 번호와 GPIO net로 각각 고정한다. UARTE00/20/21/22/30을
9,600/115,200/1,000,000 baud, 8N1/8E1, RTS/CTS off/on, 1·2개 RX buffer로 조합하고
CTS 100ms backpressure·재개, 8N1/8E1 mismatch, 1ms LOW break를 추가한 135개 준비 vector다. 이 값은 build/Host oracle 범위이며
아직 케이블을 연결하거나 실행하지 않았다.

SPI는 전송 중 cancel을 포함한 1,513개, TWI는 미등록 0x44 NACK·전송 중 cancel을 포함한
326개 vector로 확대했다. controller의 sync/async와 peripheral/target의
단일·이중 buffer를 구분하고, 이중 buffer는 서로 다른 DMA 영역·연속 payload index·각 완료 event와
전체 byte 수를 검사한다. UART/SPI/TWI 모두 RX 전체를 최대 64바이트 mailbox chunk로 읽어 Host가
독립 pattern과 비교한다. Stuck-low·clock stretch와 오류 뒤 명시적 정상 재시작 묶음은 아직 미완료다.

중간 `C:/nb/24`와 동기 전송 추가 뒤 `C:/nb/25`, 이중 buffer 추가 뒤 `C:/nb/26`에서 pair 두 역할이
각각 2/2 build-only PASS했다. 관련 Host 9개도 PASS했다. TWI는 외부 pull-up 조건을 확정하지 않아
실행기가 계속 HOLD하며, 외부 신호 HIL PASS는 없다.

전체 20개 build `C:/nb/28`은 실행 중 CTS backpressure source가 바뀌어 결과 혼합을 피하려고
명시적으로 중단했다. backpressure 추가 뒤 관련 Host 11개와 `C:/nb/29` pair 2/2 build-only가
PASS했다. 이 중단은 compile 실패가 아니며 완료 build로 세지 않는다.

Parity·break case는 예상 receiver error와 DMA guard를 확인하고 STOP한 경우에만 expected-error로
기록한다. Break generator는 확인된 fixture lease 안에서 송신 보드의 TX pad를 1ms LOW로 만들고
원래 GPIO CNF/OUT을 복원한다. 이 준비본은 관련 Host 9개와 `C:/nb/30` pair 2/2 build-only를
통과했다. 아직 실제 parity/error mask나 break 검출을 보드에서 관측한 결과는 아니다.

SPI 125kHz 1,024-byte와 TWI 100kHz 256-byte transfer는 시작 직후 cancel API를 호출하고
terminal event·guard·STOP을 확인한다. TWI 0x44는 target 미등록 주소라 NACK를 예상한다.
`C:/nb/31` pair 2/2 build-only와 관련 Host 9개가 PASS했다. 오류·취소를 실제 선에서 유도했다는
결과는 아니며, TWI는 pull-up HOLD가 해제되기 전 실행할 수 없다.
각 expected-error/cancel STOP 뒤 같은 gate lease를 갱신하고 UART/SPI/TWI별 32-byte 정상 vector를
즉시 재실행하도록 runner를 연결했다. 따라서 오류 관측과 정상 복귀는 서로 다른 result ID로 남는다.

DMA workspace가 단지 요청 buffer를 포함한다는 이유만으로 flash/peripheral/범위 끝을 넘는 주소까지
받지 않도록 nRF54L15 application RAM `0x20000000..0x2003ffff`의 **마지막 byte와 정렬**을 검사하는
공통 helper를 추가했다. Serial route의 모든 workspace, SAADC/PWM의 16-bit buffer,
PDM의 16-bit buffer, I2S의 32-bit buffer에 연결했다. 경계·overflow Host 시험 2개를 추가했고
관련 Host 11개 PASS다. `C:/nb/27`에서 pair 두 역할·M25 Analog·M25 Stream 4/4 build-only가
94.77초에 PASS했다. 이는 T07 전체 오류 복구·동시성·soak 완료나 실기 PASS가 아니다.

### T04~T08 외부 fixture 완성본과 최신 build-only 검증

TWI 목록에 독립 P1/P0 bus의 SDA stuck-low와 TWIS clock-stretch 두 case를 추가해 328개로
고정했다. 첫 case는 SDA가 LOW인 동안 `recoverBus()` 실패를 요구하고, peer가 원래 GPIO를
복원한 뒤 같은 controller의 복구 성공과 32-byte 정상 전송을 별도 result로 남긴다. 둘째는
TWIS buffer 제공을 5ms 늦춰 controller 전송이 완료되지 않은 상태를 먼저 확인한 뒤 정상 완료한다.
공통 SerialFabric recovery transaction은 stage된 route와 resource/GPIO/power snapshot을 사용한다.
복원 또는 lease rollback이 실패하면 resource를 해제하지 않고 fault를 latch한다. native Host의
성공·driver 실패·충돌·rollback 실패·정확한 GPIO/power 복원 검사를 통과했다.

회로도 9페이지를 다시 대조하고 TWI 301의 pull-up을 DUT P4.25 `VDD_MOD`에서 SDA/SCL로 각각
2.2 kΩ ±5% 한 개로 고정했다. peer 전원 rail은 연결하지 않는다. confirmation의 pull-up 확인이
없으면 실행을 거부하며, 1MHz 기능 결과를 rise-time 품질 보증으로 확대하지 않는다.

Analog/stream용 fixture 401~404/408/420/430/440과 `signal_hil.cpp`, `v04_signal.py`,
`v04_signal_run.py`를 추가했다. 401~404/408은 peer P1.14 PWM에서 DUT AIN0~3/AIN7으로
32/256 sample을 받고 PWM20/21/22의 channel slot 0~3을 순차 검사한다. AIN4 DAP 전원 감지,
AIN5 VBAT 분압기/SB4, AIN6 사용자 버튼은 무개조 peer 출력과 충돌할 수 있어 source/build 경계로
남기고 실기 PASS로 가장하지 않는다. 420은 peer P1.14/P1.10 PWM sequence를 DUT P1.4/P1.6
QDEC20/21에서 누산한다. 두 경로는 회로의 LED buffer 입력을 안전한 MCU 출력 fanout으로 사용하며
role 2만 generator가 된다. 430은 I2S20 master/slave,
16/48kHz, 8/16/24/32-bit, left/right/stereo, 단일·이중 DMA buffer의 독립 payload를 대조한다.
440은 PDM20/21 receiver clock에 SPIS21 EasyDMA bitstream source를 동기화해 mono density
25/50/75 순서와 stereo channel 분리를 검사한다. software bit-bang은 사용하지 않는다.

PDM callback이 완료 buffer의 sample 수를 0으로 내보내던 결함도 DMA lease byte 수에서 실제
`int16_t` sample 수를 복원하도록 고쳤다. 이 수명주기 보완 없이는 실제 signal runner가 완료를
인정할 수 없었다. Host 판정기는 density 순서와 stereo channel 평균 차이를 요구한다.

반복·soak 공통 도우미는 1~100회, 0~7,200초, progress 1~60초로 입력을 제한한다. 한 실행의
monotonic 구간만 `continuous_elapsed_seconds`로 기록하며 중단 전 시간을 다음 실행에 합산하지
않는다. 오류·취소 뒤 정상 복귀, DMA guard와 반환, fixture STOP/fault 결과는 기존 case별 journal과
함께 남는다. 실제 동시 실행 topology와 장시간 결과는 단독 기능이 T10~T12에서 통과한 뒤 T13에서
수행하므로 이 절은 HIL PASS가 아니다.

fixture 201 role 1에 SPIM00 1,024-byte 비동기 전송 중 TWIM22로 온보드 PMIC 0x6A/0x0C를 읽는
허용 동시성 case를 추가했다. 무배선 opcode 5는 P1.10/P1.14의 PWM20/PWM21과 내부 VDD SAADC
EasyDMA를 동시에 활성화해 32 sample·두 PWM completion·bounded STOP을 판정한다. 이 두 경우는
준비된 최소 동시성 topology이며 더 넓은 5-block 조합과 7,200초 soak는 T13 후속이다.

preflight는 현재 source·두 UID·role image hash에 묶인 confirmation 초안을 출력한다. 안전 조건을
모두 false, 확인 시각 0, 확인자 공란으로 생성하므로 사람이 T10에서 실제 결선을 확인해 채우지
않으면 실행될 수 없다. Analog는 fixture별 48개, PDM 96개, I2S 96개 vector로 고정했다.

최신 준비 source에서 v04 관련 Host 42개가 PASS했고, `C:/r43`에서 pair DUT/peer·M25 Analog·
M25 Stream 4/4가 116.44초에 build-only PASS했다. 이전 옵션으로 실행한 첫 build 명령은 현재 CI runner가
요구하는 `--workspace/--outdir` 형식과 달라 argument 단계에서 종료됐으며 source 실패로 세지
않는다. `C:/r39`의 pair 2/2도 최신 signal framework까지 build-only PASS했다. 외부 점퍼 연결,
flash, 신호 출력은 실행하지 않았으며 T10 전 모든 외부 결과는 `NOT RUN`이다.
