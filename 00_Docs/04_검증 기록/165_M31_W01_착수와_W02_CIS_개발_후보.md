# 165 — M31-W01 완료와 W02 CIS/BIS 진행

| 판정 | 결과 |
| --- | --- |
| 변경 전 기준선 | 전체 Host gate PASS; fixed SDK/board lock 대조 |
| M31-W01 | parity 703행·20/20 negative·clean HCI query 5/5·전체 Host gate PASS; W01 완료 |
| M31-W02 | clean CIS 20회 × 100 PASS; BIS 두 보드 20회 × 100 개발 후보 PASS, clean 판정 전; combined·time sync 전 |
| M31 전체 | W01 1/8 완료; W02 CIS 단일 subcase PASS, W02 작업은 진행 중 |
| 원격 CI/CD | 조회·실행·대기하지 않음 |

사용자의 C drive 승인 후 실제 `NU54DK_Arduino_Core`의 `m31-w01` 브랜치에서 작업했다.
고정 nrf/Zephyr/board revision은 [착수 계약](<../01_아두이노 코어 설계/20_M31_Bluetooth_착수_계약.md>)과
일치한다. 기본 SDC와 Zephyr LL 후보를 서로 다른 target 설정·UART `controller` 값으로
구분했다. fixed source inventory 결과는 sample 190, variant 474, source-only M31 symbol 39,
총 703행이다. M31 readiness의 작업 묶음 8, 기능 시험 family 10, subcase 28, Audio 기능
묶음 11, 역할 예제 42의 분모를 유지한다. 새 Host 시험 23개(서로 다른 오류 입력
20/20 negative 포함)와 변경 후 전체 Host 회귀,
Markdown UTF-8/local-link gate, staged `git diff --check`가 통과했다. clean source 실기와
기능별 예제는 이어서 검사한다.

clean source commit `8c125a220c4df722e4922887fdf6c5a5e3793612`에서 새 target
build를 `C:\6` capability 5/5, `C:\7` CIS 2/2로 수행했다. 원본 Twister report와
각 HEX hash/실기 transcript의 감사 결과는 [W01 exact manifest](evidence/m31-w01-exact-8c125a22/capability-manifest.json)와
[W02 exact manifest](evidence/m31-w02-exact-8c125a22/cis-manifest.json)에 보존했다.
한 보드 기본 SDC·ISO·CS·DF TX·Zephyr LL 다섯 HCI query는 모두 `source_clean=true`
PASS이다. 두 보드 CIS 20회는 매회 중앙 100 전송, 주변 100 유효 수신, 손상·중복 0,
양 역할 disconnect·STOPPED 후 새 nonce에서 재시작했다. 총 유효 2,000/2,000이다.
무효 빈 controller slot 80개는 송신 sequence 0~99의 payload 손실·손상과 구별해 원본
카운터로 보존했다. readiness에서 `M31-CAP-01:controller`와 `M31-ISO-01:cis` subcase만
PASS이며, BIS·Audio·DF raw IQ report·CS procedure를 build/HCI query만으로 PASS로
승격하지 않았다. W01은 [clean 감사 결과](evidence/m31-w01-exact-8c125a22/w01-closure-audit.json)의
703행 parity·20/20 negative·5구성 HCI query로 닫았고 M31 작업 분모는 1/8이다.
W02 작업 묶음은 BIS·combined·time sync가 남아 진행 중이다.

local target build는 `C:\5`의 capability 5/5와 `C:\4`의 CIS 양 역할 2/2를
build-only로 완료했다. 이것은 기능 runtime PASS가 아니다. [W01 개발 원본](evidence/m31-w01-dev-candidate)의
한 보드 HCI query 다섯 구성은 기본 SDC, ISO opt-in, CS opt-in, DF TX opt-in, Zephyr LL
IQ RX 후보를 각각 실제 board에서 확인했다. 기본 SDC의 IQ RX·AoD는 false다.
Zephyr LL은 connectionless CTE RX bit 20과 Host flag가 true지만 안테나 수 1과
ANT_SWITCH_RX false다. raw IQ report 수집은 `NOT_RUN`이며 안테나 배열 없는 구성의
고수준 AoA API 수락을 주장하지 않는다. DF TX 첫 시도는 Host 설정만 true이고 HCI TX bit가
false였고, 고정 SDK sample 설정을 확인해 `CONFIG_BT_CTLR_DF=y`를 추가한 뒤 같은
bit를 true로 다시 관찰했다. 첫 원본을 삭제하지 않았다.

[W02 개발 원본](evidence/m31-w02-dev-candidate)의 첫 CIS 시도는 무효/빈 ISO slot을
payload 오류로 해석해 FAIL로 남았다. 다음 시도는 100개 payload 수신을 기록했지만,
수신 callback에서 매 slot을 UART 출력해 DAPLink VCOM overflow와 종료 line 누락으로
FAIL이다. 무효 빈 slot과 유효 SDU를 구분하고 callback 출력량을 제한해 세 번째 단일
session과 두 session 재시작을 확인했다. 정식 개발 runner의 20회 결과는 매번 중앙
100 SDU 전송, 주변 100개 유효 수신, 손상·중복 0, 양 역할 disconnect→STOPPED,
다음 nonce START를 기록했다. 네 개의 초기 빈 slot/cycle은 유효 payload 손실 분모와
구별한다. 실제 개발 source가 미커밋이어서 evidence `source_clean=false`,
`PASS_CANDIDATE`이며 `M31-ISO-01:cis` 완료 상태가 아니다.

W02 BIS source/receiver는 동일 NU54DK 두 보드에서 확장·주기 광고, PA sync, BIGINFO,
1-BIS BIG sync와 8-byte sequence/checksum SDU를 실제 수행했다. receiver의 BIG 동기
확인 뒤 source에 `SEND`를 주어 초기 광고·동기 지연을 payload 손실로 오판하지 않는다.
첫 1회 개발 시도는 100/100을 확인했지만 source의 비동기 BIG terminate 완료 전에
다음 session 자원을 재사용해 20회 시도에서 두 번째 BIG 생성 `-ENOMEM`을 관찰했다.
Zephyr ISO Host의 terminate event·disconnected callback 경계를 확인해 양 역할
`BIG_DISCONNECTED` 뒤에만 `STOPPED`를 출력하도록 수정했다. 이어서 20회 실제
SDU는 2,000 송신/1,999 수신, 최소 99였으나 당시 parser가 계약의 최소 99 대신
100을 요구해 실패 원본으로 보존했다. 수락 하한을 계약과 일치시킨 뒤 순서 검사를
추가하고 [BIS 네 번째 개발 시도](evidence/m31-w02-dev-candidate/m31-bis-dev-04.json)에서
20회 × 100 유효 수신, 2,000/2,000, 중복·순서 오류·손상 0, 양 BIG 해제·재시작을
확인했다. 별도 빈 controller slot 100개는 payload 손실이 아니며 `source_clean=false`
후보이다. clean source commit 재빌드·실기 전에는 BIS subcase를 PASS로 승격하지 않는다.

두 HIL runner는 SHA-256 probe identity로 각각 한 보드/두 보드를 고르고 배타 lock을
잡는다. CMSIS-DAP V2의 비파괴 DP/AP 결과는 DP IDCODE `0x6ba02477`, AHB AP IDR
`0x84770001`, CTRL AP IDR `0x32880000`, APPROTECT 0을 보였다.
DP TARGETID `0xf0000f40`은 읽은 관찰값이며 별도 SoC 판정 mask로 확대하지 않았다.
sector flash, image SHA, nonce, 익명 역할 mapping, raw UART SHA와 실패 이유를 attempt별로
기록했다. probe UID 원문을 파일·문서에 보관하지 않았고 mass erase/recover·전원 차단을
수행하지 않았다. 원본은 새 clean commit 기반 재빌드·실기 증거와 별도로 유지한다.

W03 Audio 11개, W04 raw IQ/CTE, W05 CS procedure, W06 회귀, W07 예제
실행, W08 원장/문서 마감 순서로 진행한다. 외장 실물 운용은 사용자 후속 `NOT_RUN`으로
남기되 구현·예제·자동 검사 case는 개발 책임으로 유지한다.
