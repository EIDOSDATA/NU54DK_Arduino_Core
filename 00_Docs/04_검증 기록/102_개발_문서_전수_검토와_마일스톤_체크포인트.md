## 다음 작업의 구체적인 순서

1. T13의 전용 runner·preflight를 구현한다. 지속 payload/sequence, 실제 경과 시간·byte/sample 수,
   loss/reset·service gap·DMA/guard와 STOP 후 반환을 관측하고 Host/target에서 검사한다.
2. [103번 후속 정정](103_TIMER_기능_완료와_T13_진행_경계.md)에 따라 TIMER는 95번의 실제
   기능 PASS 범위로 완료 정리했다. 새 TIMER 반복 실행은 다음 작업이 아니다. 외부 ADC 초기
   반복 기준과 실제 sweep 차이는 별도 기록하며 기능 PASS를 지우거나 100회 PASS로 확대하지 않는다.
3. T13 실기 범위에 맞춰 C→S, 이후 S→U를 사용자에게 GPIO 번호로 안내한다. 매 변경 전 USB 분리,
   변경 후 재연결·현재 결선 확인·새 exact UID/image·10 MHz controlled flash를 유지한다.
   과거 COM 번호·07:00 KST까지의 C 세션 확인서를 새 실기에 재사용하지 않는다.
4. QDEC 비의존 단독·동시 시험과 복구/전환 100회를 실행한다. QDEC20/21·C07은 HOLD로 남긴다.
   T13 전체 계획의 순수 지속 측정은 261분이다. 이 값에는 HOLD 대상도 포함하며 구현·결선·
   preflight·복구/전환·실패 조사 시간을 포함하지 않으므로 릴리스 ETA로 제시하지 않는다.
5. T14 결함 처리·T15 지원 범위를 확정한다. QDEC 제한을 해결하거나 명시적인 지원 범위 결정이
   필요하다. REPORT IRQ는 추가 기능/queue/overflow/연속 검증 전 자동 대안이 아니다.
6. T16~T18 사용자용 API/profile/예제·문서·공개 절차 → R14/T19 RC 고정·전체 회귀 →
   T20~T21 이중 재현·설치/업로드/제거/재설치/전환·비공개 stable 검사 → T22 승인 →
   T23~T25 공개·공개 URL 설치 검증·마무리 순서로 진행한다.
