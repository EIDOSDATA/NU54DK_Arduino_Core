## 1. 감사 범위

작업 시작 시 저장소에서 보이는 Markdown 269개를 구조·현행성·중복·가독성·UTF-8·내부 링크
기준으로 검토했다. 이 가운데 main 저장소가 관리하는 문서는 263개이며, 보드 submodule 문서
6개는 원본 소유권을 보존하고 읽기 전용으로 확인했다. M28 설계·검증 기록 2개를 추가한 최종
main 문서 분모는 265개다.

| 문서군 | 검토 내용 |
| --- | --- |
| Root·AGENTS·문서 색인·TODO·인계 | 현재 지원 버전, 완료/미착수 상태, 사용자와 개발자 진입 동선 |
| 사전 조사·설계 42개 | 현행 계약과 역사 설계 구분, v0.4.1 적용성, M28 단일 원본 |
| 검증 기록 130개 | 당시 FAIL/HOLD/NOT RUN 보존, 후속 해결 링크, 최근 기록 색인 |
| 버전별 릴리스 문서 | v0.4.1만 현재 지원, 이전 버전은 immutable 역사 자료 |
| Tests·tools·packaging 문서 | 실제 명령·경로·지원 channel과 구현 일치 |
| Third-party·board submodule | 상위 저장소에서 임의 수정하지 않고 소유권·링크만 확인 |

기계 검사는 모든 제목, 파일 끝 개행, trailing whitespace, 빈 파일과 동일 byte 중복 후보도
확인했다. 최초 리팩토링 참고 문서의 줄끝 공백 2개를 제거했다.

소급 변경하지 않았다. 현재 계약을 설명하는 문서의 잘못된 “현재” 표현만 교정했다.

## 3. 삭제 판정

삭제한 문서는 없다. 삭제 후보처럼 보인 이전 TODO, 버전별 Release notes와 검증 기록은 다음
이유로 유지한다.

- 이전 tag·Release·package byte의 감사와 재현 근거다.
- 최초 FAIL과 후속 해결의 연결을 보존한다.
- 현재 문서가 과거 기준선 또는 제한의 출처로 참조한다.
- 리팩토링 최초 설계안도 현행 문서 3개가 판단 비교 근거로 참조한다.

따라서 “오래됐다”는 이유만으로 제거하면 링크와 증거 사슬을 훼손한다. 실제 중복 byte·빈 문서·
참조 없는 임시 보고서는 발견되지 않았다.

## 4. M28 준비 산출물

### 4.1 기준선과 정적 지원 원장

- v0.4.1 source version `0.4.1-dev`
- NCS `v3.4.0` revision `99553055607b2e9885fbc80ccd11fa9da81c2df0`
- Zephyr revision `bf801e4e3d19e1ffa76164346480cb7734dd2800`
- Windows Toolchain bundle `dcbdc366a1`
- 보드 revision `fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3`
- 현재 BLE: `CONFIG_BT_MAX_CONN=1`, 단일 active/pending slot, legacy 31-byte advertising

설치된 NCS source와 CI lock의 revision을 일치 확인했다. SDC multirole 변형과 Zephyr host에는
multi-role/link, extended·periodic advertising, PAST, PAwR, privacy와 link-control 후보가 있다.
이는 정적 `candidate`이며 실제 HCI는 **NOT RUN**이다.

허용하지 않는다.
