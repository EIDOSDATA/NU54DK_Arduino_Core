# 262 — M31 메모리 최적화 P2 세 축 완료

## 범위와 최종 판정

2026-09-25 `M31-MEM-OPT`의 시작 HEAD
`46d4fb101513143d89b8533636e3ed671212fea4`에서 P2의 남은 세 기술 축을 실행했다.
NCS `v3.4.0`, Zephyr `4.4.0`, 제품 Nordic SDC, board gitlink
`fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3`를 유지했다. 결과는 다음과 같다.

| P2 축 | 판정 | 완료 근거 |
| --- | --- | --- |
| 지원 범위의 미계측 오류·최악 부하 | **PASS** | CoC 상대 credit 직접 고갈·복구, 지원 Audio 다중 stream과 암호화 오류·복구, CS 256-step 진행 중 peer 이탈·복구를 유한 조건으로 실행하고 같은 수명의 stack/heap을 기록했다. |
| 메모리 안전 여유·최종 크기 | **PASS** | 정상·오류·복구 부하의 stack high-water, malloc/kernel heap 반환, bounded pool 고갈과 SDC 정적 계약을 대조했다. 축소 근거가 없는 기존 크기는 유지했다. |
| 동등 조건 Nordic native FLASH/RAM | **PASS** | 같은 SDK·보드·SDC·기능·역할·보안·MTU·codec/stream·로그·계측·linker 영역의 CoC와 Audio 두 쌍을 ELF/map 기준으로 비교했다. native에 Arduino 과대 설정을 추가하지 않았다. |

따라서 **메모리 최적화 P2는 완료**다. P0·P1·P2가 모두 완료됐지만 이는
M31-W04/W05 전체 완료, W06~W08 착수, 기본 메뉴 전환 또는 v0.5.0 공개 승인이 아니다.
다음 기능 작업은 W04·W05이며 이 기록에서는 자동 착수하지 않는다.

## 1. 오류·최악 부하 실기

각 실행은 probe SHA-256 identity·COM·역할·image SHA-256을 다시 결합하고, 두 exact 보드만
배타 lock·watchdog·명령 lease 아래 사용했다. flash는 exact 대상 sector와
`auto_unlock=false`를 유지했으며 mass erase·unlock·recover·전원/USB/배선 변경은 없었다.
원본 JSON에는 익명화한 probe hash와 COM·image hash·flash 방법·UART가 들어 있다.

| 기능 | 고정 조건 | 관찰과 복구 | 판정·원본 |
| --- | --- | --- | --- |
| CoC 상대 credit | Arduino central + native peripheral, 한 ACL·CoC 두 채널, SDU 512 B, peer 실제 초기 credit 1, client 제출 4, 정지 관찰 2,500 ms | peer가 첫 SDU 반환을 보류하는 동안 추가 수신 0. credit 1개 반환 뒤 queue의 3개 echo가 진행됐고 새 SDU 1개도 echo, 양측 STOP | **PASS**. [최종 원본](evidence/m31-p2-three-axes-20260925/coc-peer-credit-r2.json) |
| Audio 다중 stream | 지원 BAP unicast duplex의 양방향 두 stream, 각 방향 10,000 frame 및 즉시 종료 20회 | 양쪽 송신·decode 목표, drop 0, 양측 STOP | **PASS**. [258번](258_M31_P2_Audio_양방향_장시간과_종료_복구.md) |
| Audio 암호화 오류 | 암호화 BIS source/sink, LC3 16 kHz mono·40 B/10 ms, 첫 Broadcast Code 1-byte 불일치 | native `-61`, 오류 전 decode 0. 같은 source의 올바른 Code로 재시작해 100 frame·drop 0·PCM energy 확인, 양측 STOP | **PASS**. [원본](evidence/m31-p2-three-axes-20260925/audio-encryption-recovery.json) |
| CS peer 이탈 | secure ACL, local/peer 각 256 step의 최대 진단 절차, 첫 raw 전 reflector SWD CPU reset | initiator disconnect·reflector 재기동·자동 재연결 뒤 새 유효 raw 20개, counter 0~19·중복/역행 0·양측 STOP | **PASS**. [원본](evidence/m31-p2-three-axes-20260925/cs-peer-loss-recovery.json) |

첫 CoC 시도는 peer가 네 credit을 보유할 것이라는 잘못된 조건 때문에 **FAIL**했다.
고정 Zephyr endpoint가 실제 광고한 초기 credit은 1이었으며, 이 실패를 성공으로 덮어쓰지 않고
[원본](evidence/m31-p2-three-axes-20260925/coc-peer-credit.json)에 보존했다. 최종 시험은 실제 credit 1을
직접 보유하고 세 SDU의 peer-credit 대기와 반환 뒤 진행을 확인한다. [257번](257_M31_P2_CoC_송신_버퍼_부하와_복구.md)의
로컬 TX `net_buf` 네 개 포화·다섯 번째 busy와 다른 증거다. 원인 없는 재시도나 timeout 연장으로
PASS를 만들지 않았다.

최종 CoC JSON의 최초 `recovery` 설명에는 반환 credit을 4개라고 쓴 metadata 오류가 있었다.
실제 UART 원본과 분모는 처음부터 `held=1`, 반환 1개, 대기 SDU 3개였으며 해당 설명만 바로잡고
`metadata_correction`에 정정 사실을 남겼다. 측정 line과 PASS 판정은 바꾸지 않았다.

CS 이탈 주입은 물리 전원 차단이 아니라 승인 범위의 SWD CPU reset이다. 간헐적인 전진 counter gap은
비차단 관찰값이지만 이번 복구 구간은 중복·역행 없이 20개를 모두 완료했다. 제품 SDC DF IQ RX,
LL connectionless fault 해결, 임의 다중 link와 모든 조합은 P2 분모에 추가하지 않았다.

## 2. Stack·heap 여유와 최종 크기

[machine-readable 최종 판정](evidence/m31-p2-three-axes-20260925/memory-finalization.json)은 새 세 실행의
모든 `P2_STACK`·`P2_MALLOC`·`P2_KHEAP` checkpoint를 집계하고 258·260번의 지원 최악 부하와 대조한다.
아래 `used/reserved B`는 역할별 전체 관찰의 가장 큰 값이며 정적 symbol 크기와 합산하지 않는다.

| 항목 | 최댓값 | 최소 관찰 여유 | 최종 결정 |
| --- | ---: | ---: | --- |
| main | Audio duplex client `3,568/8,192` | 4,624 | `8,192` 유지. 새 오류 실행도 최대 `3,192`였으나 profile 공통 축소 근거가 아니다. |
| system workqueue | CoC native peer `912/4,096` | 3,184 | `4,096` 유지. 여러 기능이 공유하며 조합별 축소 근거가 없다. |
| BT RX workqueue | Audio/CS `1,520/3,200` | 1,680 | `3,200` 유지. 독립 지원 부하 둘에서 같은 최고치다. |
| BT long workqueue | Audio/CS `1,168/2,104` | 936 | `2,104` 유지. Bluetooth Host 공통 경로다. |
| MPSL work | CS reflector `760/1,024` | **264** | `1,024` 유지. 가장 작은 관찰 여유라 축소하지 않는다. |
| libc malloc | 모든 표본 allocated/peak `0/0`, 종료 free `8,108` | 해당 없음 | arena `8,192` 유지. 선택 경로의 0 사용만으로 standard/full·선택 library 호환 예약을 줄이지 않는다. |
| feature kernel heap | CoC allocated/peak `0/0`; CS initiator peak `264`, 종료 allocated `0` | 역할별 설정 | 현재 역할별 값을 유지. Audio source는 의도대로 kernel heap 0이다. |

257번의 다섯 번째 CoC 송신 `busy`는 bounded `net_buf` 할당 실패를 fail-closed로 처리하고 앞선 네
buffer 반환·재연결을 확인한 결과다. 이번 직접 peer-credit 고갈에서도 무한 할당·무한 재시도는 없었다.
측정 경로가 libc malloc을 사용하지 않아 인위적 malloc 고갈 주입은 `NOT RUN`이며, 지원 consumer가
없는 합성 실패를 PASS gate로 만들지 않는다. 모든 새 실행의 최종 heap allocated는 0이고 양측 STOP이다.

계측 출력은 ready·오류·복구·STOP checkpoint에 두고 acceptance counter 밖에서 실행했다.
timeout은 wall-clock 기준으로 유한하며, native 비교에도 같은 thread analyzer·heap statistics를 넣었다.
계측 때문에 실패가 성공으로 바뀌는 무한 retry 경로는 없다.

SDC pool은 [248번](248_M31_P2_SDC_pool_정적_경계_감사.md)의 고정 SDK 역할/count 산식,
초기화 시 요구량 검사와 8-byte 주소 정렬을 유지한다. `sdc_mempool` symbol은 정적 예약이며 runtime
사용량으로 해석하지 않는다. 내부 high-water 비노출은 추가 gate가 아니고, 근거 없는 pool 축소는 없다.

## 3. Nordic native 동등 조건 비교

비교 도구와 [원본 JSON](evidence/m31-p2-three-axes-20260925/native-memory-comparison.json)은 Arduino build
manifest와 양쪽 ELF/map/config hash, 상위 RAM symbol, 이름으로 명확한 Arduino/NUCODE symbol 비용
하한을 기록한다. 두 쌍 모두 NCS v3.4.0·Zephyr 4.4.0·NU54DK target·제품 SDC·loaderless
`slot0 [0, 0x16c000)`·RAM 256 KiB·로그 OFF·동일 계측 조건이다.

| 동등 기능쌍 | Arduino FLASH/RAM B | native FLASH/RAM B | Arduino-native B | 이름으로 식별한 API symbol 비용 하한 FLASH/RAM B |
| --- | ---: | ---: | ---: | ---: |
| CoC peripheral server, 1 link·2 channel·MTU/SDU 512·SMP, TX buffer 4 | `215,888 / 82,181` | `150,236 / 64,792` | `+65,652 / +17,389` | `10,408 / 12,870` |
| 암호화 LC3 BAP broadcast source, 1 stream/subgroup·40 B/10 ms·TX 6 | `246,736 / 55,747` | `240,884 / 64,528` | `+5,852 / -8,781` | `4,734 / 8,520` |

CoC Arduino image는 공개 L2CAP capability의 dual-role·`CONFIG_BT_MAX_CONN=2` 계약을 포함한다.
native는 실제 비교 역할만 `CONFIG_BT_MAX_CONN=1`로 두었고 central/observer/broadcaster를 추가해 차이를
숨기지 않았다. 이 역할 폭과 Arduino runtime·Serial·NUCODE GAP/L2CAP event/lifetime 상태는 재사용 가능한
공개 API 비용이다. ELF/map에서 동일 payload/pool의 불필요한 중복 사본은 발견하지 않았다.
`sdc_mempool`·연결 state·scan queue 차이는 이 역할/capacity 차이를 포함하므로 전체 delta를 순수 wrapper
비용이나 즉시 제거 가능한 RAM으로 계산하지 않는다.

Audio native upstream sample은 별도 encoder thread와 **16,384 B stack**을 보유한다. 그래서 raw native
RAM이 더 크지만 이를 Arduino API 절감으로 해석하지 않는다. Arduino는 inline sketch loop와 NUCODE
codec state를 사용한다. 반대로 FLASH `+5,852 B`와 이름으로 식별한 API symbol 하한은 공개 API 비용으로
명시한다. 두 비교에서 제거할 불필요한 중복 pool이 확인되지 않아 runtime source나 최종 크기를 억지로
변경하지 않았다. 조건이 다른 [250번 Nordic RAS 진단](250_M31_P2_native_CS_비교와_DF_재진단.md)은
이 PASS의 수치·분모로 사용하지 않았다.

native Audio의 첫 build는 계측 module header 포함 순서 오류로 **FAIL**, 수정 뒤 PASS했다. 저장영역을
Arduino와 맞추는 CoC 재구성도 Windows 역슬래시가 CMake escape로 해석되어 한 차례 **FAIL**했고,
forward-slash 경로로 고쳐 PASS했다. 실패 원인을 숨기지 않으며 두 최종 build만 비교 수치로 사용한다.

## 4. 변경·회귀·실물 종료 상태

추가한 재현 자산은 CoC credit 제어 native peer와 runner, Audio wrong-code sink와 runner,
CS peer-loss runner, native Audio 계측 module/overlay, 자원 비교·최종 판정 도구다. 코드 변경은
CoC client의 유한 credit 시험 명령에 한정하며 standard/full 기본값과 SDK/controller는 바꾸지 않았다.

| 검사 | 결과 |
| --- | --- |
| 새 Python runner·비교 도구 문법 | `py_compile` PASS |
| CoC Arduino client / native peer build | PASS |
| Audio wrong-code sink / native encrypted source build | PASS |
| 본 저장소 Markdown UTF-8·로컬 링크 | `python tools/ci/run_m12_gate.py docs` — 420개 PASS |
| 생성 계약·coverage 문서 drift | 4개 생성기·5개 산출물 PASS, coverage byte 비교 PASS |
| M31 readiness 계약·회귀 | `M31_CONTRACT_OK`, readiness 7/7 PASS |
| 관련 P2 Host 회귀 | CS 6/6, Audio broadcast 2/2, unicast 2/2, adaptive scan 3/3 — 합계 13/13 PASS |
| 공백·감사 원장 | `git diff --check` PASS, Markdown 426개 hash·path·중복 독립 대조 PASS |

관련 P2 Host 회귀의 첫 시스템 Python 실행은 `pyserial` 부재로 세 모듈을 import하지 못해
**FAIL**했다. 제품 회귀로 분류하거나 PASS로 덮지 않았고, 고정 NCS Python의 `PYTHONHOME`을
명시해 같은 source를 다시 실행한 10/10 결과와 의존성이 없는 adaptive 3/3만 최종 회귀로
계산했다. 최종 Arduino 재빌드의 첫 명령도 기본 설치 v0.4.0 CLI가 개발 `adaptive` 값을
거부했고, 두 번째 명령은 P2 계측 local library 경로 누락으로 compile 전에 실패했다. 저장소
개발 CLI config와 `p2_memory_telemetry` 경로를 함께 고정한 재실행에서 CoC·Audio 두 image가
각각 PASS했다. CI/CD 실행 요청·상태 조회·대기는 하지 않았다.

마지막 실기는 CS initiator/reflector가 모두 STOP을 출력하고 clock·핀 반환 경로를 완료했다. 이는 이후
연결 상태를 보증하지 않는다. 다음 HIL은 다시 probe identity·COM·role·image hash부터 확인해야 한다.
CI/CD 실행 요청·상태 조회·대기는 하지 않았다. main 반영·squash·release/tag/catalog 공개도 하지 않았다.

## 5. 인계

P2 이후 순서는 **W04·W05 → W06 → W07 → W08**이다. W04는 지원되는 CTE TX·response와 제품 SDC
IQ RX/AoD `UNSUPPORTED` 경계를 예제·지원표·원장에 마감한다. W05는 P2의 peer-loss 결과를 재사용하되
전체 기능 계약의 wrong-key와 flash 직후 경계를 별도로 닫는다. W06은 독립 role image 자원·수명주기와
M19~M30 영향 회귀이고 네 기능 전체 동시 실행 요구가 아니다. HOST-W04~W08은 사용자 지시대로 보류한다.
