## 2. W07-D 세 보드 mixed-link

세 NU54DK와 독립 DAP/UART를 peripheral·mixed·central에 하나씩 고정했다. 추가 GPIO 배선은
사용하지 않았다. Runner는 세 image의 build record, Core/application/board digest와 세 UID를
검사한 뒤 flash하고 UART를 열었다. 같은 128-bit nonce를 advertising manufacturer data와 세
transcript에 결합했고 수신측이 link별 sequence와 payload를 검증했다.

| Role | 연결 | GATT tx/rx | CoC tx/rx | 오류 |
| --- | ---: | ---: | ---: | --- |
| peripheral | 1 | 0 / 1,000 | 1,000 / 1,000 | cross-link·payload·drop 0 |
| mixed | 2 | 1,000 / 1,000 | 2,000 / 2,000 | cross-link·payload·drop 0 |
| central | 1 | 1,000 / 0 | 1,000 / 1,000 | cross-link·payload·drop 0 |

Mixed DUT는 local central 1-link와 peripheral 1-link를 동시에 유지했다. 각 link의 GATT와 CoC가
각각 1,000회 완료됐고 callback은 main thread에서 generation handle별로 분리됐다. Host source·parser
시험은 20/20 PASS, target은 peripheral/mixed/central 3/3 PASS였다.

| Role | FLASH | RAM |
| --- | ---: | ---: |
| peripheral | 252,036 B | 136,282 B |
| mixed | 256,984 B | 136,402 B |
| central | 251,608 B | 136,210 B |

## 4. Windows/Intel GATT 상호운용

Windows 11의 Intel Wireless Bluetooth와 Bleak 3.0.2 WinRT backend를 독립 central peer로
사용했다. 첫 시도는 과거 `NU54DK-HID` identity의 Windows pair/cache가 남아 새 M20 GATT service가
보이지 않아 중단했다. 해당 test identity 하나만 WinRT unpair하고 전체 GATT database를 탐색하도록
수정했다. 다음 시도는 첫 round의 GATT 동작 뒤 두 번째 scan에서 WinRT `ERROR_CANCELLED`로
종료됐다.

수동 timing probe에서 Bleak client close는 시작 후 3.11초, target의 실제 DISCONNECTED와
READVERTISE는 6.16초에 관측돼 물리 link 해제 지연이 3.05초임을 확인했다. 고정 대기를 1초에서
5초로 바꾸고 같은 조건에서 재검증했다. 무한 재시도나 오류 무시는 사용하지 않았다.

| 관측 | 결과 |
| --- | --- |
| 광고 이름·service UUID | `NU54-GATT`, `8e7e2001-…` PASS |
| service·characteristic discovery | exact UUID PASS |
| property | read, write, write-without-response, notify, indicate PASS |
| payload | 128-bit nonce read, `WR` response write, `WC` command write PASS |
| server→client | `NTF1`, `NTF2`, `IND1` PASS |
| 수명주기 | connect/disconnect 2/2, target readvertise PASS |

이 결과는 Windows/Intel의 기본 M20 GATT 범위다. Windows EATT·robust caching, 다른 adapter와
Android/iOS/Linux는 확인하지 않았다.

## 6. W08 코드·예제 재검토

세 보드 target의 `main.cpp`가 896줄로 길어진 것을 확인했다. 상태와 진입점은 146줄에 남기고
protocol, RF, traffic, GAP/CoC event, Host command를 각각 350줄 이하 implementation fragment로
분할했다. 세 role을 다시 build해 FLASH/RAM이 분할 전과 byte 단위로 같음을 확인했다. 이어 exact
`ab3f85d3cb505f8f82865becfbd8bd0fe8511f27`을 세 보드에 flash해 같은 `M29-MULTI-01`을
재실행했다. Mixed 2-link, link별 GATT·CoC 1,000회, cross-link·payload·drop 0과 callback
context PASS를 다시 확인했다. 실행 nonce는 `15d075f926c449e71e913eb6ba4524dc`이며 세 역할의
build record·image SHA-256·DAP/UART identity와 원시 transcript를 새 manifest에 결합했다.
Test 전용 구조 변경이며 production BLE library의 동작은 바꾸지 않았다.

`MixedGattCocLinks` 예제는 같은 Sketch의 `NodeRole::peripheral`, `mixed`, `central`을 바꿔 세
보드에 업로드한다. Mixed 보드는 client/server connection과 CoC channel을 각각 generation handle로
분리하고, GATT write response와 32-byte CoC echo가 모두 끝나야 같은 sequence를 PASS로 출력한다.
실패한 시작 함수와 cross-link·payload 오류는 Serial에 표시하고 추가 traffic을 중단한다.

전체 Host gate가 새 3-role testcase의 canonical Zephyr 행렬 누락을 처음 거부했다.
`run_zephyr_build.py`의 v0.5.0 그룹에 peripheral·mixed·central 3개를 등록하고
그룹 36개·전체 104개로 문서와 시험을 동기화한 뒤 같은 Host gate를 처음부터 끝까지
재실행해 PASS했다. 개별 로컬 결과는 다음과 같다.

| --- | --- |

## 7. 지원·인계 판정

- M29 W01~W08과 `M29-CAP/LONG/DESC/CACHE/COC/NEG/SIGN/EATT/MULTI/REG-01` 10개를 완료했다.
- Signed Write는 deprecated legacy opt-in, EATT는 experimental opt-in·기본 OFF 상태를 유지한다.
- SDK source candidate를 실제 HIL PASS로 대신하지 않았고 test ID별 exact evidence를 연결했다.
- 외부 RF sniffer는 사용하지 않았다. 3보드 packet 분모는 수신측 sequence·payload와 같은 nonce의
  세 UART로 검증했다.
- 다음 작업은 M30 BLE Security·Profile·최소 secure BLE DFU의 계약·capability·수치 gate다.
- 공개 v0.5.0, mobile/desktop 전체 상호운용, qualification은 M29 완료 범위가 아니다.

최종 Host·Arduino·문서·package gate와 push commit의 GitHub CI 결과는 이 기록의 완료 commit과
CI run에서 확인한다. Node.js 20 사용 중단 annotation은 비차단 경고로 분리한다.
