### 환경성 일회 실패의 분리

- 30개 예제를 병렬 compile할 때 `NUCODE BLE / CustomGattCentral` 한 건이 compiler 진단 없이
  process exit 1로 종료됐습니다. 같은 공개 설치본·설정으로 단독 재실행해 compile·link와 최종
  artifact를 확인했고 전체 결과를 30/30으로 마감했습니다. 재실행 HEX SHA-256은
  `7b41a1416110c6f65b9b1317c5ff00c5b043335fb9e56f33312d096e6f9a307b`입니다.
- 최초 Blink compile은 ELF·HEX·BIN을 정상 생성한 뒤 size helper가 Windows application control
  `WinError 4551`로 한 번 차단됐습니다. 동일 helper 직접 실행과 같은 compile 재실행은 정상이며
  Flash 107,728 byte, RAM 77,799 byte를 보고했습니다. source/package 결함으로 판정하지 않습니다.

## T25 문서·정책·CI 마감

Stable index 공개 직후 `e53affd4`의 Reproducible Builds는 통과했지만 Software Gates는 실패했습니다.
실패 원인은 새 archive가 아니라 검사 계약이 과거 `0.3.0` 단독 stable index의 크기·hash와 허용
version만 기대한 것이었습니다. 다음 항목을 공개 상태에 맞게 갱신했습니다.

- 영구 stable version/commit/archive/legal-review allowlist에 `0.4.0` 추가
- stable 생성기의 0.4.0/0.3.0 순서와 과거 0.3.0 archive 불변 계약 고정
- M18/M22/M27 release 도구의 public root index exact identity 갱신
- package·release 회귀 검사에서 공개된 0.4.0 재게시를 fail-closed로 거부
- README, TODO, 로드맵, 지원 문서와 검증 기록을 공개 완료 상태로 정리
- 기존 R12 Host fixture 2개의 clang-format drift를 교정하고 관련 native 시험과 423개 style 검사를 재통과

최종 문서·정책 commit은 release source/tag/archive byte에 영향을 주지 않습니다. 그 commit의 로컬
전체 gate와 GitHub Software Gates·Reproducible Builds 결과를 확인해 T25를 마감합니다. CI 결과는
검사 대상 commit 이후에 생성되므로 같은 commit 문서 안에 자기 자신의 run ID를 고정하지 않고
GitHub Actions의 해당 commit 결과를 최종 판정으로 사용합니다.

실행 중인 build/upload 프로세스는 없습니다. 저장소 밖 T24 격리 설치·로그는 최종 검증 증거로
보존하고, 작업 중 만든 재생성 가능한 보조 script만 제거했습니다.

## 최종 지원·비보증 경계

- QDEC20/21은 기본 정·역회전과 SAMPLE/REPORT event 누산을 지원합니다. 동작 중 반복 manual
  `read()/clear`의 무손실 누산은 보증하지 않습니다.
- 반복 Serial personality handover는 검증·보증 범위에서 제외합니다.
- 모든 주변장치 동시 조합을 보증하지 않습니다. 검증한 단독·동시·충돌 조건만 근거로 사용합니다.
- 정밀 ADC 정확도, clock jitter, 음질과 신호 무결성은 기능시험 범위 밖입니다.

위 항목은 숨은 미완료 시험이 아니라 프로젝트 소유자가 승인한 제품 지원 경계입니다. 과거 실패·
미실행 기록은 당시 조건의 이력으로 보존하며 PASS로 소급 변경하지 않습니다.
