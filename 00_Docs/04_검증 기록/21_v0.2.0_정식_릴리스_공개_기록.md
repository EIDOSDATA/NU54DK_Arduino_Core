## 1. 기록 원칙

`v0.2.0`은 RC2 tag나 자산의 이름을 바꾸지 않고 별도의 source commit, annotated tag,
stable package, Boards Manager index와 GitHub Release로 공개했다. RC1·RC2의 exact 수치와 HIL은
역사 기록으로 보존하고 stable exact HIL로 소급 표기하지 않는다.

정식 ZIP의 version-independent runtime payload는 RC2와 같은
`ec604501b2ba58b622c3490925a79c8ac716bba93f0938840e49c624a16998c8`이다. 공개 전 두 번의
독립 package 생성 결과와 공개 후 인증 없이 다시 받은 7개 자산은 각각 byte-for-byte 일치했다.

## 6. 공개 Boards Manager 수명주기

기본 Arduino 사용자 환경과 분리한 Windows 환경에서 Release asset index를 사용했다.

| 환경 | 값 |
| --- | --- |
| OS | Windows 11 Pro x64 `10.0.26200` |
| PowerShell | `7.6.4` |
| Arduino CLI | `1.5.1` / commit `01f3d4f2b` |
| Board/FQBN | NU54DK / `nucode:zephyr:nu54dk` |
| Arduino data/download/user/build | 저장소 `build/release/v0.2.0/lifecycle` 아래로 격리 |
| Nordic prerequisite | 기존 `%USERPROFILE%\ncs`와 NUCODE 완료 marker를 검증 후 재사용 |

실행 결과는 다음과 같다.

1. 공개 index 갱신과 검색에서 `0.2.0`, `0.1.0`을 열거하고 latest `0.2.0`을 확인했다.
2. `0.1.0`을 설치하고 Nordic prerequisite verifier PASS를 확인했다.
3. `0.2.0`으로 upgrade하고 설치 version과 latest가 모두 `0.2.0`인지 확인했다.
4. 공개 설치본 Blink를 clean compile했다. Flash `56,396` bytes, RAM `16,769` bytes였다.
5. `0.1.0`으로 downgrade하고 installed `0.1.0`, latest `0.2.0`을 확인했다.
6. `0.2.0`을 재설치하고 prerequisite verifier와 두 번째 Blink clean compile을 통과했다.
7. `nucode:zephyr`를 uninstall하고 Core 목록과 격리 package 디렉터리에서 제거됐음을 확인했다.

두 Blink compile은 같은 Flash/RAM 결과를 냈다. `NRF_PLATFORM_LUMOS` 폐기 경고는 알려진 NCS
경고이며 compile은 성공했다. 이 시험은 Arduino CLI 상태를 격리했지만 대용량 NCS/Toolchain은
제품 설치 계약대로 공유 prerequisite를 재사용했다.

## 7. 승격 근거와 경계

- RC2 공개 설치본의 예제 14/14 compile, 명시 UID upload, UART READY와 BLE NUS 양방향
  transparent bridge PASS를 승격 전 실기 근거로 사용했다.
- stable은 별도 exact package를 두 번 생성해 byte 재현성과 RC2 runtime payload 동등성을
  확인했다.
- stable exact package에서 RC2의 모든 물리 HIL을 다시 실행했다고 주장하지 않는다.
- 정식 공개 뒤 수행한 시험은 package 설치 수명주기와 Blink compile이며 보드 upload/HIL이 아니다.
- 배터리 전기 HIL, 범용 BLE GATT·보안, 802.15.4, Thread와 Matter의 v0.2 비지원 경계는
  [알려진 제약](../05_릴리스/v0.2.0/KNOWN_ISSUES.md)을 유지한다.

## 8. 최종 판정

`v0.2.0`은 정식 stable 및 GitHub latest로 공개 완료했다. 정식 source, tag, 7개 자산,
stable index, 공개 URL과 Boards Manager 수명주기가 모두 고정되었으므로 M18의 최종 상태는
`stable-release-published`다. 다음 개발 기준선은 M19부터 시작하는 `v0.3.0`이다.
