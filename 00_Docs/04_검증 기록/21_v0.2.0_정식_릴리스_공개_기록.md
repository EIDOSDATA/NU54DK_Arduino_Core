# v0.2.0 정식 릴리스 공개 기록

## 1. 기록 원칙

`v0.2.0`은 RC2 tag나 자산의 이름을 바꾸지 않고 별도의 source commit, annotated tag,
stable package, Boards Manager index와 GitHub Release로 공개한다. RC1·RC2의 exact 수치와 HIL은
역사 기록으로 보존하고 stable exact HIL로 소급 표기하지 않는다.

정식 ZIP의 version-independent runtime payload가 RC2의
`ec604501b2ba58b622c3490925a79c8ac716bba93f0938840e49c624a16998c8`과 같은지 확인하고,
stable 공개 URL에서 받은 자산의 크기와 SHA-256을 다시 검증한다.

## 2. 공개 identity와 자산

정식 공개가 끝난 뒤 이 절에 source commit, tag, Release 시각, 7개 자산의 크기·SHA-256과
stable index 계약을 고정한다. 값이 확정되기 전에는 RC2의 commit이나 checksum을 stable 값으로
복사하지 않는다.

## 3. Boards Manager 수명주기

정식 공개 URL을 사용하는 격리 환경에서 다음 수명주기를 확인한다.

1. stable index 갱신과 `0.2.0` 검색
2. `0.1.0` 설치 상태에서 `0.2.0` upgrade
3. package 사용자 예제 compile과 prerequisite 재사용
4. `0.2.0`에서 `0.1.0` downgrade
5. 다시 `0.2.0` 설치
6. Core uninstall 후 board 제거 확인

실행 결과, 도구 version과 공개 산출물 identity는 공개 후 확정 값으로 이 문서를 갱신한다.

## 4. 승격 근거와 경계

- RC2 공개 설치본의 예제 14/14 compile, 명시 UID upload, UART READY와 BLE NUS 양방향
  transparent bridge PASS를 승격 전 실기 근거로 사용한다.
- stable은 별도 exact package를 두 번 생성해 byte 재현성과 RC2 runtime payload 동등성을
  확인한다.
- stable exact package에서 RC2의 모든 물리 HIL을 재실행했다고 주장하지 않는다.
- 배터리 전기 HIL, 범용 BLE GATT·보안, 802.15.4, Thread와 Matter의 v0.2 비지원 경계는
  [알려진 제약](../05_릴리스/v0.2.0/KNOWN_ISSUES.md)을 유지한다.
