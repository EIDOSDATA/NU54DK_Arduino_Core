# 135 — M28-W03 확장 광고와 스캔

## 결론

M28-W03의 Host·target 범위를 완료했다. Production BLE profile은 extended advertising set 1개와
광고 payload 255 byte를 고정 상한으로 사용한다. 공개 API는 generation 기반 불투명 advertising
set handle을 사용하며, 확장 스캔 결과는 controller callback buffer를 보존하지 않고 metadata와
payload를 고정 queue value로 복사한다.

이 PASS는 production source의 Host 수명 계약과 고정 NCS v3.4.0 target compile/link에 적용한다.
두 보드 RF `M28-ADV-01`은 W07 전까지 `NOT RUN`이며 W01의 실제 HCI PASS로 대신하지 않는다.

## 구현 결과

| 항목 | 결과 |
| --- | --- |
| Public identity | `BLEAdvertisingSetHandle`, `BLEExtendedAdvertisingParameters`, `ExtendedAdvertising` |
| Set lifecycle | 고정 1-set, create/data/start/stop/remove, image 수명 generation |
| Payload | raw AD TLV 최대 255 byte·최대 16개 구조, 잘림·초과 fail-closed |
| Scan metadata | extended, SID, TX power, periodic interval, primary/secondary PHY |
| Callback isolation | instance와 generation 대조, 삭제된 set의 늦은 callback 폐기 |
| Legacy compatibility | `BLEAdvertising`·`BLEScan.start()` 유지, legacy payload 31 byte 유지 |
| 예제 | `ExtendedAdvertising`, `ExtendedScanner` |

Target build는 NCS `99553055607b2e9885fbc80ccd11fa9da81c2df0`, Zephyr
`bf801e4e3d19e1ffa76164346480cb7734dd2800`, board
`fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3`, toolchain bundle `dcbdc366a1` 조건에서 수행했다.

첫 target 시도는 시험 코드가 Zephyr 최소 C++ library에 없는 `<array>`를 사용했고 scan option의
명시적 `uint8_t` 변환이 없어 compile 단계에서 실패했다. 두 원인을 분류해 C 배열과 명시적 변환으로
수정한 뒤 같은 board·SDK·suite를 재검증해 통과했다. 이어진 실행환경 오류는 Nordic
`environment.json` 미적용으로 분리했으며, 고정 bundle PATH·PYTHONPATH·SDK 변수를 적용했다.
