## 2. 설치 예제 build와 수정

첫 두 clean campaign은 49개 중 `Lc3SyntheticLoopback` 한 개가 실패했고 제한 재시도도 실패했다.
첫 원인은 explicit compiler launcher와 Zephyr 내부 ccache의 중첩이어서 builder가 launcher를
지정할 때 `USE_CCACHE=0`을 함께 넘기도록 교정했다. 이후 verbose 직렬 build에서 Audio library가
공개 header를 통해 base `NUCODE_BLE` dependency를 노출하지 않아 backend compile이
`NUCODE_BLE.h`를 찾지 못하는 실제 원인을 확인했다.

`NUCODE_BLE.h`를 포함하도록 수정했다. 최종 source에서 LC3 단독 확인 build와 49개 전체 clean
campaign을 다시 실행해 모두 PASS했다. 앞선 primary·bounded retry 실패 JSON과 log는
`diagnostic-history.json`이 그대로 보존하며 최종 PASS로 덮어쓰지 않는다.

## 3. 3보드 HIL

최초 final-source preflight는 한 probe에서 `dp_targetid_observed` record가 누락돼 **FAIL**했다.
자동 unlock·recover를 수행하지 않고 실패 lease를 보존했다. 전원 재인가 뒤 읽기 전용 DP/AP
진단에서 3/3 접근·보호 상태를 확인하고, 허용된 제한 재시도 한 번으로 preflight를 PASS했다.

| family | 실기 결과 | 판정 |
| --- | --- | --- |
| Audio | BAP unicast duplex 종료·복구 20/20, 양측 STOP | **PASS** |
| CS | 유효 raw procedure 100/100, stop/restart 20/20, disconnect/reconnect 20/20, cleanup STOP | **PASS** |
| DF | 제품 SDC CTE beacon start/stop 20/20, invalid 20/20 거부 | **PASS** |
| ISO | peer/bridge/receiver 각 20/20, payload 2,000, missing 0, 세 역할 STOP 20/20 | **PASS** |

CS counter `58→60` 한 건은 정책대로 `observe_only`에 기록했다. 중복·역행은 없었고 유효 raw 수,
양측 STOP과 fault 조건을 모두 만족하므로 비차단이다. 정식 RAS runner도 순방향 gap은 기록하고
중복·역행만 fail-closed로 거부하도록 일치시켰다.

기능 flash는 모두 exact sector, `auto_unlock=false`로 수행했다. 자동 mass erase·unlock·recover는
사용하지 않았고, raw probe UID는 evidence에 저장하지 않았다. 마지막 ISO 시험은 세 역할의 STOP,
clock·pin 반환 경로를 확인한 상태로 종료했다.
