## GPIO/GPIOTE 준비 계약

기존 501 catalog와 명령의 의미를 보존하고 별도 공통 기능 catalog와 502 명령을 추가한다.
GPIO는 Arduino ID와 물리 net을 구분하며 API input/pull/output/open-drain과 peer pad·API
readback을 비교한다. 종료 때 입력 전환과 내부 handover로 소유권을 반환한다.

GPIOTE20 8채널·GPIOTE30 4채널을 승인 net에 순환 대응한다. 양쪽 역할에서 OUT/SET/CLR,
rising/falling/toggle, 100/1000 edge/s의 유한 1000에지를 각 10회 검사한다.
CPU task 신호원과 event poll의 실제 count·최대 poll 간격을 기록한다. 정밀 timing 측정은 아니다.
한 번에 net 하나만 출력하며 비대상 전체 net의 방향과 다른 채널 이벤트 누출을 검사한다.
잘못된 pin·채널·port는 입력 또는 사전 거부 경로로 검증한다.

이전 501의 102+3 PASS는 [99번](99_공통_결선_검사와_승인_전_자동_진행_계획.md)에 보존한다.
현재 기능 코드의 PASS로 복사하지 않는다.

## 첫 실기와 Host 판정 교정

Exact 645df82에서 clean pair 2/2와 clean M27 9/9를 확인한 뒤 controlled flash했다.
501의 102 net-round와 3 timeout, 양쪽 502 negative 2묶음은 통과했다. 첫 GPIO
A P1.14 반복 1의 open-drain LOW에서 Host가 `PIN_CNF=0x801`을 잘못 해석해 중단했다.
원본과 양쪽 cleanup은 [첫 실행 manifest](evidence/t12-common-gpio-645df82-first/manifest.json)에 보존한다.

고정 SDK `nrfx/bsp/stable/mdk/nrf54l15_types.h`의 DRIVE0[9:8]=S0(0),
DRIVE1[11:10]=D1(2)를 대조하면 0x801은 올바른 open-drain 출력이다.
Host의 이전 3bit DRIVE 해석을 `PIN_CNF & 0xF00 == 0x800`으로 교정하고 실제 첫 raw와
push-pull·다른 drive 조합의 거부를 Host 회귀에 추가했다. 코어 수정이나 현장 결선 수리로
기록하지 않는다. GPIO 완결 case는 0이며 GPIOTE task/edge도 미도달이다.
13:03:21 UTC 읽기 전용 postflight에서 두 role/source, 17 PIN_CNF=0·PWM/DPPI off를 확인했다.
