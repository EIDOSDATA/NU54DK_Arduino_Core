## GPIO/GPIOTE 준비 계약

기존 501 catalog와 명령의 의미를 보존하고 별도 공통 기능 catalog와 502 명령을 추가한다.
GPIO는 Arduino ID와 물리 net을 구분하며 API input/pull/output/open-drain과 peer pad·API
readback을 비교한다. 종료 때 입력 전환과 내부 handover로 소유권을 반환한다.

GPIOTE20 8채널·GPIOTE30 4채널을 승인 net에 순환 대응한다. 양쪽 역할에서 OUT/SET/CLR,
rising/falling/toggle, 100/1000 edge/s의 유한 1000에지를 각 10회 검사한다.
CPU task 신호원과 event poll의 실제 count·최대 poll 간격을 기록한다. 정밀 timing 측정은 아니다.
한 번에 net 하나만 출력하며 비대상 전체 net의 방향과 다른 채널 이벤트 누출을 검사한다.
잘못된 pin·채널·port는 입력 또는 사전 거부 경로로 검증한다.

이전 501의 102+3 PASS는 [99번](99_공통_결선_검사와_승인_전_자동_진행_계획.md)에 보존한다.
현재 기능 코드의 PASS로 복사하지 않는다.

push-pull·다른 drive 조합의 거부를 Host 회귀에 추가했다. 코어 수정이나 현장 결선 수리로
기록하지 않는다. GPIO 완결 case는 0이며 GPIOTE task/edge도 미도달이다.

## 다음 PWM·QDEC·I2S 기능 준비

- 508 steady PWM은 승인된 축별 축소 675조건을 실제 runner에 적용했다. 45 instance/slot/load
  identity별 15조건이다. TOP·길이 모든 값과 duty×극성을 유지하고 최장/최저속을 교차한다.
  전체 2700 Cartesian이나 완전 pairwise와 동등하다고 주장하지 않는다. 이전 full vector는 보존한다.
- 508 추가 PWM은 두 sequence의 25→75% 순서, repeats/end-delay 두 묶음(총 104주기),
  CPU/EGU20→DPPI20 START, 시작 전 peer idle LOW/HIGH의 192조건이다. triggered-step 96조건은
  25/50/75% 각각 100주기 유지와 공개 step 호출만으로 전진하는지 검사한다. 원본 TIMER edge,
  이벤트 순서·count와 16-byte guard를 기록하고 START 구독을 먼저 해제한 후 STOP한다.
- 520 QDEC은 두 instance·debounce on/off·2/10ms state·1/100/1000회전·10반복의 240조건이다.
  N회전 정방향 뒤 QDEC를 계속 실행한 채 N회전 역방향, read/clear, 대각 전이 1회전,
  stop/restart 뒤 1회전을 구별한다. ACC/ACCDBL의 작은 hardware 범위를 5ms read로 합산하며
  read 간격 15ms 초과·포화 경계는 실패다. 긴 회전 수를 invalid/restart 1회전에도 수행했다고 표시하지 않는다.
- 530 I2S는 양 master 역할·16/48kHz·8/16/24/32bit·stereo/left/right·32/256/1024 word·
  A→B/B→A/full-duplex의 432조건이다. 3 DMA 슬롯을 순환하여 초기 4개+측정 100개를 보존한다.
  장치가 모든 활성 sample을 독립 pattern과 비교하고 Host는 104개 raw CRC/첫끝 word·전역 순서·
  측정 100개의 completion 간격을 대조한다. TX-only/RX-only는 비활성 DMA에 실제 nullptr를 사용한다.
  STOP 전 tail은 100개 측정에 더하지 않는다. 시작 zero는 최대 8개 정렬 frame만 허용한다.

준비 중 I2S의 pin_size_t narrowing과 PWM peer role의 null pointer 경고를 교정했다.
통합 첫 DUT link는 RAM 5968-byte 초과로 실패했다. I2S slot을 4→3, PWM raw capacity를
1025→513으로 조정하여 요구된 word/측정 buffer/100주기를 유지했다. C:/cao04의 최종 준비
pair build는 13:47:28 UTC **2/2 PASS**다. 앞선 build 실패 원본은 삭제하지 않는다.
새 기능의 Host 12개와 T13 생산 route/결선 Host 2개가 통과했다. 이 source는 4e48252 이후
미커밋 준비이며 실제 flash용으로 쓰지 않는다. 최종 source 고정과 clean pair build가 뒤따른다.

[준비 manifest와 실패 포함 원본](evidence/t12-common-signals-preparation/manifest.json)에
91그룹 715시험(713 PASS·설치 CLI/dirty M27 조건부 SKIP 2개), 계약·package 20개·inventory와
정렬 로그를 보존했다. 이후 faulted handle을 정상 cleanup으로 반환하지 않도록 HIL STOP을
보강했고 최종 clean target에서 다시 컴파일한다. 제품 core source·board gitlink는 바꾸지 않았다.

후속 준비 commit은 c215eb84164d0a97f7898ae24e1530aa93445fcd다. 실제 flash 전에 I2S
STOP 응답의 guard와 lease 오류도 필수로 확인하도록 Host cleanup을 보강했고, 한쪽 guard 실패여도
양쪽 STOP을 시도하며 정상 PASS로 끝내지 않는 회귀를 포함해 관련 Host 3/3을 통과했다.
이 보강은 새로운 물리 실패를 고친 기록이 아니며 새 clean build로 검사한다.

## T13 조합·추가 결선 확정

[GPIO 전체 결선표·복구 판정](../../tests/hil/nu54dk/T13_PLAN.md)와
[실행 계획 JSON](../../tests/hil/nu54dk/v04_t13_topologies.json)을 추가했다. 동시 8개 중 C05만
3600초이며 나머지 7개는 900초, 단독 32개는 각 180초다. 순차 연속 측정은 4시간 21분이며
구현·복구 100회·결선·실패 조사는 별도다. 현재 C→S(P1.04/05 및 P2.02/04 교차),
S→U(UART00용 P2.00/02 및 P2.04/05 교차) 두 후속 단계가 필요하다.
단일 재결선으로 UART00·SPI00·PDM·모든 동시 조합을 완료할 수 있다고 안내하지 않는다.

실제 production `serial_fabric_routes.cpp`를 Host에서 컴파일하여 모든 계획 serial endpoint를
검사했다. 잘못된 P2 직결 SPI/UART는 거부하고 두 보드의 중복 GPIO/serial block을 검사했다.
이는 고정 board descriptor 조건의 정적 허용 증거이며 동시 DMA/clock/IRQ 실기 PASS가 아니다.
S/U는 현재 공통 catalog 허용 대상이 아니며 사람의 새 결선 확인 후 후속 runner를 준비해야 한다.
