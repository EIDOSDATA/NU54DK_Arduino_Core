# M31-W02 공개 ISO 예제 재점검과 완료 판정 정정

2026-09-17 공개 예제 구조를 다시 확인했다. `NUCODE_BLE_ISO`의 설치 `.ino` 11개는
모두 역할 enum을 선택하고 `Program::begin()`/`poll()`만 호출한다. 사용자가 `.ino`에서
SDU payload를 만들고 보내거나, 받은 payload·sequence·timestamp를 읽어 처리하는 API
호출은 없다. 실제 100-SDU 데이터·검증·재시작 절차와 `M31ISO`/`M31BIS`/`M31COMB`
Serial oracle은 `src/internal/NUCODE_ISO_*_Impl.inc`에 있는 시험 앱 구현이다.
Zephyr 직접 호출이 `.ino`에 없다는 경계는 지켰지만, 사용자가 편집할 수 있는
Arduino 데이터 예제로서의 계약은 충족하지 못했다.

이전 clean `e6ae812e…`의 11/11 package build와 CIS·BIS·암호화·wrong code·sync
loss·time sync·세 보드 combined HIL 원본은 그대로 유효하다. 그 결과는 고정 시험
payload가 실제 무선을 통과했다는 증거다. 공개 송수신 API와 예제의 완성까지 증명하지
않으므로 W02 작업 묶음을 `in_progress`, 완료 분자를 1/8로 정정했다. 167번 기록은
그 당시 판정과 원본 증거로 보존하고, 현재 완료 판정에는 이 기록을 우선한다.

`tools/ci/m31_example_audit.py`는 이제 역할별 `.ino`에서 명시적 시작·종료 및
송신/수신 데이터 API 흐름을 요구한다. 현재 82개 예제 중 ISO 11개를
`PUBLIC_ISO_DATA_FLOW_MISSING`으로 보고한다. 공개 library backend에 시험용
마일스톤 Serial oracle이 남아도 차단하도록 했다. `m31_contract.py`는 W02의
`public_example_status=PASS` 없이 완료 승격을 거부한다.

W02 완료에 남은 작업은 공개 ISO API에서 session·buffer 수명·전송·수신 frame과
sequence/timestamp·오류·종료를 노출하고, 11개 역할 예제에서 사용자 데이터 흐름을
보여 주는 것이다. Zephyr 호출은 library 내부에만 둔다. 각 역할을 다시 빌드하고
공개 `.ino`가 만든 payload의 2~3보드 HIL, 암호화·loss·재시작 회귀를 수행한 뒤
감사 0건과 새 exact source/image 근거로 W02를 다시 판정한다.

이 점검 이후 CIS central/peripheral 두 예제는 공개 `RawCis` API로 전환했고
[192번 실기](192_M31_W02_공개_CIS_사용자_SDU_실기.md)에서 검증했다. 현재 감사의
잔여 ISO 결함은 9건이며 W02 전체 완료 판정은 그대로 보류한다.

후속 [193번 BIS 실기](193_M31_W02_공개_BIS_사용자_SDU_실기.md)에서 source/receiver
두 예제도 공개 `RawBis`로 전환했다. 현재 잔여 공개 ISO 예제 결함은 **7건**이고
W02 전체 완료 판정은 계속 보류한다.

이어진 [194번 암호화 BIS 실기](194_M31_W02_공개_암호화_BIS_사용자_SDU_실기.md)에서
두 역할이 추가되어 현재 공개 ISO 예제 결함은 **5건**이다.

후속 [195번 시각 동기 BIS 실기](195_M31_W02_공개_BIS_시각동기_사용자_SDU_실기.md)에서
두 역할의 공개 payload·HCI 시각 API를 검증했다. 잔여 결함은 CIS→BIS 세 역할 **3건**이다.
