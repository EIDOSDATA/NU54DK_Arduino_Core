# T13 S 자동 실행 종료와 재개 항목

후속22:13 KST 결정: 자원 충돌은 사용자 수용으로 PASS/완료, 남은9조건 반복은 생략한다.
아래21:26의 실제 횟수는 당시 근거로 유지한다. 새 S 확인 후 세 복구 묶음 재검증은
[109번](109_T13_S_세_복구_묶음_재검증.md)을 따른다.

2026-09-08 21:26 KST 기준이다. 사용자가 지시한 U 재배치 전 자동 실행을 현재 S 확인 시간 안에서
수행했다. 마지막 실기는21:25:38에 종료했고12개 대열이 모두 종료 상태다. 시작하지 않은 조건의
`not-started-insufficient-session-time`은 실패나 합격이 아니다. S 확인 만료21:26:14를 연장하거나
새 확인으로 바꾸지 않았다. 이후 작업은 구현·Host/target·문서·Git/CI이며 새 물리 접근은 하지 않는다.

**T12 기능검증과 QDEC 문제 보고 후 검증 작업은 완료 상태를 유지한다. T13 S는 미완료다.**
S에서 남은 복구·진단을 끝내기 전에 U 배선만 바꾸면 된다고 안내하지 않는다.
아래 수치는 각각의 고정 소스와 시험 범위에 한정되며 최종 RC 소스의 전체 회귀 결과가 아니다.

QDEC 제외 결정은 이 다른 요구를 생략하는 승인으로 확대하지 않는다.

## 확인된 시험 도구 오류와 남은 실제 실패

- TWIM: 이전 정상 수신256byte의 RX AMOUNT가 다음 TX 단계 취소에도 남았다. 새 RX가 시작되지
  않았고 전체 RAM이0xCC로 유지된 증거를 필수로 확인하도록 판정기를 보강했다. core는 변경하지 않았다.
- CTS: 실제100ms HIGH 정지에 정상 전송용100ms 완료 간격을 그대로 적용했다. 양쪽 실제 HIGH가
  확인된 같은 fixture/seed의 영향받은 방향만 HIGH+frame phase+wire time+반올림을 허용한다.
  다른 방향/lane·주입 전·새 seed 재획득은100ms를 유지한다.
- UART line:9개 모두 PSEL 정상·ENABLE0·clock `[1,1,65537]` 이후 ARM 거부였고 실제 오류 주입에는
  도달하지 않았다. 고정 NCS의 `nrfx_uarte_init()`은 `prepare_tx()`에서 ENABLE을0으로 돌려두며
  RX/TX API에서 다시 활성화한다. RX 이전 ARM에 ENABLE 비영을 요구한 시험 코드가 원인이다.
  수정은 그 전제를 제거하고 selected/healthy/serial 상태·정책·준비·중복 ARM 방지는 유지한다.
  Host가 clock 실패와 ARM 거부를 구분하고 ARM 응답을 먼저 보존하도록 보강했다.
- SPI20/21/22: 최초 불일치가 모두 B P1.06→A P1.07 방향이지만 전기적 원인은 미확정이다.
  P1.07은 LED Schmitt 경로가 아니라 DAP UART CTS 경로다. RXDELAY/속도 비교는 후보이며
  아직 비교 펌웨어 구현·실기 완료 근거가 없다. SPIS 수신 실패를 SPIM RXDELAY만으로 설명하지 않는다.
- I2S B: repeat97 RX1word 불일치를 유지한다. 위 SPI와 같은 원인이라고 단정하지 않는다.
- System OFF: 이전 UART bridge error46은 event5를 뜻하지만 error mask가 없어 상세 원인 미확정이다.
  최초 UART error mask·CONFIG/PSEL·수준·clock 보존 도구는 준비됐고 새 실기는 미실행이다.

상세 원인 대조·Nordic/회로도 출처와 준비 소스별 Host/target은
[107번](107_T13_S_자동_진행과_System_OFF_계획.md)을 따른다.
UART ARM 수정 초안은 관련 Host6시험·전체 T13 Host89시험·두 역할 target2/2를 통과했다.
정확한 base+patch·검사 로그·이미지 해시는 [ARM 수정 초안](evidence/t13-uart-arm-candidate-2e5a2c5/manifest.json)에 보존했다.
초안 빌드를 새 exact 소스의 실기 PASS나 릴리스 근거로 사용하지 않는다.

직전 고정 소스2e5a2c5의 [원격 검사 원본](evidence/t13-ci-2e5a2c5-complete/manifest.json)은15/15 성공이며
Host109묶음818시험을 포함한다. 이 결과를 이후 ARM 수정 커밋의 CI로 재사용하지 않는다.
후속 커밋은 push 뒤 그 exact SHA의 검사15개를 별도로 확인한다.

## 종료·원본 감사와 다음 순서

[종료 감사](evidence/t13-s-session-final-2e5a2c5/manifest.json)에12개 대열의 최종 상태,
56개 완료 실행의 압축/원본 해시 대조와 양쪽 STOP·clock0·GPIO 반환 감사, UART ARM9개 원본 대조를
보존했다. 이56은 완료한 실행 파일 수이며 T13 합격 조건 수가 아니다. 실패 실행도 포함한다.
감사는 저장된 기록의 읽기 전용 대조이며 만료 후 SWD 재접속을 하지 않았다.

1. 새 S 실행 때 현재17신호+GND·DAP UART 분리/SWD 연결을 다시 확인하고 exact UID를 새로 식별한다.
   이전 COM·확인 만료를 재사용하지 않는다. SWD10MHz·controlled flash·unlock/recover 금지는 유지한다.
2. 수정된 TWIM/CTS/UART line와 System OFF bridge 및 아직 실행하지 못한 독립 예행부터 확인한다.
   통과한 예행만 정식100회로 올린다. 같은 기존 실패 소스의 반복 대신 원인 보강 여부를 먼저 대조한다.
3. SPI/I2S 실제 실패를 조치하고, 남은9개 충돌·기타 요구별 시험과 S 복구 근거를 완료한다.
4. S 완료 후 U 배치를 GPIO 번호로 다시 안내한다. A P2.00/.02/.04/.05에서 오는 B 쪽 끝만
   각각 P2.02/.00/.05/.04로 옮긴다. 당시 현재 연결 확인 후 U UART00 검증을 시작한다.
5. T14 결함 조치·T15 지원 범위, T16~T18 사용자 기능/패키지·문서·절차 통합,
   R14/RC 소스 고정·전체 회귀를 진행한다. 사용자 승인·정식 공개는 별도이며 수행하지 않았다.

문서 입구16곳의 정상 안정성29/36 표현을36/36으로 정정했다. readiness의 QDEC 전면 재진단
선행조건은 소유자의 보고 후 종료 결정과 맞췄으며 gate `state`/`required` 값은 바꾸지 않았다.
QDEC 알려진 제한은 T15 지원 범위에 여전히 반영해야 한다.
