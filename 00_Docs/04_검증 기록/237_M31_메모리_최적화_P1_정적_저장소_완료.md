# 237 — M31 메모리 최적화 P1 정적 저장소 구현 완료

## 1. 판정 범위

P1의 **정적 source·상태·pool 역할 분리와 선언 용량 연결**을 완료했다. 이 판정은
P0의 55개 image 기준선, P1의 단계별 동일 image 전후 비교, 최신 adaptive BLE
10역할 fresh build, 실제 GATT Peripheral/Central adaptive·full build와 Host 회귀에
한정한다. `malloc_arena`, stack, Zephyr heap, controller pool의 안전한 최소 크기나
실행 중 high-water를 증명하지 않는다. 그것은 P2 실물 부하 측정 범위다.

| 동일 image | 해당 단위의 비교 기준 RAM | 변경 뒤 RAM | 절감 |
| --- | ---: | ---: | ---: |
| Core SPI adaptive | 50,877 B | 20,589 B | 30,288 B |
| CoC-only adaptive | 91,037 B | 70,081 B | 20,956 B |
| GATT 1×1/1-link/64 B server fixture | 113,218 B | 48,581 B | 64,637 B |
| 실제 `CustomGattPeripheral` adaptive | 59,519 B | 48,763 B | 10,756 B |
| 실제 `CustomGattCentral` adaptive | 59,214 B | 52,582 B | 6,632 B |

서로 다른 image의 RAM 차이를 절감량으로 합산하지 않는다. `standard`/`ble` full
호환 profile은 선택 시 기존 broad 기능과 공개 512 B GATT payload 계약을 유지한다.
Adaptive의 작은 결과를 full image와 직접 비교해 호환 경로가 회귀했다고 판정하지 않는다.
공개 Peripheral/Central 두 행의 비교 기준은 GATT capacity 변경을 이미 적용한
P1-11 방향 분리 직전 image이므로 P1 전체 절감량이라고 부르지 않는다.

## 2. 구현과 재발 방지

- pin runtime state·single-resource lease·route·resource table의 중복 정적 예약을
  중앙 owner/generation과 transaction 수명에 맞게 제거했다.
- CoC-only firmware에서 사용하지 않는 NUCODE 범용 GATT facade·dynamic DB·event
  queue/state를 제외했다.
- GATT service/characteristic·client link 수·event/TX/inline value·shared TX context를
  선언 용량에 연결했다. server/client 방향과 비동기 수명도 분리했다.
- scan/periodic/PAwR와 GATT/CoC/CS 전용 저장소는 최종 기능·방향·역할에만 남게
  source selection과 ELF forbidden-symbol 검사를 적용했다. 10개 BLE 역할과 실제
  Central adaptive/full의 symbol matrix를 대조했다.
- 선언 초과나 pool 고갈은 값 절단·조용한 성공으로 숨기지 않고 오류로 거부한다.

CoC의 512 B SDU, CS 최대 step, scan/event queue depth와 stack/heap/controller
pool은 지금 단계에서 임의 축소하지 않는다. 결과 유실·fragmentation·연결 복구·최대
payload를 포함한 P2 실물 부하 계측 후 조정한다. 최적화 image의 W04/W05 잔여
HIL, W06~W08 독립 역할 검증과 릴리스 승인은 이 P1 판정으로 완료되지 않는다.
