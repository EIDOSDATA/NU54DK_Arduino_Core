# 244 — M31 P2 연결형 DF IQ 수신 내부 진단

## 범위와 판정

고정 NCS v3.4.0, NU54DK 두 대에서 Zephyr LL 연결형 AoA RX 내부 진단 앱과
공개 Arduino `ConnectedCteResponder`의 adaptive 이미지를 실행했다. 이전
진단에서 `Failed LE Set PHY (-13)`와 재연결이 함께 관찰되어 RX 진단 앱의
자동 central PHY 변경만 `CONFIG_BT_AUTO_PHY_CENTRAL_NONE=y`로 제외했다.
이전과 응답자 image·시작 방식도 다르므로 이 설정을 과거 불안정의 **원인
수정으로 단정하지 않는다**. 공개 Host API의 단일 안테나 거부를 우회하는
Host 내부 상태 동기화는 이 진단 앱에만 있으며 제품/Arduino RX API가 아니다.

| 실행 | 결과 | 원본 |
| --- | --- | --- |
| 첫 실행 | **FAIL 보존**. 실제 유효 IQ 5건·410 sample 뒤 같은 event 59의 `status=1`/`status=0` 두 callback을 판정기가 중복으로 오판했다. 양측 연결 종료와 RX cleanup은 확인됐다. | [최초 UART·이미지/프로브 해시](evidence/m31-p2-df-connected-045f6339/phy-none-01.json) |
| 판정기만 수정한 재실행 | **연결형 내부 진단 국소 PASS**. 유효 report 20건·1,640 sample, packet status 0 20건, Host gate drop 0. 11.419초, request/sampling disable·Host state 반환·ACL disconnect·receiver STOP·상대 disconnect 확인. | [재실행 UART·이미지/프로브 해시](evidence/m31-p2-df-connected-045f6339/phy-none-02.json) |

재실행에서 공개 `bt_df_conn_cte_rx_enable()`는 여전히 `-22`였다. 원시 HCI
수신 설정과 요청은 각각 0으로 수락됐고, 내부 Host RX state 동기화 뒤에만
IQ callback을 받았다. 연결 이벤트 counter 20개는 서로 다르며 각 report의
sample 82개가 양수다. 첫 실행의 `status=1` report는 유효 표본에 넣지
않고 같은 event의 후속 `status=0` report만 계수하도록 판정기를 바로잡았다.
상대는 연결 해제 callback에서 responder를 종료하므로 별도 `CTE responses
stopped` 문구는 없으며, 원본의 `responder_stopped=false`를 숨기지 않는다.

두 image는 자동 unlock·mass erase 없이 sector flash하고 exact 두 VCOM을
검증한 뒤 reset-halt-drain-resume으로 시작했다. 수신 native LL build는
FLASH 142,172 B, RAM 31,872 B다. Arduino adaptive 응답자는 FLASH
134,700 B, RAM 44,578 B다. 두 역할은 서로 다른 기능이므로 이 숫자의
차이를 Arduino 오버헤드나 P2 native 동등 비교로 계산하지 않는다.

Windows 짧은 경로 개발 설치본으로 두 image를 빌드했다. 내부 수신 fixture와
공개 응답자 예제의 내용은 실제 저장소와 줄 끝을 제외하고 일치함을 대조했다.
그러나 설치본 Git 기저는 현재 저장소 commit이 아니고 실행 전 진단 설정·
판정기 수정이 아직 미커밋이었으므로 두 원본의 `source_clean=false`를
정확한 clean-source 증거로 승격하지 않는다. image hash, board/probe 역할,
실제 UART와 controller 범위의 관찰로 한정한다.

P2에서 DF TX 20회는 [242번](242_M31_메모리_최적화_P2_DF_beacon_TX_계측.md),
연결형 내부 IQ RX 20건은 이 기록으로 분리한다. connectionless IQ RX,
Arduino/SDC RX 경로, RX high-water·오류/복구 최악값, 안테나 전환·각도 측정은
여전히 `HOLD` 또는 `NOT RUN`이다. 이 결과만으로 P2나 W04를 완료하지 않는다.
