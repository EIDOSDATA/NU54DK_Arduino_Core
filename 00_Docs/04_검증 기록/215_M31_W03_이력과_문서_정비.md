# M31 W03 이력 squash와 문서 전수 정비

2026-09-21 사용자가 개발 커밋 squash, 전체 문서 검토·정리, 이후 main 업데이트를 요청했다.
M31-W01~W03 완료 **3/8**, W03 LE Audio **11/11**을 기준으로 현재 안내를 맞췄다.
W04 DF·W05 CS는 미완료이고 W06~W08은 미착수다. HOST-W04 이후의 사용자 보류를 유지했다.

## 이력 정리

| 항목 | 고정 값 |
| --- | --- |
| 기존 main | `eff575da948f96fe8361b16f0475f7eb113ccf50` |
| 기존 개발 HEAD | `dac8ea8a85b8d2e1a84aa4299529a37e10f6c0f7` |
| 원본 이력 보존 태그 | `archive/m31-w03-before-squash-dac8ea8a` |
| Squash 커밋 | `d18309a1a9c64cbb4941efefb7189c8d99fcedf6` |
| 개발 이력 | 기존 main 이후 51개 → 1개 |
| 문서 정비 | squash 뒤 별도 커밋으로 기록 |

Squash 커밋의 Git tree는 기존 개발 HEAD와 동일하다. 이력 정리로 firmware, 보드 submodule,
SDK lock, 설치본 증거를 변경하지 않았다. 문서 정비 후 main은 기존 main에서 fast-forward하며,
개발 브랜치 갱신은 기존 원격 HEAD를 지정한 `--force-with-lease`로 제한한다.
보존 태그로 과거 HIL에 기록된 source SHA와 수정 전 문서를 조회할 수 있다.

## 문서 검토와 정리 기준

검토 분모는 작업 전 Git이 추적한 Markdown 문서 전체와 board submodule의 Markdown 문서다.
파일별 분류와 LF 정규화 본문 SHA-256은 [문서 감사 목록](../document-review.json)에 기록한다.
외부 원본과 생성 문서는 각각 고정 revision 보존·생성기 일치 검사 대상으로 구분한다.

- README·문서 목차·TODO·HANDOFF·설계·예제·도구 안내를 M31 3/8과 W03 11/11에 맞췄다.
- 재개 브랜치를 main으로 통일하고 W03 종료 및 HOST-W04 이후 보류를 명시했다.
- v0.4.1 지원 package와 0.4.1-dev 개발 결과, 계획과 실제 PASS를 구분했다.
- 인계·개발 계획의 반복된 단계별 결과를 제거하고 완료 기록·readiness로 연결했다.
- 검증 기록 색인의 누락을 보완하고 깨진 소스 링크와 공백 경로의 Markdown 표기를 교정했다.
- DF의 target build·보드 진단 수행과 raw IQ 수신 미확인을 구분했다.

문서 파일 자체의 삭제 후보도 전수 검토했다. 준비·실패·진단 기록, 구버전·RC 문서,
200번 다른 PC 인계, 초기 리팩토링 설계에는 고유한 당시 결정과 들어오는 참조가 있어 보존했다.
고유 정보 없는 임시·중복 문서 파일은 확인되지 않았다. 중복 설명을 현행 문서에서 제거했으며,
원래 본문은 위 보존 태그로 복구할 수 있다. 과거 PASS/FAIL/HOLD/NOT RUN 결과와 W02·W03 원본
evidence는 소급 수정하거나 삭제하지 않았다. 역사 문서 172/178/179/180의 변경은 소스 링크 교정뿐이다.

## 검증 범위

작업 전 추적 Markdown 368개와 board submodule 6개, 총 **374개**를 검토했다.
새로 추가한 이 기록을 포함해 저장소 Markdown **369개**의 UTF-8·로컬 링크 검사를 통과했다.
생성 계약·coverage, 제품 identity·inventory, M31 원장과 Git diff 검사도 통과했다.
공개 예제 경계는 **16 libraries · 113 examples · 0 issues**다.

로컬 host 회귀는 180 suites·1,443 cases 중 **1,441 PASS·2 SKIP**다. 문서 축약으로 빠진 계약
참조를 복구하고 해당 readiness 23 tests 및 나머지 126 suites를 통과했다. SKIP은 선택형 설치 CLI
검사 미활성화와 문서 편집 중 dirty checkout 조건이며 물리 시험 PASS로 계산하지 않는다.
검사 명령·범위·보존/수정 분류는 문서 감사 목록에 고정한다.
이번 정비는 문서·이력 작업이며 새 firmware build·보드 HIL·Host OS 설치 실적을 추가하지 않는다.
CI/CD 실행 요청·조회·대기는 기존 사용자 지시대로 생략한다.
