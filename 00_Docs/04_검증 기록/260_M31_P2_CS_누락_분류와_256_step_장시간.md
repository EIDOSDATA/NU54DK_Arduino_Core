# 260 — M31 P2 CS 누락 원인 계수·256-step 장시간

## 실기 결과

고정 NCS `v3.4.0`·두 exact NU54DK에서 공개 CS initiator/reflector의
보안 연결·RAS 경로를 사용했다. 매 실행 전 probe UID·app/aux COM·image
SHA-256을 대조했고 자동 unlock·mass erase·세 번째 보드 접근은 없었다.
`RasInitiator::statistics()`에 로컬 busy·overflow, 절차/subevent abort,
RAS counter 불일치·오류, 로컬 결과 부재·유효 RTT 없는 결과·queue 포화를
각각 누적시켰다. fixture는 종료 시 원인을 출력하고 원본 UART와 양측 STOP을
기록한다. 이 수치는 같은 연결 수명의 **집계**이며 gap마다 원인을 1:1로
대응시킨 trace는 아니다.

마지막 1,000건의 RTT step은 50~61, tone step은 189~200이었다. 이전
[255번](255_M31_P2_CS_256_step_분할_RAS_진단.md)에서 확인한 다중 ATT
segment 재조립 경로를 같은 256-step 설정으로 장시간 반복한 것이다.
`valid_rtt_samples=0`인 불완전 결과는 `RasReading`의 거리 측정 완료로
공개하지 않고 `invalid_readings`에 계수한다. 유효한 tone만 있는 raw의
독립 공개 API는 이번 변경으로 제공하지 않는다. 최대 진단 image의 FLASH/RAM
`245,220/110,193 B`에는 **진단용 1,024-counter 배열**이 포함돼 제품 기본
image 예산으로 옮길 수 없다. 진단 설정(`channel_map_repetition=3`, 긴
procedure/subevent)은 build 후 제품 기본값으로 되돌렸다.
최종 제품 기본 image는 그 소스에서 다시 빌드해 initiator만 exact sector
flash했다. HEX SHA-256은
`7ab5a1aba64ac0dd613fcd265c7119f2c4ef67da99fb643745e8efc8c01aa2d4`,
정적 FLASH/RAM은 `244,404/80,494 B`다. 복구 첫 100건의 gap 1을
10건 후속 PASS로 덮어쓰지 않는다. reflector image는 변경하지 않았다.

마지막 진단 실행의 STOP high-water는 initiator BT RX WQ `1,520/3,200 B`,
BT LW WQ `936/2,104 B`, MPSL Work `504/1,024 B`, main `1,104/8,192 B`;
reflector BT RX WQ `1,232/3,200 B`, BT LW WQ `1,168/2,104 B`,
MPSL Work `760/1,024 B`, main `1,032/8,192 B`였다. libc malloc은 두
역할 모두 `allocated=0`, 관찰 peak `0 B`다. reflector MPSL Work의
관찰 여유는 264 B이므로 stack을 줄이지 않는다. controller 내부 pool
high-water도 미노출이다.

3개 gap은 실측 사실이며 3개 subevent abort만으로 정확한 원인 비율을
단정할 수 없다. RAS segment 손실·재전송, peer 이탈 뒤 최대 절차 복구,
물리 전원 차단·다중 link 및 정상 callback 뒤 잔여 gap의 1:1 원인 분류는
이번 실행으로 닫히지 않았다. 따라서 CS 전체와 P2 전체를 완료라고
기록하지 않으며 기본 제품 image 복구 검증을 별도로 남긴다.

## 문서·회귀 범위

네 축의 원본 JSON 35개는 저장소에 보존하고 JSON 파싱 오류 0건을 확인했다.
Markdown 416개의 strict UTF-8·로컬 링크 gate와 제품 inventory gate가
통과했다. Arduino CLI 공개 예제 목록 gate의 Audio/DF/CS 기대 목록을 현재
저장소의 실제 공개 예제로 갱신했으며 재실행 PASS다. 이 목록 갱신은
기능 실기 PASS로 계산하지 않는다. 최종 제품 코드 기준 NCS Python 전체
Host suite는 **1,496건, skip 2, 오류 0**으로 통과했다. 이후 발견한
공개 CteBeacon adaptive capability probe의 revision 매크로 경계는
해당 sketch의 `adaptive`·기본 `ble` target build를 각각 통과시켜 검증했다.
Git diff whitespace 검사는
오류 0건이다.
