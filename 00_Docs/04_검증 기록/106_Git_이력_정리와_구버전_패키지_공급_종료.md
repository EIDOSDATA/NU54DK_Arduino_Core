# Git 이력 정리와 구버전 패키지 공급 종료

2026-09-08 소유자가 0.3.0 이전 이력·공급 패키지 정리와 이후 개발 이력의 의미별 묶음을
승인했다. 기존 보존 정책에 대한 이 요청의 명시적 예외이며, v0.4.0 공개 승인이 아니다.

  각 묶음 끝 tree 및 최종 tree가 원본과 일치한다. 후속 정책·증거 커밋은 별도다.

## 공개 catalog와 payload

0.3.0 미만 범위는 v0.1.0·v0.2.0, v0.1.0-rc.2, v0.2.0-rc.1/2,
v0.3.0-rc.1/2/3 및 m10-preview-0.0.90~97이다. 정확한16개 이름·기존 ref는 inventory에 있다.
Stable root와 v0.3.0 Release catalog는0.3.0만 제공하고 preview URL은 빈 platforms를 유지한다.
삭제한 옛 Release 다운로드 URL은 더 이상 공급 endpoint가 아니다. 기존 PC 설치는 지우지 않는다.

v0.3.0 ZIP은1,660,169 bytes, SHA-256
`138740bcf6c458992fdb5c8eb81d6110d28b0baee18c68f5d8cb050e2e0e1ecc`를 유지한다.
해당 Release의 ZIP·CHECKSUMS·manifest·SPDX·license inventory·notices 6개 자산을 바꾸지 않는다.
Catalog는 CHECKSUMS/manifest의 payload hash 대상이 아니며 원본을 보존한 뒤 공급 목록만 바꾼다.
새 stable catalog는1126 bytes, SHA-256 `97e842248772d1e19b4649574008b24b405bde092c2f9df98d115dc65b2f5b57`다.

역사 package build allowlist와 원본 source identity는 재현을 위해 유지한다. M18/M22는
종전 exact index 허용목록을 보존하고 공급 종료 catalog identity를 별도로 추가한다.
Preview의 빈 catalog는 일반 package 생성/검증 입력이 아니라 공급 종료를 표시하는 현재 feed다.

## 다른 PC와 진행 중 HIL

기존 수정은 commit 또는 별도 백업으로 보존한 뒤 `git fetch origin`하고 새 main을 별도
worktree/clone으로 연다. 원본 개발 이력과 새 main을 일반 merge로 합치지 않는다.
원본 재현은 archive 브랜치를 fetch한 뒤 증거의 original source SHA로 별도 checkout한다.
원격 archive가 있는 clone에서는 원본 SHA를 직접 조회할 수 있고, 로컬 bundle로도 복구할 수 있다.
새 commit의 CI/HIL을 기존 original SHA 결과와 섞지 않는다.

T13 serial100회는별도 `C:/tr13dev`의clean4aadf29와그빌드에서계속실행한다.
이번정리는보드재플래시·배선·확인서만료를변경하지않는다. T12/QDEC검증작업완료와알려진문제는
유지하며 T13전체·U·지원범위확정·RC·정식공개는미완료다.
