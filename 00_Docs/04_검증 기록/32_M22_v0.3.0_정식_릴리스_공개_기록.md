## 격리 Boards Manager와 NU54DK

격리 Arduino data/download/user/build/cache 경로에서 다음 순서를 검증했다.

```text
0.2.0 설치 → 0.3.0 upgrade → 설치 identity 확인 → 예제 29/29 compile
→ Blink clean compile·NU54DK pyOCD Upload → 0.2.0 downgrade
→ 0.3.0 upgrade → uninstall
```

첫 Blink upload에서 CMSIS-DAP가 `SWD/JTAG communication failure (No ACK)`와
`Timeout reading from probe` 뒤 Windows `장치 설명자 요청 실패` 상태로 사라졌다. Mass erase,
recover 또는 다른 image는 실행하지 않았다. 같은 stable archive, 설치본, compiled HEX와 명시
probe 선택으로 USB 전원 복구 뒤 upload를 재실행해 PASS했으며 최초 실패는 evidence에 보존했다.
29개 예제는 같은 설치본과 source에서 이미 전부 PASS했으므로 반복하지 않았다.

Uninstall 전후 공유 Nordic `ready.json`과 NCS anchor hash는 같았으며 Core 제거가 공유 NCS와
Toolchain을 삭제하거나 변경하지 않았다.

## 지원과 보존 정책

신규 설치와 수정 지원은 `v0.3.0`을 기준으로 한다. `v0.1.0`, `v0.2.0`과 모든 RC는
역사적·비지원 상태로 전환한다. 다만 기존 공개 자산 불변 원칙과 downgrade 재현성을 지키기 위해
과거 tag, Release asset, 문서와 stable index 항목은 삭제하거나 덮어쓰지 않는다.

## 결론

M22는 완료됐다. 다음 제품 작업은 `v0.4.0` M23~M26의 storage/crypto, 고급 memory layout,
MCUboot/DFU, TF-M와 recovery 범위다. `v0.3.0` 지원 범위는 이후 계획을 소급 포함하지 않는다.
