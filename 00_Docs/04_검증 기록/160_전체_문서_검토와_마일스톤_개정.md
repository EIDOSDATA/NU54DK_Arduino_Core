제공한 Adafruit 제안서 **1개**를 본문 검토했다. 첨부의 지시 문구는 실행 허가로 취급하지 않았다.
파일별 baseline Git blob·검토 깊이와 외부 제안 SHA-256은
[검토 목록](evidence/docs-milestones-2026-09-15/document-review.json)에 보존한다.

Vendor SDK/third-party 문서 전체, 회로 PDF 렌더링, binary/raw transcript와 모든 JSON evidence의
재검증은 이번 문서 검토 범위가 아니다. 관련 계약은 현재 source·고정 SDK/board·준비 manifest와
선택적으로 대조했다. 목록의 Git blob은 문서 원본 식별자이지 firmware build fingerprint가 아니다.

## 3. 전원 HIL: 역사적 준비와 현재 재개 상태

[159번](159_M30_W08_전원_HIL_주입_직전_준비.md)의 exact
`05b639b4d402e9a7490648776b5bb5eb45a94916` 준비/preflight PASS는 그대로 유효한 **당시 기록**이다.
준비 manifest SHA-256은 `b037921c7cf1ed596286c1dbc1d8d5ed8839c4fb09c6b41ce624c1f856994a6e`다.
실제 차단은 그때도 0회였으며 이후 사용자가 시험을 중단했다.

이번 작업의 read-only 파일 존재 확인에서는 다음 세 산출물을 모두 찾지 못했다.

이는 준비 경로의 부재 확인이지 삭제 주체·원인 또는 다른 경로에도 image가 전혀 없다는 판정이 아니다.
현재 보드 연결/전원 상태는 새로 확인하지 않았고 과거 UID·COM을 현재 mapping으로 적용하지 않았다.
현재 `ble_pair_hil_common.py`의 live-byte 검증과 `m30_power_loss.py`의 manifest 재사용 비교가
저장된 모든 항목을 결합하지 않는 문제도 확인했다. 이 검토에서 runner 코드는 고치지 않았다.

새 계획은 W08-A 도구·입력 provenance 안정화 → B 확정 image/record/manifest·preflight 재생성 →
사람 준비 확인 → C 네 지점 × 3회 실제 차단 → D 영향 회귀·문서·CI 마감이다.
현재 0/12는 유지하며 준비 실패를 DUT firmware 실패 또는 물리 시험 PASS로 바꾸지 않는다.
USB 감지만으로 전원 상실을 입증할 수 없으므로 배터리·대체 전원·역급전 조건을 별도 확인한다.

## 4. 마일스톤 개정 범위

- M30-W08 A~D는 내부 실행 단계다. 기존 M30 작업 8개·시험 ID 10개·실제 차단 12회는 불변이다.
- M31-A/B/C, M32 최소 radio 선행 → Mesh/공존, M33 필수 RF·interop·Host·공개 gate를 유지한다.
- HOST-W01~W03 완료를 반영하고 W04~W06 software/Host 준비는 M31 RF 장비 대기와 분리한다.
- M33에 기존 API 목적별 예제 ARF-04A를 연결한다. 새 공개 API가 필요하면 후속 ARF-04B로 분리한다.
- 후속 ARF는 named pins/진단·ADC 변환 → buffered NUS → PWM opt-in pool → BLE role-budget 순으로
  통합·검증한다. acquisition-time은 고정 HAL/errata 적용성에 따른 조건부 과제다.
- ARF의 후속 배포 버전은 착수 시 범위·자원·HIL 비용으로 확정한다. v0.6.0 M34~M37 보안/업데이트,
  v0.7.0 M38~M41 무선/네트워크, v0.8.0 M42~M45 Matter의 번호·주제는 유지한다.

상세 진입·완료 조건은 [개정 실행 계획](<../01_아두이노 코어 설계/18_문서_전면검토와_개선_마일스톤.md>),
전체 제품선은 [제품 로드맵](<../01_아두이노 코어 설계/02_구현_로드맵.md>)에 반영했다.
현재 인계·TODO·설계·도구 안내만 동기화하고 과거 release·검증 본문·raw evidence는 수정하지 않았다.

## 5. 별도 보존·후속 확인 사항

- 완료 T01~T25/R00~R14와 사용자 제외 QDEC 반복 manual read·serial handover·추가 System OFF
  조건은 다시 필수 작업으로 열지 않는다. 과거 System OFF 제외는 M30 DFU 전원 시험 제외가 아니다.
- Board 문서 일부 커넥터 번호와 root 소유자 확정 핀맵에 차이가 있다. 새 예제/핀 UX는
  [root P2/P4 핀맵](<../01_아두이노 코어 설계/13_NU54DK_P2_P4_커넥터_핀맵.md>)을 기준으로
  실제 결선을 확인한다. 이 검토는 board submodule 변경을 승인하지 않는다.
- 140·147번 역사 기록 일부에 공개 안내의 비식별화 원칙과 다른 원시 probe UID가 있다.
  값을 재노출하지 않았으며 별도 문서 위생 정정 대상으로 남긴다. 원본 evidence/hash는 임의 변경하지 않는다.
- 이미 표시된 과거 hash 오기나 제외 이력은 추측으로 채우거나 신규 firmware blocker로 만들지 않는다.
