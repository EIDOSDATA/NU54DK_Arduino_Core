# 329 — M33-W07 v0.6.0 OS 지원 범위와 Windows 11 진행

2026-11-15 프로젝트 소유자가 v0.6.0 지원 목표를 Windows 11 x64, Ubuntu 24.04 LTS와 26.04 LTS AMD64,
macOS 26과 27 Apple Silicon의 다섯 행으로 확정했다. Windows 10과 Ubuntu 26.10은 이번 대상에서 제외했다.
공개된 v0.5.0 Windows 10/11 지원과 [328번](328_HOST_W07_C5_필수_자동검증과_사용자_OS_gate.md)의 일곱 행 및
기존 PASS·FAIL·중단 이력은 당시 기록으로 보존한다.

현재는 **M33-W07의 HOST-W07 Windows 11 RC1 검증 완료·OS 1/5**이며 Host는 6/8이다. 후보는 C5
`5ee7c10368b554ca23d68f8f82e39308b91df6de`, RC 버전 `0.6.0-rc.1`이다. 지원 범위 결정과 문서 커밋은 C5 제품 검증과 별도다.

Windows 11 Pro build 26300에서 공개 v0.5.0 원형을 별도 Arduino CLI 데이터에 설치하고 C5 RC1으로 갱신했다.
RC post-install, 라이브러리 24개와 예제 204개 발견, 갱신 후 Blink 빌드, 기존 v0.5.0 설치와 사용자 데이터·SDK 보존을
확인했다. 실제 종료는 `852d4b/exit0`, 결과 SHA-256은 `cf303b349713f549e7bf8b770d1152e69c80d958abc65c4ada04053fba6383a0`이다.
NU54DK의 CMSIS-DAP과 VCOM 두 개가 USB 분리 때 함께 사라졌다가 같은 장치로 복귀했다. 재연결 관찰은
`5e1450/exit0`으로 통과했다. 잘못된 probe UID는 업로드 시작 전에 `E_PROBE_SHA256`과 exit 2로 거부됐다.

COM5·6 보드에서 기본 속도와 500kHz로 C5 Blink 업로드를 각각 실행했다. 두 시도 모두 pyOCD의 AP 탐색 중
`No ACK`로 종료됐다. 실제 종료는 `c1c0c7/exit1`, `2be2ab/exit1`이며 플래시 쓰기는 0회다.
같은 probe에서 DP와 AP0·1·2 식별자가 응답했고 전체 attach에서 칩과 CPU 식별도 한 번 성공했다.
HID와 bulk USB 전송, 100kHz·50kHz, 명시적 SWD 재연결에서도 초기화 오류가 발생했다.
작업자는 `DISABLE_SWD`가 OFF라고 확인했다. SWD 전송 실패 지점은 확인했으며 근본 원인은 미확정이다.

작업자가 하드웨어가 정상이라고 보고하여 케이블 비교를 생략했다. 이후 같은 PC 포트에 연결된 NU54DK는 앞서 시험한 장치와 probe·칩 식별자와 DAP 빌드가 다르다.
두 번째 보드의 고정 SDK 읽기 전용 attach 4회에서 2회 통과하고 2회 실패했다. 이후 같은 보드에서 공식 pyOCD
commander로 칩과 CPU를 읽는 시험은 4회 통과했다. 이 보드의 별도 읽기 결과는 기존 보드의 업로드 판정에 합산하지 않는다.
작업자 지정에 따라 COM17·18의 NU54DK에서 C5 Blink를 기본 속도와 CMSIS-DAP으로 업로드했다. 20개 섹터에
81,920바이트를 기록했고 실제 CPU 명령이 ELF와 일치했다. 실행을 재개한 뒤 83회 샘플에서 LED0(P2.09)의
출력 토글 8회를 관측했다. 업로드와 실기 모두 `44cc56/exit0`으로 기록했다. COM5·6의 원본 FAIL은 따로 보존했다.
같은 C5 SerialEcho를 재빌드 없이 업로드했다(`eef7ca/exit0`). UART 경로 식별에서 COM17은 응답 시간 초과였고,
COM18은 두 번 열기·닫기와 fresh nonce 6개를 통과했다(`a5516a/exit0`). 실제 USB 소실과 같은 장치 복귀를 관측했다.
복귀 직후 첫 UART 검사는 장치 식별 단계에서 실패했다(`f5e7e2/exit1`). 해당 FAIL을 보존하고 재열거 상태를
연속 5회 확인한 뒤 fresh attempt에서 nonce 6개와 두 번 열기·닫기를 다시 통과했다(`d76e06/exit0`).
보드는 C5 SerialEcho를 실행 중이다. IDE의 비공개 RC1 설치와 단독 Blink Verify를 완료했다. 이후
[실기 절차](<../02_빌드 설계/15_Host_RC1_실기_도구와_증거_절차.md>)에 따라 나머지 네 행을 검증한다.
HOST-W08에서 지원표와 설치·문제 해결·릴리스 문서를 마감한 뒤 M33-W07 완료를 판정한다.

W06의 실제 PASS 46개와 사용자 수락 #29·#40·#44, 기존 FAIL과 source별 실적을 보존한다.
#29 원인 분석은 유예하며 자동점검 `w06`은 `PAUSED`다.


### IDE 실행 도우미 교정 — 2026-11-15

사용자가 IDE 화면 조작을 허용해 Arduino IDE 2.3.11·내장 CLI 1.6.0에서 검증했다.
초기 도우미의 `THEIA_CONFIG_DIR`는 Arduino 전용 설정에 적용되지 않아, 별도 `USERPROFILE/.arduinoIDE`로
교정했다. 이 임시 프로필에 AppData 폴더가 없으면 CLI가 경고를 출력하고 IDE가 daemon 실행을 반복했다.
폴더와 process-local `LOCALAPPDATA`·`APPDATA`를 설정한 단독 기동 검사는 stderr 없이 통과했다.
해당 시도의 소유 프로세스만 종료했고, 정리 후 남은 daemon은 0개였다(`31aa99/exit0`).

`w11i4`에서는 Boards Manager로 RC1 설치에 성공했고 설치파일 960개가 원본 archive와 일치했다.
첫 Blink Verify는 `E_HOST_READY`로 실패했다. 설치기용 `NUCODE_NCS_INSTALL_ROOT`만 설정한 도우미가
빌더용 `NUCODE_NCS_ROOT`를 빠뜨려, 빌더가 기존 `C:/ncs`를 찾아 준비 marker의 `D:/w06/host-w07/sdk`와
달랐다. 동일 SDK root를 명시한 읽기 전용 준비 검사는 통과했다(`0024b1/exit0`). 제품과 SDK를 고치지 않았다.

교정된 새 설치 `w11i5`의 첫 Verify는 빈 스케치의 자동 언어 분석 구성 작업과 겹쳐 `E_SDK_PATCH`로
거부됐다. 승인된 임시 patch의 네 파일을 다른 작업이 사용 중인 상태였으며, 이 오류를 PASS로 바꾸지 않았다.
백그라운드 구성이 끝난 뒤 SDK 내용 변경 0개를 확인했다(`42a7f5/exit0`). 빈 창을 닫고 Blink 창 하나에서
다음 Verify attempt에서 실제 컴파일·링크와 이미지 생성을 통과했다. 동시 SDK 사용 제한이 해결된 것으로 확대하지 않는다.
원본 UI 오류·프로세스 정리·각 설치 관측은 `D:/w06/control/host-w07-c5-Windows11-IDE-helper-diagnosis-20261115.json`과
`D:/w06/w11i1`~`w11i5`에 보존하며, 과거 C5 전체 빌드나 물리 PASS와 합산하지 않는다.


### Windows 11 RC1 검증 마감

`w11i5`의 GUI Verify 두 번째 attempt가 성공했다. Arduino IDE 2.3.11·CLI 1.6.0에서
NU54DK Standard의 설치 예제 Blink를 열고 실행했으며, 설치파일 960개가 C5 archive와 일치했다.
실제 ELF·HEX·BIN·MAP의 hash와 manifest의 C5 source·고정 SDK·Standard profile을 대조했다.
종료 뒤 SDK 내용 변경은 0개였고 IDE와 소유 CLI를 종료했다. 이 결과는 SDK당 단일 compile 조건의
비공개 RC1 검증이며 GitHub 공개 URL 다운로드 검증·IDE 동시 실행 정상성을 뜻하지 않는다.
최종 증거는 `D:/w06/control/host-w07-c5-Windows11-IDE-closure-20261115.json`이다.
Windows는 다섯 OS 중 첫 행을 완료했다. 사용자가 Windows 마감 후 Ubuntu 환경을 준비하기로 했다.
HOST-W07 전체·HOST-W08과 M33-W07 전체는 아직 미완료이며 공개는 별도 승인 단계다.

### 후속 문서 전수 점검과 기록 커밋

사용자 요청으로 추적 Markdown 536개 전체의 UTF-8·로컬 링크·상태 문구를 검사하고 현행 안내와
연결된 근거를 다시 검토했다. 이전 Host 3/8·W06 미완료·W07 준비 안내, 완료된 W06을 재개하도록
읽히는 인계 순서와 CI 생략 문구를 고쳤다. 소스의 `coreVersion()`·공개 stable `0.5.0`과
비공개 C5 설치 패키지 `0.6.0-rc.1`도 구분했다. 검토 범위·방법·정독의 한계와 파일별 해시는
[문서 감사 원장](../document-review.json)의 최신 후속 항목에 기록한다.

문서 커밋의 CI는 해당 SHA로 확인하며 기존 C5 48개 job·204개 빌드·실기와 합산하지 않는다.
Windows 11 이후 사용자가 Ubuntu 환경을 준비하며, 이번 문서 작업에서 새 실기·SDK 변경·공개 게시를 수행하지 않는다.
