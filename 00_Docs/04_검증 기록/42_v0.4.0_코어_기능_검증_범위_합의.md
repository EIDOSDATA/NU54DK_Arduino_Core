## 1. 결정

별도 로직 분석기·오실로스코프·교정 전압원·오디오 신호원을 필수 준비물로 요구하지 않는다.
NU54DK 온보드 자원과 두 NU54DK 사이의 안전한 배선, 시험용 신호 생성·수신을 사용해 **코어의
기능 계약**을 검증한다. 실제 마이크·코덱·엔코더 등 외부 부품별 호환성, 정밀 아날로그 성능과
최종 제품의 신호 품질은 이 릴리스의 필수 gate에서 제외하고 사용자의 제품 통합 검증으로 분리한다.

이는 계측 결과를 확보했다는 뜻이 아니다. 코어의 잘못된 데이터 처리, DMA 메모리 접근,
프로토콜 구현 오류와 복구 실패는 여전히 코어가 책임지고 수정해야 한다.
이 결정은 `v0.4.0`에만 적용하며 이후 BLE·RF·제품 인증 마일스톤의 조건은 변경하지 않는다.

## 2. 유지하는 시험과 제외하는 보증

| 영역 | 코어 릴리스에서 필수인 기능 검증 | 필수 gate에서 제외하는 항목 |
| --- | --- | --- |
| UART·SPI·I2C | 승인한 instance/route의 실제 송수신, 기대 데이터 대조, DMA·flow control·오류 복구 | 계측기로 측정한 setup/hold 여유·rise/fall·파형 품질, 개별 외부 장치 호환성 |
| SAADC | 안전한 LOW/HIGH 등 시험 입력, 채널 선택·순서·sample 수·DMA·calibration API 동작 | 교정 전압 정확도, 선형성, ENOB·SNR·노이즈 보증 |
| PWM·timer/event | 다른 보드의 capture/counter로 주기·듀티의 기본 동작, sequence·event·채널 소유권 확인 | 정밀 절대 주파수·jitter·전기 파형 보증 |
| PDM·I2S | 실제 핀을 통과하는 합성 신호/loopback, bit/frame·sample 순서, clock 역할, 연속 DMA·buffer 반환·underrun/overrun | 특정 마이크·코덱 호환성과 음질·왜곡·오디오 인증 |
| QDEC | 다른 보드의 quadrature 시험 신호에 대한 방향·count·경계·복구 확인 | 실제 엔코더 모델별 접점·배선·EMI·신호 품질 |
| 공통 | 같은 자원 충돌 거부, 허용 동시 조합, cancel/stop/restart, 데이터 손실·처리량·장시간 soak | 외부 계측 기반 CPU 전력·전류·정밀 시간 특성 보증 |

각 경로에 적용되는 경우에만 DMA·flow control 등 해당 기능을 시험한다. 전원 모드의 올바른
획득·해제와 소프트웨어에서 관측 가능한 성능·오류 카운터는 계속 기록한다. 전력 실측과 내부
카운터를 혼동하지 않는다. 알려진 silicon errata와 SDK workaround 검토·기능 회귀도 면제하지 않는다.

## 3. 시험 성립 조건

1. Source/build 성공이나 handle 생성만으로 실제 데이터 경로를 PASS 처리하지 않는다.
2. 두 번째 보드도 시험 프로그램이므로 기대 패턴·count·독립 assertion과 순서/nonce 검사를 사용한다.
   양쪽의 같은 구현 오류가 왕복 비교만으로 가려지지 않도록 판정한다.
3. PDM/I2S/QDEC 신호 발생 능력과 가능한 속도는 먼저 검증한다. 합성 peer를 아직 구현하지 못했거나
   유효한 물리 신호를 만들 수 없으면 그 기능은 `NOT RUN`/HOLD이며 자동 면제하지 않는다.
4. 측정 가능한 rate·buffer 크기·동시 topology·soak 시간과 허용 오차는 시험 전에 정하고 결과에 남긴다.
   시험한 속도를 넘는 동작이나 모든 조합의 동시 사용을 추정하지 않는다.
5. 배선표·전압·공통 GND·pull-up·DAP UART switch·출력 충돌 방지를 확인한 뒤에만 실행한다.
   특정 경로에 필요한 수동 부품까지 불필요해진 것은 아니다.
6. 두 보드의 상대 시간/capture와 내부 VDD raw sample은 교정 계측값이 아니다. 제외한 측정은
   `범위 밖·미측정`으로 표시하고 PASS나 성능 보증 수치로 바꾸지 않는다.

## 4. 릴리스 조건 반영

- [M27 readiness](../../variants/nu54dk/v0.4.0-release-readiness.json)의
  `verification_scope`에 이 결정을 연결한다. `m24_fixture_hil`, `m25_fixture_hil`은
  **required/physical/HOLD를 유지**하며 NU54DK 기반 기능 시험 증거를 요구한다.
- 온보드 기본 PASS는 [41번 기록](41_M24_M26_온보드_protocol_교정과_실기_재검증.md)의 범위 그대로다.
  이번 범위 조정으로 과거 `NOT RUN`을 PASS로 바꾸거나 기존 증거를 소급 수정하지 않는다.
- 남은 기능 시험 뒤 frozen RC의 Host·문서·전체 build·이중 package 재현성·설치본 예제·실제 upload·
  설치/제거/재설치/버전 전환 검증은 그대로 필요하다.
- 이번 결정은 최종 공개 승인이 아니다. 모든 기술 gate 뒤 프로젝트 소유자의 공개 승인을 별도로 받는다.
- 기존 `v0.3.0` 이하 공개 tag·asset·index와 과거 검증 기록은 변경하지 않는다.

## 5. 다음 실행 순서

온보드 추가 기능 시험 → 두 보드의 role image/runner와 승인 배선표 준비 → 사용자 배선 확인 →
M24 실제 통신 → M25 합성 신호·capture → 오류·동시성·soak → frozen RC/M27 검증 순서로 진행한다.
본 변경에서는 범위·문서·계약만 갱신하며 보드 flash나 새 실기 시험은 수행하지 않는다.
