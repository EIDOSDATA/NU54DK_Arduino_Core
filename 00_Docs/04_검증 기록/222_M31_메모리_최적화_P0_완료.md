# 222 — M31 메모리 최적화 P0 완료

## 1. 판정

2026-09-22 `M31-MEM-OPT`의 선언 기반 capability 해석과 완전 제외 P0를 완료했다.
compiler-assisted probe, 공개 role/capacity declaration, fail-closed resolver, 최종 Kconfig·
Devicetree·source 선택과 cache identity를 하나의 `resolved-capabilities.json`에서 재현한다.
기존 `standard`·`ble` full profile과 기본 보드 선택은 바꾸지 않았고 `adaptive`는 명시적
실험 선택지로 유지한다.

이 완료는 정적 build/map/symbol 판정이다. P1의 공통 고정 저장소 right-size와 P2의 runtime
stack/heap/controller high-water는 포함하지 않는다. 물리 장치에는 접근하지 않았다.

## 2. 완료 범위

- 실제 sketch·외부 library reference를 cross compiler와 section GC 조건으로 판정하고,
  안정된 공개 capability ID로 변환한다. source 문자열이나 정규식 API 검색은 사용하지 않는다.
- library feature의 간접 요구와 sketch root의 `nucode-build.json` role/capacity를 합성한다.
  누락·순환·충돌·허용 role 부재·capacity 불일치는 조용한 full fallback 없이 중단한다.
- 미선택 Kconfig를 명시적으로 끄고 기능별 overlay와 source 목록을 생성한다. final `.config`가
  resolver 결정을 되돌리면 중단한다.
- 총 52개 role preset과 55개 고정 build image를 연결했다. 같은 role을 다른 공개 예제에서
  검증하는 BAP 중복 때문에 preset 수와 image 수는 같지 않다.
- artifact manifest에 최종 `.config`, Devicetree, source manifest, ELF, map, capability 결과의
  hash, FLASH/RAM 사용량·headroom과 상위 RAM symbol 32개를 기록한다.
- adaptive RAM 75% 경고·85% 실패와 비활성 scan/periodic/PAwR/NUS/GATT/CoC/Security
  정적 저장소 금지 symbol gate를 적용한다.
- Central capability가 최종 Kconfig와 같은 `CONFIG_BT_OBSERVER=y`를 명시하도록 GAP/NUS,
  GATT/NUS, CoC와 CS initiator declaration을 보정하고 Host 불변식으로 고정했다.

## 5. P1 인계

P1은 public API와 ownership generation/rollback 의미를 유지하면서 영구 정적 저장소를
right-size한다. 첫 대상은 SPI adaptive image의 `pin_runtime_states` 25,856 byte다.
각 pin의 `PinRuntimeState`가 16-entry `IoResourceLease` 전체를 보존하지만 현재 구현은 commit 뒤
그 필드를 release/rollback에 읽지 않는다. transaction 동안의 지역 lease는 유지하고 commit 뒤
중복 보존만 제거한 후 AC-02A ownership/handover 회귀와 fresh ELF delta를 확인한다.

다음 대상은 부팅 고정 UART20의 792-byte lease, SPI runtime route 4,224 byte, I/O resource table
2,320 byte와 역할별 GATT queue/state다. L2CAP 대표 image의 GATT event queue는 17,664 byte이므로
server/client 및 event depth 분리를 map 근거 없이 축소하지 않는다. stack, heap, SDC/controller pool은
P2 high-water 전에는 줄이지 않는다.
