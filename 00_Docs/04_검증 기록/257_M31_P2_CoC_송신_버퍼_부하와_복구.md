# 257 — M31 P2 CoC 송신 버퍼 포화·재연결 부하

## 판정

고정 NCS `v3.4.0`, `M31-MEM-OPT`의 공개 CoC client/server를 두 exact
NU54DK에 빌드·sector flash했다. probe UID와 app/aux COM, HEX SHA-256을
실행 전에 대조했고 자동 unlock·mass erase·세 번째 보드 접근은 없었다.
한 ACL의 두 CoC 채널을 모두 연 뒤 한 채널에 512 B SDU 네 개를 연속 제출했다.
다섯 번째 제출은 송신 `net_buf` pool 포화에 의한 `BLEError::busy`였고, 앞선 네 개의
echo가 모두 돌아온 것을 확인한 다음 복구 cycle을 시작했다.

| 부하·복구 | 결과 | 원본 |
| --- | --- | --- |
| 초기 네 SDU, 다섯 번째 busy, ACL disconnect/reconnect 20회 | **PASS**. 초기 echo 4개와 복구 echo 42개, 두 채널 재준비 20/20, 양측 STOP | [실기 JSON](evidence/m31-p2-four-axes-20260925/coc-burst-acl20.json) |
| 동일 전송 대기 뒤 server SWD reset·peer loss 20회 | **PASS**. echo 46개, 두 채널 재준비 20/20, 양측 STOP | [실기 JSON](evidence/m31-p2-four-axes-20260925/coc-burst-reset20.json) |

client HEX SHA-256은
`6f9309ef7e5c802fe5f3b2cafaaf5b9cc29a5a2f469e1974c6f14797a9d63b5`,
server는
`b4ed2f52a44c7308a5714633bb5ccd6bbfc256a1b5419de39f659e8c625c88ad`다.
client 정적 FLASH/RAM은 `217,276/82,636 B`다. 실행기는 READY 이전 UART
줄을 제외하고 각 전송·echo·STOP을 확인한다. server reset은 SWD CPU reset이며
물리 전원 차단과 같지 않다. 고점유 시에도 두 역할의 STOP phase에서 libc
`allocated=0`, 관찰 peak `0 B`였다. 이 부하에서 client MPSL Work는
`356/1,024 B`였다. controller 내부 pool 최고치는 이 계측으로 알 수 없다.

이 결과는 **로컬 송신 버퍼 포화**와 그 뒤의 재연결을 닫지만, 상대 L2CAP
credit 자체의 고갈을 직접 계측한 것은 아니다. 다중 ACL·물리 전원 차단·
다른 MTU/SDU 조합의 최악값을 증명하지 않는다. 이는 증거의 한계이며 모든 조합을
새 필수조건으로 추가한다는 뜻은 아니다. 다음 부하는 선언된 지원 용량에서의
**상대 credit 고갈·복구와 stack/heap 여유**로 고정하고 [M31 TODO](../TODO_M31.md)의
세 축 안에서 판정한다. pool/stack은 축소 근거가 없어 유지하며,
[251번](251_M31_P2_CoC_재연결_메모리_계측.md)의 기본 복구 증거와 구분한다.
