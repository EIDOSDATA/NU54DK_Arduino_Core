# T13 S GPIO 전수 결선 진단

2026-09-08 사용자 요청에 따라 T13 통신·복구 실기를 정지하고 S의17개 신호를 모두 검사했다.
전수 진단은100% 완료했으며 **16개 연결 정상, A GPIO P2.04 ↔ B GPIO P2.02 한 연결 실패**다.
실패 신호를 정상으로 처리하거나 T13 통신 실기를 재개하지 않았다.

## 실제 실행과 판정

- Exact43bc032/C:/t4c04 두 역할, 새 probe 열거·UID hash·identity/plan 확인, SWD10MHz·controlled flash.
- 2026-09-08T04:56:38Z~04:58:08Z. 각 net 양방향10회, 총340회의 단일 open-drain LOW/입력 해제.
- LOW 요청 후 목표5/50/150ms의 세 관측과 해제 후 관측. 실제 Host 시각을 개별 보존했다.
- 각 LOW의 첫 관측에서 CPU를 halt하지 않고 GPIO IN/OUT/DIR/PIN_CNF도 직접 읽었다.
  직접 읽기와 firmware 관측은 동시 계측이 아니며 각각 시각을 남겼다.
- 총20개의 실패 pulse가 모두 같은 연결에 집중됐다. Peer firmware60개·직접 GPIO20개가 HIGH로 불일치했다.
  다른16개 연결의320pulse는 두 방향·모든 관측이 일치했다. 해제 후 입력 관측680개는 모두 HIGH였다.
- 실패 관측은 LOW 요청 후15~172ms이며 pulse·lease 만료는0이다. 양쪽 STOP·소유권 반환 후
  17개 PIN_CNF가 모두0(입력·pull 없음), 두 CPU SLEEPING을 확인했다.

각 방향10회 모두의 자기 출력 readback·전체 peer 입력·초기/후속 LOW·해제·직접 읽기가 일치한 pulse만 정상으로 센다.

## 확인된 사실과 다음 조작

불량 경로는 양방향 모두 출력 보드의 실제 GPIO가 LOW이고 반대 보드는 HIGH였다.
CPU가 만든 검사 메시지뿐 아니라 GPIO IN 직접 읽기도 같은 불일치를 보였다.
현재 이 두 핀 사이에서 신호 전달이 되지 않는 것은 확인했지만 점퍼·접점·보드 핀 경로 중
어느 부품이 원인인지는 아직 확정하지 않았다. 회로도9쪽에서 GPIO P2.04는 connector P2의17번,
GPIO P2.02는 connector P4의21번이다. 따라서 점검 대상은 **A P2-17 ↔ B P4-21**이다.
GPIO 이름이 기준이며 GPIO P2.04를 connector P2-4로 해석하지 않는다.

Board submodule의03_PINOUT.md에는 P2.4를 P2-16으로 적은 불일치가 있으나 원본 회로도9쪽은
P2-17이다. 기존 COMMON_WIRING.md의 P2-17과 일치하며, 이번에는 회로도에서 직접 대조했다.
고정 board gitlink와 submodule 문서는 변경하지 않고 이 정정 근거를 남긴다.
GND 점퍼 자체의 연속성·접촉 저항·전압 품질까지 이 디지털 검사로 증명하지 않는다.

두 USB를 분리하고 해당 연결의 양끝 위치·접촉 및 점퍼를 확인한 뒤 S 결선 유지 상태로 재연결해야 한다.
현재 사용자는 T13을 정지했다. 다음 연결 확인 후에도 먼저 GPIO 재검사를 하고,
T13 통신·복구는 사용자의 재개 지시 없이 자동 시작하지 않는다.
