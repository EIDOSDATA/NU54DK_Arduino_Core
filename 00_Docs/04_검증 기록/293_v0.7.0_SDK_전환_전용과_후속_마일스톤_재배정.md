# 293 — v0.7.0 SDK 전환 전용과 후속 마일스톤 재배정

결정일: **2026-10-01** · 브랜치: `Dev-0.6.0-M32`

## 사용자 결정

**제품 v0.7.0에서는 NCS 3.4.0을 3.4.1로 전체 전환하는 작업만 수행한다.**
Storage·새 보안 API·TF-M 확장·다중 update transport·Radio/Network·Matter 등의 신규 기능을
이 버전에 함께 넣지 않는다. 앞선 ‘v0.7.0 이후 SDK 전환 검토’와 ‘v0.7.0 Security/Update’ 배정은
이 결정으로 대체한다. [v0.7.0 TODO](../TODO_v0.7.0.md)가 전환 작업과 완료 조건을 소유한다.

이번 요청은 마일스톤·계획 문서 수정이다. 실제 SDK 설치·checkout·lock·toolchain·board
gitlink·firmware를 변경하거나 중단한 M32 실기를 재개하지 않았다.

합치거나 자동 해제하지 않는다. 후속 세 제품선은 기존 순서를 유지하도록 한 버전씩 옮겼다.

## ‘전체 전환’의 의미와 제외 범위

- 공식 NCS 3.4.1 manifest가 선택한 module revision·지원 toolchain·board 호환성을 새 기준선으로
  고정한다. 모든 하위 component의 버전 문자열을 일률적으로 ‘3.4.1’로 바꾸는 작업은 아니다.
- 기존 Core/library/API·Kconfig/DTS·공개 예제·profile을 새 SDK에 맞춰 이관하고 필요한 호환
  수정을 수행한다. 새 SDK에 추가된 기능을 자동으로 공개 지원에 넣지 않는다.
- 기존 기능의 clean build·자원·오류 처리·기능 회귀와 설치기·빌더·cache·CI·package·문서·원장
  전환이 모두 포함된다. SDK 설치 또는 버전 문자열 치환만으로 완료하지 않는다.
- 활성 제품 경로에 이전 SDK pin/cache가 섞이지 않게 검증한다. 과거 tag·Release·asset·3.4.0
  lock·원본 evidence는 이력과 비교 기준선으로 보존하며, 역사 자료를 새 SDK 결과로 덮어쓰지 않는다.
- 기존 기능의 정상 동작 유지에 필요한 수정·검증은 전환 범위다. 새 Storage/crypto wrapper,
  TF-M 서비스 확대, 고급 layout/transport, 신규 무선·Matter 기능은 해당 후속 M owner의 범위다.
- SDK 전환 계획 확정은 실제 완료·지원 확대·공개 승인과 다르다. 현재 SDK 작업은 **0/6 미착수**다.
