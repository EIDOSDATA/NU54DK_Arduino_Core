## 2. 발견한 결함과 수정

`PwmSequenceFabric`은 `pwm_block` 자원을 `driver->p_reg` domain과 함께 요청했지만,
public PWM runtime은 null domain의 `pwm_block + instance`를 사용했습니다. 같은 PWM20/21/22를
서로 다른 자원으로 인식할 수 있으므로 Fabric 쪽을 공통 `peripheralIoResource()` 키로 교정했습니다.

Host 회귀에는 Fabric이 public runtime과 같은 키를 사용하는지, 중복 요청이 거부되는지,
실패 뒤 기존 소유자 snapshot이 바뀌지 않는지를 추가했습니다. 이것은 **결함 해결 완료**입니다.

## 3. 세 요구 판정

| 요구 | 판정 | 근거와 경계 |
| --- | --- | --- |
| 전체 GPIO alias·DMA overlap | **검증·판정 완료** | production `IoResourceManager` Host 시험에서 같은 물리 GPIO의 alias 중복과 겹치는 DMA 범위를 거부하고 기존 소유자 snapshot을 보존했습니다. M14 variant 계약이 31개 물리 pad의 alias mapping을 전수 검사합니다. |
| 활성 GPIOTE·DPPI 충돌 | **검증·판정 완료** | production event Host 시험에서 DPPI20 channel을 enable한 상태의 중복 lease와 충돌 publisher를 거부하고 channel enable·endpoint를 보존했습니다. 실제 내부 DPPI10/20 route는 두 보드에서 반복 실행·반환했습니다. |
| Fabric PWM과 public PWM API | **결함 해결·판정 완료** | 자원 식별 불일치를 교정하고 동일 block 중복 요청·기존 소유자 보존을 Host에서 확인했습니다. PWM20/21/22의 실제 시작·정지·반환은 두 보드 HIL로 확인했습니다. |

현재 Kconfig는 Analog Fabric이 `CONFIG_NUCODE_ARDUINO_ADC` 및
`CONFIG_NUCODE_ARDUINO_PWM`과 상호 배타적이므로, 지원 구성에서 Fabric PWM과
`analogWrite()`/`tone()`/`Servo`가 한 image 안에서 동시에 활성화되지는 않습니다. 따라서 동시 API의
물리 충돌 시험을 허위로 PASS 처리하지 않았습니다. 이번 공통 키 교정은 구성 경계가 바뀔 때도
소유권 계약이 깨지지 않게 하며, 현재 지원 범위는 T15에서 그대로 명시합니다.

## 4. 회귀와 실기 결과

| 계층 | 결과 |
| --- | --- |
| 계약 | 46개 PASS |
| inventory·생성 계약 | PASS, generated contract 5개 일치 |
| Host 전체 gate | `M12_GATE_PASS=host` |
| 문서 gate | Markdown 231개 UTF-8·로컬 링크 검사 PASS |
| C++ 정렬 | 420개, 실패 0 |
| target build | v0.3 `nucode.ac02b.analog_contract`, v0.4 `nucode.m25.analog`·`event`·`nojumper_hil` 4/4 PASS |
| 두 보드 HIL | **PASS**, 28 command·520 cycle |

각 보드는 PWM20/21/22의 네 mode를 20회씩 실행한 240 cycle과 대표 DPPI10/20 route를
10회씩 실행한 20 cycle, 합계 260 cycle을 통과했습니다. 종료 뒤 두 보드 모두 PWM enable은
`[0, 0, 0]`, DPPI channel은 `[0, 0, 0, 0]`, SAADC enable은 `0`이었고 P1.14 설정도
원래 값으로 복구됐습니다.

Host 실행 전 C 드라이브 정리로 PyYAML 등 locked dependency가 사라진 상태와 NCS Python 환경
누락을 각각 확인했습니다. `requirements-host.txt`의 hash 고정 의존성과 NCS toolchain 환경을
복원한 뒤 동일 gate를 통과했으므로 코어 실패로 분류하지 않습니다. GCC 16.1 MinGW의 PE/COFF
weak BLE link 문제는 LLVM Host gate로 분리했고 이번 변경의 자원 계약 실패로 계산하지 않습니다.
