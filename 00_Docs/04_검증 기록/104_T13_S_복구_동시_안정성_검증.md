## 진행 순서와 현장 경계

1. T13 전용 runtime/Host runner와 S 결선 검사를 구현한다. 기존 C 전용 기능 명령을 S에서 실행하지 않는다.
2. Host·style·계약·영향 target를 검사하고 clean source에서 exact 두 image를 빌드한다.
3. 새 UID/image·S 확인서와 SWD 10 MHz·controlled flash를 대조한 뒤 제한된 결선 검사부터 실행한다.
4. 짧은 기능 preflight, S 단독/복구/전환, C07 제외 동시/안정성 결과를 개별 ID로 보존한다.
5. 실패는 원본과 cleanup을 남기고 원인에 맞는 보완·영향 회귀를 수행한다. 중단 시간을 합산하지 않는다.
6. S 묶음 종료 후 U의 GPIO 표를 다시 안내하고 사용자의 변경 완료 확인을 받는다.

System OFF 기본 wake는 기존 M15/M26 근거가 있다. T13의 새 DMA/복구 요구에 재시험이 필요한지
먼저 대조한다. 현재 별도 실행 조건·ID가 없는 격리·재연결을 반드시 필요한 수동 단계로 안내한
표현을 정정한다. 새 조건이 필요한 경우 근거와 조작을 구체화하며, 기본 wake 근거를 새 복구
조건의 PASS로 확대하지 않는다. U·RC·공개는 아직 미실행이다.

## 첫 serial 실행기 준비 검사

S/U 고정 GPIO·현재 세션·nonce/sequence·plan hash를 갖춘 전용 firmware를 추가했다.
현재 구현은 UART/SPI/TWI의 활성 유지·20ms frame 간격·두 DMA slot 반환 후 재공급이며,
stream·복구/전환 100회는 구현 중이다. 미구현 stream case는 실행을 거부하며 무부하 성공으로
대체하지 않는다. T13 단독/동시 실제 PASS는 아직 0회다.

- Dirty 준비 target 두 role 2/2 build-only PASS(111.71초). Flash에는 후속 clean exact build를 사용한다.
- T13 관련 Host 9개 PASS: 생산 route·S/U 분리·만료/UID·실제 완료 길이/패턴·가드·생성 일치.
- 문서 217개 링크 PASS, 계약 45개 PASS, 첫 C/C++ 정렬 396개 PASS. 이후 추가 파일은 최종 검사한다.
- 최초 Host fixture의 dict alias 오류는 교정했고 원래 실패 log를 보존한다. 전체 Host의 target 수
  고정값 28도 새 S 두 role 추가에 맞춰 30으로 갱신한다. 제품 core·SDK·board gitlink 변경은 없다.
- SPI/TWI 단독의 두 역할은 동일 결선·속도·버퍼·180초를 요구하므로 한 물리 실행에서 양쪽을

  중복 9회(27분)만 제거하며 어떤 instance의 180초 요구도 줄이지 않는다.
