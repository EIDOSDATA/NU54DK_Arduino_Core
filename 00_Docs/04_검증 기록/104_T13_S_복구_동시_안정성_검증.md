4. 짧은 기능 preflight, S 단독/복구/전환, C07 제외 동시/안정성 결과를 개별 ID로 보존한다.

stream·복구/전환 100회는 구현 중이다. 미구현 stream case는 실행을 거부하며 무부하 성공으로
대체하지 않는다. T13 단독/동시 실제 PASS는 아직 0회다.

## Exact 7a33b77의 결선 검사와 UART 시작 교정

Clean `7a33b77f9ed49a671deb2673441c6adc271c6f73`의 두 role 2/2 target build를
`C:/t3e04`에서 완료했다. 기존 출력 경로 재사용을 거부한 첫 build도 실패 원본으로 보존한다.
이 commit은 main에 push했다. 앞선 6155a85 CI는 15/15 SUCCESS, 7a33b77은 조회 시
Software 7개와 Zephyr v0.1.0 성공·나머지 재현 build 7개 진행 중이었다.

- 첫 S 결선 실행은 A GPIO P1.05 → B GPIO P1.04의 LOW 전달 불일치로 정지했다.
  별도 제한된 방향/시각 진단에서 해당 선은 양방향 peer 읽기 12회 불일치,
  인접 A P1.04 ↔ B P1.05는 24회 일치했다. LOW 후 15~125ms 관측이므로 500ms pulse 만료가 아니다.
- 사용자가 두 USB 분리·해당 점퍼 확인·재연결과 S 유지를 확인했다. USB/exact UID를 새로 열거하고
  repair1 확인서를 만들었으며 원래 세션 종료 `2026-09-08T12:26:14Z`를 연장하지 않았다.
- 두 번째 controlled flash(SWD 10MHz) 후 **17신호×양방향×3회=102 + pulse/lease 3 =105/105 PASS**.
  이전 실패는 삭제하거나 PASS로 바꾸지 않는다.
- 이어진 첫 UART20 preflight에서 B START 명령이 403으로 거부됐다. Reset 없는 SWD 읽기로
  두 보드의 첫 UART event 오류 25, hardware error mask `0x0C`(framing/break), TX 제출 0개를 확인했다.
  원인은 시험 프로그램이 상대 TX idle 준비 전에 RX DMA를 켜는 순서였다. T13 시험기의 RX 공급을
  양쪽 prepare 완료 뒤 START로 옮기고, Host는 양쪽 준비 상태와 lane raw를 먼저 저장한다.
- 두 보드의 engine lease 만료는 0, UART active=0, lane_count=0, 모든 17개 GPIO input을
  읽어 확인했다. B의 원래 mailbox는 poison 상태여서 STOP 명령 확인을 성공으로 쓰지 않으며,
  별도 read-only 관측과 구분한다. 새로운 실행은 controlled flash로만 시작한다.

실패·결선 성공·진단·exact build 원본 14개와 hash는
[7a33b77 preflight manifest](evidence/t13-s-preflight-7a33b77/manifest.json)에 보존한다.
