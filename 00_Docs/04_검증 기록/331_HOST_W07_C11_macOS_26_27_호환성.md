# HOST-W07 C11 — macOS 실행기 교정과 26·27 호환성

기준일: 2026-11-16. 현재 M33-W07 / HOST-W07, Host6/8·지원3/5다.
사용자는 Mac이 없는 상태에서 가능한 macOS26·27 검증과 공통 실행기 수정을 지시했다.
C5 Windows 기준선, C10 Ubuntu24.04·26.04 WSL2 완료와 원본 PASS·FAIL은
[330번](330_HOST_W07_C6_WSL2_지원과_Ubuntu24.04_검증.md)에 보존한다.

## 원인과 교정 범위

C10 `4890f697ab80dfed3cff62bd42acc42b0f3e1a34`의 prerequisite run43743775292/job132902468528은
SDK 설치 전 손자 process 정리 시험에서 `PermissionError`로 실패했다. 별도 진단 run43745916309의
원형10회 중3회에서 같은 PGID의 SIGTERM 성공 뒤 SIGKILL EPERM을 관측했다. 직후 그룹 목록은 비어 있었다.
별도 zombie 실험도 EPERM을 재현했지만 원형 실패 순간이 zombie-only였다고 직접 입증한 것은 아니다.

C11은 Darwin의 마지막 SIGKILL이 EPERM일 때만 같은 소유 PGID에 signal0을 최대0.5초 조회한다.
실제 ESRCH를 확인해야 정리 성공을 인정한다. 조회 성공(그룹 생존), 지속 EPERM, 다른 errno는 계속 실패한다.
추가 종료 신호나 외부 process 열거는 하지 않는다. 원래 exit code·출력·timeout·사용자 중단 판정을 유지한다.
SDK·compiler·firmware·board pin·컴파일 recipe는 바꾸지 않는다.

## 새 검증의 경계

- 로컬 Windows 변경 영향 검사: 70개 중68 PASS·조건부SKIP2, `fd23ad/exit0`.
- 로컬 Linux 실제 자식·손자 정리와 오류 경계: 14 PASS, `2f4da3/exit0`.
- 최초 비격리 SDK Python 실행은6개 실제 Windows 시험의 `AttributeError`로 실패했다(`de1f7e/exit1`).
  원본 `D:/w06/h7c11/owned-windows-local-a001.log`를 보존한다. 격리 실행14PASS(`d8ad09/exit0`)와
  후속70개 결과를 별도로 기록한다. 내부 환경 충돌의 상세 원인까지 확정한 것은 아니다.
- macOS26·27 fresh CI는 교정 source 고정 뒤 실행한다. 준비 상태를 PASS로 기록하지 않는다.
- 전체204·기존 보드 HIL·W06 #29 분석을 반복하지 않는다. 기존 C5/C10 실적을 C11 실적으로 합산하지 않는다.

새 [집중 CI](../../.github/workflows/host-macos-compatibility.yml)는 Windows·Linux·macOS26·27의
관련 단위검사와 Mac 두 버전의 고정 SDK 설치·lifecycle·대표4cold/4warm을 담당한다.
같은 C11 source로 만든 host.1→RC1 두 version fixture는 설치 전이 시험이며 이전 공개판의 실적이 아니다.
실제 macOS major·ARM64·image·run/attempt를 기록하고 각 OS 원본 artifact를 구분한다.

## 실제 Mac 준비와 남은 순서

1. CI에서 macOS 실행기·설치·대표 build를 확인한다. 원본 C10 FAIL을 보존한다.
2. Apple Silicon Mac 한 대를 대여하거나 테스터를 확보한다. 26·27을 각각 실행할 수 있어야 하며 두 대를 살 필요는 없다.
3. NU54DK 한 대의 CMSIS-DAP USB, 데이터 케이블, 필요 시 Mac 포트에 맞는 어댑터를 준비한다.
   BLE 두 보드 시험이 실제 배정될 때만 두 번째 NU54DK를 추가한다.
4. IDE를 사용할 계정과 고정 `/opt/nordic/ncs` 설치 권한을 준비한다. 비밀번호를 채팅에 보내지 않는다.
5. Mac에서 IDE 설치·Verify와 USB upload·serial·debug·재연결을 검증하고 지원표를 갱신한다.
6. HOST-W08 문서·지원표·설치 안내를 마감한 뒤 M33-W07을 종료한다. 공개 tag·Release·index는 M33-W08의 별도 승인 단계다.

원격 Mac을 이용하려면 그 Mac에 NU54DK를 직접 연결할 수 있어야 한다. GitHub runner의 software PASS는
사용자 USB·IDE 실기 PASS가 아니며 지원3/5·Host6/8을 자동으로 올리지 않는다.
