### 추정 원인과 보완·재개 조건

1. 가장 유력한 구간은 유효 SAMPLE의 누산 갱신과 동작 중 수동 read/clear의 상호작용이다.
   입력과 SAMPLE 합 400에 누산 399, 종료 후 읽기 30 회 일치, 샘플 직후 읽기 30 회 일치가
   이를 지지한다. 단순 DSB·5 µs 지연·read 구간 IRQ 보호는 재현을 없애지 못했다.
   SDK/HAL 접근 순서인지 실리콘 내부 경계인지 확정하지 못했으며 공식 atomic 계약 위반으로
   단정하지 않는다. 수치 보정과 원인 불명의 core/SDK 변경은 적용하지 않았다.
2. REPORT-only IRQ20 회 일치는 후속 대안 후보의 근거다. 실제 SAMPLE/REPORT IRQ를 시험했지만
   독립 GPIOTE ISR quadrature decoder는 아직 시험하지 않았다. IRQ 대안을 사용하려면 두
   instance·정역·debounce·속도·연속 동작·queue overflow·ACCOF·STOP/restart를 별도로
   검증하고 manual read와 자동 report를 혼용하지 않는 계약을 정해야 한다. 짧은 진단을
   제품 지원 확정이나 기능 240 PASS로 대신하지 않는다.
3. 완료 후 읽기 방식은 누산 포화 전의 짧은 유한 이동에 한정한 관측이다. 장시간 누산,
   read 없이 무한 실행, 값을 매번 읽고 0으로 쓰는 STM32식 대안을 그대로 적용하지 않는다.
4. P1.10/P1.14의 LED 버퍼 입력 분기는 확인했지만 아날로그 신호와 부하 없는 핀 대비는
   미측정이다. 재개 시 같은 source로 GPIO 입력을 새 승인 핀에 옮기는 유한 대비 또는
   장비가 있을 때 A 입력단 파형을 확인할 수 있다. 이 미측정을 현재 전기적 결함 확정이나
   릴리스의 외부 계측 장비 필수 요구로 바꾸지 않는다.
5. 사용자가 미해결이면 보완 후 다음 작업으로 진행하도록 지시하여 원인 진단 반복을 끝낸다.
   [T13 계획](../../tests/hil/nu54dk/T13_PLAN.md)의 QDEC20/21 단독·C07에 명시적 선행
   HOLD를 추가했다. 원래 manual read 기반 시험은 해당 경로 해결과 기능 240 통과가 필요하며
   IRQ 방식 자동 대체는 금지한다. 다른 T13 조합의 계획은 유지한다. T13 실기·T12 전체·
   지원 범위 확정·RC·공개는 미완료이며 다음 허용 작업은 증거·문서·검사·commit/push·CI다.

## GPIO 전기 설정 대조

사용자가 풀업·풀다운·오픈드레인 요구를 질문하여 nRF54L15 문서와 실제 SDK 경로를 대조했다.
[QDEC 핀 설정표](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-concept_t2t_myd_4r)는
ENABLE 전에 Phase A/B와 LED의 GPIO 방향을 Input으로 설정하고 유지하도록 요구한다.
풀업·풀다운·오픈드레인 필수 요구는 해당 표에 없다. QDEC가 취득한 핀은
[CPU가 읽을 수 있다](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-concept_pgt_gyd_4r).

| 위치 | 실제 코드가 적용하는 설정 | 근거 |
| --- | --- | --- |
| A P1.14·P1.10 | Input, input buffer Connect, No pull, S0S1, Sense disabled | `nrfx_qdec.c:qdec_configure`가 `nrfy_gpio_cfg_input(..., NRF_GPIO_PIN_NOPULL)`을 호출한다. 현재 core는 `skip_gpio_cfg`를 켜지 않는다. |
| B P1.14·P1.10 | Output, input buffer Disconnect, No pull, S0S1 push-pull, Sense disabled | `common_qdec_hil.cpp`의 `nrf_gpio_cfg_output`과 `nrf_gpio.h`의 구현이다. 파형 시작 전에 LOW를 설정한다. |
| 시험 종료 | 두 보드 모두 Input/No pull | A QDEC를 먼저 STOP하고 B 출력을 해제한다. 각 캠페인 postflight에서 PIN_CNF를 읽어 확인했다. |

[PIN_CNF 문서](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/gpio.html-register.pin_cnf)는
입력 버퍼, pull, DRIVE0/DRIVE1을 별도로 정의한다. 현재 B는 HIGH/LOW를 모두 구동하므로
이 공통 결선 시험에 추가 풀업을 요구하지 않는다. 외부 open-drain 엔코더를 사용한다면
HIGH를 형성하는 풀업이 필요하며 엔코더 출력 회로·전압·속도에 맞춰 별도 검토해야 한다.
그 외부 엔코더 조건을 현재 보드 대 보드 push-pull 시험으로 검증했다고 표시하지 않는다.

GPIO 전이와 hardware SAMPLE이 모두 400인 실행에서 누산만 399로 남았으므로 현재 근거는
입력 pull 누락보다 동작 중 read/clear 구간을 가리킨다. 아날로그 파형을 측정한 것은 아니다.
추가로 `nrfy_qdec_periph_configure`는 LED가 disconnected이면 API의 `led_pre_us=0` 대신
`NRF_QDEC_LEDPRE_DEFAULT`(nRF54L15 정의 16 µs)를 설정한다. 이전 page0 계측에는 LEDPRE가
없었으므로 요청 설정 0을 실제 레지스터 0이라고 해석하지 않는다. 이 SDK 동작을 누락 원인으로
확정하거나 변경하지 않았다.

## 샘플 시점 대비 결과

exact `a7e9b55ba5a8769c34c660d9288392174422b7d6`의 `qdec-timing-diagnostic`에서
방법 0(공개 read), 3(동일 task 뒤 DSB를 넣은 HAL 진단), 4(새 SAMPLE 관측 후
32~64 µs에 공개 read)를 각 30 회 비교했다.
방법 4는 진단의 고정 256 µs 샘플 조건에서만 사용하고, IRQ를 잠근 상태에서 새 SAMPLE을
4 µs 간격으로 관측하되 대기는 1024 µs로 제한한다. GPIO/SAMPLE 관측과 기존 포화·lease·STOP
검사를 유지한다. 이 시험의 기다리는 방법을 제품 API로 채택한 것이 아니다.
page6에 read 시 SAMPLE 관측 경과의 최소/최대µs와 최대 대기µs를 기록한다.
기대 카운트는 보정하지 않으며 실패 원본을 유지한다. 이 대비도 기능 240 또는 T13 실기 PASS가 아니다.

| 방법 | 비교 | 누산 불일치 | 최대 GPIO poll / SAMPLE gap | read 시 샘플 경과 |
| --- | ---: | ---: | --- | --- |
| 공개 read | 30 | 5 | 119 / 344 µs | 4~257 µs |
| HAL + DSB | 30 | 5 | 111 / 351 µs | 4~258 µs |
| 샘플 후 공개 read | 30 | 0 | 104 / 261 µs | 33~40 µs |

DSB 방식 repeat9는 398이며 나머지 불일치는 399다. 모든 GPIO/SAMPLE은 400·double0,
제어 오류 0, cleanup 93(기능 90+501정리 3), 종료 postflight PASS다. 샘플 후 방식의 최대
대기는 288 µs·최대 read 간격 512 µs였다. [실패·분석·Host·target·정렬·software 원본](evidence/t12-common-qdec-a7e9b55-timing/manifest.json).
session15696은 종료했다. 이 결과는 DSB만의 수정으로 충분하지 않으며 clear 시점의 영향을
지지한다. 장시간 IRQ를 잠그는 진단을 그대로 제품 구현으로 채택하지 않는다.

[nRF54L15 READCLRACC 레지스터 설명](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-register.tasks_readclracc)은
snapshot과 clear가 원자적이라고 명시한다. 따라서 위 관측만으로 그 하드웨어 보장이
깨졌다고 단정하지 않고 task 이후 반환 레지스터의 반영 지연도 분리해야 한다.

### 관측 품질 판정 보완

128 µs GPIO 간격을 SAMPLE poll의 대용 지표로 사용한 판정은 GPIO 처리와 SAMPLE 읽기의
실제 경계를 구별하지 못했다. 다음 source는 page9에 `observeSample` 시작 간 최대 간격P,
함수 안의 최대 실행시간D(선점 포함), 호출 수를 직접 기록한다. 고정 SAMPLEPER256 µs에서
1 MHz 시간 양자화 여유 2 µs를 더해 `W=P+D+2 < 256`이고,
실제 SAMPLERDY 관측 최대 간격G에 대해 `G+W < 512`여야 한다. 처리 완료까지 다음
샘플 주기를 넘지 않는지와 한 샘플을 건너뛸 경우의 최소 관측 간격을 각각 검사한다.
GPIO는 10 ms phase보다 충분히 짧은 256 µs 미만을 요구하며 발신 400·GPIO400·SAMPLE400·
double0과 마지막 phase0은 그대로 대조한다. GPIO 기준은 128→256 µs로 바뀌지만
샘플 누락 판정은 직접 측정한P/D와 결합한다. 이전 실패를 새 기준의 PASS로 재분류하지 않는다.
Host는 누락 카운트·P/D 초과·관측 호출 부족·한 샘플 누락 가능 간격을 주입해 거부를 확인했다.

## 사용자 제안: IRQ·DMA·LED 회로 분리

사용자가 현재 비교를 끝낸 뒤 인터럽트 카운팅, DMA와 GPIO의 LED/슈미트 부하를 빠르게
대조하도록 지시했다. 다음 `qdec-irq-diagnostic`은 QDEC20/21 × SAMPLE IRQ/REPORT IRQ ×
10 회, 총 40 회다. 같은 P1.14/P1.10·256 µs SAMPLE·400 개 10 ms 전이를 유지한다.
방법 7은 `sample_events=true`, `report_events=false`로 공개 SAMPLE 이벤트를 합산하면서
기존 공개 read/clear 반환값도 별도로 기록한다. 방법 8은 `sample_events=false`,
`report_events=true`로 자동 shortcut/REPORT IRQ 이벤트만 합산하고 명시적 read/clear를
섞지 않는다. 각각 실제 INTEN5/6·SHORTS0/1을 검사한다. page10에 IRQ 합·개수·double·
큐 오류·서비스 간격을 보존한다. GPIO400·서비스 256 µs 미만·오류 0이 선행 조건이며
숫자 불일치는 양쪽 STOP 뒤 다음 비교로 진행하고 기능 240의 PASS로 표시하지 않는다.
이는 QDEC SAMPLE/REPORT IRQ 진단이며 별도의 GPIO GPIOTE ISR 디코더 실기를 했다는 뜻은 아니다.

QDEC20/21의 현재 SDK 레지스터/드라이버와 core에는 EasyDMA 버퍼 경로가 없다.
[QDEC 레지스터 목록](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-topic)을
따르며 DMA와 혼동하지 않는다. 예전 Fixture420의 DMA는 B의 PWM 파형 생성에 사용했다.
현재 common QDEC는 B CPU가 GPIO OUT으로 파형을 생성하고 모든 PWM ENABLE이 0인 상태에서도
누락을 재현하므로 PWM DMA가 이 재현에 필수인 원인은 아니다.

[85번 기본 48 조건](85_T12_Fixture_420_current_source_QDEC_재검증.md)은
A P1.04/P1.06 ← B P1.14/P1.10에서 1/100 회전·정역·debounce를 검사했고 22.063 초 동안
±4/±400을 통과했다. 당시 Host는 B 유한 파형 완료 후 opcode37로 누산을 읽었다.
현재는 A도P1.14/P1.10이고 동작 중 반복read/clear·1000 회전·반복 10 회가 추가돼
조건과 관측 창이 다르다. 기본 48 조건의 성공은 현재 동작 중 read 회귀의 성공을 보장하지 않는다.

[보드 회로도](../../board_package/NU54DK_Zephyr_DTS/NU54-DK%20Schematic.pdf) sheet1·8을
직접 렌더링해 대조했다. P1.10=LED2, P1.14=LED4다. GPIO는 330Ω(R32/R34)을 거쳐
NC7WZ17P6X의 입력(U8B/U9B)으로 분기되고, 출력은 EMH60T2R과 LED를 구동한다.
버퍼가 A/B 사이 QDEC 신호에 직렬로 들어가는 구조는 아니다. 현재 양쪽 보드의 LED 입력
부하는 공유되며 깜빡임은 신호 전이로 설명된다. 입력 용량·배선/접지 잡음·실장 이상까지
회로도나 GPIO 관측만으로 배제하지 않는다. 아날로그 edge 지연·ringing은 아직 측정하지 않았다.
회로도 hash와 실제 board gitlink는 동일 source의 증거에 연결한다.

## IRQ40 비교 완료와 NVIC 대조

exact `3a0e976f7567f032cf8e5abded3cf33ee213434c` C:/cbx04에서 SAMPLE IRQ20 회·자동
REPORT IRQ20 회 모두 400/400으로 일치했다. SAMPLE 이벤트 336,710 개, REPORT 이벤트 8,000 개,
IRQ 오류 0, 최대 이벤트 서비스 간격 128 µs, cleanup 43·양쪽 postflight PASS다.
[원본·NVIC·회로도 hash·검사](evidence/t12-common-qdec-3a0e976-irq/manifest.json).
이 40 회도 진단이며 실패한 기능 240을 완료시키지 않는다. GPIO 전이를 CPU ISR에서 별도로
decode한 결과가 아니라 QDEC의 SAMPLE/REPORT IRQ와 공개 이벤트 큐를 사용한 결과다.

`StreamFabric.cpp`는 QDEC20/21 IRQ를 `IRQ_PRIO_LOWEST`로 연결한다. Zephyr nrfx glue의
`NRFX_IRQ_PRIORITY_SET`은 빈 동작이라 config의 우선순위만 고치는 것은 실제 변경이 아니다.
이 빌드는 priority bits3·zero-latency IRQ off, Zephyr IRQ offset 1이므로 논리 6이 NVIC7이다.
종료 후 리셋/halt/flash 없이 두 보드의 NVIC를 읽어 IRQ224/225의 priority byte0xE0,
PRIGROUP0을 확인했다. 종료 시 켜진 IRQ219/228/261/269는 0x40(우선순위 2)이었다.
QDEC IRQ는 종료 후 disable됐고 이 snapshot을 시험 중 enable 상태로 해석하지 않는다.

기존 실패는 SAMPLE/REPORT IRQ off·ACCOF만 on이므로 QDEC IRQ 이벤트 처리 지연으로
단정하지 않는다. 다른 IRQ의 CPU 선점 가능성을 분리하기 위해 다음 비교는 공개 read0과
방법 9(read 구간만 irq_lock·샘플 위상 대기 없음)를 30 회씩, 총 60 회다. 방법 9는 진단 전용이며
page11에서 실제 NVIC7·enabled1·read 보호 128 µs 미만·BASEPRI/PRIMASK 복원을 검사한다.
샘플 직후 방식 4의 성공이 선점 억제 때문인지 샘플 위상 때문인지 구별하는 마지막 짧은 대비다.

사용자는 이 대비들 이후에도 미해결이면 유력 원인·보완·제한을 남기고 다음 허용 작업으로
넘어가도록 지시했다. 재현되는 동작 중 read/clear를 PASS로 바꾸거나 숫자를 보정하지 않는다.
기본 종료 후 read와 IRQ40의 제한된 근거는 유지하고, manual read와 긴 IRQ 안정성/동시성의
지원 확정은 HOLD한다. 이번 요청의 다음 작업은 이미 확정한 T13 조합/결선 계획과 전체 문서·
증거·commit/push·CI 정리이며 T13 외부 실기/soak·RC·정식 배포를 자동 완료하지 않는다.

## STM32 커뮤니티 유사 사례의 범위

사용자 요청으로 [ST 커뮤니티의 2023-08-25 STM32F030 사례](https://community.st.com/stm32-mcus-products-25/weird-behavior-of-timer-after-setting-cnt-register-to-0-after-specific-time-120265)를
확인했다. TIM3 encoder CNT를 100 ms마다 읽고 0으로 쓴 뒤 기대 20보다 적은 카운트를
보고한 사례다. 답변은 읽기와 0 쓰기 사이 펄스 손실 가능성·높은 IRQ 우선순위에 따른
지연을 지적하고, 연속 CNT의 차이 계산과 overflow 처리 또는 DMA를 제안했다.
다만 작성자는 입력 필터 10으로 개선됐고 두 방식의 결과가 같다고 후속 보고했으며,
채택 답변도 잡음과 필터 적용 전 DIR 판정에 초점을 둔다. 따라서 STM32에서도 관련
경합·잡음 논의가 있었다는 근거로만 쓰며 동일 실리콘 결함이나 nRF54 해결책으로 단정하지 않는다.
STM32의 별도 CNT 읽기/0 쓰기와 Nordic의 원자적 READCLRACC task는 하드웨어 계약이 다르다.
