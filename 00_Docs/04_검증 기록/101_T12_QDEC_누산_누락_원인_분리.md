## GPIO 전기 설정 대조

사용자가 풀업·풀다운·오픈드레인 요구를 질문하여 nRF54L15 문서와 실제 SDK 경로를 대조했다.
[QDEC 핀 설정표](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-concept_t2t_myd_4r)는
ENABLE 전에 Phase A/B와 LED의 GPIO 방향을 Input으로 설정하고 유지하도록 요구한다.
풀업·풀다운·오픈드레인 필수 요구는 해당 표에 없다. QDEC가 취득한 핀은
[CPU가 읽을 수 있다](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-concept_pgt_gyd_4r).

| 위치 | 실제 코드가 적용하는 설정 | 근거 |
| --- | --- | --- |
| A P1.14·P1.10 | Input, input buffer Connect, No pull, S0S1, Sense disabled | `nrfx_qdec.c:qdec_configure`가 `nrfy_gpio_cfg_input(..., NRF_GPIO_PIN_NOPULL)`을 호출한다. 현재 core는 `skip_gpio_cfg`를 켜지 않는다. |
| B P1.14·P1.10 | Output, input buffer Disconnect, No pull, S0S1 push-pull, Sense disabled | `common_qdec_hil.cpp`의 `nrf_gpio_cfg_output`과 `nrf_gpio.h`의 구현이다. 파형 시작 전에 LOW를 설정한다. |
| 시험 종료 | 두 보드 모두 Input/No pull | A QDEC를 먼저 STOP하고 B 출력을 해제한다. 각 캠페인 postflight에서 PIN_CNF를 읽어 확인했다. |

[PIN_CNF 문서](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/gpio.html-register.pin_cnf)는
입력 버퍼, pull, DRIVE0/DRIVE1을 별도로 정의한다. 현재 B는 HIGH/LOW를 모두 구동하므로
이 공통 결선 시험에 추가 풀업을 요구하지 않는다. 외부 open-drain 엔코더를 사용한다면
HIGH를 형성하는 풀업이 필요하며 엔코더 출력 회로·전압·속도에 맞춰 별도 검토해야 한다.
그 외부 엔코더 조건을 현재 보드 대 보드 push-pull 시험으로 검증했다고 표시하지 않는다.

GPIO 전이와 hardware SAMPLE이 모두 400인 실행에서 누산만399로 남았으므로 현재 근거는
입력 pull 누락보다 동작 중 read/clear 구간을 가리킨다. 아날로그 파형을 측정한 것은 아니다.
추가로 `nrfy_qdec_periph_configure`는 LED가 disconnected이면 API의 `led_pre_us=0` 대신
`NRF_QDEC_LEDPRE_DEFAULT`(nRF54L15 정의16µs)를 설정한다. 이전 page0 계측에는 LEDPRE가
없었으므로 요청 설정0을 실제 레지스터0이라고 해석하지 않는다. 이 SDK 동작을 누락 원인으로
확정하거나 변경하지 않았다.

## 샘플 시점 대비 결과

exact `a7e9b55ba5a8769c34c660d9288392174422b7d6`의 `qdec-timing-diagnostic`에서
방법 0(공개 read), 3(동일 task 뒤 DSB를 넣은 HAL 진단), 4(새 SAMPLE 관측 후
32~64µs에 공개 read)를 각 30회 비교했다.
방법 4는 진단의 고정 256µs 샘플 조건에서만 사용하고, IRQ를 잠근 상태에서 새 SAMPLE을
4µs 간격으로 관측하되 대기는 1024µs로 제한한다. GPIO/SAMPLE 관측과 기존 포화·lease·STOP
검사를 유지한다. 이 시험의 기다리는 방법을 제품 API로 채택한 것이 아니다.
page6에 read 시 SAMPLE 관측 경과의 최소/최대µs와 최대 대기µs를 기록한다.
기대 카운트는 보정하지 않으며 실패 원본을 유지한다. 이 대비도 기능240 또는 T13 실기 PASS가 아니다.

| 방법 | 비교 | 누산 불일치 | 최대 GPIO poll / SAMPLE gap | read 시 샘플 경과 |
| --- | ---: | ---: | --- | --- |
| 공개 read | 30 | 5 | 119 / 344µs | 4~257µs |
| HAL + DSB | 30 | 5 | 111 / 351µs | 4~258µs |
| 샘플 후 공개 read | 30 | 0 | 104 / 261µs | 33~40µs |

DSB 방식 repeat9는398이며 나머지 불일치는399다. 모든 GPIO/SAMPLE은400·double0,
제어 오류0, cleanup93(기능90+501정리3), 종료 postflight PASS다. 샘플 후 방식의 최대
대기는288µs·최대 read 간격512µs였다. [실패·분석·Host·target·정렬·software 원본](evidence/t12-common-qdec-a7e9b55-timing/manifest.json).
session15696은 종료했다. 이 결과는 DSB만의 수정으로 충분하지 않으며 clear 시점의 영향을
지지한다. 장시간 IRQ를 잠그는 진단을 그대로 제품 구현으로 채택하지 않는다.

[nRF54L15 READCLRACC 레지스터 설명](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/qdec.html-register.tasks_readclracc)은
snapshot과 clear가 원자적이라고 명시한다. 따라서 위 관측만으로 그 하드웨어 보장이
깨졌다고 단정하지 않고 task 이후 반환 레지스터의 반영 지연도 분리해야 한다.
