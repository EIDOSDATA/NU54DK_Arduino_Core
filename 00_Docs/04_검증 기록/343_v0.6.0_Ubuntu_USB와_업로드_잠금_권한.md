# v0.6.0 Ubuntu USB와 업로드 잠금 권한

2026-11-24 KST에 Ubuntu 26.04.1 LTS AMD64 native, Arduino IDE 2.3.11에서 공개 v0.6.0 설치본으로 스케치를 빌드했습니다. 제품 소스는 `0a63c501ccd0d2e26298f1ad98a81a99cddc565f`입니다. 설치 기록에서 NCS 버전 `v3.4.0`과 상태 `ready`를 확인했습니다.

| 단계 | 관찰 결과 |
| --- | --- |
| IDE 빌드 | `[NU54 5/5]` 산출물·메모리 검증 완료. 스케치는 프로그램 공간 78,184바이트를 사용했습니다. |
| udev 적용 전 Upload | `E_PROBE_NONE`으로 중단됐습니다. Linux는 `0d28:0204`와 시리얼 포트 2개를 열거했지만 USB 장치 노드는 `root:root`, `0664`였습니다. 동봉 툴체인의 pyOCD 0.42.0이 `Permission denied`를 기록하고 사용 가능한 프로브 0개를 반환했습니다. |
| udev 적용 후 Upload | USB 장치 노드는 `root:plugdev`, `0660`으로 변경됐습니다. `NU54_UPLOAD_START`로 CMSIS-DAP 프로브 선택을 확인했고, `E_LOCK_PERMISSION`으로 플래시 실행 전에 중단됐습니다. 이 시도의 HEX SHA-256은 `4ff94c0a35f312fbb74562a8d30a031cc1027786c779c3a0448da6944e8d2d1d`입니다. |
| 잠금 오류 재현과 복구 | 실제 `/tmp/n54`의 소유자는 IDE 실행 계정이고 권한은 `775`였습니다. 설치본의 잠금 코드를 임시 경로에서 `umask 0002`로 실행해 같은 권한과 오류를 재현했습니다. 실제 경로를 `700`으로 조정한 뒤, 연결된 프로브에 대해 같은 설치본으로 배타 잠금 획득과 해제를 확인했습니다. 플래시 실행은 `NOT_RUN`입니다. |

잠금 코드는 프로브별 상태 경로의 상위 디렉터리를 먼저 생성합니다. 이때 생성된 `/tmp/n54`에 그룹 쓰기 권한이 있으면 이후 POSIX 잠금 코드가 그 경로를 거부합니다. [잠금 구현](../../tools/nu54-builder/src/nu54_builder_impl/locking.py)

위 결과는 Ubuntu에서 보고된 두 오류에 대한 진단입니다. 후속 IDE Upload 성공과 보드 동작은 미확인입니다. [사용자 복구 절차](<../05_릴리스/v0.6.0/TROUBLESHOOTING.md#linux에서-업로드-오류가-날-때>)
