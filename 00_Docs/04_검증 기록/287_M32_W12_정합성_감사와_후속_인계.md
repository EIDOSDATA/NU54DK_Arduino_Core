경로, 74개 M32 예제, 15개 자원 profile, 24개 test family/case와 대조했다. 최종 원장은
`work_completed=12`, `test_family_passed=23`이다. `M32-ACL-01`은 controller experimental=true와

source `94f02544…`를 바꾸거나 해당 HIL을 `49099e74…`에서 재실행했다는 뜻은 아니다.

## 2. HIL 실패 보존과 접근 경계

Privacy 첫 exact 실행은 identity_b `session_timeout`으로 FAIL했다. 원본을 삭제하거나 PASS로 덮지
않았고, 같은 clean SHA·동일 image의 허용된 1회 bounded retry에서 A/B 20/20과 peer 200/200을
PASS했다. 나머지 11개 family도 같은 exact source에서 PASS해 closure는 12/12다.

세 보드 access preflight는 모두 `ahb_debug_enabled=true`, `eraseall_required=false`였다. 사용자는
CTRL-AP ERASEALL과 기존 flash 삭제를 명시적으로 승인했지만 이번 exact 실행에는 필요하지 않아
ERASEALL·mass erase·recover를 수행하지 않았다. 증거에는 raw UID나 private signing key를 넣지 않고
probe 식별자는 hash로만 보존했다.

## 3. 지원 승격과 증거 경계

`validated_support_candidates`는 `target_applicability=applicable`이고 NU54DK native build,
Arduino build, runtime capability, functional HIL을 충족한 capability ID만 허용한다. 최종 후보는
**38개**이며 `publication_status=not_published`다. 이는 M32 개발 검증 후보 집합이지 v0.6.0 지원
catalog나 공개 승인이 아니다.

외장 storage, 실제 1-wire 결선, 상용 peer와 Ubuntu/macOS 실물은 각 소유 원장의 `NOT_RUN`을
유지한다. 이 항목은 M32의 내부 3보드 기능 closure를 차단하지 않지만 해당 외부 환경 지원을
선언하는 근거로도 사용하지 않는다. HOST-W04~W08 사용자 보류도 그대로 유지한다.

## 4. M33과 후속 작업 인계

| 후속 | 인계 내용 | 현재 판정 |
| --- | --- | --- |
| M33 | 74개 M32 설치 예제, profile/resource 선택, known limitation, 미공개 지원 후보, cross-vendor·외장 장치 `NOT_RUN` | 준비 완료, M33 0/8 유지 |
| M36 | Mesh update storage와 새 power-cut 정책 | 후속; M30 전원 차단 이력과 합산 금지 |
| M38·M39 | IEEE 802.15.4·ESB 최소 radio/public 확장 | W09 단독 HIL 완료, 공개 API 확장 후속 |
| M40·M42 | 실제 적용 공존 조합과 상위 network/Matter 연계 | W10 세 내부 조합 exact PASS를 선행 입력으로 사용 |
| HOST-W07 | Host 중립 upload/debug/serial/lifecycle 자동 검사와 최종 사용자 실물 절차 | 절차 연결 완료, 실제 Host 작업은 사용자 보류 |

다음 기능 작업은 M33-W01 전체 sample inventory와 설치 catalog 정렬이다. 이후 표준 GATT/beacon,
외부 ecosystem, DTM/HCI, 역할별 설치 예제, 교차 기능 회귀, Host·package·RC, 별도 공개 승인 순으로
8개 작업을 수행한다. M32 완료는 M33 구현이나 v0.6.0 공개 완료를 뜻하지 않는다.

## 5. 릴리스 경계와 최종 판정

현재 GitHub workflow의 push branch filter는 `main`과 `0.5.0-RC2`이고
`Dev-0.6.0-M32`를 포함하지 않는다. 따라서 branch push 자체의 자동 CI는 미구성이고,
`M12 Software Gates`를 `workflow_dispatch`로 exact branch SHA에 실행한다.

이번 작업은 tag·Release·catalog·제품 version을 만들거나 바꾸지 않는다. `v0.6.0` 공개는 M33의
기능·Host·package gate와 별도 소유자 승인을 거쳐야 하며 과거 v0.5.0 공개 승인을 재사용하지 않는다.
W12 원장·문서·예제·지원 승격 gate·후속 인계 감사가 PASS했으므로 M32는 **12/12 완료**다.
