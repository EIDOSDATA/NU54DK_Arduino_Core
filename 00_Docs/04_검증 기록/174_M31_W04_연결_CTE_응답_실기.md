# M31-W04 연결 기반 AoA CTE 응답 실기

고정 NCS v3.4.0, NU54DK 두 대, CMSIS-DAP V2로 공개 Arduino
`ConnectedCteResponder` 예제를 검증했다. 공개 코어 revision은
`426faf0e72bc3d34bf7ce198557869a4fa8dc55b`이며 clean Arduino 빌드는
FLASH 361452 B, RAM 229594 B(87%)였다. 응답 image SHA-256은
`256f75eb0d334f66d8da8f34fdb85520b943cf71e235857df5748f0a20713b8f`이다.
Probe 식별자는 SHA-256으로만 기록하고 DP/AP register identity를 확인한 뒤
sector flash와 hardware reset만 사용했다.

| Controller·역할 | 관찰 결과 | 근거 |
| --- | --- | --- |
| 기본 SDC, upstream native 응답 역할 | 연결은 성립하지만 HCI `0x2055`가 `0x01`(Unknown HCI Command)로 실패 | [SDC 진단](evidence/m31-w04-df-connected-426faf0e/sdc-native-fail.json) |
| Zephyr LL, upstream native 응답 역할 | `CONFIG_BT_CTLR_DF_CONN_CTE_RSP=y` 적용 후 같은 peer와 연결, CTE 응답 활성화 성공 | [LL 진단](evidence/m31-w04-df-connected-426faf0e/ll-native-enabled.json), [추가 설정](evidence/m31-w04-df-connected-426faf0e/native-ll-extra.conf) |
| Zephyr LL, 공개 Arduino 응답 역할 | 연결·응답 시작 1회, 중단 21회, 재시작 20회 오류 없이 완료 | [clean 이미지 실기](evidence/m31-w04-df-connected-426faf0e/arduino-20-cycle-pass.json) |

Arduino 실기는 sector flash 직후 연결에서 첫 중단을 확인하지 못했다. 같은 두
image를 **다시 flash하지 않고** 양쪽 hardware reset 후 재시험하여 20회를 완료했다.
앞선 실패의 원인은 확정하지 않았으며, 성공 기록은 reset-only 시험 범위에 한정한다.
상대 보드는 임시 `GAPCentral` 이름 필터 변형으로 연결만 수행했다. 이 시험은
CTE 응답 명령의 수락과 start/stop 수명주기를 입증한다. 상대의 실제 CTE 요청,
IQ sample 수신, AoA 각도 계산은 입증하지 않는다. 기본 안테나 raw IQ 수신은
[별도 진단](172_M31_W04_DF_기본안테나_IQ_수신_진단.md)의 실패 상태 그대로다.
