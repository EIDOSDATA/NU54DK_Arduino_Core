# 246 — M31 P2 연결형 DF IQ 수신의 내부 LL 메모리 계측

> **후속 지원 판정:** 아래 수치는 내부 LL 진단의 관찰이다. 고정 NCS `v3.4.0`의
> 제품 SDC IQ RX는 `UNSUPPORTED`·P2 비차단이며 제품 수신 peak로 옮기지 않는다. [259번](259_M31_P2_DF_고정_SDK_지원_경계.md)

## 범위와 결과

고정 NCS v3.4.0·Zephyr 4.4.0의 `bt-ll-sw-split`을 사용한 NU54DK
수신 진단 image에 thread analyzer와 heap runtime stats를 켰다.
상대는 공개 Arduino `ConnectedCteResponder` image다. exact 두 probe와
app/aux COM을 확인하고 자동 unlock 없는 sector flash 및
reset-halt-drain-resume으로 시작했다. 원시 probe UID·Bluetooth 주소는
증거에 저장하지 않았다.

[실기 원본](evidence/m31-p2-df-memory-53e8bbad/connected-rx-memory-01.json)에서
유효 연결형 IQ report 20건·sample 1,640개, controller event/Host callback
각 20건, Host gate drop 0을 확인했다. 16.167초 후 raw request·sampling
disable, Host 상태 해제, ACL disconnect, 수신자 STOP과 상대 disconnect를
확인해 **내부 연결형 RX 국소 PASS**다. 상대의 별도 `CTE responses stopped`
문구는 없고, 연결 해제 callback에 따른 정지를 확인했다. 이전 [244번](244_M31_P2_DF_연결_IQ_진단.md)의
실패 원본·후속 PASS는 별도로 보존한다.

수신 image의 linker 예약은 FLASH 143,984 B, RAM 32,568 B다. 계측 전
image와 설정·source가 다르므로 차이 696 B를 계측 기능의 순수 오버헤드나
Arduino 대비 절감량으로 단정하지 않는다. 이번 계측 image에서 STOP 뒤
관찰한 thread/ISR stack 최고치는 다음과 같다.

| Thread/ISR | 사용 / 예약 B |
| --- | ---: |
| BT CTLR RX | 224 / 896 |
| BT CTLR RX pri | 216 / 448 |
| BT RX WQ | 480 / 1,200 |
| BT TX processor | 744 / 904 |
| BT LW WQ | 1,056 / 2,104 |
| sysworkq | 336 / 1,024 |
| logging | 496 / 768 |
| main | 716 / 4,096 |
| ISR0 | 680 / 2,048 |

`P2_MALLOC`은 해당 실행에서 allocated/peak 0 B를 보고했고 별도
`P2_KHEAP` 항목은 없었다. 이 통계는 controller 내부 pool의 실행 중
high-water가 아니다. 측정되지 않은 오류·복구·장기 부하의 여유로 해석해
stack이나 pool을 축소하지 않는다.

수신 fixture의 `prj.conf`·`main.c`는 실제 저장소와 짧은 경로 개발 설치본의
내용 hash가 일치하도록 수정한 뒤 새로 빌드했다. 실행 시 저장소에 미커밋
변경이 있었으므로 원본의 `source_clean=false`를 유지한다. source/HEX hash와
실제 UART·역할 증거 범위에 한정하며 exact clean-source release 근거가 아니다.

이번 수치는 **Zephyr LL 내부 진단 수신자**의 값이다. Arduino/SDC 공개 RX,
connectionless RX, 안테나 전환·각도와 그 역할의 메모리 high-water,
역할·부하를 맞춘 native 대 Arduino 비교는 여전히 `HOLD`/`NOT RUN`이다.
P2 전체나 M31-W04/W06 완료로 승격하지 않는다.
