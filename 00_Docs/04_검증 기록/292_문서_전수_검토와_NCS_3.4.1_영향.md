# 292 — 문서 전수 검토와 NCS 3.4.1 개발 영향

검토일: **2026-10-01** · 브랜치: `Dev-0.6.0-M32`

> 같은 날 후속 사용자 결정으로 **v0.7.0은 SDK 전환 전용**으로 확정했다.
> 아래 당시의 ‘v0.7.0 이후 검토’ 정책은 [293번](293_v0.7.0_SDK_전환_전용과_후속_마일스톤_재배정.md)에서
> 대체하며, 이번 기록의 실제 검사 결과·SDK 영향 분석과 미실행 사실은 그대로 보존한다.

## 결론

현행 안내의 오래된 M32 진행률·실패 원인 단정을 교정하고 중복 인계 설명을 줄였다.
NCS 3.4.1의 공개 수정은 현재 코드·생성 설정과 대조해
[별도 영향 검토](<../00_사전 리서치/03_NCS_3.4.1_변경과_개발_영향.md>)에 정리했다.
현재 NCS 3.4.0을 유지하며 전환은 사용자 방침대로 **제품 v0.7.0 이후 검토**한다.
새 SDK 설치나 M32 실기 재개는 수행하지 않았다.

## 반영한 정리

- README·TODO·설계/지원표·검증/릴리스 색인의 오래된 M32 0/12·2/12·5/12·6/12를
  **W01~W07·W09 완료 8/12**와 실제 잔여 항목으로 맞췄다. M33은 0/8, HOST는 3/8이며
  HOST-W04~W08 보류를 M32 연속 작업 요청으로 해제한 것으로 쓰지 않는다.
- [HANDOFF](../HANDOFF.md)는 중단 상태·확인 사실·재개 순서 중심으로 줄이고,
  실행별 source/수치는 [M32 TODO](../TODO_M32.md)와 원본 기록에 연결했다.
- W03~W07·W09의 완료된 개발 HIL과 v0.5.0 stable의 지원 범위를 분리했다.
  과거 M17 radio build 실패나 이미 해결한 probe 접근 장애를 현재 blocker로 남기지 않았다.
- W08은 target B debugger에서 완료 상태를 관측했지만 최종 UART `RESULT/END`와 session
  STOP 증거가 없다. **공식 FAIL 유지**, VCOM 재개방 경합은 원인 후보이며 정확한 유실 위치는
  미확정이다. 반복 결과 출력 보강의 Host/build PASS는 실기 재시험 PASS가 아니다.
- 283번 역사 기록은 원문을 보존하면서 원인 단정의 한계와 MDFU 분모
  **5 cycle × 2 target = 10회 배포**를 날짜 있는 보완 주석으로 정리했다.
  286번의 동일 반복 문장을 제거했다.
- 140·147번 설명문에 남은 원시 probe UID 7곳을 역할명으로 비식별화하고 160번에 보완 이력을
  남겼다. raw evidence·hash·COM·시험 수치·과거 PASS/FAIL/HOLD/NOT_RUN은 수정하지 않았다.
- Windows 안내에 **CMSIS-DAP V2**와 일반적인 `under-reset` 사용의 위험 경계를 연결했다.
  문서 갱신을 장비 접속·flash·recover 허가로 해석하지 않는다.

과거 릴리스별 README/CHANGELOG/설치 안내와 원본 리팩토링 제안은 당시 snapshot으로 보존했다.
역사 문서의 v0.5.0 TODO 연결은 그 완료 기록을 거쳐 현행 v0.6.0 안내로 이동할 수 있으므로
대량 치환하지 않았다. 공개 tag·Release·asset과 generated 문서도 변경하지 않았다.
Board 원본 PINOUT의 P2 표 차이는 기존 275번 기록과 core 확정 핀맵의 우선순위를 유지한다.

## SDK 영향 판단

공식 3.4.1 release notes와 SDC/MPSL·Mbed TLS·TF-PSA changelog를 대조했다.
SDC의 latency/Subrating·CIS/BIS·CS, Mesh LPN 종료와 MCUboot watchdog은 조건부로 관련된다.
nRF54LM 전용 MPSL 수정은 nRF54L15 전체 결함으로 확대하지 않는다. W08 BLOB 결과 누락을
이 수정 목록으로 설명할 근거는 확인하지 못했다.

TLS 미사용만으로 보안 수정 전체를 무관하다고 하지 않는다. 확인한 W08 config에는 X.509/PK
parser 옵션이 있으므로 실제 입력 도달성·사용자 커스텀 `prj.conf`는 별도 평가가 필요하다.
현재 구성 관찰과 향후 전환의 clean build·보안/무선/DFU 회귀 항목을 SDK 문서에 분리했다.
SDK가 patch라는 이유만으로 기존 HIL을 면제하거나 현재 실패를 해결됐다고 표시하지 않는다.
