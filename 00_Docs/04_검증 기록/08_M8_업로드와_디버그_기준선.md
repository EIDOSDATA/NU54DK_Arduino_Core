## 1. 목적과 판정

M8은 Arduino Build Adapter가 생성한 Full Zephyr image를 Arduino IDE/CLI의 일반 Upload
action으로 안전하게 기록하고, 같은 ELF로 source-level debug가 가능한지 검증하는 단계다.

다음 결과를 확보해 M8을 **완료**로 판정한다.

- Arduino IDE와 CLI가 공유하는 pyOCD 기본·J-Link 선택 Upload recipe 구현
- manifest와 export/native artifact의 board·size·SHA-256 검증
- 단일 CMSIS-DAP 자동 선택과 명시 UID·없음·다중 probe 경계 구현
- Arduino CLI pyOCD upload 10/10 실기 통과
- 마지막 reset 후 COM10 sketch 생존 표식 확인
- Full Zephyr ELF의 원본 `.ino` `setup()` source breakpoint 통과
- M8 host contract unittest 10/10과 전체 staged Builder named group 9/9 통과
- 일반 Upload에서 mass erase, recover와 runner fallback 미사용

외장 J-Link는 사용자가 이미 flash/debug 동작을 확인했다고 명시했다. 이번 M8 run에서는
외장 probe 실기를 중복 실행하지 않았으며, 설치 도구·runner metadata·Arduino 선택 recipe와
명시 serial 계약을 검증했다.

## 2. 구현 범위

### 2.1 Build Adapter

`nu54-builder flash`는 다음 입력을 받는다.

~~~text
nu54-builder flash
  --manifest <project>.nu54-build.json
  --runner pyocd|jlink
  [--probe-id <UID_OR_SERIAL>]
~~~

검증 순서는 다음과 같다.

~~~text
manifest path·schema·adapter version
  → FQBN·Zephyr board·non-sysbuild context
  → export HEX/ELF path·size·SHA-256
  → native zephyr.hex/zephyr.elf와 export hash 일치
  → runners.yaml YAML parsing과 runner 고정 argument
  → probe 선택과 probe lock
  → west flash --no-rebuild
  → flash.log 기록과 child exit code 반환
~~~

M8은 sysbuild를 지원한다고 주장하지 않는다. `sysbuild=true` manifest는
`E_FLASH_SYSBUILD_UNSUPPORTED`로 거부하고 non-sysbuild `zephyr.hex`만 사용한다.

### 2.2 Arduino platform 연결

`boards.txt`에 다음 선택을 제공한다.

~~~text
Tools
└─ Upload probe
   ├─ CMSIS-DAP (pyOCD)
   └─ SEGGER J-Link
~~~

pyOCD는 기본 `upload.tool.default`다. J-Link는 임의 probe를 고르지 않도록 Arduino upload
field에서 serial number를 요구한다. IDE toolbar의 Upload와 `arduino-cli upload`는 같은
`tools.<id>.upload.pattern`을 사용한다.

### 2.3 안전 정책

일반 Upload 명령은 다음을 포함하지 않는다.

- `--erase` mass erase option
- recover
- chip erase
- 실패 후 다른 runner 자동 선택
- 실패 후 보호 상태 자동 해제

pyOCD의 sector program은 firmware가 차지하는 sector를 지우고 다시 기록하므로 mass erase와
다르다. M8 image에서는 14 sectors, 57,344 bytes였다.

| J-Link device metadata | `nRF54L15_M33` |
| J-Link speed metadata | `4000` kHz |
| default flash/debug runner | `pyocd` |

pyOCD probe 열거는 CLI text를 parsing하지 않고 `ConnectHelper` API를 사용한다. 이 방식은
Windows CP949 console에서 `pyocd list`의 Unicode 기호가 출력될 때 발생한 encoding 오류를
Upload 경로에서 제거한다.

probe 선택 규칙은 다음과 같다.

- pyOCD probe 1개: UID 자동 선택
- pyOCD probe 0개: `E_PROBE_NOT_FOUND`
- pyOCD probe 여러 개와 UID 없음: `E_PROBE_AMBIGUOUS`
- pyOCD 명시 UID가 목록에 없음: `E_PROBE_NOT_FOUND`
- J-Link: serial number 명시 필수

## 4. pyOCD smart-flash 안정화

초기 반복시험에서는 동일 image의 page 비교·skip 경로에서 CMSIS-DAP timeout이 발생했다.

| 예비 run | 성공 후 실패 | 관찰 결과 |
| --- | --- | --- |
| 1 | 4회 성공, 5회차 실패 | `Timeout reading from probe`, 자동 recover 없음 |
| 2 | 7회 성공, 8회차 실패 | 동일 timeout 재현 |
| 3 | VCOM 중간 확인 제거 후 2회 성공, 3회차 실패 | VCOM이 원인이 아님을 확인 |

로그상 timeout은 pyOCD가 동일 14 pages를 비교해 skip하는 진행 구간에서 발생했다. 이를
바탕으로 온보드 CMSIS-DAP 경로에 `-Osmart_flash=false`를 적용했다. 이후 pyOCD는 image
범위의 sector만 매회 erase/program했고 최종 10/10을 통과했다. 이 판정은 log와 옵션 적용
전후 결과에 근거한 원인 추론이며 CMSIS-DAP firmware 자체의 결함을 단정하지 않는다.

trade-off는 다음과 같다.

- 장점: 동일 image page 비교 read 경로를 제거해 10회 반복 안정성 확보
- 비용: 동일 image도 14 sectors를 다시 기록하므로 skip 경로보다 flash wear와 시간이 증가
- 안전 경계: 전체 chip mass erase와 recover는 여전히 실행하지 않음

## 9. 범위와 남은 제약

- M8은 non-sysbuild build-context Upload만 지원한다.
- `arduino-cli upload --input-dir`의 export-only Upload는 아직 지원하지 않는다.
- 자동 recover, mass erase와 protection 해제 기능은 제공하지 않는다.
- Arduino IDE debug UI 전체 자동 구성은 M8 범위가 아니다.
- IDE toolbar와 CLI는 동일 Upload recipe를 사용하며 이번 HIL 실행기는 CLI였다.
- 여러 실제 CMSIS-DAP를 동시에 연결한 HIL은 없으며 synthetic host contract로 안전 거부를 검증했다.
- J-Link는 SEGGER software를 재배포하지 않으며 사용자가 serial number를 명시해야 한다.
- 외장 J-Link 실기는 사용자의 기존 PASS를 유지했으며 이번 run에서 재실행하지 않았다.

이 경계는 M8 완료를 취소하지 않으며 지원하지 않는 동작을 자동 추정하거나 파괴적 복구로
대체하지 않는다.
