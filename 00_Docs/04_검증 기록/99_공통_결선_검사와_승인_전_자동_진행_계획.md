## 결선 검사 준비 — Fixture 501 revision 1

[공통 결선 catalog](../../tests/hil/nu54dk/v04_common_fixture.json)의 17 신호+GND만 사용한다. P1.06/P1.07 두 data 선만 교차하며 다른 신호는 동일 GPIO끼리 1:1이다. GPIO P2.07/P2.08, 전원 레일, 외부 출력과 외부 풀업은 포함하지 않는다. 이전 408/420/430의 catalog·확인서 의미는 변경하지 않는다.

검사 펌웨어는 부팅 시 17 개 신호를 입력으로 두고 명시적인 arm 뒤에만 약한 pull-up과 단일 open-drain LOW를 사용한다. HIGH를 push-pull로 출력하지 않는다. 한 선씩 LOW로 당겨 양쪽 모든 선을 관측하고, 해제 뒤 복귀를 확인한다. A→B/B→A를 각 3 회 반복해 단선·교차 오류·선간 연결·stuck level을 판정한다. 한 LOW는 최대 500 ms이고 Host 통신이 끊겨도 펌웨어가 해제한다. arm lease는 10 초이며 만료되면 핀을 입력으로 반환한다.

임의 주소/핀 명령을 받지 않으며 핀 소유권과 다른 HIL 모드의 배타 관계를 검사한다. 계측용 HAL 경로이므로 checker 통과를 Arduino GPIO API·GPIOTE 기능 PASS로 확대하지 않는다. USB 등 다른 GND 경로가 존재할 수 있어 이 검사는 GND 점퍼 자체의 연속성이나 접촉 저항을 독립적으로 증명하지 않는다. 전원·스위치·GND 연결은 사용자 확인과 함께 사용한다.

실행은 새로 열거한 exact UID, SWD 10 MHz, 배타 lock, `auto_unlock=false`, sector flash, controlled reset/halt/identity/start를 사용한다. 새 source·HEX·catalog hash와 30 분 이내 실제 사용자 확인을 대조한다. 이전 COM/확인 시각을 복사하지 않는다. 실패 원본과 cleanup을 보존하며 실패가 있으면 다음 출력 모드로 진행하지 않는다.

## 자동 진행과 현장 조작의 경계

T12 기능 → T13 복구/동시/안정성 → T15 지원 범위 → T16~T18 사용자 설치 경로/문서/공개 준비 → R14/T19 RC 고정 및 전체 회귀 → T20/T21 비공개 패키지 재현·설치·업로드까지 자동으로 가능한 작업을 진행한다. 결함이 발견되면 T14 수정과 영향 회귀를 수행한다. T22에서 exact commit·최종 자산·검사 결과를 제시하고 사용자 승인을 받는다. 승인 전 tag/Release/공개 index 쓰기는 하지 않는다.

현재 17 신호 결선은 남은 PWM/GPIO/GPIOTE/QDEC/I2S를 묶기 위한 것이다. 통신의 넓은 동시 topology, PDM 회귀, System OFF 복구, 설치본 예제의 출력 배치는 별도로 대조해야 한다. 해당 배선·DAP 스위치·USB 재연결이 필요하면 현장 조작을 요청한다. 공통 결선 하나로 승인 직전까지 무인 완료가 보장되는 상태는 아니다. 자동화 프로그램·heartbeat/cancel도 필요한 만큼 구현/검증하며 timeout이나 확인서 만료를 제거해 무인 실행으로 보이게 하지 않는다.

## 잠정 일정

현재 미구현 시험·통합 작업을 포함한 계획 예산이며 측정된 완료 ETA가 아니다. 큰 결함 없이 진행될 때 결선 checker 준비/실기 1~2 시간, 남은 T12 시험 보완/실기 6~12 시간, T13 준비·복구·안정성 5~8 시간, 지원 범위/사용자 통합 4~8 시간, RC/패키지/설치 회귀 4~8 시간으로 **약 20~40 시간의 실제 작업 시간**을 잡는다. 현장 조작 대기·CI 대기와 결함 수정/재시험은 별도이며 각 단계 완료 후 실제 측정으로 다시 추정한다. 안정성 순수 측정 시간만으로 릴리스 준비 전체가 끝나는 것은 아니다.
