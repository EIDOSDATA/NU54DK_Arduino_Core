## TIMER 판정과 실제 반복 수

[95번 원본](95_T12_내부_ADC_TIMER_이벤트_무점퍼_검증.md)의 exact `874658a` 결과를 사용한다.

| 대상 | 실제 조건·반복 | 두 보드 결과 |
| --- | --- | --- |
| TIMER00/10/20~24 | 44 CC × clear/stop 4조합 × 1000/10000 tick × 각 10 회 | compare/capture·stop·clear 7,040 회 PASS |
| EGU/DPPI | 480조합 × 1000 event × 10 회 | 9,600,000 event PASS |
| PPIB | 44조합 × 1000 event × 10 회 | 880,000 event PASS |
| GRTC 기존 시간 함수 | 1/10 ms × busy/sleep × 각 100 회 | 800 회 PASS |

TIMER 기능 검증은 위 범위로 완료 정리한다. 초기 `V04-EVENT`의 공통 `events=1000`을
TIMER의 새 필수 반복으로 확대하지 않는다. 시험 JSON은 TIMER·EGU/DPPI/PPIB·GRTC의
반복 항목을 나누어 실제 기준을 명시했다. TIMER 각 조건 1000 회나 정밀 절대 주파수·jitter를
측정한 것으로 고쳐 쓰지 않으며 95번의 당시 원본·실패·정정 이력을 보존한다.
[102번](102_개발_문서_전수_검토와_마일스톤_체크포인트.md)의 TIMER 잔여 안내는 이 결정으로 대체한다.

## T12 대조에서 함께 남길 사실

외부 ADC 401~408은 [83번 누계](83_T12_Fixture_408_current_source_PWM_ADC_검증.md)의
276기능·59,616 samples·276 cleanup PASS다. 여덟 실행 JSON 모두 `repetitions=1`,
`campaign.completed_cycles=1`이며 초기 `V04-ADC.parameters.repetitions=100`과 다르다.
기능 sweep 완료와 100 회 반복 충족을 혼동한 이전 요약을 정정한다. 내부 ADC의 100 회 반복은
95번에서 별도로 수행했으며 외부 ADC 반복을 대신하지 않는다. 이번 사용자 지시는 TIMER
완료 정리이므로 외부 ADC 100 회 면제나 재결선·재실기 승인으로 확대하지 않는다.
이 차이는 지원·검증 범위를 닫을 때 명시적으로 처리하며 T13의 독립적인 준비를 막지 않는다.

PDM 기본·연속 PASS는 [91번](91_T12_Fixture_440_PDM_밀도와_연속_DMA_검증.md)과
[92번](92_T12_Fixture_440_PDM_연속_전체_검증.md)의 범위다. 25/50/75% 밀도 비교는 모노,
스테레오는 0/100% 반대 레벨과 채널 부호·순서를 검증했다. 실제 스테레오 세 밀도 전수를
검증했다고 확대하지 않는다. 기존에 명시한 신호원 제한이며 새 필수 품질 계측을 추가하지 않는다.

QDEC는 사용자가 지시한 대로 [101번 문제·보완 기록](101_T12_QDEC_누산_누락_원인_분리.md)을
남기고 진단을 종료했다. 해결 대기 중인 전체 작업으로 안내하지 않는다. 실패는 PASS로 바꾸지
않으며, 기존 QDEC20/21·C07 자동 실행 차단은 알려진 실패 경로를 실행하지 않기 위한 것이다.
QDEC 재진단·수정·240 조건 재시험을 다른 T13 조합의 필수 선행 작업으로 요구하지 않는다.
알려진 제한과 지원 범위는 T14/T15 및 최종 사용자 안내에 반영한다.

## 당시 후속 작업과 필요한 현장 조작

다음 마일스톤은 **T13 복구·동시·안정성 실기**다. 현재는 계획만 완료했고 실기는 0 회다.
먼저 전용 runner·preflight·복구/전환 100 회 판정·지속 측정 코드를 구현하고 Host/target에서
검사해야 한다. 이 준비는 현재 결선 C를 유지한 채 진행할 수 있다.

실기 결선은 [T13 GPIO 표](../../tests/hil/nu54dk/T13_PLAN.md)의 **C→S→U 두 단계**다.
추가 점퍼선은 확정되어 있지 않으며 기존 17 신호+GND의 B 쪽 끝을 재배치한다.

| 단계 | B 쪽 재배치 후의 A→B GPIO | 용도 |
| --- | --- | --- |
| C→S | P1.04→P1.05, P1.05→P1.04, P2.02→P2.04, P2.04→P2.02 | SPI00·PDM 포함 첫 단독/동시/복구 묶음 |
| S→U | P2.00→P2.02, P2.02→P2.00, P2.04→P2.05, P2.05→P2.04 | UART00 송수신·flow·복구·안정성 |

다른 선과 GND, P1.06↔P1.07 교차는 유지한다. P2.07/08·전원 레일은 연결하지 않는다.
각 변경은 양쪽 USB를 분리한 뒤 하고, 재연결·현재 결선 확인·새 UID 식별·해당 결선 검사 후
실행한다. SWD 10 MHz와 controlled flash를 유지한다. 과거 COM 번호나 C 확인서를 재사용하지 않는다.
기존 C 전용 시험 펌웨어를 S/U에서 그대로 실행해서는 안 된다.

System OFF 복구의 신호 격리·전원/USB 재연결은 별도 현장 조작이며 위 두 번에 포함되지 않는다.
I2C는 내부 pull-up으로 목표 속도 preflight를 먼저 수행한다. 실패하면 실제 원인을 기록하고
추가 pull-up 필요 여부를 판단한다. 현재 외부 저항 추가는 확정하지 않았고 속도를 낮춘 결과를
원래 목표의 PASS로 표시하지 않는다.

## T13부터 최종 승인 직전까지

| 마일스톤 | 자동으로 진행할 작업 | 사람 또는 실제 조건이 필요한 경계 |
| --- | --- | --- |
| T13 | runner 구현·Host/target·확인된 결선의 단독/동시/복구/안정성 실행·증거 감사 | C→S→U 재배선·현재 확인, System OFF 격리/재연결, 장치 연결 문제 |
| T14/T15 | 결함 조치·영향 회귀·검증/지원 범위 정리, QDEC 알려진 제한 명시 | 합의한 범위를 바꾸는 새 결정이 필요한 경우 해당 사실 제시 |
| T16~T18 | 사용자 API/profile/예제·문서·패키지와 공개 절차 구현·검사 | 변경 기능의 실기에 필요한 결선·장치 조작 |
| R14/T19 | RC 소스 고정·전체 software/target/CI·필요한 기능 회귀 | 회귀 대상의 결선·스위치 변경이 필요한 경우 |
| T20/T21 | 비공개 RC/stable 산출물·이중 재현·설치/제거/재설치/전환·예제 build/upload 검사 | 예제 실행에 필요한 결선, USB/전원 조작 |
| T22 | exact commit·자산·검증·제한을 검토 가능하게 제시 | 사용자의 최종 공개 승인 |

현장 조작과 조건 확인을 사용자가 맡으면 자동으로 가능한 개발·검사를 이어갈 수 있다.
현재 완성된 단일 자동 실행기로 T13부터 승인 직전까지 무인 수행할 수 있다는 뜻은 아니다.
실패나 장치 불응을 숨기거나 미완료 gate를 PASS로 바꾸지 않는다. T22 승인 전 tag·Release·
공개 index를 쓰지 않으며 T23~T25는 승인 이후다.
