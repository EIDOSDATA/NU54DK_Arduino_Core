# W06 명시 수락 정정과 HOST-W04 착수

기록일: 2026-11-10 · branch: `Dev-0.6.0-M33` · Host 구현은 진행 중이다.

W06은 **실제 기술 PASS46 + 명시 수락 #29·40·44 = 수락49**로 마감했다.
처음 #29 지시를 #40·44에 적용한 것은 assistant의 종속 항목 해석이었다.
이를 사용자 개별 명시 승인처럼 표현한 것은 부정확했다. 사용자는 설명을 받은 뒤
2026-11-10에 “#40, #44도 #29와 같은 기준으로 수락 처리하고 W06 마감해”라고 별도 승인했다.
이번 명시 승인은 당시 해석과 시점을 구분하며 과거 승인을 소급하지 않는다.
[310번](310_M33_W06_사용자_수락_마감_완료.md)의 수락 집계에 대한 최신 승인 근거다.

| 항목 | 수락 근거 | 실제 기술 PASS 여부 |
| --- | --- | --- |
| #29 `families/new_profiles` | 앞선 사용자 지시 | 전체 PASS 미확정·원인 분석 유예 |
| #40 `resources/profiles_companion` | 이번 별도 명시 승인 | companion 구성요소 PASS, 전체 PASS 미확정 |
| #44 `automatic_peers/profiles` | 이번 별도 명시 승인 | #29와 공유하는 profile 전체 PASS 미확정 |

W06 구현/HIL source는 `b46ce5708a17da788644d3e87021b5ab54a6e4c6`(S19)로 보존한다.
실제 PASS46과 원형 FAIL, source·attempt·native 종료 및 동결 비공개11,831개 파일을 유지한다.
원형 strict 기술 완료나 전체49 실제 PASS로 승격하지 않는다. #29 원인 분석은 사용자 지시로 유예한다.

기록 C `8d642e849244675666aaa941777ca6983fbade97`의 CI `42666271639`는 8성공/1실패다.
고정 launcher가 초기 core9.0.0을 선택하여 고정8.2.1 검사에 거부됐다. 사용자 승인으로 CI만 교정했다.
중간 `e9692e98…`의 CI `42730961998`은 8성공/1조건부SKIP이며 full9 성공으로 세지 않는다.
최종 `d1b320bdb0f009d7e01aaab243c5a0e42c64f3c2`의
[CI 42731935391](https://github.com/EIDOSDATA/NU54DK_Arduino_Core/actions/runs/42731935391)은
core8.2.1·원형 prerequisite·6종 대표 build를 포함하여 실제9/9·SKIP0이다.
1,800초 soak native72157/exit0도 S19 증거로 보존한다.

사용자는 이어 HOST-W04부터 순차 진행, W06 실적·FAIL 보존, 지속 보고와 모든 문서 갱신을 지시했다.
현재 단일 writer를 새로 인수하여 **HOST-W04 진행 중·Host 완료3/8**로 기록한다.
공식 OS별 launcher/core/sdk-manager·SDK·toolchain·Arduino CLI manifest와 공통 Python 설치·검증기를 추가했다.
최초 로컬 Windows bootstrap은 새 parser가 공식 다중 행 version 출력을 단일 행으로 오판하여 실패했다.
실제 core8.2.1을 확인했고 원본 실패는 `D:/w06/control`에 보존했다. 교정 후 fresh A002에서
core8.2.1·sdk-manager1.16.1 실제 실행을 확인했다. 이는 개발 작업본의 bootstrap 검사이며
SDK 설치·실제 USB·정식 Host 지원 PASS가 아니다. 이후 첫 세 OS native CI의 SDK 설치 실패와
교정 작업은 [312번](312_HOST_W04_최초_CI_실패와_교정_검증.md)에 기록한다. 최초 실패를 PASS로 바꾸지 않는다.
