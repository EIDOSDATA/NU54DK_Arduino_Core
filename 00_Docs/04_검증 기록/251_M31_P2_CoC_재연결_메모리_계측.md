# 251 — M31 P2 두 채널 CoC 재연결 메모리 계측

## 실기 판정

두 exact NU54DK에 현재 저장소의 `adaptive` CoC client/server 스케치를
각각 빌드해 기록했다. 같은 BLE link의 LE CoC 두 채널에서 최대 크기 512 B
echo를 유지하고, client가 ACL을 20회 명시적으로 끊은 뒤 재스캔·재연결했다.
각 재연결은 두 채널 준비 신호와 뒤따르는 echo 2건으로 확인했다.
probe UID/COM과 image SHA-256은 실행 전 확인했고, 자동 unlock 없는 sector
flash와 reset-halt-drain-resume으로 시작했다. 두 image는 현재 저장소를
짧은 Windows junction으로 가리키는 격리 Arduino 사용자 경로에서 빌드했다.
SDK·board 원본 또는 이전 단축 설치본을 수정하지 않았다. 실행 당시 스케치·
문서 작업이 미커밋 상태였으므로 이 기록의 `source_clean=false`이며
image/hash 범위의 HIL이다.

| 실행 | 판정 | 근거 |
| --- | --- | --- |
| 새 실행 이전 UART echo 21·22를 함께 센 최초 3회 시도 | **판정기 FAIL**. 보드 오류가 아니라 READY 전 남은 줄을 새 echo 1·2와 섞어 gap으로 읽었다. 실패 뒤 양측 STOP. | 작업용 원본 `C:\r31k\p2_coc_recovery-3.json` |
| READY 뒤 줄만 센 3회 재시험 | **국소 PASS**. 세 번의 ACL disconnect/reconnect와 각 연결의 두 채널 echo, 양측 STOP. | 작업용 원본 `C:\r31k\p2_coc_recovery-3b.json` |
| 현재 image 20회 | **PASS**. 20/20 ACL 재연결, 매회 두 채널 준비와 다음 echo 2건, 누적 42개 512 B echo·내용 오류 0, 양측 STOP. | [실기 JSON](evidence/m31-p2-native-comparison-2cf92933/coc-512-recovery-20.json) |

20회 image SHA-256은 client
`b800232cd7e6f0c04cb87337e8d0f233c76c700fde2e10356214066bb140311c`,
server `b4ed2f52a44c7308a5714633bb5ccd6bbfc256a1b5419de39f659e8c625c88ad`다.
정적 FLASH/RAM 예약은 client `216,872/82,626 B`, server
`215,888/82,181 B`다. 이전 [239번 100 echo](239_M31_메모리_최적화_P2_CoC_CS_계측.md)와
빌드 시점·source·역할 부하가 달라 이 차이를 순수 최적화 증감으로 해석하지
않는다.

## 관찰 high-water

같은 image의 STOP 시 출력한 thread/ISR 최대 사용량이다. 예약량을 동적 사용량에
다시 더하지 않는다.

| Thread/ISR | client used/reserved B | server used/reserved B |
| --- | ---: | ---: |
| BT RX WQ | 960/3,200 | 400/3,200 |
| BT TX processor | 548/904 | 404/904 |
| BT LW WQ | 948/2,104 | 936/2,104 |
| sysworkq | 304/4,096 | 296/4,096 |
| MPSL Work | 356/1,024 | 356/1,024 |
| main | 800/8,192 | 1,008/8,192 |
| ISR0 | 432/2,048 | 508/2,048 |

종료 시 두 역할의 libc malloc은 `allocated=0`, 관찰 peak `0 B`, 별도
Zephyr `k_heap` 역시 `allocated=0`, 관찰 peak `0 B`였다. 이는 이 20회
복구 실행의 계측 범위이고 controller 내부 `sdc_mempool` high-water나
모든 peer loss·MTU·credit 고갈·다중 link의 안전 여유가 아니다. 따라서
stack·heap·controller pool은 줄이지 않았고 **P2 전체는 미완료**다.
