## 1. 구현 결과

`NUCODE_BLE_Mesh_Management` library와 `nucode.ble.mesh-management` feature를 추가했다.
공개 header는 Zephyr type을 노출하지 않고 다음 일곱 기능군을 제공한다.

- Remote Provisioning scan·stop·link close·PB-Remote provisioning과 bounded scan event queue
- SAR Transmitter/Receiver get·set과 각 wire field 범위 검증
- Opcodes Aggregator sequence 시작·남은 길이·전송·취소
- Large Composition Data와 Models Metadata의 64-byte bounded page 조각
- Private Beacon·Private GATT Proxy·Private Node Identity·On-Demand Private Proxy 설정
- Solicitation PDU 송신과 acknowledged/unacknowledged SRPL 범위 삭제
- Subnet Bridge 상태와 단방향/양방향 forwarding table 추가·삭제

동적 할당은 사용하지 않는다. Remote Provisioning 광고 자료는 최대 31 byte, large data는 최대
64 byte로 복사하며 queue overflow는 누적 counter로 노출한다. 동기 관리 요청은 `begin()`에서
100~60,000 ms로 제한한 timeout을 사용한다.

고정 SDK의 Mesh Kconfig를 다시 대조했다. W07 소유 선택 기능은 readiness의 일곱 capability와
일치하며, BLOB/DFU/Distribution은 W08 소유다. 고정 source에 없는 Directed Forwarding은
W07 지원으로 승격하지 않는다.

## 3. exact HIL 완료 판정

2026-10-01 `f95cca6c…` clean source를 client·server·target 세 image로 빌드한 뒤
CMSIS-DAP v2로만 DP/AP identity를 재확인하고 sector flash를 수행했다. Client가
server를 PB-ADV로 직접 provisioning하고, server의 Remote Scan과 PB-Remote로 target을
추가했다. 두 provisioning link의 close를 확인한 뒤 AppKey를 배포하고 SRPL
Client/Server model을 bind했다.

실기 결과는 다음과 같다.

- Remote Provisioning report 1회, 직접 node 1개와 PB-Remote node 1개 추가 PASS
- SAR·Opcodes Aggregator·Large Composition/Metadata·Private Beacon/Proxy·Solicitation/SRPL·
  Subnet Bridge 일곱 기능군, 10 loop·350/350 관리 operation PASS
- malformed·out-of-range·replay range·wrong subnet 네 negative class 모두 fail-closed
- client·server·target 세 역할 RESULT·END·STOP cleanup PASS
- CDB 3 node slot에서 local provisioner 1개를 제외한 remote capacity 2, subnet 2,
  AppKey/model bind slot 2를 READY preflight로 확인

증거는
[`m32-mesh11-01.json`](<evidence/m32-w07-exact-f95cca6c/m32-mesh11-01.json>)과
[`w07-closure-audit.json`](<evidence/m32-w07-exact-f95cca6c/w07-closure-audit.json>)이 소유한다.
여기서 Subnet Bridge는 기능 활성화와 잘못된 동일 subnet table entry 거부까지를
실물로 확인했다. 세 보드를 넘는 두 subnet end-to-end forwarding topology는 외부
interop와 같이 `NOT_RUN`이며 W07 완료 분자에 포함하지 않았다.

## 4. 세 보드 exact HIL 경로 준비

Revision `c499aa891807…`에서 client·Remote Provisioning server·target 세 image와 V2 전용
runner를 추가했다. Client는 server를 PB-ADV로 먼저 추가한 뒤 그 server의 Remote Scan과
PB-Remote를 통해 target을 `0x0200`에 추가한다. 이어서 열 번의 35-operation loop로 SAR,
Opcodes Aggregator, Large Composition/Models Metadata, Private Beacon/Proxy, Solicitation RPL,
Subnet Bridge의 일곱 기능군 350회를 실행한다.

Exact runner는 세 SHA-256 probe mapping, v2 DP/AP identity, sector flash, hardware reset,
source revision·nonce, 역할별 RESULT·STOP을 같은 attempt로 검증한다. malformed, out-of-range,
replay range, wrong subnet 입력도 각각 fail-closed로 요구한다. HIL 구현 중 foundation model을
Aggregator에 넣을 remote Device Key index 공개 경계가 빠진 것을 발견해 `0xFFFD` 상수를
추가하고 backend validation을 교정했다.

세 image build는 client FLASH 347,644 B / RAM 79,831 B, server와 target 각각 FLASH
338,100 B / RAM 79,727 B로 PASS했다. M32 Host 계약은 72/72이고 contract check도 PASS다.
이후 실기 디버그에서 CDB의 local provisioner slot, provisioning link close 순서,
SRPL의 AppKey bind, Opcodes Aggregator 내부 request의 비동기 응답 처리, Proxy Solicitation
Kconfig를 교정했다. 최종 `f95cca6c…` 세 보드 실행으로 `M32-MESH11-01`을
PASS하고 W07을 완료했다.
