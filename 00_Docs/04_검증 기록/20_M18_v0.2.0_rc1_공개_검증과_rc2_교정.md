## 4. RC1에서 발견한 결함

### 4.1 다중 CMSIS-DAP 선택 불가

RC1의 pyOCD Upload recipe는 Builder가 지원하는 `--probe-id`를 Arduino upload field로 노출하지
않았다. CMSIS-DAP가 둘 연결되면 Builder는 임의 첫 장치를 선택하지 않고
`E_PROBE_AMBIGUOUS`로 안전하게 중단했지만, Arduino IDE/CLI 사용자가 정확한 UID를 전달할
경로가 없었다. `-p COMx`는 serial port 선택이며 이 문제의 해결책이 아니다.

### 4.2 NUSPeripheral 수신 로그 간섭

RC1 `NUSPeripheral`의 event callback은 `received` event가 발생할 때마다 숫자 상태 로그를
payload와 같은 `Serial`에 출력했다. BLE byte 전달 자체는 양방향 모두 성공했지만
Central→Peripheral payload의 각 byte 사이에 `BLE event: 5`가 들어가 Stream 예제의 원문
출력 계약을 훼손했다.

## 5. RC2 교정

| 결함 | 교정 |
| --- | --- |
| 다중 CMSIS-DAP | 별도 `CMSIS-DAP with UID (pyOCD)` 경로가 필수 UID를 `--probe-id`로 전달 |
| 단일 CMSIS-DAP | 기본 `CMSIS-DAP (pyOCD)` 경로가 field 없이 유일한 probe를 자동 선택 |
| 모호하거나 잘못된 UID | 임의 선택 없이 기존 fail-closed 오류 유지 |
| NUS 수신 로그 | `Event::received`는 상태 로그를 출력하지 않고 Stream 경로가 byte 원문만 출력 |
| NUS 상태 진단 | 광고·연결·ready·해제·오류만 이름이 있는 로그로 유지 |

명시 UID 실기 증거에는 실제 UID를 저장하지 않고 `probe_id=redacted`,
`probe_selection_mode=explicit`, `upload_probe=pyocd_uid`만 남겼다. 생성 HEX의 SHA-256은
`c69dc81011a263a40efb5dc677925b8b27850a1068e223736b5a7d26b5e47dea`이며,
`mass_erase_requested=false`, `recover_requested=false`, upload 종료 코드는 `0`이었다.

RC2 package를 공개한 뒤에는 RC2 전용 public index를 사용한 Boards Manager 설치,
`post_install`, 14개 설치본 예제 compile, 명시 UID upload와 두 보드 NUS 양방향 payload를
다시 검증한다. 이 공개 설치본 검증 전에는 `v0.2.0` stable 완료로 해석하지 않는다.

## 7. 공개 경계

- RC2 예정 index URL은
  `https://github.com/EIDOSDATA/NU54DK_Arduino_Core/releases/download/v0.2.0-rc.2/package_nucode_nu54dk_rc_index.json`이다.
- RC2가 Public Prerelease가 되기 전에는 위 URL을 설치 완료 근거로 사용하지 않는다.
- RC1 Release와 asset을 삭제·교체하지 않는다.
- RC2는 `latest`가 아니며 최신 정식 버전은 계속 `v0.1.0`이다.
- RC2 공개 설치본 검증과 프로젝트 소유자 승인을 거쳐야 `v0.2.0` stable을 검토한다.
