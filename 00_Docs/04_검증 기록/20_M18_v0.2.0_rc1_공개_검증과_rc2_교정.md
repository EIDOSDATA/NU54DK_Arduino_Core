## 4. RC1에서 발견한 결함

### 4.1 다중 CMSIS-DAP 선택 불가

RC1의 pyOCD Upload recipe는 Builder가 지원하는 `--probe-id`를 Arduino upload field로 노출하지
않았다. CMSIS-DAP가 둘 연결되면 Builder는 임의 첫 장치를 선택하지 않고
`E_PROBE_AMBIGUOUS`로 안전하게 중단했지만, Arduino IDE/CLI 사용자가 정확한 UID를 전달할
경로가 없었다. `-p COMx`는 serial port 선택이며 이 문제의 해결책이 아니다.

### 4.2 NUSPeripheral 수신 로그 간섭

RC1 `NUSPeripheral`의 event callback은 `received` event가 발생할 때마다 숫자 상태 로그를
payload와 같은 `Serial`에 출력했다. BLE byte 전달 자체는 양방향 모두 성공했지만
Central→Peripheral payload의 각 byte 사이에 `BLE event: 5`가 들어가 Stream 예제의 원문
출력 계약을 훼손했다.

## 5. RC2 교정

| 결함 | 교정 |
| --- | --- |
| 다중 CMSIS-DAP | 별도 `CMSIS-DAP with UID (pyOCD)` 경로가 필수 UID를 `--probe-id`로 전달 |
| 단일 CMSIS-DAP | 기본 `CMSIS-DAP (pyOCD)` 경로가 field 없이 유일한 probe를 자동 선택 |
| 모호하거나 잘못된 UID | 임의 선택 없이 기존 fail-closed 오류 유지 |
| NUS 수신 로그 | `Event::received`는 상태 로그를 출력하지 않고 Stream 경로가 byte 원문만 출력 |
| NUS 상태 진단 | 광고·연결·ready·해제·오류만 이름이 있는 로그로 유지 |

### 6.3 RC2 공개 설치본 검증

저장소 checkout이 아니라 공개 RC index와 격리된 Boards Manager 설치본을 사용했다. 실제
CMSIS-DAP UID는 evidence와 이 문서에서 공개하지 않는다.

| 시험 | 결과 |
| --- | --- |
| 공개 RC index 다운로드·SHA-256 | PASS |
| RC2 ZIP 다운로드·SHA-256 | PASS |
| 격리 Boards Manager 설치와 `post_install` | PASS |
| 설치된 package 사용자 예제 열거 | 14개 PASS |
| 설치된 package 사용자 예제 compile | 14/14 PASS |
| 설치본 Blink, `upload_probe=pyocd_uid` 명시 UID upload | PASS |
| 설치본 M8 대응 UART `NUCODE_M8_UPLOAD_READY` | PASS |
| 설치본 NUS Peripheral/Central startup `BLE NUS ready` | PASS |
| 설치본 NUS Peripheral→Central 고유 payload 원문 연속 수신 | PASS |
| 설치본 NUS Central→Peripheral 고유 payload 원문 연속 수신 | PASS |
| RC1의 수신 상태 로그 payload 삽입 | 재현 없음 |

공개 package의 기존 14/14 compile 산출물인 `NUSPeripheral`과 `NUSCentral` HEX를 서로 다른
두 NU54DK에 DAPLink sector flash로 기록했다. 두 장치 startup에서 `BLE NUS ready`를 확인하고
양방향 고유 payload가 중간 상태 로그 없이 원문 그대로 연속 수신되는 것을 확인했다.

| 산출물 | SHA-256 |
| --- | --- |
| 설치본 `NUSPeripheral` HEX | `e2a0e95e4d4239b62548d9a76b81653b14b3cfec88b567b699b23ea13ded0e4d` |
| 설치본 `NUSCentral` HEX | `553f2c9a723aeac60679643dbc2f52cfb20882deed4df5091bff19f01a7d4dcf` |

로컬 로그 basename은 `rc2-public-nus-20260830155354.log`이며 `build/m18/hil/`의 ignored
artifact다. 공개 문서에는 UID, COM과 volume을 기록하지 않는다. 이 실행에서 mass erase,
recover와 PMIC write는 수행하지 않았다.

이번 RC2 공개 예제 HIL의 판정 범위는 startup, Peripheral↔Central transparent bridge와 RC1
상태 로그 삽입 회귀다. 기존 M16/RC1 전문 HIL의 1·20·21·64-byte frame boundary,
disconnect/reconnect와 Arduino main-thread callback 전체를 다시 실행한 시험은 아니다.
