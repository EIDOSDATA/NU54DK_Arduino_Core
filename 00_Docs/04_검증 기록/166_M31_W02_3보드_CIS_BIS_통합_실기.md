2026-09-16 현재 W02의 CIS·BIS·ISO time sync와 세 보드 CIS→BIS 기능은 각각 clean source에서
검증했다. `M31-ISO-01` 네 subcase가 PASS가 되어 M31 test family는 3/10 PASS다. W02 작업 묶음은

## 개발 실패와 수정 근거

[원본 개발 attempt](<evidence/m31-w02-dev-candidate/m31-combined-dev-03.transcript.log>)에서
peripheral의 HCI `LE Setup ISO Data Path` opcode `0x206e`는 status `0x07`(memory capacity)를 반환했다.
controller ISO TX buffer count 4→8과 stream PDU buffer count 3→8만 바꿔도 같은 상태였고,
`bt_iso_chan_get_info()`로 읽은 peripheral의 협상 `max_sdu=23`이 target의 ISO TX MTU 16을
초과했다. CIS central의 실제 8-byte payload에 맞춰 RX QoS `sdu=8`과 peer TX QoS `sdu=8`을
고정하자 협상 `max_sdu=8`, 동일 HCI 명령 status `0x00`, 실제 CIS/BIS 100-SDU 전달을 확인했다.
TX buffer 증설은 최종 image에 포함하지 않았다.

첫 10-ms 동시 CIS/BIS 반복과 단순 20-ms 동기 주기에서 몇 회의 수신이 99/100 최소 기준 아래로
떨어졌다. 이 실패도 [dev-20](<evidence/m31-w02-dev-candidate/m31-combined-dev-20.transcript.log>)·
[dev-24](<evidence/m31-w02-dev-candidate/m31-combined-dev-24.transcript.log>)에 남겨 PASS로
승격하지 않았다. controller의 CIS/BIS 간격을 20 ms로 두고 peripheral의 HCI SDU 준비 work를
18 ms로 앞당긴 마지막 개발 시도
[dev-25](<evidence/m31-w02-dev-candidate/m31-combined-dev-25.transcript.log>)가
20회×100 전 구간 2000/2000/2000/2000을 통과했다. 같은 설정을 commit `9e49bee2…`의 세
clean image로 재생성해 exact 실기를 다시 통과했다. 18-ms 준비 work는 controller의
20-ms ISO 송신을 보장하는 시간 정확도 측정이 아니라 HCI buffer를 미리 공급하는 구현 설정이다.

## 다음 개발 경계

현재 기능 image는 Arduino runtime을 사용하는 Zephyr target 앱이다. 설치 가능한 raw ISO 역할별
Arduino 예제와 package discovery·compile·Serial oracle는 별도 미완료이며 W02/W07에 그대로
남긴다. W03의 LC3와 전체 LE Audio profile 구현도 아직 착수하지 않았다. W02 전체 완료나
Arduino IDE sketch 성공으로 이 기능 HIL을 확대하지 않는다.
