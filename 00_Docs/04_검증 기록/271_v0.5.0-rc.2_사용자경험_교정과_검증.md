# v0.5.0-rc.2 사용자 경험 교정과 검증

## 1. 판정

`0.5.0-RC2` 브랜치에서 예제 안내, Upload probe 선택, UTF-8 진단, Verify 진행 표시,
Windows CI 분할과 설치 수명주기 자동화를 구현했다. 자동 검증과 실제 CMSIS-DAP upload는
PASS했지만 Arduino IDE 2.x의 실제 GUI 조작 화면을 이 실행 환경에서 읽거나 제어할 수 없었다.
따라서 `v0.5.0-rc.2` 공개 판정은 **HOLD**이며 tag, GitHub Pre-release, RC catalog 갱신을
수행하지 않는다.

## 2. 사용자 경험 교정

- 공개 예제 113개에 Feature set, 보드 수와 역할, Serial 기대 출력, upload 선택 안내를
  한 원본에서 생성하고 감사한다.
- Arduino IDE에서는 CMSIS-DAP 한 대만 자동 선택한다. 여러 대의 exact UID는 Arduino CLI
  실행 전에 `NUCODE_PROBE_UID` 환경 변수로 전달한다. Arduino CLI가 비대화형 실행에서
  `upload.field` 입력을 요구하던 경로는 제거했다.
- probe 없음, 다중 probe, placeholder, 형식 오류, 미연결 UID, J-Link 미설치, target 전원과
  SWD No ACK를 구분한다. 일반 출력에는 원시 UID를 남기지 않는다.
- Verify 기본 출력에 환경 확인, 구성, compile, link, artifact의 5단계와 실제 Ninja 진행량,
  장기 무출력 heartbeat, configure/build/cache 계측을 추가했다.
- Windows 예제 shard는 RC2 실측 부하를 16개 내부 worker에 먼저 균등 배치한 뒤 두 worker씩
  여덟 shard로 묶는다. example worker마다 내부 builder 병렬도를 제한하고, 실패 시 상세
  builder log를 별도 artifact로 보존한다.

## 3. 자동 검증

| 범위 | 결과 | 근거 |
| --- | --- | --- |
| 예제 안내 생성·감사 | PASS | `RC2_EXAMPLE_GUIDANCE_PASS=examples:113;mode:check` |
| Host 전체 회귀 | PASS | 1,564 tests, 652.196초, skip 1 |
| upload 환경 변수·비대화형 recipe | PASS | sentinel 치환, exact 값 우선, 명령행 비노출 단위 검사 |
| Windows 설치 수명주기 | PASS | 짧은 root에서 RC1→RC2, 제거·재설치, negative와 설치 예제 12단계 |
| 긴 경로 설치 | FAIL 원본 보존 | Windows 경로 길이 한계로 실패; 짧은 격리 root 재검증은 PASS |

Host 전체 회귀는 upload HIL harness, package 예제와 release 차단 계약을 포함한다. mock·Host 결과를
물리 flash나 GUI PASS로 해석하지 않는다.

## 4. 여섯 Feature set 로컬 성능

`c3fa16f50228d3a4fbfe992f4ec4de22487de8eb` 설치 package, 12개 worker와 임시 P-256 DFU
서명 key로 cold, no-change, Sketch 수정 순서를 측정했다. 여섯 profile 18회가 PASS했고 UTF-8
replacement character는 0이었다. 아래는 wall time 초다.

| Profile | Cold | No-change | Sketch 수정 | 판정 |
| --- | ---: | ---: | ---: | --- |
| standard | 141.143 | 18.356 | 21.057 | cache hit |
| ble | 181.528 | 21.204 | 24.283 | feature cache hit |
| adaptive | 174.871 | 23.327 | 143.997 | 수정 뒤 feature 재구성 1회 |
| fabric | 177.961 | 22.700 | 25.201 | feature cache hit |
| secure_ble_dfu | 374.192 | 26.793 | 38.303 | sysbuild artifact 포함 |
| ble_audio_io | 225.642 | 32.234 | 29.543 | feature cache hit |

성능 수치는 upload recipe 최종 교정 전 package의 동일 builder 구현을 측정한 참고값이다. 최종
source의 correctness는 전체 Host와 package 재현성으로 다시 판정하며, 이 수치를 최종 source의
exact benchmark로 바꾸어 기록하지 않는다.

RC2 전수 실측을 수집한 `c9527c689ba1e03053b0c6bd785a4d5bf5fa06f2` 후보 archive
SHA-256은 `2127044f8edb072c9a4e66219df9932992c51ef33b4ec4676d6824aa04435d6b`,
runtime payload SHA-256은
`61e3e30ee797bc019dd3d3c49479b706ed35a49bcc4e6f8114d85f1f3c24d5c8`이다.
이 후보의 113개 compile은 모두 PASS했지만 가장 느린 worker가 43분 46초 걸렸다. 실측값으로
16개 worker를 다시 계획한 예상 부하는 worker당 2,018.750~2,019.842초이고 최대/최소 비율은
1.000541이다. 이 변경은 예제 분모와 compile 동작을 바꾸지 않고 병렬 배치만 교정한다.

## 5. 실제 보드와 설치본

세 CMSIS-DAP probe와 여섯 serial port를 직전에 다시 열거하고 원시 identity는 기록하지 않았다.
설치 package의 M8 fixture를 compile한 뒤 안전한 pyOCD sector flash를 한 번 실행했고, 320/320
build, HEX SHA-256 `97082547dc872304fe6008aa5583f8291d8b1c0274bd07ec27e055aab92faf17`,
upload 10.828초, UART ready token 1/6을 확인했다. mass erase, recover, unlock은 요청하지 않았다.

첫 물리 PASS의 exact source는 `c3fa16f50228d3a4fbfe992f4ec4de22487de8eb`이다. 비대화형
UID 전달과 영어권 Windows의 CP949 진단 복원을 교정한 뒤 당시 후보
`0345ece69bc97dd820c573aaa6fbd5a1859a27e8` package로 같은
HEX를 다시 compile·flash하고 UART ready를 확인했다. 환경 변수 없이 세 probe가 연결된 upload는
flash 전에 `[NU54:E_PROBE_AMBIGUOUS]`와 종료 코드 1로 차단됐다. 따라서 해당 후보의 exact UID
upload와 다중 probe fail-closed가 모두 실제 설치본에서 PASS했다.

이후 `c9527c689ba1e03053b0c6bd785a4d5bf5fa06f2` package에서도 같은 HEX를 320/320으로
compile하고 pyOCD sector flash 한 번, UART ready를 다시 확인했다. FLASH는 81,704 bytes,
RAM은 29,440 bytes였고 환경 변수 없는 다중 probe upload는 `E_PROBE_AMBIGUOUS`, 종료 코드 1,
`NU54_UPLOAD_START` 없음으로 차단됐다. 원시 probe UID는 증거에 기록하지 않았다.

Arduino IDE 2.3.10 process와 RC2 설치본은 준비했지만 현재 자동화 표면에 native IDE window가
노출되지 않았다. Blink, NUS 역할, Channel Sounding 역할의 메뉴·Verify·한글·memory·오류 화면을
실제 GUI에서 판정할 수 없으므로 이 항목은 **HOLD**다. CLI PASS로 대체하지 않는다.

## 6. 공개 경계

사용자는 모든 필수 gate가 PASS일 때 RC2 공개를 승인했다. 실제 IDE GUI gate가 HOLD이므로
조건을 충족하지 않았다. `v0.5.0-rc.2` tag, GitHub Pre-release, RC catalog와 공개 다운로드
smoke는 생성하지 않는다. stable `v0.5.0` 공개도 여전히 별도 승인 범위다.
