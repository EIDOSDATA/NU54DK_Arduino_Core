# M30-W08 전원 HIL 주입 직전 준비

## 판정

`M30-POWER-01`의 image 생성, fail-closed runner, 세 role target build, 두 보드 저장영역 초기화와
secure BLE DFU retry preflight를 통과했다. 실제 target USB 전원 차단은 **0회**이며 power HIL은
**NOT RUN**이다. 따라서 M30은 작업 묶음 **7/8**, test ID **9/10 PASS**를 유지하고 W08을 완료로
판정하지 않는다.

준비 기준 core revision은 `05b639b4d402e9a7490648776b5bb5eb45a94916`, board submodule은
`fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3`, NCS는 `v3.4.0`이다. 기계 증거는
[`m30-power-01-preparation.json`](evidence/m30-w08-05b639b4-power-prep/m30-power-01-preparation.json)에
보존하며 SHA-256은 `b037921c7cf1ed596286c1dbc1d8d5ed8839c4fb09c6b41ce624c1f856994a6e`다.

## 자동 준비 결과

| 항목 | 결과 |
| --- | --- |
| confirmed Peripheral image | v40, build PASS |
| unconfirmed Peripheral image | v41, build PASS |
| Central relay image | build PASS |
| recovery retry image | v42, full BLE DFU PASS |
| Peripheral DUT | DAPLink `E:`, target UART `COM13`, nRF54L15 탐지 |
| Central relay | DAPLink `G:`, target UART `COM10`, nRF54L15 탐지 |
| 보안 상태 | Security Level 4, encryption key 16 bytes |
| bond/settings | bond 1, rejected bond 0, settings valid 1 |
| bond 저장영역 | 두 보드 36 KiB 초기화·reset 전 전량 readback PASS |
| 실제 전원 차단 | 0회 |

Probe UID는 SHA-256만 저장했고 raw UID, passkey, OOB secret과 private signing key는 증거·문서·저장소에
남기지 않았다. Mass erase, chip erase와 recover는 실행하지 않았다.

## 준비 중 확인한 결함과 수정

Zephyr `settings_load_one()`은 존재하지 않는 metadata key에 길이 0을 반환할 수 있었지만 기존 bond
복원 로직은 이를 오류로 분류했다. 빈 slot은 정상 빈 항목으로 처리하도록 수정하고 Host 회귀 시험을
추가했다.

nRF54L RRAM에서는 일반 sector erase 성공 로그만으로 실제 byte가 `0xFF`가 됐다고 볼 수 없었다.
Runner는 exact probe를 reset-and-halt한 뒤 storage partition `0x174000`부터 36 KiB를 page 단위로 직접
`0xFF` program하고, target reset 전에 전량 readback이 일치할 때만 진행하도록 바꿨다. Reset 뒤에는
정상 ZMS 관리 데이터가 다시 기록될 수 있으므로 erase 판정에 사용하지 않는다.

## 실제 주입 계약

다음 네 지점에서 각각 세 번, 총 12회의 실제 target USB 전원 차단과 복구가 필요하다.

1. `slot1_transfer`
2. `image_validation_write`
3. `mcuboot_test_swap`
4. `new_image_first_boot`

Runner는 주입 지점을 arm한 뒤 Peripheral DUT의 DAPLink mass-storage와 target UART가 함께 안정적으로
사라지고, 같은 endpoint가 다시 나타난 경우만 실제 차단으로 계산한다. Enter 입력, software reset,
debug reset은 대체 증거가 아니다. 복귀 후 image 상태, 부팅, bond/settings와 전체 retry DFU를 다시
검증하며 모호한 중단 상태에서는 자동으로 PASS하지 않는다.

## 현재 중단점과 다음 동작

두 보드는 preflight 후 재현 가능한 기준 상태에 있다. 다음 동작은 runner의 실행 모드 시작이며 첫
`slot1_transfer` arm 메시지가 표시된 시점에 사람이 **Peripheral DUT의 target USB 전원을 실제로
분리하고 다시 연결**하는 것이다. 이 물리 동작 전까지 자동으로 수행 가능한 구현·build·flash·검증·증거
생성은 완료했다.

계약과 현재 상태는 [M30 착수 계약](<../01_아두이노 코어 설계/17_M30_BLE_Security_Profile_DFU_착수_계약.md>)과
[`m30-ble-readiness.json`](../../variants/nu54dk/m30-ble-readiness.json)에 고정한다.
