이번 사용자 지시는 USB 상태에서 가능한 실제 검증과 불필요 파일 정리, 문서·commit·main push까지다.
앞선 R00~R13 무인 작업의 flash 금지는 그 작업의 종료 범위로 보존한다. 이번에는 새 지시에 따라
기존 canonical 무배선 runner의 exact 두 역할 image를 flash해 온보드 기능을 시험했다.
외부 Fixture 101~301, analog/stream 결선, 스위치 수동 조작과 공개는 실행하지 않았다.

## 실제 장치와 입력

CMSIS-DAP 두 개, DAP VCOM COM5/COM6 및 COM7/COM8을 관측했다. UID 원문은 기록하지 않는다.
보드 A/DUT는 UID SHA-256 `32f71533ff6ba27fd38ed32a17bf6d80a90d4f4980221051ed5c5a2e7fdb63a9`,
보드 B/peer는 `4574ee31f25fe05f154395ea4d8c6aa0583b04a4f7a0ea97fe3d13b05eea8ca0`다.
두 보드 모두 SWD 10 MHz attach에서 CPUID `0x411fd210` 읽기를 통과했다. USB·COM 관측과
SWD 응답을 각각 기록했으며 UART 전기 연결이 확인됐다는 뜻으로 확대하지 않는다.

R13 종료 시 준비한 `C:/r13h` DUT/peer ELF·HEX와 clean exact source를 사용했다. Core 0.4.0-dev,
NCS v3.4.0, bundle dcbdc366a1의 Python 3.12.4·pyOCD 0.42.0이다. 두 HEX의 SHA-256은
DUT `90e852bd86ded64ccfaa99bc374113e762dde9ebbd0d2730c1083ad28686e843`,
peer `8cd085bf5a2cb423595dbd264a407b70925270d0539ca07a38d7a30e40c22cda`다.

canonical `tests/hil/nu54dk/v04_pair.py`를 `--onboard-suite primitives --rounds 100
--swd-frequency-hz 10000000 --execute-onboard`로 실행했다. 같은 UID를 다른 장치로 자동 대체하지
않았고 sector erase, `auto_unlock=false`, no recover를 유지했다. SDK 환경과 원문 UID 출력 방지만
작업 wrapper가 담당하며 oracle·명령·PASS 판정은 canonical runner 그대로다. 진행 체크포인트는
clean checkout을 요구하는 HIL 동안 작업 폴더에 기록하고 종료 후 이 문서와 활성 TODO에 반영했다.

PMIC 데이터 register는 쓰지 않았고 pointer write/repeated-start read만 사용했다. 내부 ADC의
허용 범위는 기능 확인이며 교정 전압·정밀 정확도 판정이 아니다. PWM/SAADC 동시성은 DMA와
수명주기 확인이며 외부 핀 파형·최대 topology·장시간 soak PASS가 아니다. 이번 결과로 T11/T12/T13,
물리 BLE/Storage, 최종 지원 matrix·RC·공개를 완료 처리하지 않는다.

pyOCD의 `Board ID 5415 is not recognized`와 `NRF54L15 is not in a secure state` 메시지도
원본 log에 보존했다. 명시적 nrf54l target, CPUID 및 exact runtime identity를 검증했고 unlock이나
보호 해제를 요청하지 않았다. 실행 후 두 보드에는 위 c94298f DUT/peer image가 남아 있다.

## 불필요 파일 정리

이전 검증 root 15곳의 재생성 가능한 `.obj`, `.obj.d`, `.a` 중간 파일 **55,537개**를
삭제했다. 종료한 일회성 편집·분할·format·기록 script **50개**는
`work/archive/r00-r13-authoring-scripts.zip`으로 압축하고 entry별 원본 SHA-256 대조 후 원래 위치에서
정리했다. 두 범주의 원래 파일 합계는 **55,587개, 2,303,344,327 bytes
(약 2.15 GiB)**다. 압축 보관본이 있으므로 순 회수 공간은 이 값보다 조금 작다.
first-party Python cache는 13개 디렉터리의 285개 파일
(6,026,972.0 bytes)을 제거했다. 정리 manifest에는 삭제 전 경로·크기·SHA-256을 남겼다.

기존 root의 ELF/HEX/BIN/MAP·설정·build record·compile commands·build log 등
**2,911개 보존 파일**은 정리 전후 SHA-256가 같다. `C:/r13h` 실기 입력,
설치 package·예제·오류 증거, QEMU runtime, SDK·board·third-party·공개 자산과 과거 Git evidence는
정리 대상이 아니다. 이 단계에서 Git tracked source는 바뀌지 않았고 추적된 `.tmp/.orig/.bak/.rej`
잔여 파일도 없었다. 호환 CLI 진입점·시험·계획 문서는 계속 필요하므로 보존했다.

정리한 root의 incremental build가 필요하면 canonical runner가 삭제된 중간 파일을 다시 생성해야
한다. 과거 evidence에 적힌 일회성 script 원래 위치는 위 archive에서 복원할 수 있다.
이번 현재 문서·증거 commit은 제품 실행 source를 바꾸지 않는다. 따라서 이미 완료한 60개 target·
639 Host PASS 등 전체 software gate를 무조건 반복하지 않고 문서·contract·inventory·style와
제품 source 불변성을 다시 확인했다. 새 문서 commit의 해시는 작업 `outputs/usb-followup-report.md`에
기록하고, 최종 Git 동기화·process 종료를 확인한다.

DAP UART 연결 상태가 필요하다. 외부 current-source T11을 시작할 때는 두 보드의 전원을 끄고
[Fixture 101](44_M24_Fixture_101_UART_실기_검증.md)의 UART 4선+GND를 연결하며 DAP UART를 분리한다.
현재 보드 간 선은 없으므로 이전 Fixture 301 선이 남았다고 가정하지 않는다. 외부 결선 완료 확인
전에는 T11 fixture 명령을 보내지 않는다. 문서 commit 뒤 exact HEAD image가 필요하면 source·
artifact identity를 대조하고 새 revision으로 build한다.

## 후속 사용자 확인 — DISABLE_UART Disabled

2026-09-06 사용자가 DISABLE_UART가 현재 Disable 상태라고 확인했다. 현재 상태는 두 보드 각각
USB 연결, 보드 간 결선 없음, DAP UART 분리다. 이 확인은 사용자 전달이며 추가 SWD/COM 관측이나
물리 스위치 조작·flash·UART/BLE 시험은 수행하지 않았다. 앞선 904 PASS와 당시 미실행 사유는
그대로 보존한다.

다음 추가 USB-UART/BLE 검증을 위해 두 보드 USB와 다른 전원을 모두 끈 뒤 DISABLE_UART를
**DAP UART 연결 상태**로 전환하고 USB를 다시 연결한다. DISABLE_SWD는 SWD 연결 상태를 유지하며
보드 간 신호선은 연결하지 않는다. 사용자 완료 확인 뒤 exact source/image를 대조해 실행한다.
외부 current-source T11을 시작할 때는 다시 전원을 끄고 Fixture 101을 연결하면서 DAP UART를
분리하는 별도 단계가 필요하다. 이번 변경은 상태·다음 행동의 문서 정정이며 새 실기 PASS가 아니다.
