## 상태와 실패 후 자원

`Phase`는 empty/staged/active/faulted를 구분한다. `AcquiredResources`는 lifecycle과
별개로 실제 획득한 항목을 보존하므로 fault라는 이유만으로 기록을 비우지 않는다.
같은 route의 호출은 기존 backend mutex가 직렬화하며 route 내부에 새 lock을 추가하지 않는다.
manager는 ISR을 먼저 거부하고 기존 mutex 하나로 table 함수 전체를 보호한다.
입력 검증도 잠금 안으로 들어가지만 validation·transaction 본문과 오류 우선순위는 유지한다.

| 실패 지점 | 남는 상태와 후속 동작 |
| --- | --- |
| block 충돌 또는 PM 사전조건 | stage 보존, 새 pin·PM reference 없음; 충돌 해소 후 재시도 |
| 중간 begin/commit 또는 PM get 실패, 역순 복구 성공 | 실제 획득한 pin만 복구, block rollback, stage에서 재시도 |
| activate 복구 중 PM put 실패 | PM reference·pinctrl·block 및 pin 기록 유지; prepared pin lock만 반환, fault |
| activate 복구 중 pinctrl 복원 실패 | PM 반환 후 pinctrl·pin·block 기록 유지; prepared pin lock만 반환, fault |
| pin rollback/restore 실패 | 다른 pin의 복구를 계속 시도하고 실패 pin과 block 유지, fault |
| active route의 PM put 실패 | active와 PM reference 유지, deactivate 재시도 가능 |
| deactivate의 pinctrl 복원 실패 | PM 반환 완료, pinctrl·pin·block 유지, fault |
| stale block release | 다른 generation 소유권을 건드리지 않고 fault; 성공으로 표시하지 않음 |

소멸자는 lease·PM·pin을 자동 반환하지 않는다. 동적 할당, 두 번째 manager,
새 public API, 새로운 하드웨어 지원 상태는 도입하지 않는다.

같은 pair DUT 구성의 flash는 183,800 → 184,000 bytes, RAM은 161,472 → 161,480 bytes다.
이 구성은 runtime route를 선택하지 않으며 manager의 새 table object는 6,160 bytes,
기존 mutex는 20 bytes다. 기존 image에는 6,144-byte slots와 8-byte generation이 남았고
epoch는 별도 object로 남지 않았으나 새 table은 epoch 8 bytes를 포함한다. 이 비용을
메모리 개선으로 주장하지 않는다. route가 실제 링크되는 B2/analog 구성도 build PASS다.

기존 source 위치를 읽던 static 계약은 해당 책임을 소유한 새 파일을 읽도록 변경했다.
PM·pinctrl·pin handover 장애 주입은 실제 manager와 실제 route를 연결하지만 driver는
Host mock이다. GPIO 전기 상태, target PM의 실기 정지 및 재부팅 동작은 입증하지 않는다.

## R09 선택/비선택 검증에서 발견한 R08 보완

source 목록으로 manager를 컴파일한다. 여기에 새 table 구현을 누락해 링크가 실패했다.
