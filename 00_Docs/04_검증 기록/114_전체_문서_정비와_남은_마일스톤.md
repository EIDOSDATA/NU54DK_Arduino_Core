## 문제 문서 후속 정비

2026-09-10 사용자 요청에 따라 문제 상태를 다시 대조했다. 해결한 문제에는 **해결 완료**를
바로 붙이고, 제외된 항목은 현행 문제·잔여 표에서 삭제했다. 과거 실패 source·횟수·원본은
그대로 보존하며 후속 해결 결과를 구분해 연결했다. 문서 변경만 수행하고 보드에는 접속하지 않았다.
문제 관련 Markdown 29개를 정비했고 전체 229개 문서 검사와 diff 검사를 통과했다.
현행 잔여 표의 충돌 검증 3종·U 실기, 제외 항목 행 0개와 비문서 변경 0개를 대조했다.
이번 후속 정비의 커밋·푸시는 수행하지 않았다.

| 문제 | 현재 상태 | 확인할 기록 |

## 완료 상태와 남은 경계

S의 요청 범위는 **56 PASS + System OFF 추가 결합 제외 2 / 58**, 범위 종료율 100%다.
이는 58/58 실기 PASS나 v0.4.0 전체 완료율이 아니다. U 준비는 100%, U 실기는 NOT RUN이다.
정확한 image·Host·CI·마지막 GPIO 정리 근거는 [113번](113_T13_S_범위_종료와_U_준비.md)에 있다.

S 정상 36조건에는 대표 C05 3600초 soak가 포함된다. 이미 끝난 시험을 남은 일정에 다시 넣지
않는다. QDEC 추가 진단과 Serial handover 제외도 유지한다. 기존 M15의 GRTC·버튼 System OFF
PASS는 유지하며, T13 UART21 DMA·peer 제어 결합의 미실기를 그 PASS로 바꾸지 않는다.

후속 사용자 확인으로 과거 I2S 수신 오류·전이 손실은 결선 문제로 정리해 현재 미해결 목록에서
제거했다. I2S 정식 role2 100/100은 유지하며 당시 원본은 삭제하지 않는다.
같은 날 사용자 지시로 GPIO 전달·SWD 진단도 현재 문제 목록에서 제거했다.
SPI CS 조기 종료의 별도 slave 판정은 추가 검증에서 제외했다. TWIS는 완료한 2ms 공급 지연
4조건×100회로 수용하며 별도 read-request 지연 시험을 요구하지 않는다.
이 세 항목은 남은 작업이 아니며, 기존 원본 보존과 새 실기 PASS 추가 없음은 유지한다.

110번 요구 대조 중 다음 세 경계는 충분한 기존 증거, 필요한 추가 구현·실기 또는 명시적
지원 제한을 T14/T15에서 판정해야 한다. 문서 대조 1/1 완료가 이들의 실기 PASS는 아니다.
아래 항목은 확인된 고장 목록이 아니라 추가 증거가 필요한 시험 조건 목록이다.

| 남은 항목 | 현재 상태 |
| --- | --- |
| 전체 GPIO alias·DMA overlap active 충돌 | **검증·판정 미완료** |
| 실제 GPIOTE/DPPI active 충돌과 기존 출력 보존 | **검증·판정 미완료** |
| Fabric PWM과 analogWrite/tone/Servo active 충돌·출력/buffer 보존 | **검증·판정 미완료** |
| U UART00 full-duplex·RTS/CTS·DMA 취소/복구 | **준비 완료 / 실기 미실행** |

예제 발견의 첫 호출은 Arduino CLI 경로 인자가 없어 실행 전 거부됐다. 실제 설치된 CLI를 명시한

명시해 수행했다. 도구·SDK 설치나 보안 설정 변경은 하지 않았다.

보드 실기·전체 로컬 target build·패키지 공개는 이번 검사로 수행하지 않았다. 원격 CI는

기록하지 않는다. 당시 다음 작업은 U 실기·T14/T15 판단이었으며, 완료한 S 재실행이 아니었다.

## 후속 U 시작 상태

문서 전수 정비가 끝난 뒤 사용자는 UARTE00 4신호+GND 결선 완료와 중단 없는 시험을 지시했다.
`7f78a36c`에서 U open-drain 검사를 실제 연결한 net 11·13·15·16으로 한정하고 S의 17신호 검사는
유지했으며, 관련 Host 30/30을 통과했다. C drive 정리로 기존 `C:/tz20`은 삭제되어 clean exact
source에서 두 역할 image를 다시 생성한다. 이 절은 실행 시작 상태이며 U 물리 PASS 기록이 아니다.
