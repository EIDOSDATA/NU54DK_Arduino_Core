## 1. 판정과 경계

M24~M26 후보 source와 무배선 HIL runner를 M27 비공개 후보 package로 통합했다. ZIP·checksum·
SBOM·license inventory·notices를 두 번 독립 생성해 byte identity를 대조했고, Git-less staging
설치본에서 Arduino 예제 29개를 모두 발견·compile했다. 기존 Arduino15와 공개 index는 수정하지
않았고 tag나 GitHub Release도 만들지 않았다.

이 결과는 M24~M27 전체 완료나 `v0.4.0` 지원 선언이 아니다. 연결된 probe의 SWD `No ACK` 때문에
M24 UARTE/TWIM, M25 내부 event/VDD, M26 TEMP/WDT30의 runtime gate가 실행되지 않았다. 외부
serial·analog·audio·encoder fixture와 계측 gate, 실제 upload를 포함한 Boards Manager 수명주기도
남아 있다. 현재 사용자용 stable은 계속 `v0.3.0`이다.

## 4. HOLD의 의미

`m27_release.py prepare`는 성공해도 `M27_RELEASE_PREPARE_HOLD=1`을 출력한다. Readiness ledger의
host/docs/Zephyr/package `pending`은 지금까지 실행한 시험의 실패가 아니라, physical 수정까지
끝낸 **frozen RC commit에서 다시 실행해야 하는 release gate**라는 뜻이다. Staged 29/29 compile도
공개 URL 설치·실제 upload·제거·재설치·version 전환을 대신하지 않는다.

| 남은 항목 | 필요한 조건 |
| --- | --- |
| M24 무배선 UARTE 4개·TWIM 3개 | SWD 연결 복구 후 기존 runner 재실행 |
| M25 무배선 event·내부 VDD | SWD 연결 복구 후 기존 runner 재실행 |
| M26 TEMP·WDT30 reset | SWD 연결 복구 후 기존 runner 재실행 |
| M24 외부 serial 16개·최대 동시·복구·성능·전력 | 승인 배선, peer와 계측 장비 |
| M25 SAADC·PWM·PDM·I2S·QDEC·soak | 승인 source/sink·encoder·계측 fixture |
| Frozen RC 회귀·공개 수명주기 | 위 physical gate와 수정 완료 뒤 exact commit 고정 |
| Stable 공개 | 모든 technical gate와 프로젝트 소유자 승인 |

외부 fixture의 신호원·계측기와 연결 상태는 host에서 추정하지 않는다. 부품과 배선이 확정되지
않은 경로를 자동으로 구동하거나 source/build PASS로 물리 검증을 대체하지 않는다.

## 5. 재개 순서

1. USB probe와 두 VCOM 포트를 확인하고, 보드의 **debug-control 2연 SW1 중 `DISABLE_SWD`가
   연결을 끊는 위치인지** 확인한다. 이는 Arduino 사용자 버튼 SW1/P1.09와 다른 부품이다.
   현재 `No ACK`의 원인으로 확정한 것은 아니며 SWD 배선·전원 상태와 함께 확인한다.
2. SWD가 복구되면 새 exact clean commit의 image로 M24 UARTE→TWIM, M25, M26 온보드 runner를
   순서대로 실행한다. Mass erase/recover를 자동 선택하지 않는다.
3. 승인된 fixture를 연결해 외부 단독·동시·오류·장시간·계측 gate를 수행한다.
4. 발견한 결함을 수정한 뒤 RC commit을 고정하고 자동 gate와 Boards Manager 수명주기를 재실행한다.
5. 증적·known limitation·지원 matrix를 일치시킨 뒤에만 공개 승인을 받는다.

Package 실행 도구와 명령은 [M27 준비 도구](../../tools/release/M27_README.md)를 참조한다.
