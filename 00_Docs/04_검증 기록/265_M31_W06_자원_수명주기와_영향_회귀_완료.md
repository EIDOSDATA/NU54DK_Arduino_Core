# M31-W06 자원·수명주기와 영향 회귀 완료

## 1. 결론

M31-W06을 **PASS·완료**로 판정했다. ISO·LE Audio·Direction Finding·Channel
Sounding의 독립 role image 4개 family에서 P2의 stack/heap·buffer·stream/connection
계측과 종료 반환을 자원 manifest로 확정했고, 축소 근거가 없는 최종 크기는 모두 유지했다.
`M31-NEG-01:target_recovery`의 peer loss·wrong key·resource exhaustion은 class별 20회,
`M31-REG-01:m19_m30`은 12 family를 현재 소스 build·전체 Host 회귀와 기존 exact 물리
분모로 닫았다. cross-link·자원 누수는 0이다.

이 완료로 M31은 **W01~W06 6/8**이다. 다음 작업은 W07 설치 예제·적용 역할 HIL이며
W08·v0.5.0 공개·tag·catalog는 완료하거나 승인하지 않았다.

## 3. 자원 manifest와 수명주기

| family | 자원·종료 판정 | 결과 |
| --- | --- | --- |
| raw ISO | 공개 11역할의 stream stop/restart·disconnect와 session ownership 반환 | PASS |
| LE Audio | 암호화 오류 뒤 stream 복구·양측 STOP, heap 반환 | PASS |
| Direction Finding | 지원 TX/response stop·link/radio 반환; 제품 SDC IQ RX는 기존 `UNSUPPORTED` 유지 | PASS |
| Channel Sounding | procedure stop·ACL disconnect·양측 STOP에서 CS/link/radio 반환 | PASS |

최종 크기는 main stack 8,192 B, system workqueue 4,096 B, BT RX 3,200 B,
BT long workqueue 2,104 B, MPSL work 1,024 B, libc heap 8,192 B를 **KEEP**했다.
P2 지원 부하의 최소 관찰 stack 여유는 264 B이며 allocation failure·종료 후 미반환·누수는
0이다. 고정 SDK SDC pool은 역할/count별 요구량과 8-byte 정렬을 유지한다.

현재 source의 M19~M30 대표 target 18개도 모두 build PASS했다. 최대 정적 RAM은
M28 mixed image의 148,715 / 262,144 B(56.73%), 최대 FLASH는 M29 mixed image의
254,212 / 1,560,576 B다. 이 값은 정적 image footprint이며 runtime 사용량으로 확대하지 않는다.
첫 M28 호출은 `BOARD_ROOT`·`EXTRA_ZEPHYR_MODULES` 누락으로 compile 전에 실패했으며,
고정 경로를 보완한 세 역할 pristine build만 PASS다. 초기 setup 실패는 manifest에 보존했다.

## 4. 오류·복구와 M19~M30 영향 회귀

| target recovery class | 20회 기준 | 판정 |
| --- | --- | --- |
| peer loss | 암호화 BAP source reset 20/20 탐지·30초 내 복구; 별도 current-runtime 256-step CS peer-loss에서 유효 raw 20개·양측 STOP | PASS |
| wrong key | wrong Broadcast Code 20/20 거부·정상 Code 20/20 복구; current-runtime 계측에서도 `-61` 뒤 100 frame·양측 STOP | PASS |
| resource exhaustion | 로컬 TX pool 4개 포화 뒤 ACL disconnect/reconnect 20/20; 별도 peer-credit fixture에서 실제 credit 1 고갈·반환·새 SDU 복구 확인 | PASS |

resource exhaustion은 로컬 `net_buf` 포화와 상대 credit 고갈을 합치지 않았다. 20회 recovery
분모는 bounded local pool saturation 뒤 재연결 원본이며, 상대 credit 직접 고갈 여부는 별도
`coc-peer-credit-r2.json`으로 확인한다. 원인 없는 재시도나 무한 재전송으로 PASS를 만들지 않았다.

M19~M30 12 family는 다음 근거를 결합했다.

- M19~M21 두 역할, M24~M26 onboard, M28~M30 세 역할의 현재 source target build 18/18
- 현재 source 전체 Host 회귀 1,508건·2 skip·실패 0 PASS
- M19~M30 각 완료 시점의 exact 물리·릴리스 원본과 family별 기존 정량 분모
- M28~M30 세 보드 원본의 peer/link 분리, cross-link 0, 최종 자원 누수 0

새 firmware를 실물에 flash해 과거 HIL을 성공으로 재표시하지 않았다. current build·Host는 변경
영향을, 기존 physical baseline은 실제 radio/board 동작을 각각 소유한다.

## 5. 새 실물 진단 HOLD와 안전 상태

HIL 직전 세 probe의 SHA-256 identity·COM·역할·image를 다시 결합했다. 한 probe는 접근할 수
있었지만 두 probe가 `APPROTECT 0x3` 상태여서 exact sector flash 전후의 target core 접근을
확보하지 못했다. 첫 실행은 45초 timeout, 후속 접근은 no-core로 끝났으므로 **HOLD**다.
기능 transcript나 새 물리 PASS는 0건이며 W06 PASS 분모에 넣지 않았다.

`auto_unlock=false`를 유지했고 mass erase·recover·전원/USB·배선 변경은 실행하지 않았다.
접근 가능한 한 보드는 `STOP` 응답을 확인했다. 나머지 두 보드의 최종 firmware 상태는
확인할 수 없어 `UNKNOWN_HOLD`다. W07 실물 전 사용자가 두 보드를 물리 재연결 또는 전원
재인가한 뒤 identity·COM·접근성·role·image를 다시 확인해야 한다. 별도 승인 없는 unlock/recover는
계속 금지한다.
