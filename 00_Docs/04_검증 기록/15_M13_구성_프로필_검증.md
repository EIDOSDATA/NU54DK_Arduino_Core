# M13 구성 프로필 및 예제 배포 검증

- 상태: **완료**
- 검증일: 2026-08-29
- 대상: `standard` profile, bundled library feature allowlist, 공개 예제 7개
- 환경: Windows x64, Arduino CLI 1.5.1, NCS v3.4.0, Zephyr 4.4.0

## 구현 계약

`boards.txt`의 `Feature set` 메뉴는 검증된 `standard` profile을 선택한다. Builder는 profile JSON을 엄격히 검증하고 최소 platform 설정, profile, 사용자 sketch의 `prj.conf`/`app.overlay` 순서로 병합한다. 따라서 일반 사용자는 공개 예제 폴더의 Zephyr sidecar를 직접 편집하지 않으며, 전문 사용자의 마지막 override 경로는 유지된다.

`NUCODE_NU54DK`, `Wire`, `SPI`만 초기 allowlist에 포함한다. `prepare`는 라이브러리 탐색 전의 임시 profile cache를 만들고, `link`는 Arduino source record에서 실제 선택된 bundled library만 판별한다. 선택 결과와 manifest/fragment hash로 최종 cache key를 다시 계산하고 workspace, context와 source record를 최종 key로 이관한다. 외부 library의 manifest는 실행하지 않는다.

`standard` profile은 공개 예제 전체가 별도 설정 없이 동작하도록 Wire, SPI, ADC와 PWM을
미리 활성화한다. 따라서 선택 library feature는 이 profile에서 주변장치를 켜고 끄는 역할이
아니라 실제 library 선택, 호환성·충돌 검사와 cache/evidence 출처를 기록하는 역할이다.

각 `feature.yml`은 파일명과 관계없이 schema v1에서 UTF-8 JSON 문법을 사용하는
선언형 데이터이다. 일반 YAML 문법, command, script, 환경 변수 또는 CMake 실행
항목을 허용하지 않는다. 최종 context와 artifact manifest에는 선택 library, feature
ID 및 hash가 남는다.

## 검증 명령

```powershell
python -m unittest -v tests.host.test_m13_profiles
python tests/arduino-cli/run_smoke.py `
  --cli "C:\Program Files\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe" `
  --tests blink m6 m7 examples
```

공개 예제 7개는 `Blink`, `InterruptButton`, `AnalogReadA0`, `PWMFade`, `SerialEcho`, `WirePmicId`, `SPITransaction`이며 예제 directory 내부에 `prj.conf` 또는 `app.overlay`를 배포하지 않는다.

## 실제 Arduino CLI 확인

현재 checkout을 독립 Arduino data/download/user directory에 배치해 실제 Full Zephyr compile을
수행했다.

| Library | 예제 | Compile | 선택 feature |
| --- | --- | --- | --- |
| `NUCODE NU54DK` | `Blink` | PASS | 없음 |
| `NUCODE NU54DK` | `InterruptButton` | PASS | 없음 |
| `NUCODE NU54DK` | `SerialEcho` | PASS | 없음 |
| `NUCODE NU54DK` | `AnalogReadA0` | PASS | 없음 |
| `NUCODE NU54DK` | `PWMFade` | PASS | 없음 |
| `Wire` | `WirePmicId` | PASS | `nucode.wire` |
| `SPI` | `SPITransaction` | PASS | `nucode.spi` |

결과는 `blink`, `m6`, `m7`, `examples` 네 gate 모두 PASS이며 실제 compile은 7/7이다.
Arduino CLI JSON에서 library별 예제 집합도 위 표와 정확히 일치했다. Arduino IDE가 같은 CLI
backend 결과로 `파일 → 예제`를 구성하며, 실제 GUI 렌더링의 clean Windows 수동 확인은 M18
release gate에서 다시 수행한다.

Wire와 SPI에서는 provisional key와 최종 key가 서로 달랐고, 선택 feature가 없는 Blink에서는
같은 구성 identity를 유지했다. profile target 불일치, 알 수 없는 schema, Windows/상위 경로,
feature 충돌, cache prefix 충돌과 최종 configure 실패는 모두 fail-closed 단위시험을 통과했다.
