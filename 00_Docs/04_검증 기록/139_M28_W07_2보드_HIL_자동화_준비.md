# 139 — M28-W07 2보드 HIL 자동화 준비

## 결론

M28-W07의 2보드 선행 시험을 위한 peripheral/central image, `M28B2` fixed protocol, fail-closed
Host parser와 exact build/evidence runner를 구현했다. Host parser 10/10과 고정 NCS target 2/2
build-only가 PASS했다. 실제 두 보드 RF HIL과 `M28-REG-01`은 이 기록 시점에 `NOT RUN`이다.

## 실패 분류와 수정

1. System Python 실행은 Twister의 `colorama`가 없어 target 구성 전에 중단됐다.
2. Bundled Python만 직접 호출한 실행은 toolchain `environment.json` 미적용으로 `ctypes/natsort`에서
   중단됐다. 고정 PATH·PYTHONPATH·Zephyr SDK 변수를 적용해 환경 원인으로 분리했다.
3. 첫 image compile은 role 반대편 helper·상태의 `-Werror=unused-*`를 거부했다. 해당 symbol을
   `[[maybe_unused]]`로 명시해 공통 source의 role 경계를 보존했다.
4. 첫 완전 link는 security manager가 참조하는 고정 profile backend source 누락을 검출했다.
   M21에서 검증한 동일 security source 집합을 CMake target에 포함했다.
5. 수정 뒤 새 짧은 outdir의 동일 두 role 조건에서 2/2가 warning 없이 PASS했다.

이 과정의 환경·compile·link 실패를 RF 기능 실패나 PASS로 계산하지 않는다. 이유 없는 반복 없이
각 원인을 수정한 뒤 동일 조건으로 재검증했다.
