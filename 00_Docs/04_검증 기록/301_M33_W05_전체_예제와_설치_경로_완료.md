# M33-W05 전체 예제와 설치 경로 완료

## 1. 판정

M33-W05를 완료한다. 기능 source는
`5f9b2257e2d9630fc919d9cd6508f918d93207cc`이며, 별도 clean checkout과 별도 Arduino
설치 checkout을 같은 revision으로 고정했다. NCS v3.4.0, Zephyr·board lock을 유지한 Windows
clean 설치 검사에서 공개 예제 204개를 모두 발견하고 204/204 compile과 잘못된 profile 9/9
거부를 확인했다.

이 판정은 설치·발견·compile·문서화된 역할 절차의 완료다. Compile을 실제 기능 runtime으로
확대하지 않으며, 외장 장치·Apple/Google 제품·각 예제의 물리 역할 실행은 기존 owner 증거 또는
사용자 후속 `NOT_RUN` 상태를 그대로 사용한다.

## 3. 구현

- `libraries/example-metadata.json`에 24개 library의 204개 예제를 등록했다. 목적·준비물·설정·실행
  순서·성공 출력·흔한 오류·다음 예제와 profile·보드 수·역할·제한·보안·negative·증거 분류를
  기계 판정 가능한 단일 원장으로 유지한다.
- `libraries/EXAMPLES.md`는 12개 Start Here 시나리오, 29개 기능별 Recipe, 전체 204개 Reference의
  세 단계 진입점을 제공한다. 대표 Sketch는 24개이고 전체 예제는 숨기거나 삭제하지 않았다.
- 204개 공개 `.ino`에 생성 가능한 한국어 Doxygen 안내를 적용했다. 안내 drift는
  `tools/examples/sync_example_guidance.py --check`가 거부한다.
- Peripheral Fabric에 ADC 연속 DMA, PWM sequence, 자원 충돌, 비동기 SPI loopback, TWIS double
  buffer, 비동기 UARTE 예제 6개와 README를 추가했다.
- 설치 검사기는 source와 설치본의 분리, 동일 clean revision, library tree·metadata 동일성,
  Arduino CLI 발견 경로, profile, build manifest, NCS/Zephyr/board revision, HEX hash, timeout,
  expected error marker와 검사 후 불변성을 fail-closed로 확인한다.

## 5. 진단 기록과 경계

첫 준비 과정에서 Git metadata가 없는 단순 복사 설치본을 사용하자 builder가
`[NU54:E_PACKAGE_MANIFEST]`로 즉시 거부했다. 이는 release manifest가 없는 Git-less package 입력
오류이며 NCS 결함이나 예제 compile 실패로 기록하지 않았다. 설치본을 exact 독립 Git checkout으로
교정하고 처음부터 새 build/evidence 경로에서 재실행했다.

이번 단계는 보드 flash·reset·debugger 조작을 수행하지 않았다. 따라서 자동 mass erase·unlock·recover도
없었다. 물리 기능 회귀, 자원 부하, scripted peer, 1,800초 soak는 M33-W06에서 별도 exact 증거로
수행한다. Apple/Google peer와 외장 장치 실기는 사용자 후속 `NOT_RUN`, Ubuntu/macOS 실제 지원 검증은
RC 단계로 유지한다.

## 6. 다음 작업

M33은 5/8이며 다음은 M33-W06이다. 33개 기능 family, 8개 자원 group, 8개 자동 peer group과
3보드 1,800초 soak를 실제 기능별 실행기로 검증한다. W02에서 남긴 BMS 재부팅 영속성·native 두 번째
peer와 기록된 SDK 조건부 위험도 이 단계에서 재검사하되, 재현 근거 없이 SDK를 실패 원인으로
단정하지 않는다. HOST-W04 이후 작업은 W06 완료 전까지 시작하지 않는다.
