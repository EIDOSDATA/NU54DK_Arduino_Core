## 1. 지원 목표의 정의

이 프로젝트의 목표는 모든 NCS sample을 같은 형태의 `.ino` wrapper로 다시 작성하는 것이
아니다. 다음 조건을 만족하는 기능을 분류하고 가장 적합한 사용 경로를 제공하는 것이다.

> NCS v3.4.0에서 nRF54L15 CPUAPP를 지원하거나 NU54DK 하드웨어로 실현 가능한 기능을
> Arduino wrapper, NCS 직접 사용 예제, 검증된 build profile 또는 application template 중
> 적절한 형태로 제공하고, build·semantic·HIL 증거를 구분한다.

NCS 공개 API를 Sketch의 `.cpp`에서 직접 사용할 수 있는 것도 정식 경로다. 다만 직접 API가
compile된다는 사실을 Arduino wrapper 지원으로 표시하지 않는다.

## 2. 상태 vocabulary

| 상태 | 의미 |
| --- | --- |
| Inventory | upstream 경로와 NU54DK 적용 가능성을 조사함 |
| Build PASS | 고정 profile에서 compile/link됨 |
| Semantic PASS | API 의미와 오류 경로를 자동 시험함 |
| HIL PASS | 실제 NU54DK와 필요한 fixture에서 검증함 |
| Partial | 명시된 모드·pin·외장 hardware 범위만 지원 |
| Deferred | 가치가 있으나 현재 제품 milestone 밖임 |
| Not applicable | MCU/NU54DK 회로 또는 제품 구조와 맞지 않음 |

`Build PASS`만으로 `HIL PASS`나 제품 지원을 추정하지 않는다.

## 3. 제공 형태

| 형태 | 적용 기준 |
| --- | --- |
| Arduino wrapper | 일반 사용 빈도가 높고 안정적인 80% 사용 사례를 단순화할 가치가 있음 |
| NCS direct example | 공식 Zephyr/NCS API와 type을 그대로 쓰는 것이 더 정확함 |
| Validated profile | Kconfig, DTS, partition 또는 sysbuild 조합이 기능의 핵심임 |
| Application template | Matter/DFU처럼 독립 application 구조를 유지해야 함 |
| External hardware | 센서, codec 또는 nRF70 등 추가 장비가 필요함 |

하나의 기능이 여러 형태를 함께 가질 수 있다. 예를 들어 BLE는 기본 GATT wrapper와 고급
`bt_*` direct example, BLE profile을 동시에 제공할 수 있다.

## 6. NU54DK 자원 제약

- BLE, 802.15.4와 ESB는 같은 radio를 공유한다. 검증된 MPSL/multiprotocol profile 없이
  독립 객체를 동시에 시작하지 않는다.
- P1.2/P1.3은 현재 I2C22로 사용하며 NFC 기능과 동시에 사용할 수 없다.
- NU54DK에는 공식 nRF54L15 DK와 같은 MX25R64 외장 flash가 없다. 외장 flash 기반 settings,
  Mesh 또는 DFU 구성은 별도 hardware profile 없이는 지원하지 않는다.
- `spi00`과 `uart00`처럼 동일 instance를 공유하는 peripheral은 profile에서 상호 배타로
  관리한다.
- HPF는 CPUAPP+FLPR multi-image와 experimental 기능을 요구하므로 일반 Arduino API보다
  application profile로 다룬다.
- native USB device가 없으므로 `SerialUSB`, Keyboard와 Mouse는 Core만으로 제공하지 않는다.

## 7. Sample 추적 record

각 upstream sample 또는 기능군은 다음 필드를 가진 machine-readable record로 이전한다.

```yaml
schema_version: 1
id: ncs.bluetooth.peripheral_uart
upstream_path: nrf/samples/bluetooth/peripheral_uart
upstream_revision: 99553055607b2e9885fbc80ccd11fa9da81c2df0
target: nrf54l15dk/nrf54l15/cpuapp/nu54dk
delivery: arduino-wrapper
required_profile: ble
required_hardware:
  - nu54dk
adapted_example: libraries/NUCODE_BLE/examples/PeripheralUart
build: not-run
semantic: not-run
hil: not-run
```

필수 필드는 다음과 같다.

- upstream path, testcase와 exact revision
- upstream 및 파생 파일 license
- NU54DK 적용 가능성
- 제공 형태와 요구 profile
- 추가 hardware/배선
- adapted example 경로
- build, semantic와 HIL 상태
- 제외 이유와 재검토 조건

## 8. v0.2 우선 coverage

1. 현재 GPIO/Serial/Wire/SPI/ADC/PWM 예제의 표준 Arduino 노출
2. Counter/GRTC, watchdog, power와 settings의 board/system 계층
3. Zephyr/NCS public header를 `.ino`와 추가 `.cpp`에서 직접 사용하는 reference
4. basic BLE advertise, scan, GATT와 notify
5. 대표 sensor polling/trigger pattern
6. crypto/random direct example의 build feasibility

Thread, Matter, DFU와 multiprotocol은 profile schema가 sysbuild·partition·radio 충돌을 표현할
수 있는지 먼저 검증하고 다음 제품선에서 지원을 선언한다.

## 9. 완료 판정 규칙

- upstream sample 수를 wrapper 수와 동일시하지 않는다.
- hardware가 없는 기능은 HIL PASS로 표시하지 않는다.
- 공식 driver/API 대신 register를 직접 제어하는 호환층을 만들지 않는다.
- 실제 값을 얻을 수 없는 radio·counter 정보는 합성값으로 반환하지 않는다.
- profile 또는 application template이 적절한 기능을 억지로 Arduino singleton으로 만들지 않는다.
- `지원` 표시는 API 문서, example, 자동 시험과 필요한 HIL이 함께 있을 때만 사용한다.

M17부터 이 문서를 사람이 편집하는 요약표와 machine-readable coverage record에서 자동 생성한
통계로 교차 검증한다.
