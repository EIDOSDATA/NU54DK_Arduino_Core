## 1. 지원 목표의 정의

이 프로젝트의 목표는 모든 NCS sample을 같은 형태의 `.ino` wrapper로 다시 작성하는 것이
아니다. 다음 조건을 만족하는 기능을 분류하고 가장 적합한 사용 경로를 제공하는 것이다.

> NCS v3.4.0에서 nRF54L15 CPUAPP를 지원하거나 NU54DK 하드웨어로 실현 가능한 기능을
> Arduino wrapper, NCS 직접 사용 예제, 검증된 build profile 또는 application template 중
> 적절한 형태로 제공하고, build·semantic·HIL 증거를 구분한다.

NCS 공개 API를 Sketch의 `.cpp`에서 직접 사용할 수 있는 것도 정식 경로다. 다만 직접 API가
compile된다는 사실을 Arduino wrapper 지원으로 표시하지 않는다.

## 2. 상태 vocabulary

| 상태 | 의미 |
| --- | --- |
| Inventory | upstream 경로와 NU54DK 적용 가능성을 조사함 |
| Build PASS | 고정 profile에서 compile/link됨 |
| Semantic PASS | API 의미와 오류 경로를 자동 시험함 |
| HIL PASS | 실제 NU54DK와 필요한 fixture에서 검증함 |
| NOT RUN | 시험 자산이 없거나 승인된 범위에서 실행하지 않음; PASS로 해석하지 않음 |
| Partial | 명시된 모드·pin·외장 hardware 범위만 지원 |
| Deferred | 가치가 있으나 현재 제품 milestone 밖임 |
| Not applicable | MCU/NU54DK 회로 또는 제품 구조와 맞지 않음 |

`Build PASS`만으로 `HIL PASS`나 제품 지원을 추정하지 않는다.

## 3. 제공 형태

| 형태 | 적용 기준 |
| --- | --- |
| Arduino wrapper | 일반 사용 빈도가 높고 안정적인 80% 사용 사례를 단순화할 가치가 있음 |
| NCS direct example | 공식 Zephyr/NCS API와 type을 그대로 쓰는 것이 더 정확함 |
| Validated profile | Kconfig, DTS, partition 또는 sysbuild 조합이 기능의 핵심임 |
| Application template | Matter/DFU처럼 독립 application 구조를 유지해야 함 |
| External hardware | 센서, codec 또는 nRF70 등 추가 장비가 필요함 |

하나의 기능이 여러 형태를 함께 가질 수 있다. 예를 들어 BLE는 기본 GATT wrapper와 고급
`bt_*` direct example, BLE profile을 동시에 제공할 수 있다.

## 6. NU54DK 자원 제약

- BLE, 802.15.4와 ESB는 같은 radio를 공유한다. 검증된 MPSL/multiprotocol profile 없이
  독립 객체를 동시에 시작하지 않는다.
- P1.2/P1.3은 현재 I2C22로 사용하며 NFC 기능과 동시에 사용할 수 없다.
- NU54DK에는 공식 nRF54L15 DK와 같은 MX25R64 외장 flash가 없다. 외장 flash 기반 settings,
  Mesh 또는 DFU 구성은 별도 hardware profile 없이는 지원하지 않는다.
- `spi00`과 `uart00`처럼 동일 instance를 공유하는 peripheral은 profile에서 상호 배타로
  관리한다.
- HPF는 CPUAPP+FLPR multi-image와 experimental 기능을 요구하므로 일반 Arduino API보다
  application profile로 다룬다.
- native USB device가 없으므로 `SerialUSB`, Keyboard와 Mouse는 Core만으로 제공하지 않는다.

## 7. M17 machine-readable coverage ledger

M17은 `coverage/ncs-v3.4.0/`을 coverage 단일 원본으로 추가했다.

```text
coverage/ncs-v3.4.0/
├─ manifest.json
├─ records/
│  ├─ arduino.adafruit-lsm6ds.json
│  ├─ board.system.json
│  ├─ nrf.802154-phy-test.json
│  ├─ nrf.ble-nus.json
│  ├─ nrf.crypto-rng.json
│  ├─ nrf.matter-template.json
│  ├─ nrf.openthread-cli.json
│  ├─ zephyr.sensor-direct.json
│  └─ zephyr.settings-storage.json
└─ generated/
   ├─ summary.json
   └─ summary.md
```

Manifest는 NCS `99553055607b2e9885fbc80ccd11fa9da81c2df0`, Zephyr
`bf801e4e3d19e1ffa76164346480cb7734dd2800`, board
`fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3`을 고정하고 각 record SHA-256을 검증한다.
`tools/coverage/m17_coverage.py`는 duplicate key, schema, revision, repository/path, license,
route/status/profile/hardware, evidence 경로와 manifest hash를 fail-closed로 검사한다. 생성 요약은
deterministic output이며 직접 편집하지 않는다.

| record | 제공 경로 | 제품 상태 | M17 검증 요약 |
| --- | --- | --- | --- |
| `board.system` | Arduino wrapper | supported | M15 HIL PASS 증거 연결 |
| `nrf.ble-nus` | Arduino wrapper | supported | M16 두 보드 HIL PASS 증거 연결 |
| `zephyr.settings-storage` | Arduino wrapper | supported | M15 persistence HIL PASS 증거 연결 |
| `arduino.adafruit-lsm6ds` | build-profile-only | build-only | LSM6DS3TR-C Arduino compile PASS; runtime/HIL NOT RUN |
| `zephyr.sensor-direct` | NCS/Zephyr direct example | build-only | NU54DK compile/link PASS; wrapper 없음 |
| `nrf.crypto-rng` | NCS direct example | build-only | 공식 보드·NU54DK build PASS |
| `nrf.802154-phy-test` | excluded/deferred | deferred | 공식 PASS, NU54DK NVMC symbol 오류 |
| `nrf.openthread-cli` | excluded/deferred | deferred | 공식·NU54DK build PASS |
| `nrf.matter-template` | excluded/deferred | deferred | 공식 PASS, NU54DK `factory_data_partition` 누락 |

M17 결과 분류의 상세 증거와 범위는
[M17 NCS 기능과 예제 Coverage 기준선](<../04_검증 기록/19_M17_NCS_기능과_예제_Coverage_기준선.md>)을

## 8. v0.2 우선 coverage

1. 현재 GPIO/Serial/Wire/SPI/ADC/PWM 예제의 표준 Arduino 노출
2. Counter/GRTC, watchdog, power와 settings의 board/system 계층
3. Zephyr/NCS public header를 `.ino`와 추가 `.cpp`에서 직접 사용하는 reference
4. basic BLE NUS advertise, exact name scan, RX write와 TX notify — M16 완료
5. 대표 sensor direct build와 외부 LSM6DS3TR-C library compile — M17 build-only PASS
6. crypto/random direct example의 공식/NU54DK build feasibility — M17 PASS

Thread, Matter, DFU와 multiprotocol은 profile schema가 sysbuild·partition·radio 충돌을 표현할
수 있는지 먼저 검증하고 다음 제품선에서 지원을 선언한다. M17에서 IEEE 802.15.4,
OpenThread와 Matter build feasibility는 실행했지만 세 항목 모두 v0.2.0에서 deferred·미지원이다.

## 9. 완료 판정 규칙

- upstream sample 수를 wrapper 수와 동일시하지 않는다.
- hardware가 없는 기능은 HIL PASS로 표시하지 않는다.
- 공식 driver/API 대신 register를 직접 제어하는 호환층을 만들지 않는다.
- 실제 값을 얻을 수 없는 radio·counter 정보는 합성값으로 반환하지 않는다.
- profile 또는 application template이 적절한 기능을 억지로 Arduino singleton으로 만들지 않는다.
- `지원` 표시는 API 문서, example, 자동 시험과 필요한 HIL이 함께 있을 때만 사용한다.

BQ25186은 예외적으로 board 전용 제한 adapter를 제공한다. 보드 DTS의 charger node를 disabled로
유지하고, `pmicBegin()` read-only, 매 boot RAM write 승인, 허용 field 목록, 범위 검사와
reserved-bit 보존을 모두 적용한다. 공개 raw register API는 제공하지 않는다. 이 예외는 다른
Zephyr driver 장치의 임의 register 직접 제어를 허용하는 일반 규칙이 아니다. 배터리 전기 HIL은
`NOT RUN`이며 실제 NTC 온도 보호는 미지원이다.

M16 완료 범위는 NUS Peripheral/Central Stream과 해당 profile·예제다. 동적 GATT, read,
indication, bonding과 SMP는 포함하지 않으며 NUS HIL을 이 기능들의 지원 증거로 확대하지 않는다.
Zephyr/NCS `bt_*` 직접 사용은 가능하지만 각 기능은 별도 record와 검증이 필요하다.

M17부터 이 문서를 사람이 편집하는 요약표와 machine-readable coverage record에서 자동 생성한
통계로 교차 검증한다.

M17 완료는 9개 record의 경로와 상태를 정확히 분류하고 실제 build 결과를 연결했다는 뜻이다.
Sensor compile을 실기 동작으로, 공식 DK build를 NU54DK 적용성으로, OpenThread NU54DK build를
network runtime 지원으로 확대하지 않는다. 특히 IEEE 802.15.4와 Matter의 NU54DK build 실패는
숨기지 않고 deferred record의 적용성 결과로 유지한다.
