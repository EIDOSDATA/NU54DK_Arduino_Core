이 프로젝트의 목표는 NCS sample을 모두 같은 `.ino` wrapper로 다시 작성하는 것이 아니다.
기능마다 Arduino wrapper, NCS direct example, validated profile, application template 또는
명시적 제외 중 적합한 경로를 제공한다. **Build 성공, 제품 지원과 HIL 성공을 서로 같은
상태로 취급하지 않는다.**

## 1. 세 가지 독립 분류

### 제공 경로

| 경로 | 의미 |
| --- | --- |
| Arduino wrapper | 반복 사용 가치가 높은 안정적인 사용 사례를 Arduino API로 제공 |
| NCS direct | 별도 direct/native application 또는 library `.cpp`에서 Zephyr/NCS 공개 API를 사용. 설치용 공개 `.ino`는 C++/`NUCODE_*` API 흐름을 유지 |
| Validated profile | Kconfig, DTS, partition 또는 sysbuild 조합이 기능의 핵심 |
| Application template | Matter/DFU처럼 독립 application 구조를 유지 |
| External library | NUCODE가 소유하지 않는 Arduino library와의 compile 호환성 |
| Excluded | hardware·제품 정책 또는 검증 비용 때문에 제공하지 않음 |

### 제품 상태

| 상태 | 의미 |
| --- | --- |
| `supported` | 공개 API/예제/문서와 필요한 자동·HIL 근거가 있음 |
| `partial` | 명시한 pin, mode 또는 외장 hardware 범위만 지원 |
| `build-only` | compile/link만 검증했으며 runtime 지원이 아님 |
| `planned` | 승인된 향후 제품선 계획이며 아직 공개 지원이 아님 |
| `deferred` | 가치가 있지만 현재 제품선 밖 |
| `not-applicable` | MCU, NU54DK 회로 또는 제품 구조와 맞지 않음 |

### 검증 상태

| 상태 | 의미 |
| --- | --- |
| `inventory` | upstream 경로와 적용 가능성만 조사 |
| `build-pass` | 고정 환경에서 compile/link 성공 |
| `semantic-pass` | API 의미와 오류 경로를 자동 시험 |
| `hil-pass` | 실제 NU54DK와 필요한 fixture에서 검증 |
| `not-run` | 실행하지 않았으며 PASS로 해석하지 않음 |
| `build-fail` | 적용 build가 실패했고 원인을 기록 |

하나의 기능은 세 축을 모두 가진다. 예를 들어 외부 sensor library는 `External library / build-only /
build-pass`일 수 있으며, 이를 `supported / hil-pass`로 확대하면 안 된다.

## v0.4.1 현재 지원 요약

현재 package는 library 9개와 예제 30개를 제공하며 `standard`, `ble`, `fabric` profile을
지원합니다. 아래 표는 v0.3.0 기능에 추가한 `fabric` 범위입니다. 이전 버전의 도입·검증 이력은
2~3절에 분리해 보존합니다.

| 영역 | 제공 경로 | 공개 범위와 검증 경계 |
| --- | --- | --- |
| Serial Fabric | `fabric` profile + 직접 API | UARTE 5·SPIM 5·SPIS 5·TWIM 4·TWIS 4 identity와 검증된 route |
| Analog Fabric | `fabric` profile + 직접 API | SAADC scan/continuous DMA, PWM20/21/22 sequence |
| Event Fabric | `fabric` profile + 직접 API | GPIOTE·EGU·DPPIC·PPIB·TIMER identity별 자원 계약 |
| Stream Fabric | `fabric` profile + 직접 API | PDM20/21·I2S20 double buffer; QDEC20/21 기본 정·역회전과 SAMPLE/REPORT event |
| System Fabric | `fabric` profile + 직접 API | TEMP와 WDT30/31; 기존 Board/System은 `standard`/`ble`에서 유지 |

75개 hardware identity 중 public surface는 64개이며 HIL `pass` 62개와 QDEC20/21 `partial`
2개를 구분합니다. 반복 manual QDEC read/clear의 무손실 누산, 반복 Serial personality handover,
모든 주변장치 동시 조합, 정밀 ADC 정확도·jitter·음질·신호 무결성은 보증하지 않습니다.
세부 지원은 [Arduino API 범위](04_Arduino_API_지원_범위.md), identity별 상태는
[M23 매트릭스](09_M23_Peripheral_인스턴스_매트릭스.md), 공개 package 결과는
[125번 기능 공개 기록](<../04_검증 기록/125_v0.4.0_정식_릴리스_공개와_T24_T25_마감.md>)과
[129번 현재 package 기록](<../04_검증 기록/129_v0.4.1_설치기_유지보수_릴리스.md>)을 따릅니다.

### 개발 진행 중 확정할 지원 경계

M28·M29·M30 production 구현·HIL은 완료했지만 v0.5.0 제품 공개는 아직 아니다.
M30은 W01~W08·10/10 test ID와 실제 전원 차단 12/12를 완료했다.
M31-W01은 parity·capability 계약을, W02는 설치 ISO 예제와 실제 기능 HIL을, W03은 Audio
11/11을, W04는 DF 지원 TX·response와 미지원 경계를, W05는 connected CS의 지원·negative·복구 경계를, W06은 독립 image 자원·수명주기·M19~M30 회귀를 완료했다. M31은 **6/8**이고
W07~W08은 미착수다. [W04 완료](<../04_검증 기록/263_M31_W04_Direction_Finding_완료.md>), [W05 완료](<../04_검증 기록/264_M31_W05_Channel_Sounding_완료.md>), [W06 완료](<../04_검증 기록/265_M31_W06_자원_수명주기와_영향_회귀_완료.md>)와
[readiness](../../variants/nu54dk/m31-ble-readiness.json)가 근거이며 M32·M33은 미착수다.
`development-complete`는 개발 진도 표시이며
이 문서의 공개 제품 상태 `supported`와 다르다.
SDK의 기능 존재 여부와 제품의 공개 지원 정책을 구분하고 판정·시험을 완료하기 전에는 위 표의
상태를 `supported`로 올리지 않는다.

2026-09-21 결정에 따라 v0.5.0은 M31 완료 후 Windows 우선으로 릴리스한다. 완료한 메모리 최적화·W04 이후
W07~W08 및 Windows package·설치·RC·공개 gate를 완료해야 한다. M32·M33 추가 기능과
Ubuntu/macOS 지원 확대는 버전 미정 후속 범위이며 현재 미착수 상태를 유지한다.

## 5. Machine-readable coverage 단일 원본

M17 기능별 exact revision, license, hardware, route, status와 evidence는
`coverage/ncs-v3.4.0/`이 소유한다. 이 9개 record는 M17에서 검증한 경로의 고정 기준선이며,
v0.4.0에서 도입해 v0.4.1에서 유지하는 Peripheral Fabric의 지원 원장은 별도
`variants/nu54dk/peripheral-manifest.json`이다.

- [Coverage manifest](../../coverage/ncs-v3.4.0/manifest.json)
- [자동 생성 Markdown 요약](../../coverage/ncs-v3.4.0/generated/summary.md)
- [자동 생성 JSON 요약](../../coverage/ncs-v3.4.0/generated/summary.json)
- [M17 검증 기록](<../04_검증 기록/19_M17_NCS_기능과_예제_Coverage_기준선.md>)
- [전체 검증 기록](<../04_검증 기록/README.md>)

`tools/coverage/m17_coverage.py`는 schema, exact repository/path/revision, license, profile,
hardware, evidence와 record SHA-256을 fail-closed로 확인한다. `generated/`는 직접 편집하지
않는다. 이 문서의 표는 사용자용 분류이며 9개 M17 record의 exact 값을 복제하지 않는다.

M31-W01에서 구현한 [sample parity 원장](../../variants/nu54dk/ncs-v3.4.0-bluetooth-sample-parity.json)은
전체 Bluetooth sample/test·source symbol 703행의 추가 원장이다. 기존 M17의 9개 검증 record와
생성 결과를 보존하고 upstream 발견 목록·owner·Arduino 제공 방식·source/build/runtime 상태를
연결한다. 원장/수집기 완료와 각 예제의 실행 완료는 독립이며 기존 M17 coverage 9개로 전체
Bluetooth 예제 coverage를 주장하지 않는다.

## 6. NU54DK 자원 제약

- BLE, IEEE 802.15.4와 ESB는 같은 radio를 공유한다. 검증된 MPSL/multiprotocol profile 없이
  동시에 시작하지 않는다.
- P1.2/P1.3은 I2C22로 사용하며 NFC와 동시에 사용할 수 없다.
- NU54DK에는 Nordic DK와 같은 MX25R64 외장 flash가 없다. 외장 flash 기반 Settings, Mesh나
  DFU 구성을 동일하게 적용하지 않는다.
- 동일 serial block을 공유하는 UARTE, SPIM/SPIS와 TWIM/TWIS personality는 profile과
  `IoResourceManager`에서 상호 배타로 관리한다. 서로 다른 block의 동시 사용은 별도 HIL 증거가 필요하다.
- native USB device가 없으므로 `SerialUSB`, Keyboard와 Mouse를 USB API로 제공하지 않는다.

## 7. 지원 판정 규칙

1. Upstream sample 수를 wrapper 수나 지원률로 바꾸지 않는다.
2. 공식 DK build를 NU54DK runtime PASS로 표시하지 않는다.
3. Hardware가 없으면 HIL PASS로 표시하지 않는다.
4. 실제 값을 얻을 수 없는 radio/counter 정보를 합성하지 않는다.
5. Profile이나 application template이 맞는 기능을 억지로 Arduino singleton으로 만들지 않는다.
6. Zephyr driver가 있는 장치를 일반적인 raw-register Arduino API로 우회하지 않는다.
7. 지원 상태 변경은 coverage record, 예제, 자동 시험과 필요한 HIL을 함께 갱신한다.

v0.5.0의 외부 장치 경로는 구현·예제·자동 검사와 실제 장치 검증 상태를 함께 표시해 배포할 수 있다.
사용자 추후 검증으로 확정한 외부 실기의 `NOT RUN`은 공개 차단이 아니며, `supported`·호환성 또는
실제 HIL PASS의 근거가 되지는 않는다. 보드 기반 기능과 M31 Windows 릴리스 gate는 별도로
충족하며 세 Host 확대의 필수 증거는 해당 후속 제품선에서 검증한다.

BQ25186의 제한 adapter는 board 전용 예외다. DTS node disabled, read-only `pmicBegin()`, 매 boot
RAM write 승인, 허용 field, 범위 검사와 reserved-bit 보존을 적용한다. 이 예외를 다른 driver의
임의 raw register 접근 허용으로 확대하지 않는다.
