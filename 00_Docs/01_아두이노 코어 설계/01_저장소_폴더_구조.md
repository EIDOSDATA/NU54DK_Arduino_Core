# NU54DK Arduino Core 저장소 폴더 구조

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 구조 확정 — 구현 전 |
| 작성자 | Quantum / NUCODE |
| 대상 | Loader 없는 Native Full Zephyr Arduino Core |
| 기준 보드 정의 | [Nucode01/NU54DK_Zephyr_DTS](https://github.com/Nucode01/NU54DK_Zephyr_DTS) |

---

## 1. 설계 원칙

1. NU54DK의 물리 GPIO, 주변장치, pinctrl 및 보드 메타데이터는 `NU54DK_Zephyr_DTS`가 단독으로 소유한다.
2. Arduino Core는 해당 저장소를 `board_package/NU54DK_Zephyr_DTS` Git 서브모듈로 고정하여 실제 빌드에 사용한다.
3. 이 저장소 안에 별도로 수정되는 두 번째 `boards` 원본을 만들지 않는다. 보드 변경은 보드 저장소에서 먼저 반영한 후 서브모듈 commit을 갱신한다.
4. Arduino Core의 variant는 `D0`, `A0`, `LED_BUILTIN` 같은 논리 이름과 순서만 제공한다.
5. 실제 GPIO controller, pin, polarity 및 peripheral route는 Devicetree 생성 정보를 통해 얻는다.
6. west-native PoC를 먼저 완성하고 Arduino CLI Build Adapter를 곧바로 검증한 뒤 API를 확장한다.
7. 빌드 결과와 캐시는 소스 트리의 `build` 또는 외부 캐시 경로에 두며 Git에 포함하지 않는다.

## 4. 보드 정의 연결

개발 단계에서는 Arduino Core에 연결된 서브모듈 루트를 `BOARD_ROOT`로 전달한다.

~~~text
-DBOARD_ROOT=<NU54DK_Arduino_Core>/board_package/NU54DK_Zephyr_DTS
~~~

현재 로컬 저장소의 절대 경로 예시는 다음과 같다.

~~~text
-DBOARD_ROOT=C:/Users/eidos/GitHub/NU54DK_Arduino_Core/board_package/NU54DK_Zephyr_DTS
~~~

Build Adapter는 설치 위치에 따라 다음 경로를 동적으로 계산해야 한다.

~~~text
{runtime.platform.path}/board_package/NU54DK_Zephyr_DTS
~~~

Arduino Core는 다음 정보를 해당 보드 정의에서 소비한다.

- `DT_ALIAS(led0)` 등 LED와 버튼 alias
- UART, I2C, PWM, ADC 및 GPIO device node
- pinctrl과 peripheral 활성 상태
- Flash/RAM partition 및 Zephyr board metadata
- pyOCD/J-Link runner 설정

소스 저장소 사용자는 최초 복제 시 `--recurse-submodules`를 사용하거나 `git submodule update --init --recursive`를 실행해야 한다.

공개 배포 단계에서는 GitHub가 자동 생성한 source archive에 의존하지 않는다. release staging 도구가 고정된 서브모듈 commit을 checkout하고, `.git` 메타데이터를 제외한 실제 보드 파일과 라이선스를 `board_package/NU54DK_Zephyr_DTS` 경로에 포함한다. 따라서 Boards Manager로 설치한 사용자는 Git 또는 서브모듈 명령 없이 바로 빌드할 수 있어야 한다.

## 5. 최초 구현 시 생성할 파일

첫 번째 west-native Blink PoC에서 다음 파일을 실제 구현한다.

~~~text
zephyr/module.yml
zephyr/CMakeLists.txt
zephyr/Kconfig

cores/arduino/Arduino.h
cores/arduino/main.cpp
cores/arduino/wiring_digital.cpp
cores/arduino/wiring_time.cpp
cores/arduino/internal/pin_description.h

variants/nu54dk/variant.h
variants/nu54dk/variant.cpp

samples/zephyr/blink/CMakeLists.txt
samples/zephyr/blink/prj.conf
samples/zephyr/blink/src/Blink.cpp
~~~

첫 PoC에서는 `LED_BUILTIN`을 `DT_ALIAS(led0)`에 연결한다. 전체 Arduino 논리 핀맵은 PoC가 통과한 후 실제 NU54DK 회로에 노출된 핀만 대상으로 별도 설계한다.

## 6. Arduino CLI 통합 시 추가할 파일

west-native PoC가 통과하면 다음 영역을 구현한다.

~~~text
boards.txt
platform.txt
programmers.txt                         # 필요할 때만 생성

tools/nu54-builder/src/
tools/nu54-builder/tests/
tools/nu54-builder/templates/zephyr-app/

examples/01.Basics/Blink/Blink.ino
tests/arduino-cli/
~~~

Build Adapter는 Arduino의 `.ino` 전처리와 library discovery 결과를 NCS/Zephyr 전체 정적 빌드에 전달한다. 최종 산출물은 Loader나 LLEXT extension이 아니라 완전한 `zephyr.elf`, `zephyr.hex` 또는 `merged.hex`여야 한다.
