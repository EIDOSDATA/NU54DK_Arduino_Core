## 1. 목적

`v0.3.0`은 두 작업선을 병렬로 진행한다. 첫 번째는 `v0.2.0`에서 제한 또는 미구현으로 남은
NU54DK 적용 가능 Arduino API를 보강하는 **Arduino compatibility 작업선**이고, 두 번째는 검증한
NUS Peripheral/Central 수직 경로를 범용 BLE Arduino API로 확장하는 **BLE 작업선**이다. 목표는
일반 사용자가 `prj.conf`, Devicetree overlay나 Zephyr 내부 API를 직접 편집하지 않고 다음 기능을
사용할 수 있게 하는 것이다.

Compatibility 작업선의 목표는 다음과 같다.

- NU54DK connector GPIO와 classic timing·shift API
- 추가 Serial, Wire/SPI ownership, ADC/PWM, tone과 Servo 확장
- EEPROM과 대표 Arduino library 호환성 기준선

BLE 작업선의 목표는 다음과 같다.

- 장치 초기화, 이름, advertising, scanning과 connection lifecycle
- 사용자 정의 GATT service와 characteristic
- GATT read, write, write without response, notify와 indicate
- pairing, bonding, SMP와 passkey
- Battery Service, Device Information Service와 BLE HID

`v0.3.0`은 Zephyr/NCS를 숨기거나 대체하지 않는다. 고급 사용자의 Zephyr/NCS 직접 사용 경로를
유지하며 Arduino wrapper와 직접 API의 소유권·검증 범위를 구분한다. 목표 표현도 "모든 Arduino
보드와 library의 완전 호환"이 아니라 **NU54DK hardware에 적용 가능한 Arduino API 호환 기준선**으로
한정한다.

## 2. 설계 원칙과 비지원 경계

1. Loader나 별도 BLE firmware를 두지 않고 기존 Full Zephyr image 안에서 구현한다.
2. NCS v3.4.0과 Zephyr 4.4.0의 공개 Bluetooth API를 사용한다.
3. 일반 사용자는 Arduino Tools의 검증된 `ble` profile과 library 선언으로 구성을 선택한다.
4. M16 `BLESerial` NUS Sketch와 예제를 깨지 않고 매 단계에서 회귀 시험한다.
5. Bluetooth stack callback에서는 사용자 code를 직접 실행하지 않는다. bounded event queue로
   전달한 뒤 `poll()`을 통해 Arduino main-thread에서 callback을 호출한다.
6. GATT service schema는 Bluetooth 시작 전에 선언·등록하는 수명주기를 기본으로 한다.
7. UUID, value buffer, connection과 CCC의 수명·소유권을 공개 계약으로 고정한다.
8. 기능을 사용할 때 필요한 RAM/flash·connection·MTU 제한을 숨기거나 합성하지 않는다.
9. Compatibility API도 pin·bus·timer·storage 자원 소유권과 실패 진단을 먼저 고정한다.
10. 이름만 존재하거나 build만 성공한 API를 지원으로 표시하지 않는다.
11. Zephyr 안전을 깨뜨리거나 driver가 보장하지 않는 의미는 feasibility gate를 통과하기 전 구현을
    약속하지 않는다.

다음 기능은 `v0.3.0` 범위가 아니다.

- BLE Mesh
- Channel Sounding와 Bluetooth ISO
- BLE/IEEE 802.15.4/Thread/ESB multiprotocol coexistence
- 실행 중 임의 GATT service schema 추가·삭제
- 무제한 동적 할당과 Bluetooth callback 문맥의 사용자 callback
- OTA/DFU와 MCUboot
- native USB HID

다음은 NU54DK/nRF54L15 hardware에서 같은 방식으로 제공할 수 없으므로 `v0.3.0`뿐 아니라 Arduino
호환 목표에서도 영구 제외한다.

| 영구 제외 | 이유 |
| --- | --- |
| native USB, `SerialUSB`, `PluggableUSB`, USB Keyboard/Mouse | target에 native USB device 경로가 없음 |
| DAC | target에 DAC peripheral이 없음 |
| Wi-Fi/Ethernet | 해당 controller·PHY가 없음 |
| AVR식 `PROGMEM`/Harvard memory 의미 | Arm unified memory 구조와 다름 |
| AVR/SAMD direct register·port API | SoC·driver 종속이며 Zephyr resource ownership을 우회함 |

BLE HID는 Bluetooth GATT profile이다. NU54DK에 없는 target native USB device를 제공하거나
USB Keyboard/Mouse API를 지원한다는 뜻이 아니다.

## 4. AC-01 — Core/GPIO/시간 호환성

AC-01은 보드 pin resource와 classic Arduino timing API의 공개 의미를 먼저 고정한다. Arduino
호환 이름을 추가하는 것보다 DTS ownership, thread/ISR 문맥과 실패 진단을 보존하는 것이 우선이다.

| 개별 항목 | 난이도 | 구현·feasibility 핵심 | 완료 gate |
| --- | --- | --- | --- |
| 일반 connector GPIO pin map | 상 | 보드 DTS alias와 Variant sparse ID를 추가하고 UART/I2C/SPI/PWM 소유 pin을 중복 노출하지 않음 | 모든 공개 pin의 capability host test, NU54DK target build, input/output/edge HIL PASS |
| `OUTPUT_OPENDRAIN` | 중 | Zephyr GPIO open-drain flag와 외부 pull-up 전기 조건을 공개 계약으로 고정 | drive-low, release-high, 잘못된 capability와 외부 pull-up HIL PASS |
| level `LOW`/`HIGH` interrupt | 상 | level 유지 중 interrupt 폭주, callback 재진입과 re-arm 정책을 결정 | trigger/detach/re-arm, 지속 level과 event overflow negative HIL PASS |
| `pulseIn()` | 상 | microsecond 측정, timeout과 scheduler 개입 범위를 고정 | HIGH/LOW pulse, timeout, 최소·최대 경계와 loopback HIL PASS |
| `pulseInLong()` | 상 | 긴 timeout, 32-bit 반환 rollover와 sleep 가능 측정 방식을 고정 | 긴 pulse·timeout, rollover 차분과 다른 thread 진행 회귀 PASS |
| `shiftIn()` | 하 | bit order와 clock edge를 기존 GPIO 의미 위에 구현 | MSB/LSB, `0x00`, `0xff`, pattern loopback PASS |
| `shiftOut()` | 하 | data setup/hold와 bit order를 기존 GPIO 의미 위에 구현 | `shiftIn()` 상대 loopback과 invalid pin 진단 PASS |
| `noInterrupts()`/`interrupts()` | 매우 상 | Zephyr 전체 IRQ disable은 kernel·BLE를 깨뜨릴 수 있으므로 nested 범위와 Arduino-owned IRQ 경계를 먼저 증명 | safety gate, nested 호출, 다른 thread·BLE NUS·scheduler 회귀 PASS 뒤에만 지원 선언 |

`noInterrupts()`/`interrupts()` safety gate가 AVR식 전역 IRQ 차단으로 Zephyr와 BLE의 liveness를
보장하지 못하면, v0.3.0에서는 Arduino가 소유한 callback/IRQ만 중첩 안전하게 차단하는 callable
대체 계약을 구현하고 `의미 차이`로 표시한다. 이름만 정의한 no-op이나 복구할 수 없는 전역 lock은
허용하지 않는다.

### AC-01 완료 기준

- 각 항목의 public signature, host semantic·negative test와 target build PASS
- connector resource conflict, ISR/thread 문맥과 진단 code 검증 PASS
- 필요한 두 보드 loopback·GPIO HIL 증거 보존
- 기존 M3·M6·M14 GPIO·시간·interrupt 회귀 PASS
- feasibility 실패 항목은 지원으로 합성하지 않으며, 안전한 대체 계약 구현 또는 별도 scope 개정이
  승인될 때까지 AC-01을 완료하지 않음

## 5. AC-02 — Peripheral/Analog 호환성

AC-02는 AC-01의 pin·ownership 계약 위에서 UART, I2C, SPI, ADC와 PWM 기능을 확장한다. 추가
instance는 SoC에 controller가 존재한다는 이유만으로 만들지 않고 고정 board DTS가 실제 pin과
소유권을 제공할 때만 공개한다.

| 개별 항목 | 난이도 | 구현·feasibility 핵심 | 완료 gate |
| --- | --- | --- | --- |
| `Serial1` | 상 | `uart30`의 profile, SB5~SB8/DAP LPUART 연결 조건, IRQ RX/TX와 ownership을 고정 | 두 보드 baud·TX/RX loopback, overflow, begin/end와 rebegin PASS |
| 기본 `Serial.begin()`/`end()` 확장 | 매우 상 | `Serial`은 Zephyr console non-owning wrapper이므로 UART 재구성과 console 보존이 충돌함 | console·log를 깨뜨리지 않는 ownership gate와 기존 Serial 회귀 PASS 뒤 지원 범위 결정 |
| Serial TX/`flush()`/`availableForWrite()` 확장 | 상 | polling 1-byte 계약을 bounded TX queue와 실제 drain 의미로 확장 | queue full·partial write·flush timeout·재시작과 RX/TX 동시 HIL PASS |
| Wire target `begin(address)` | 상 | Zephyr I2C target mode와 controller mode 전환, address와 buffer 수명을 고정 | 두 보드 controller↔target read/write와 mode 전환 HIL PASS |
| Wire `onReceive()`/`onRequest()` | 상 | driver callback에서 사용자 callback을 직접 실행하지 않는 bounded event 계약 필요 | 순서, overflow, callback 문맥, timeout과 detach/restart HIL PASS |
| `requestFrom(..., false)` | 매우 상 | 독립 호출 사이 bus hold/no-STOP을 driver가 보장하는지와 transaction owner를 먼저 증명 | analyzer 또는 검증된 peer로 STOP 부재, 후속 repeated-start, timeout·취소·교착 negative PASS |
| `Wire1` controller | 상 | 고정 board DTS에 승인된 두 번째 SERIAL instance·pin 역할과 profile이 필요 | schematic·DTS resource gate, 두 bus 동시 controller HIL PASS일 때만 객체 노출 |
| 추가 SPI instance | 상 | 승인된 SPIM instance, pinctrl, chip-select와 profile ownership이 필요 | instance conflict negative와 각 bus loopback HIL PASS |
| SPI transaction 공유 보호 | 중 | Arduino Sketch와 다른 Zephyr client 사이 mutex·설정 복원 계약 필요 | 중첩·경쟁·mode/bit-order 전환과 ownership negative PASS |
| `usingInterrupt()`/`notUsingInterrupt()` | 상 | 지정 Arduino GPIO IRQ만 transaction 동안 suspend/restore하고 nested 상태를 보존 | 잘못된 interrupt, nested transaction, edge 주입과 복원 HIL PASS |
| SPI `attachInterrupt()`/`detachInterrupt()` | 매우 상 | legacy API가 뜻하는 peripheral/target IRQ 의미와 SPIS 필요성을 먼저 고정 | API 의미 승인, 정상·오류·복원 시험과 실제 사용 가치 gate PASS |
| ADC resolution API | 중 | SAADC 지원 resolution과 software scaling의 관찰 가능한 의미를 고정 | 8/10/12-bit 범위, saturation과 invalid resolution PASS |
| 추가 analog input | 상 | 실제 connector AIN, DTS channel과 analog logical ID가 선행되어야 함 | 각 공개 AIN target build, raw-read·invalid pin HIL PASS |
| PWM resolution·frequency API | 상 | 같은 PWM instance의 period 공유, channel과 duty 변환을 조정 | resolution/frequency/duty 경계, 충돌·복구와 기존 PWM 회귀 PASS |
| 추가 PWM-capable pin | 상 | static pinctrl와 channel allocator 없이 임의 GPIO PWM을 약속하지 않음 | board resource gate, 각 공개 pin 출력·detach·재소유 HIL PASS |
| `tone()`/`noTone()` | 상 | PWM/GRTC channel, duration work와 기존 PWM·BLE timer 충돌을 관리 | 주파수·duration·중단·재호출, resource conflict와 두 보드 capture PASS |
| Servo 기본 library | 상 | 50 Hz pulse, 다중 channel, jitter와 tone/PWM ownership을 고정 | 최소·중앙·최대 pulse, attach/detach, 동시 channel과 conflict HIL PASS |

`requestFrom(..., false)`는 API가 존재한다는 이유만으로 지원하지 않는다. NCS v3.4.0 I2C driver가
호출 경계를 넘어 bus를 점유하고 다음 transaction까지 no-STOP을 보장하지 못하면 안전하게 거부하고
진단을 유지한다. Core-owned transaction을 포함한 안전한 구현이 없으면 AC-02와 M22를 완료하지
않는다. 제외로 바꾸려면 별도 scope 개정과 프로젝트 소유자 승인이 필요하다.

### AC-02 완료 기준

- 공개 instance·pin·channel별 host contract, target build와 필요한 HIL PASS
- `standard`·`ble` profile의 resource resolver와 conflict negative test PASS
- unsupported board resource는 가짜 객체로 만들지 않고 machine-readable capability에 반영
- 기존 M7 Wire/SPI/ADC/PWM과 M16 BLE NUS 회귀 PASS
- feasibility·ownership gate 결과와 남은 의미 차이를 API matrix에 반영

## 6. AC-03 — Storage/Library 호환성

AC-03은 기존 Settings/ZMS 수직 경로를 Arduino 사용자가 익숙한 저장 API로 연결하고, 실제 package에
포함되는 대표 library의 compile/runtime 호환 범위를 고정한다.

| 개별 항목 | 난이도 | 구현·feasibility 핵심 | 완료 gate |
| --- | --- | --- | --- |
| Arduino EEPROM facade | 상 | ZMS 위에 byte address, RAM mirror, `update()`·`commit()`과 wear·오류 의미를 설계 | read/write/update/commit, bounds, reset persistence와 손상·공간 부족 negative PASS |
| internal filesystem facade | 매우 상 | RRAM partition, Settings·향후 MCUboot/DFU와 migration·복구 정책을 함께 고정 | partition overlap 없음, format/mount/reset/corruption recovery와 upgrade gate PASS |
| legacy compatibility header | 중 | `WString.h`, `HardwareSerial.h` 등 승인한 전통 include를 canonical API로 전달 | 대표 library include·link positive와 지원하지 않는 backend negative PASS |
| library metadata와 Arduino IDE 노출 | 하 | `library.properties`, architecture, include와 example category를 package 원본에 고정 | clean install 뒤 Library/Examples 노출과 Arduino CLI compile PASS |
| 대표 library compile matrix | 중 | Servo, EEPROM, sensor 등 승인 목록과 exact revision을 고정 | standard·ble profile의 positive/negative compile 결과를 machine-readable ledger로 보존 |
| 대표 library runtime matrix | 상 | compile 성공을 제품 지원으로 확대하지 않고 peripheral별 fixture를 지정 | 승인 library의 NU54DK HIL, 오류·복구와 example transcript PASS |
| compatibility diagnostics·문서 | 하 | unsupported와 hardware-unavailable을 동일 오류로 합성하지 않음 | API matrix, known limitation, example와 진단 token 일치 검사 PASS |

Filesystem은 v0.3.0 구현 목표다. AC-03에서 향후 M23~M26의 storage·DFU 공간을 침범하지 않는
partition subset, mount·format·corruption recovery와 migration 계약을 고정해야 한다. 이를 안전하게
완성하지 못하면 M22를 차단하며, 단순 known limitation으로 자동 이월하지 않는다. `Client`, `Server`,
`Udp` 같은 network backend는 실제 transport를 다루는 후속 radio/network 제품선 전까지 library
compile 이름만으로 지원을 선언하지 않는다.

### AC-03 완료 기준

- EEPROM과 승인 library의 host·target·package test 및 필요한 HIL PASS
- clean Windows에서 library/example 검색, compile, upload와 reset persistence PASS
- storage corruption, bounds, resource conflict와 unsupported library negative PASS
- `v0.2.0` 공개 example와 Settings storage 회귀 PASS
- filesystem partition·복구 결과와 영구 하드웨어 제외 경계를 release known issues에 반영

## 7. BLE 공통 공개 구조

공개 진입점은 기존 `libraries/NUCODE_BLE/`를 유지한다. 다음 이름은 목표 역할을 설명하는
API surface이며 각 마일스톤에서 signature·오류 code·수명주기를 시험과 함께 고정한다.

| 계층 | 목표 객체 | 책임 |
| --- | --- | --- |
| Core/GAP | `BLEDevice` | stack 초기화, local identity, poll과 전체 lifecycle |
| Advertising | `BLEAdvertising` | flags, service UUID, manufacturer/service data, interval과 시작·정지 |
| Scanning | `BLEScan` | active/passive scan, 이름·UUID·주소 filter와 결과 event |
| Connection | `BLEConnection` | peer 정보, 연결·해제, MTU·보안 상태와 connection parameter 요청 |
| GATT server | `BLEService`, `BLECharacteristic` | service schema, value, permission과 server callback |
| GATT client | `BLEClient`와 remote service/characteristic handle | discovery, read/write와 subscription |
| Security | `BLESecurity` | pairing, bonding, passkey, security level과 bond 관리 |
| 표준 profile | BAS, DIS, HID library·example | 반복 사용 가능한 표준 service와 사용자 예제 |

M16의 `BLESerial`은 위 공통 lifecycle을 사용하도록 내부를 정리할 수 있지만 공개 NUS
`Stream` 의미와 예제 동작을 유지한다. 범용 API가 NUS 구현 세부 type을 외부에 요구하지 않는다.

## 8. M19 — BLE Core와 GAP

### 구현 범위

- Bluetooth stack의 한 번만 수행되는 초기화와 종료 가능 범위
- UTF-8/길이 제한을 명시한 local name
- connectable/non-connectable advertising
- advertising flags, 16/32/128-bit service UUID, manufacturer data와 service data
- advertising interval과 scan response 구성
- active/passive scan과 이름·UUID·주소 filter
- scan 결과의 bounded copy와 lifetime
- connect, disconnect, reconnect와 상태 event
- MTU, PHY, TX power와 connection parameter는 NCS가 실제 제공하는 범위만 노출
- 하나 또는 여러 connection 지원 여부를 compile-time/profile 제약으로 명확히 표시

### 오류·동시성 계약

- 잘못된 초기화 순서, 중복 start, 광고 payload 초과와 동시 scan/advertise 충돌을 진단한다.
- stack callback은 connection reference와 작은 event record만 보존한다.
- event overflow, scan result overflow와 unsupported option을 구분한다.
- `poll()`을 호출하지 않아 event가 지연되는 사실을 문서화한다.

### 완료 기준

- 공개 header와 implementation의 host compile/link 계약 PASS
- profile/feature resolver와 잘못된 조합 negative test PASS
- NU54DK target build와 메모리 report 보존
- 두 NU54DK의 advertise→filter scan→connect→disconnect→reconnect HIL PASS
- 이름, UUID, manufacturer data와 interval 경계 시험 PASS
- callback이 Arduino main-thread에서 실행됨을 확인
- M16 NUS Peripheral/Central 전체 회귀 PASS

### 범위 제외

- custom GATT schema
- pairing/bonding과 사용자 security UI
- 여러 peer 동시 연결의 지원 선언
- scan 결과를 무기한 소유하는 heap 객체

## 9. M20 — 범용 GATT server/client

### 구현 범위

- 16-bit와 128-bit service/characteristic UUID
- Bluetooth 시작 전 service·characteristic 선언과 등록
- 고정 또는 사용자 제공 bounded value buffer
- Read, Write, Write Without Response, Notify와 Indicate property
- read/write permission과 CCC 상태
- offset, prepare/long operation은 실제 지원 범위를 별도 표시
- generic client service/characteristic discovery
- client read, write, subscribe와 unsubscribe
- disconnect/reconnect 뒤 handle·subscription의 무효화와 재발견

### 공개 의미

- server write callback은 수신 data를 내부 bounded queue에 복사한 뒤 main-thread에서 전달한다.
- read callback이 stack의 동기 응답 시한을 요구하면 안전한 cached value 계약을 사용하고,
  임의 장시간 사용자 callback을 stack 문맥에서 실행하지 않는다.
- notification과 indication을 구분하고 indication confirmation/timeout을 노출한다.
- CCC는 connection별 상태이며 disconnect 뒤 자동으로 영구 보존한다고 가정하지 않는다.
- characteristic value 길이, ATT MTU와 전송 단위의 차이를 API 문서와 예제에서 설명한다.

### 완료 기준

- UUID, property, permission, value length와 lifecycle host semantic test PASS
- 잘못된 schema, 중복 UUID/registration, oversize value와 미연결 operation negative PASS
- 두 보드 custom service discovery PASS
- read/write/write-no-response 양방향 HIL PASS
- notify/indicate, CCC enable/disable와 confirmation HIL PASS
- ATT MTU 경계와 reconnect 뒤 재발견·재구독 HIL PASS
- 기존 NUS API·M19 GAP 회귀 PASS

### 범위 제외

- stack 시작 뒤 service schema 변경
- Zephyr 내부 attribute pointer를 portable Arduino API로 노출
- GATT database persistence의 자동 보장

## 10. M21 — BLE 보안과 표준 profile

### 구현 범위

- LE pairing과 SMP lifecycle
- bonding enable/disable, bond 목록과 명시적 삭제
- Just Works, passkey display/input/confirm 중 NCS와 시험 환경에서 검증한 방식
- characteristic별 encryption/authentication permission
- Settings 기반 bond persistence와 storage 오류 처리
- Battery Service(BAS)와 Device Information Service(DIS)
- BLE HID keyboard 기본 profile과 예제

### 보안 원칙

- 개발 편의를 위해 고정 passkey나 암호화 생략을 기본값으로 두지 않는다.
- passkey와 key material을 일반 Serial log에 출력하지 않는다.
- bond storage가 실패했을 때 bonded라고 보고하지 않는다.
- erase-all-bonds와 factory-reset 범위를 분리한다.
- security level과 MITM 요구를 실제 connection 상태에서 확인한다.

### 완료 기준

- pairing state machine과 오류/취소/timeout host test PASS
- 두 NU54DK pairing, encrypted GATT access와 bond reset-persistence HIL PASS
- bond 삭제 뒤 재-pairing HIL PASS
- BAS read/notify와 DIS field 자동 검증 PASS
- Windows 또는 검증된 스마트폰에서 HID pairing과 실제 key 입력 수동 확인
- NUS·M19·M20 전체 회귀 PASS

### 수동 확인 경계

Windows/스마트폰의 OS pairing UI와 실제 HID 입력 표시는 자동 UART HIL만으로 대체하지 않는다.
자동 시험은 protocol state와 firmware event를 검증하고, 수동 결과는 OS/version·장치·절차와
함께 별도 evidence로 기록한다.

### 범위 제외

- BLE Mesh provisioning/security
- LE Secure Connections의 모든 association model
- 모바일 companion application 제공
- 제품 인증 또는 보안 인증 획득 주장

## 12. 시험 자동화 경계

| 항목 | 자동화 | 사람 확인 |
| --- | --- | --- |
| Core/GPIO/time semantic·negative | 가능 | connector fixture 최초 식별 |
| Serial1, Wire/SPI와 ADC/PWM loopback | 대부분 가능 | 배선과 전기 조건 최초 확인 |
| `requestFrom(false)` no-STOP | driver·peer 자동화 가능 | 최초 analyzer/peer 기준 확정 |
| tone/Servo pulse와 timing | 두 번째 보드 capture 가능 | 제품 정확도 기준 승인 |
| EEPROM persistence·storage negative | 가능 | filesystem partition·복구 정책 승인 |
| 대표 Arduino library matrix | compile 자동화, 일부 HIL 가능 | 지원 목록과 exact revision 승인 |
| API compile·semantic·negative | 가능 | 불필요 |
| 두 보드 advertising/scanning/GATT | 가능 | fixture 최초 식별 |
| pairing·bond persistence | 대부분 가능 | passkey 입력 방식에 따라 필요 |
| BAS/DIS | 가능 | 선택적 앱 표시 확인 |
| Windows/스마트폰 HID | protocol 자동화 가능 | OS pairing UI와 실제 입력 확인 필요 |
| Boards Manager package lifecycle | clean Windows runner 가능 | stable 공개 승인 필요 |

사람 확인이 필요한 항목을 자동 PASS로 합성하지 않는다. 반대로 OS UI 확인이 불필요한 protocol
경로는 UART/HCI evidence로 자동화해 반복 검증한다.
