이 문서는 작업자나 대화 컨텍스트가 바뀌어도 리팩토링 순서와 남은 일을 잃지 않기 위한 활성
체크리스트다. 제품 기능의 T01~T25 상태는 [v0.4.0 TODO](../../TODO_v0.4.0.md), 실제 PASS/FAIL은
[검증 기록](<../../04_검증 기록/README.md>)이 소유한다. R 항목의 완료는 M24~M27 또는 공개
승인을 자동으로 뜻하지 않는다.

## 1. 현재 고정할 사실

- [x] Fixture 101~103 UART, 201~203 SPI, 301 TWI의 승인 route 단독 기능 HIL을 완료했다.
- [x] Fixture 301 원시 JSON/JSONL과 SHA-256, exact image·board identity를 50번 기록에 연결했다.
- [x] Host·문서·inventory·package gate와 DUT/peer 증분 target build를 통과했다.
- [x] 이 문서 정비가 반영된 최종 commit과 원격 `main`을 R00 기준선으로 고정한다.
- [x] R00에서 공개 API·CLI·artifact·저장 형식·HIL 계약과 기준 측정값을 [51번 기록](<../../04_검증 기록/51_R00_리팩토링_기준선.md>)에 작성했다.

현재 보드에는 Fixture 301의 SDA·SCL·GND 점퍼가 남아 있다. R00~R13의 구현·Host·target build에는
새 외부 결선이 필요하지 않다. 중간 실기는 결함 원인 분리에 꼭 필요한 진단으로만 제한하고 PASS
승격에 사용하지 않는다. R13과 전체 software gate가 끝나면 두 USB 전원을 끄고 current-source T11
회귀의 첫 fixture부터 연결표와 새 confirmation을 사용한다.

## 2. `v0.4.0` 통합 실기 전에 수행할 정확성 안정화

- [x] **R00 — 기준선과 characterization 계약**
  - 시작 조건: 이 문서 정비 commit이 원격 `main`과 일치한다.
  - 작업: Core/board/NCS/toolchain, 공개 API·symbol, builder/package 외부 계약, 대표 ELF·RAM/flash,
    기존 Host/target/HIL 증거와 NOT RUN을 기록한다.
  - 완료: 다음 수정의 전후 차이를 같은 입력으로 비교할 수 있고 금지 변경과 영향 회귀가 명시된다.
  - 증거: exact ec3bba3, Host 597 PASS/2 조건부 SKIP, contract 45/45, package 20/20, inventory·docs·examples 발견·style PASS, 대표 target 10/10 build-only와 hash/symbol/메모리 기준선. 새 HIL NOT RUN.

- [x] **R01 — CMake source 소속 정리**
  - 작업: SPIM/SPIS/TWIM/TWIS source를 명시적인 `nucode_arduino_core` target에 한 번만 등록한다.
  - 금지: Kconfig 재설계, SDK·board 변경, public API 또는 Fabric 파일 이동을 섞지 않는다.
  - 완료: 선택/비선택·단독·허용 조합의 resolved config, target membership, 실제 link와 package gate가
    통과한다.
  - 증거: [52번 기록](<../../04_검증 기록/52_R01_CMake_source_소속_교정.md>), 수정 전 5개 구성 실패·수정 후 7개 통과, 실제 7개 personality 조합+pair 2개 target 9/9, Host/contract/package/inventory/docs/style PASS. 실기 NOT RUN.

- [x] **R02 — Serial 전송 완료·timeout·동시 호출 정확성**
  - 작업: stale completion, operation generation, event 소비자, timeout과 DMA buffer 반환, 같은 handle의
    submit/cancel/deactivate 계약을 고정하고 필요한 최소 수정과 실패 회귀를 추가한다.
  - 완료: Host/fault-injection과 target build를 통과하고, runtime payload 영향과 최종 T11 회귀
    범위를 기록한다. 이 단계에서 중간 PASS 캠페인을 만들지 않는다.
  - 증거: [53번 기록](<../../04_검증 기록/53_R02_Serial_완료와_DMA_수명주기.md>), production adapter 수정 전 11개 실패·수정 후 24개 PASS, Host 600 PASS/2 조건부 SKIP, target 12/12 build-only. current-source T11 NOT RUN.

- [x] **R03 — Analog/Stream ISR·stop 동기화**
  - 작업: ISR/thread writer·reader, 진단 snapshot, overflow, stop generation과 lock 대기 경계를 먼저
    기록하고 파일 이동 없이 정확성만 수정한다.
  - 완료: stale stop·overflow·timeout 뒤 callback·반복 start/stop·다른 block 진행을 software에서
    검증하고 R11 및 최종 T12 image가 지켜야 할 동작 계약을 고정한다.
  - 증거: [54번 기록](<../../04_검증 기록/54_R03_Analog_Stream_ISR_정지_동기화.md>), production 회귀 26개, Host 602 PASS/2 조건부 SKIP, target 5/5, contract/inventory/style PASS. 새 실기 NOT RUN.

R01~R13에서 runtime byte가 바뀌면 과거 exact HIL은 역사 증거로 보존하되 새 source의 PASS로
복사하지 않는다. 영향 T11 회귀는 R13과 전체 software gate가 끝난 최종 source에 한 번 연결한다.

검사를 통과한 exact source만 최종 실기 캠페인에 사용한다.
