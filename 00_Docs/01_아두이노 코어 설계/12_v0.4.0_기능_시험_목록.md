# v0.4.0 기능 시험 목록

이 문서는 `v04_test_plan.json`에서 생성한다. 손으로 수정하지 않는다.

**준비 기준선이며 실기 결과·최종 지원 선언이 아니다.** 수치는 코어 기능 검증을 위한 초기 engineering 기준이며 최대 성능 보증이나 사용자와 합의한 실측값이 아니다.

T02에서 API/핀/clock 성립을 대조하고 T04~T08에서 실행 vector·fixture를 고정한다. 불가능한 필수 조합은 HOLD로 남긴다. 실제 실행 전 계획 개정·image·배선표 hash를 함께 고정한다.

- 범위: [42번 합의](<../04_검증 기록/42_v0.4.0_코어_기능_검증_범위_합의.md>), 진행: [TODO](../TODO_v0.4.0.md).
- 원본: [시험 JSON](../../tests/hil/nu54dk/v04_test_plan.json), 검사: [verify_v04_test_plan.py](../../tools/peripheral/verify_v04_test_plan.py).
- 각 family/instance/mode는 별도 결과 ID를 가진다. 적용 불가 mode는 이유를 기록하며 암묵적으로 PASS하지 않는다.
- 기능 sweep는 각 rate·buffer·mode를 기준 설정에서 하나씩 변경하고, protocol mode×bit order는 전 조합을 검사한다. soak는 단독 통과한 기준 설정으로 별도 실행한다.
- 동일 block 방향 있는 충돌 조합은 86개다. 두 board의 같은 roundtrip 오류를 가리지 않도록 독립 pattern과 count를 검사한다.
- errata 조건·workaround는 고정 SDK와 silicon revision으로 T02/T07에서 구체화한다. 번호가 있다는 사실만으로 회귀 시험이 준비된 것은 아니다.
- QDEC·GPIO·event는 DMA로 세지 않는다. M26 16개는 기존 지원 경계 전수 판정이며 raw 보안/RADIO 실행 대상이 아니다.

## 2. 시험 family

### V04-UART-DATA

- 대상: uarte00, uarte20, uarte21, uarte22, uarte30
- 실행 자원: `primary-route`
- 모드: 8N1, 8E1, tx, rx, full-duplex, double-buffer
- 수치: `{"baud": [115200, 1000000], "buffer_bytes": [1, 32, 256, 1024], "repetitions": 100}`
- 합격 기준: nonce와 sequence로 독립 생성한 양방향 payload를 byte 단위 대조. 완료 길이·buffer 소유권·guard 일치, 미신고 loss 0.
- 준비 의존성: T04: 모든 mode firmware/runner. DAP 비지원 baud/parity는 승인 peer route 사용. 비지원을 PASS로 처리하지 않음.
- 기존 runner 참고: tests/hil/nu54dk/m24_uarte_onboard.py; errata: 7

### V04-UART-FLOW

- 대상: uarte00, uarte20, uarte21, uarte22, uarte30
- 실행 자원: `peer`
- 모드: rts-cts, backpressure, parity-error, break-framing-error
- 수치: `{"baud": [115200], "buffer_bytes": [256], "pause_ms": 100, "repetitions": 100}`
- 합격 기준: CTS 정지 중 미완료, 재개 후 byte 완전 일치. 의도한 parity/break의 error mask를 검출하고 정상 frame으로 복귀.
- 준비 의존성: T04/T08: 4신호 route와 독립 peer 오류 주입. DAP flow 동작만으로 모든 case를 대체하지 않음.
- 기존 runner 참고: 신규 필요; errata: 7

### V04-SPI-DATA

- 대상: spim00, spim20, spim21, spim22, spim30, spis00, spis20, spis21, spis22, spis30
- 실행 자원: `peer`

- 수치: `{"buffer_bytes": [1, 2, 31, 32, 255, 256, 1024], "frequency_hz": [2000000, 4000000, 8000000], "repetitions": 100}`
- 합격 기준: 각 role·mode·bit 순서의 독립 pattern 일치, CS 경계별 길이 일치. TX-only/RX-only와 비대칭 길이의 ORC 대조. sync는 SPIM, double-buffer는 SPIS에 적용.
- 준비 의존성: T04/T08: controller↔peripheral peer와 CS route. instance별 실효 clock 기록.
- 기존 runner 참고: 신규 필요; errata: 8, 21, 54

### V04-ADC

- 대상: saadc
- 실행 자원: `peer`
- 모드: ain0-ain1-ain2-ain3-ain7, board-shared-ain4-ain5-ain6-contract-only, manual-sample, single-buffer, double-buffer
- 수치: `{"buffer_samples": [32, 256], "buffers": [1, 2], "fixture_ids": [401, 402, 403, 404, 408], "manual_interval_us": 2000, "oversample": [1], "repetitions": 100, "resolution_bits": [12]}`
- 합격 기준: 같은 3.3V domain의 peer PWM을 안전한 AIN0~3/AIN7에 묶음별로 연결한다. DMA 완료 길이·buffer 반환·guard와 HIGH code를 검사한다. 정밀 전압 정확도 시험이 아니며 AIN4 DAP 감지, AIN5 VBAT 분압기, AIN6 버튼에는 peer 출력을 연결하지 않는다.
- 준비 의존성: T05/T08: fixture 401~404/408을 전원 분리 상태에서 하나씩 재결선. AIN4~6은 board-shared 제한을 문서화하고 실기 PASS로 승격하지 않음.
- 기존 runner 참고: 신규 필요; errata: 해당 목록 없음

### V04-PWM

- 대상: pwm20, pwm21, pwm22
- 실행 자원: `peer`
- 모드: channels-0-1-2-3, common, grouped, individual, wave-form, invert, sequence0-1, loop, dppi-start, triggered-step
- 수치: `{"base_clock_hz": 1000000, "buffer_values": [4, 32, 256], "capture_periods": 100, "duty_percent": [0, 25, 50, 75, 100], "tolerance_percent": 5, "top": [1000, 4000]}`
- 합격 기준: peer capture로 period/duty ±5% 이내, 0/100%는 정적 level 확인. 12channel을 개별 구별하고 sequence 순서·end/repeat·STOP 확인. wave-form의 TOP word는 별도 해석.
- 준비 의존성: T05/T08: 안전한 P1.14 한 선에서 instance별 channel slot 0~3을 순차 검사. common/grouped/wave/invert/triggered mode는 target 계약과 후속 승인 fixture로 구분하고 기존 analogWrite/tone/Servo 충돌을 검사.
- 기존 runner 참고: 신규 필요; errata: 해당 목록 없음

### V04-PDM

- 대상: pdm20, pdm21
- 실행 자원: `peer`

### V04-I2S

- 대상: i2s20
- 실행 자원: `peer`

- 준비 의존성: T06/T08: clock role별 peer와 packing oracle. 성립하지 않는 width/rate를 조용히 생략하지 않음.

### V04-QDEC

- 대상: qdec20, qdec21
- 실행 자원: `peer`
- 모드: forward, reverse, direction-change, debounce, double-transition, read-clear, restart
- 수치: `{"cycles": [1, 100, 1000], "repetitions": 10, "state_interval_us": [2000, 10000]}`
