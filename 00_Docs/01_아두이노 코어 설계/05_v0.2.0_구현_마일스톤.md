## 1. 목표

`v0.2.0`은 `v0.1.0`의 Native Full Zephyr build/upload 기반을 유지하면서 Arduino 사용성과
NU54DK 고유 기능을 확장한 두 번째 정식 릴리스다.

- exact NCS 기반 CI/CD와 재현 build
- 일반 사용자가 `prj.conf`/overlay를 직접 편집하지 않는 profile·feature resolver
- Arduino IDE에 노출되는 package 예제
- Core API와 DTS 기반 Variant 정리
- NU54DK Board/System library
- 공식 Zephyr Bluetooth stack 기반 BLE NUS Peripheral/Central
- NCS 기능·예제 coverage ledger와 지원 경계

## 2. 고정한 범위

## 4. 단계별 종료 조건

### M12 — CI/CD

- exact NCS/Zephyr/Toolchain lock을 검증한다.
- host, docs, package, example과 대표 Zephyr build를 분리한다.
- Linux/Windows 재현 build와 cold/warm cache를 확인한다.
- 장치 없는 software CI와 self-hosted HIL을 같은 PASS로 합치지 않는다.

### M13 — Profile과 예제 UX

- 일반 예제는 `.ino`와 Arduino Tools menu만으로 compile할 수 있다.
- profile, library feature와 전문가 override의 병합 순서가 결정적이다.
- 충돌·미등록 feature는 configure 전에 fail-closed 한다.
- 실제 예제 목록은 `libraries/*/examples`를 단일 원본으로 한다.

### M14 — Core API와 Variant

- v0.1 공개 API를 회귀시키지 않는다.
- 논리 pin은 board DTS alias와 capability에서 생성한다.
- 지원 API에는 semantic test와 필요한 HIL 근거가 있다.
- 미구현 기능은 성공하는 stub이나 합성값을 반환하지 않는다.

### M15 — NU54DK Board/System

- board identity, reset/uptime, watchdog, GRTC, Settings/ZMS와 System OFF API를 제공한다.
- BQ25186는 DTS에서 disabled를 유지하고, write는 매 boot 명시 승인과 허용 field로 제한한다.
- timed GRTC와 사용자 SW0 wake를 active SWD가 개입하지 않는 결합 HIL로 확인한다.
- 배터리 충전·rail·ship/shutdown 전기 동작과 NTC 보호는 `NOT RUN`·사용자 책임으로 공개한다.

### M16 — BLE NUS

- Zephyr Bluetooth host/controller와 NUS service/client를 backend로 사용한다.
- RX write, TX notify, reconnect와 frame boundary를 두 NU54DK에서 검증한다.
- Bluetooth callback에서 사용자 code를 직접 실행하지 않고 Arduino main-thread로 전달한다.
- 범용 GATT, bonding/SMP와 표준 profile은 지원 범위로 확대하지 않는다.

### M17 — NCS coverage

- 기능마다 Arduino wrapper, NCS direct example, build/profile-only 또는 deferred 중 경로를 정한다.
- upstream path, exact revision, license, NU54DK 적용성과 검증 상태를 machine-readable record에 둔다.
- sensor direct와 외부 library compile을 runtime/HIL 또는 NUCODE sensor wrapper로 표시하지 않는다.
- OpenThread/802.15.4/Matter feasibility를 `v0.2.0` 정식 지원으로 해석하지 않는다.

### M18 — 공개

- package 예제 전체 compile, 명시 probe UID upload와 대응 UART/BLE 실기를 검증한다.
- 공개 RC 결함은 같은 artifact를 덮어쓰지 않고 다음 RC에서 교정한다.
- archive, index, checksum, SBOM, license inventory와 release note identity를 고정한다.
- 프로젝트 소유자 승인 뒤 별도 stable package·tag·Release를 공개한다.

## 5. 의도적으로 남긴 경계

- PMIC register 변환 구현은 실제 배터리 충전·전원 안전성 PASS가 아니다.
- BLE NUS 지원은 범용 BLE GAP/GATT API 지원이 아니다.
- sensor와 radio의 build feasibility는 hardware runtime 지원이 아니다.
- RC2의 설치·HIL 결과를 stable exact package의 전체 물리 HIL 재실행으로 소급하지 않는다.
- 전문가가 Zephyr/NCS API를 직접 사용할 수 있어도 모든 API가 Arduino-friendly wrapper라는 뜻은 아니다.

## 6. 후속

다음 단계는 [v0.3.0 구현 마일스톤](07_v0.3.0_구현_마일스톤.md)의
`AC-01 → AC-02 → AC-03` Arduino Compatibility와 `M19 → M20 → M21` BLE 병렬 작업선이다.
두 작업선은 M22 package·RC/stable gate에서 통합한다. AC-03은 기존 Settings/ZMS 위의
제한된 EEPROM/FS facade와 대표 library matrix를 다루며, secure storage·PSA Crypto·DFU,
저전력 radio/OpenThread와 Matter는 Master roadmap의 후속 제품선에서 관리한다.
이 문서에는 후속 버전의 상세 계획을 중복하지 않는다.
