## 1. 목표

`v0.2.0`은 v0.1.0의 Full Zephyr 빌드·업로드 기준선을 유지하면서 Arduino 사용성을
확장하는 릴리스다. 우선순위는 다음 순서를 유지한다.

1. Zephyr/NCS 구조와 기능을 훼손하지 않는다.
2. 고급 사용자가 NCS 공개 API와 프로젝트 구성을 사용할 자유를 유지한다.
3. 일반 사용자는 Arduino IDE에서 예제와 검증된 기능 profile을 선택해 사용한다.
4. 유지보수자는 기능마다 별도 runtime이나 가짜 hardware abstraction을 만들지 않는다.

`v0.2.0`의 핵심 결과는 다음과 같다.

- 반복 가능한 CI/CD 기준선
- Arduino IDE에서 실제로 보이는 예제
- 일반 사용자가 `prj.conf`와 overlay를 편집하지 않는 profile/feature 설정
- v0.1 API 부채 정리와 NU54DK board/system library
- 공식 Zephyr Bluetooth stack 기반의 기본 BLE Arduino library
- NCS v3.4.0 기능·예제 coverage ledger와 첫 지원 묶음

## 2. 범위 경계

### 반드시 포함

- NCS v3.4.0/Zephyr 4.4.0 고정
- Loader 없는 전체 Zephyr 정적 이미지
- Windows 사용자 경로 유지
- Linux 기반 자동 build/test runner 추가
- CMSIS-DAP V2/pyOCD 기본 upload 유지
- v0.1.0 공개 API 회귀
- 예제 메뉴와 profile resolver
- basic BLE GAP/GATT 사용 사례

### 후속 버전

- 802.15.4/Thread의 완전한 Arduino-friendly 계층
- Matter 제품 profile
- MCUboot/DFU/OTA
- Linux/macOS 사용자 지원 선언
- native USB API
- 모든 NCS sample을 동일한 Arduino wrapper로 재작성하는 일

후속 범위라도 NCS 공개 API를 직접 사용하는 `.ino` reference example은 coverage 판단에 따라
먼저 제공할 수 있다.

## 4. M12 — CI/CD와 재현 가능한 자동 검증

### 작업

- GitHub Actions host test와 문서/link 검사를 구성한다.
- 고정 NCS v3.4.0 build 환경의 출처, digest, license와 Toolchain identity를 검증한다.
- 사용할 수 있는 공식 container가 계약을 충족하면 digest로 고정하고, 그렇지 않으면 검증된
  설치 script와 cache를 사용한다.
- host unit, Zephyr ztest/Twister build, Arduino CLI compile과 package validation을 분리한다.
- NU54DK HIL은 self-hosted runner에서만 실행하며 repository secret와 장치 lock을 사용한다.
- GitHub-hosted runner는 물리 장치 PASS를 추정하지 않는다.

### 완료 기준

- pull request에서 host/document/package/example-discovery gate가 자동 실행된다.
- main에서 대표 Zephyr/Arduino example build가 재현된다.
- NCS와 Toolchain cache key에 exact revision/digest가 포함된다.
- HIL이 없어도 software gate와 hardware gate 상태가 구분된다.
- release는 사람 승인 전까지 draft/RC 자산만 생성한다.

## 5. M13 — 구성 프로필과 Arduino 예제 UX

### 작업

- [ADR-0002](../00_사전%20리서치/02_Arduino_구성_프로필과_예제_노출_결정.md)의 profile
  schema와 병합 순서를 구현한다.
- `variants/nu54dk/profiles/<id>`와 versioned `profile.json` 계약을 만든다.
- NUCODE library의 `zephyr/feature.yml`을 Build Adapter가 허용목록 기반으로 읽게 한다.
- `boards.txt`에는 실제 검증한 curated feature set만 제공한다.
- M7 예제의 `prj.conf`/`app.overlay` 설정을 내부 profile/manifest로 이전한다.
- `File → Examples`와 `arduino-cli lib examples` 열거 시험을 release gate에 추가한다.

### 완료 기준

- 기본 예제는 `.ino`만 알아도 compile/upload할 수 있다.
- 공개 예제 7개가 Arduino CLI와 IDE 메뉴에 나타난다.
- profile/library/override 출처와 hash가 manifest와 cache key에 기록된다.
- SPI/UART와 radio stack 같은 충돌 조합은 configure 전에 명확히 실패한다.
- 전문가 override가 없는 예제에는 사용자 편집용 conf/overlay가 없다.

## 6. M14 — Core API와 Variant 기준선 정리

### 작업

- v0.1 지원표의 `부분 지원`·`미구현` 항목을 실제 수요와 비용으로 재분류한다.
- `constrain`, `min`, `max`, bit utility, random 계열의 기본 계약을 완성한다.
- 공개 가능한 NU54DK connector pin을 capability 기반 논리 pin으로 확장한다.
- 오류 조회와 diagnostic 형식을 Core/library에서 일관되게 만든다.
- exception/RTTI, `F()`, timing, Serial 세부 의미는 지원·의미 차이·제외 중 하나로 확정한다.

### 완료 기준

- API 표의 모든 `지원` 항목에 compile, semantic test와 필요한 HIL 근거가 있다.
- pin map은 DTS 단일 원본에서 생성되며 Variant에 물리 핀을 두 번째 원본으로 복제하지 않는다.
- v0.1 Sketch와 library corpus가 회귀 없이 동작한다.
- 구현하지 않은 기능은 성공처럼 보이는 stub 또는 합성값을 반환하지 않는다.

## 7. M15 — NU54DK board/system library

### 후보 범위

- `NUCODE_NU54DK` 보드 진입점과 board identity
- PMIC/전원 rail의 안전한 board control
- watchdog의 begin/feed/stop 가능 범위
- hardware counter/alarm과 software timer의 명확한 구분
- reset reason, uptime와 저전력 준비 API
- settings/storage의 최소 Arduino-friendly adapter

### 설계 원칙

- Zephyr driver가 소유한 장치는 Zephyr API를 통해서만 제어한다.
- hardware가 없을 때 software fallback으로 성공을 가장하지 않는다.
- 시간 단위, blocking 여부, callback 문맥과 복귀 여부를 API 이름과 문서에 표시한다.
- system off처럼 복귀하지 않는 API는 `[[noreturn]]` 의미와 wake 실패를 분리한다.

### 완료 기준

- board-specific 회로 지식이 library 내부에 캡슐화된다.
- 예제, unit/ztest, HIL과 오류 경로가 함께 제공된다.
- PMIC write처럼 위험할 수 있는 동작은 허용 register와 사전조건을 명시한다.

## 8. M16 — Basic BLE Arduino library

### 지원 목표

- stack 초기화와 local name
- advertising/scanning
- service/characteristic 등록
- read/write/notify/indicate
- connect/disconnect와 실제 연결 상태
- callback을 안전한 Arduino 실행 문맥으로 전달
- 필요하면 NUS/Serial 스타일 상위 예제

### 구현 금지

- 실제 controller에 적용되지 않은 TX power를 성공으로 반환하지 않는다.
- access address, CRC, channel map 또는 event counter를 합성하지 않는다.
- Zephyr Bluetooth가 소유한 radio/IRQ/register를 Core가 직접 제어하지 않는다.
- 지원하지 않는 LL 정보는 고정값 대신 명시적 오류로 반환한다.
- scan과 connection callback에서 사용자 blocking 코드를 직접 실행하지 않는다.

### 완료 기준

- 공식 Zephyr/NCS Bluetooth host/controller API만 backend로 사용한다.
- advertise, scan, GATT read/write와 notify를 NU54DK HIL로 검증한다.
- object lifetime, heap failure, disconnect와 재시작 회귀를 통과한다.
- 고급 사용자는 Zephyr `bt_*` API를 같은 Full Zephyr image에서 직접 사용할 수 있다.

## 9. M17 — NCS 기능·예제 coverage 첫 묶음

NCS sample을 그대로 복사하는 것이 아니라
[NCS 기능과 예제 지원 매트릭스](06_NCS_3.4.0_기능과_예제_지원_매트릭스.md)에서 다음 네
경로 중 하나로 분류한다.

| 경로 | 의미 |
| --- | --- |
| Arduino wrapper | 반복 사용 가치가 높은 안정적인 Arduino API 제공 |
| NCS direct example | `.ino`에서 공식 Zephyr/NCS API를 직접 사용하는 reference 제공 |
| Build/profile only | API wrapper 없이 필요한 profile과 module 연결만 제공 |
| 제외/보류 | NU54DK hardware 부적합, 보안·제품 정책 또는 검증 비용 때문에 미지원 |

첫 묶음은 GPIO/버스 이후의 board/system service, BLE, settings/storage, crypto/random과
대표 sensor pattern을 우선한다. 802.15.4/Thread/Matter는 matrix와 build feasibility를
확보하되 v0.2 stable 지원 선언은 별도 gate에서 결정한다.

### 완료 기준

- 선택한 모든 upstream sample에 NCS 경로, revision, license, NU54DK 적용성 상태가 있다.
- 지원 example은 Arduino IDE에서 열리고 clean compile된다.
- 하드웨어 의존 example은 fixture와 HIL 결과를 연결한다.
- wrapper 수보다 coverage 상태의 정확성을 우선한다.

- 프로젝트 소유자가 known issues, license, HIL과 clean Windows 결과를 승인한 뒤 stable을
  공개한다.
- 공개된 버전은 exact commit과 패키징 도구 commit을 함께 고정하며 같은 버전 이름으로 다른
  archive를 만들지 않는다.

## 11. 제품 장기 로드맵

| 제품선 | 목표 | 대표 범위 |
| --- | --- | --- |
| `v0.1.x` | 첫 stable 유지보수 | P0/P1 Core, build/upload, packaging 결함 수정 |
| `v0.2.x` | Arduino UX와 첫 고급 기능 | profile, IDE examples, board services, basic BLE |
| `v0.3.x` | 저전력 무선과 networking | 802.15.4, Thread, network client 계층 |
| `v0.4.x` | NCS 응용 subsystem 확대 | Matter 평가, storage, security, audio/sensor 묶음 |
| `v1.0.0` | 장기 호환 계약 | 안정 API, 지원 OS/보드 확대, migration 정책 |

버전 번호는 기능 수가 아니라 호환성·검증·배포 계약으로 결정한다. 특정 subsystem이 준비되지
않으면 전체 릴리스를 과장하지 않고 다음 minor로 이동한다.
