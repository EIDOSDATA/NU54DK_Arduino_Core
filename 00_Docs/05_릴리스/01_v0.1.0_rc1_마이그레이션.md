# v0.1.0-rc.1 마이그레이션 안내

> **배포 중단:** `v0.1.0-rc.1`은 Arduino IDE의 `post_install` 완료 응답에서
> `grpc: ... string field contains invalid UTF-8`가 발생할 수 있어 회수 대상으로 결정했다.
> 설치 자체는 완료됐을 수 있지만 이 버전을 새로 설치하지 말고 `v0.1.0-rc.2`가 공개되면
> 업그레이드한다. 자세한 내용은 [배포 중단 기록](./00_v0.1.0_rc1_배포_중단_기록.md)을
> 따른다. 아래 내용은 당시 artifact의 역사적 안내로 보존한다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 소스 저장소 직접 빌드 또는 M10 preview에서 `v0.1.0-rc.1`로 이동하는 사용자 |
| 작성자 | Quantum / NUCODE |
| 구조 | Loader/LLEXT 없는 Native Full Zephyr image |
| 기준 SDK | nRF Connect SDK v3.4.0 / Zephyr 4.4.0 |

> **역사적 상태:** 프로젝트 소유자의 승인에 따라 `v0.1.0-rc.1` GitHub Prerelease를
> 게시했고 당시 RC index 공개 다운로드와 SHA-256 검증을 통과했다. 이후 위 결함을 발견해
> 배포 적합성 판정을 철회했다.

## 1. 변경되지 않는 것

- 보드 FQBN은 `nucode:zephyr:nu54dk`다.
- 물리 핀과 peripheral route의 단일 원본은 고정된
  `board_package/NU54DK_Zephyr_DTS`다.
- 기본 Upload는 온보드 CMSIS-DAP V2와 pyOCD이며, 외장 J-Link는 선택 경로다.
- Sketch는 Loader에 동적으로 적재되지 않고 Core·Zephyr와 함께 하나의 ELF/HEX로 링크된다.

## 2. 소스 저장소 직접 빌드에서 이동

Boards Manager archive에는 고정된 NU54DK 보드 파일이 포함되므로 Git과 서브모듈을 별도로
설치할 필요가 없다. 기존에 Zephyr workspace나 VS Code application에 복사한
`boards/nucode/nu54dk`는 Boards Manager platform과 합치거나 덮어쓰지 않는다.

1. 기존 Sketch와 사용자 library를 별도 위치에 보존한다.
2. 공식 package index를 Arduino IDE의 Additional Boards Manager URLs에 등록한다.
3. `nucode:zephyr`의 검증된 release candidate를 설치한다.
4. `NU54DK (nRF54L15, Zephyr)`를 선택한다.
5. Blink를 한 번 clean compile한 뒤 기존 Sketch를 빌드한다.
6. 기존 build directory나 M9 cache를 수동으로 새 platform directory에 복사하지 않는다.

기존 NCS v3.4.0이 있어도 package는 revision, Toolchain bundle, nRF Util byte와 완료 marker가
정확히 일치할 때만 재사용한다. 다른 NCS/Toolchain을 환경변수나 CMake registry로 선택해
release build를 우회하지 않는다.

## 3. M10 preview에서 이동

`0.0.96`과 `0.0.97`은 clean Windows 수명주기를 검증하기 위한 preview다. RC는 별도
package index와 별도 GitHub prerelease를 사용하며 preview archive를 덮어쓰지 않는다.
`0.0.94`와 `0.0.95`는 PowerShell 5.1 runner 수정 전 Arduino CLI identity preflight에서
실패한 immutable 이력이므로 이동이나 되돌리기 기준으로 사용하지 않는다.

- Core upgrade 전에 열려 있는 Arduino IDE와 Serial Monitor를 닫는다.
- 기존 build output은 삭제하고 RC에서 다시 compile한다.
- 공유 prerequisite인 `%USERPROFILE%\ncs\v3.4.0`과
  `%USERPROFILE%\ncs\toolchains\dcbdc366a1`은 자동 삭제하지 않는다.
- 설치 검증이 실패하면 설치된 platform의 `post_install.bat`을 일반 사용자 권한으로 다시
  실행한다.
- downgrade가 필요하면 원하는 version을 명시해 설치하고 같은 version에서 다시 compile한다.

## 4. API 이동 시 확인할 차이

- `Serial`은 target native USB CDC가 아니라 DAP UART 기반 Zephyr console wrapper다.
- Arduino 논리 핀은 Variant capability table에 등록된 핀만 허용한다. 임의 Nordic port/pin
  번호를 Arduino pin 번호처럼 전달하지 않는다.
- `Wire`는 I2C22 P1.2/P1.3, `SPI`는 SPI00 P2.1/P2.2/P2.4에 고정된 기본 instance다.
- `analogRead()`는 A0/P1.12의 12-bit raw 값, `analogWrite()`는 P1.10의 20 ms·8-bit PWM이다.
- C++ exception/RTTI, AVR register/PROGMEM 의미, USB, BLE Arduino wrapper는 호환 대상으로
  선언하지 않는다.

정확한 상태와 의미 차이는
[Arduino API 지원 범위](<../01_아두이노 코어 설계/04_Arduino_API_지원_범위.md>)를 따른다.

## 5. 되돌리기

Boards Manager에서 RC를 제거하거나 이전 preview version을 명시해 다시 설치할 수 있다.
Core uninstall은 공유 NCS/Toolchain을 삭제하지 않는다. 이를 수동 삭제하면 다음 설치에서
대용량 다운로드가 다시 수행된다. Sketch와 사용자 library는 Core 제거 대상이 아니다.
