# v0.1.0-rc.1 문제 해결

| 항목 | 내용 |
| --- | --- |
| 작성자 | Quantum / NUCODE |
| 공식 지원 범위 | Windows 10/11 x64, NCS v3.4.0, NU54DK |
| 기본 Upload | 온보드 CMSIS-DAP V2 + pyOCD |

> **공개 경계:** 아래 RC 전용 URL은 프로젝트 소유자가 `v0.1.0-rc.1` GitHub prerelease
> 공개를 승인하고 게시한 뒤 사용할 수 있다. 게시 전 HTTP 404는 설치 결함이 아니다.

## 1. Core가 Boards Manager에 보이지 않음

Additional Boards Manager URLs에 RC 전용 index URL이 한 줄로 등록됐는지 확인한다.

~~~text
https://github.com/EIDOSDATA/NU54DK_Arduino_Core/releases/download/v0.1.0-rc.1/package_nucode_nu54dk_rc_index.json
~~~

preview `0.0.96`/`0.0.97`을 설치하는 경우에만 main의
`package_nucode_nu54dk_preview_index.json`을 사용한다. 그다음 index를 갱신한다.

`0.0.94`/`0.0.95`는 PowerShell 5.1 runner의 비동기 Task 반환값 누출 때문에 Arduino CLI
identity preflight에서 실패한 immutable preview다. 해당 version으로 재시도하지 말고 현재
검증 쌍을 설치한다.

~~~powershell
arduino-cli core update-index
arduino-cli core search nucode
~~~

HTTP 오류가 나면 GitHub 접근, proxy, TLS 검사 제품과 시스템 시간을 확인한다. checksum이
다르면 파일을 우회 설치하지 말고 download cache를 지운 뒤 다시 받는다.

## 2. post-install 또는 prerequisite 검증 실패

설치된 version의 `post_install.bat`을 일반 사용자 권한으로 다시 실행한다. 이 작업은 단계별
marker를 사용하므로 중단된 download와 설치를 재개한다.

~~~powershell
& "$env:LOCALAPPDATA\Arduino15\packages\nucode\hardware\zephyr\<VERSION>\post_install.bat"
~~~

주요 진단 의미는 다음과 같다.

| 진단 | 의미와 조치 |
| --- | --- |
| `E_PREREQUISITE_PINS` | package와 설치 pin이 다름. 해당 Core를 제거하고 index에서 다시 설치 |
| `E_PREREQUISITE_READY` | 설치 완료 marker가 없거나 불일치. `post_install.bat` 재실행 |
| `E_PREREQUISITE_TOOLCHAIN` | 고정 Toolchain bundle이 없거나 손상됨. 설치 log 확인 후 재개 |
| `E_PREREQUISITE_NRFUTIL` | nRF Util byte hash 불일치. 임의 binary 사용 금지, 다시 download |
| `E_PREREQUISITE_NCS` | NCS revision 불일치. 다른 workspace를 섞지 말고 고정 설치 복구 |

설치 log는 `%LOCALAPPDATA%\NUCODE\NU54DK_Arduino_Core\logs`에 있다. 공개 issue에
첨부하기 전에 사용자 이름, device UID, token과 사설 경로를 제거한다.

## 3. Windows에서 build path 또는 command 오류

M9의 기본 cache는 긴 Nordic object path를 피하기 위해 `%LOCALAPPDATA%\NU54\c`를 사용한다.
이를 더 긴 OneDrive·네트워크·다중 한글 경로 아래로 옮기지 않는다. BAT/CMD가 깨진 명령으로
해석되면 `0.0.90`~`0.0.93`이 아닌 Windows-safe version인지 확인하고 Core를 다시 설치한다.

동일 입력에서 cache 이상이 의심되면 Core 전체나 NCS를 먼저 삭제하지 말고 Build Adapter의
cache diagnostic과 단일 cache entry 정리 절차를 사용한다. 자세한 내용은
[빌드 캐시와 산출물](<../02_빌드 설계/04_빌드_캐시와_산출물.md>)을 따른다.

## 4. NU54DK 또는 CMSIS-DAP가 보이지 않음

- data 통신이 가능한 USB cable과 다른 USB port를 사용한다.
- DAPLink mass-storage와 serial port가 Windows 장치 관리자에 나타나는지 확인한다.
- Arduino Serial Monitor, debugger와 다른 pyOCD process를 닫는다.
- probe가 0개 또는 2개 이상이면 자동 선택하지 않는다. 하나만 연결하거나 명시적으로 선택한다.

일반 Upload는 mass erase/recover를 실행하지 않는다. 보안 상태 복구나 전체 erase는 별도
고위험 유지보수 작업이며 Upload 오류를 숨기기 위해 자동 실행하지 않는다.

## 5. Upload는 성공했지만 Serial 출력이 없음

NU54DK의 DAP UART port를 115200 8N1로 연다. CMSIS-DAP 자체 제어 port와 UART port를
혼동하지 않는다. `Serial`은 USB CDC가 아니므로 USB device 이름이 Arduino USB Serial처럼
보이지 않아도 정상이다. 다른 monitor가 port를 점유하면 먼저 닫고 reset한다.

## 6. Sketch compile 오류

- `nucode:zephyr:nu54dk`가 선택됐는지 확인한다.
- 오류가 난 Arduino API가 지원표에서 `미구현` 또는 `하드웨어 미지원`인지 확인한다.
- Zephyr API를 직접 사용할 때는 필요한 Zephyr header를 Sketch에 명시적으로 include한다.
- library가 AVR register, `PROGMEM`, USB 또는 특정 vendor HAL을 요구하면 이 Core에서 그대로
  호환되지 않을 수 있다.
- 이전 build directory를 재사용하지 말고 새 directory에서 한 번 compile한다.

재현 시에는 Core version, Sketch 최소본, 전체 첫 오류, Windows version과 사용 probe 종류를
함께 기록한다. device UID와 자격 증명은 공개하지 않는다.
