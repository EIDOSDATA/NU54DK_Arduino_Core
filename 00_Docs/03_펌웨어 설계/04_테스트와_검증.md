# NU54DK Arduino Core 테스트와 검증

| 항목 | 내용 |
| --- | --- |
| 문서 ID | FW-TEST-001 |
| 문서 개정 | 3.6 |
| 문서 상태 | `v0.2.0` 검증 계약 / `v0.3.0` 실행 상태 |
| 최종 갱신일 | 2026-09-01 |
| 현재 검증 단계 | M21·AC-02A 완료 / AC-02B 자동 구현·host/target build PASS, 물리 HIL 배선 대기 |

## 1. 목적

이 문서는 변경을 병합하거나 release할 때 필요한 시험 계층과 증거 경계를 정의한다. 실행별
수치, log, commit, CI run과 HIL transcript는 `04_검증 기록`의 milestone 문서가 소유한다.
설계 문서에는 그 값을 다시 복제하지 않는다.

## 2. 판정 원칙

1. Compile, emulator, target build와 실제 hardware 동작을 구분한다.
2. Build-only 성공을 runtime 또는 HIL 지원으로 확대하지 않는다.
3. Negative test는 성공 경로와 같은 release gate에 포함한다.
4. 실제 pin·probe·전원 조건이 필요한 주장은 HIL 없이 지원으로 올리지 않는다.
5. 고정 NCS/toolchain/board/Core identity를 evidence에 기록한다.
6. 실패를 retry로 숨기지 않고 최초 오류와 복구 여부를 함께 보존한다.
7. PMIC, System OFF와 destructive flash는 명시적 안전 조건 없이는 자동 실행하지 않는다.

## 3. 시험 계층

| 계층 | 목적 | 지원 주장 가능 범위 |
| --- | --- | --- |
| Python host unittest | source/schema/parser/package 계약 | host logic만 |
| Arduino CLI smoke | 실제 package recipe와 example compile | compile·artifact 생성 |
| Zephyr Twister/ztest | Kconfig, DTS, C/C++ target 의미 | target/emulator 계약 |
| west-native build | Core module과 production target 통합 | build·link |
| NU54DK HIL | GPIO, UART, bus, reset, power, BLE 실물 동작 | 해당 fixture 범위 |
| release lifecycle | 설치, upgrade/downgrade, uninstall, 재현성 | 공개 package 범위 |

## 4. Python host test

`tests/host`는 CMake/CTest project가 아니라 Python `unittest` 모음이다. 표준 discovery 계약은
다음과 같다.

```powershell
python -m unittest discover -s tests/host -p "test_*.py"
```

Release 고정 gate를 사용할 때는 다음 host subcommand가 같은 discovery 계약을 실행한다.

```powershell
python tools/release/run_fixed_gate.py host --repo-root .
```

Host test는 source/header 계약, profile/feature resolver, cache 안전성, package allowlist,
HIL protocol parser와 release metadata를 검사한다. Hardware 동작을 모사했다는 이유만으로 HIL
PASS를 선언하지 않는다.

## 5. Arduino CLI 시험

실제 소문자 경로를 사용한다.

```text
tests/arduino-cli/local_library/local_library.ino
tests/arduino-cli/compile_error/compile_error.ino
tests/arduino-cli/config_overlay/config_overlay.ino
tests/arduino-cli/multi_tab/multi_tab.ino
tests/arduino-cli/zephyr_coexist/zephyr_coexist.ino
```

존재하지 않는 대소문자 변형을 문서나 script에 사용하지 않는다. Windows에서도 repository
spelling을 그대로 사용해 Linux CI와 같은 입력을 보장한다.

CLI gate는 다음을 확인한다.

- `.ino` 전처리, multi-tab과 local library discovery
- compile 오류의 원본 Sketch 경로·행 표시
- profile/feature 및 expert conf/overlay 전달
- public Arduino example의 독립 compile
- 동일 input의 artifact와 cache identity
- package 설치본과 source tree 경로의 분리

## 6. Zephyr target 시험

`tests/zephyr`는 실제 소문자 경로다. Twister/ztest는 다음 계약을 검증한다.

- runtime 수명주기와 scheduler policy
- Variant의 `NUM_PIN_ROLES=32`, `NUM_DIGITAL_PINS=32`, `NUM_PHYSICAL_PINS=31`, 기본
  `NUM_DIGITAL_CAPABLE_PINS=20`과 `NUM_ANALOG_INPUTS=8` 불변식
- DAP UART GPIO `+4`, LFXO GPIO `+2` 조건부 capability와 system/input-only/transferable policy
- 모든 P2 pin의 `NOT_AN_INTERRUPT`, P0/P1의 capability 기반 GPIOTE 노출
- GPIO, time, interrupt, Serial, Wire, SPI, ADC/PWM 의미
- diagnostics projection과 C/C++ header 계약
- Board/System과 BLE production API compile/link
- 필수 DTS chosen/alias 누락, peripheral 충돌과 잘못된 profile의 expected-fail
- AC-02A owner/resource batch 원자성, rollback/release, stale lease, ISR 거부와 thread 경쟁
- AC-02B GPIO handover의 mode·latch·interrupt snapshot, rollback, restore와 fatal fault latch
- 부팅 고정 UART20과 dynamic UART30/I2C22/SPI00/PWM20/21/22 lifecycle 경계
- Wire target/no-STOP/Wire1, SPI1과 SPI peripheral interrupt의 fail-closed negative 계약

NU54DK target build와 QEMU/native simulation은 구분한다. Emulator PASS를 physical pin, RF 또는
전원 동작으로 확대하지 않는다.

## 7. NU54DK HIL

### 7.1 공통 안전 계약

- 보드와 probe UID를 명시적으로 선택한다.
- 여러 probe가 있는데 UID가 없으면 임의 선택하지 않고 실패한다.
- 일반 HIL은 mass erase나 보안 해제를 수행하지 않는다.
- UART port, baud, fixture wiring과 전원 조건을 manifest에 기록한다.
- HIL 종료 뒤 board가 안전한 예제 또는 알려진 상태로 복구됐는지 확인한다.

### 7.2 범위

| 기능 | 필요한 physical evidence |
| --- | --- |
| GPIO/interrupt | 실제 output/readback, pull과 edge |
| Serial | DAP UART READY·송수신 |
| Wire/SPI | 고정 fixture의 실제 transaction |
| ADC/PWM | 승인된 입력/출력 경로; 계측하지 않은 정확도는 주장 금지 |
| Variant M14 | 추가 LED/button의 output, pull-up, edge |
| Board/System | reset, watchdog, GRTC, settings와 SWD 격리 System OFF wake |
| BLE NUS | 서로 다른 두 보드의 Peripheral/Central 연결·양방향 data·재연결 |
| AC-01 | P2.5↔P2.6 loopback/open-drain/pulse·shift와 SW0 level/mask |
| M19 BLE GAP | 두 보드 advertise/scan/filter/connect/disconnect/reconnect |
| M20 범용 GATT | 두 보드 discovery/read/write/notify/indicate와 reconnect |
| M21 보안/HID | 두 보드 pairing·bond persistence·erase/re-pair·BAS/DIS/HID protocol; OS HID 입력은 수동 |
| AC-02B | 두 보드 UART/I2C/PWM·ADC와 단일 보드 SPI loopback; exact image/nonce/UID/COM 바인딩 |

M14 신규 pin HIL은 완료됐다. 상세 pin, 반복 횟수와 transcript는
[M14 기준선](<../04_검증 기록/16_M14_Core_API와_Variant_기준선.md>)만 소유한다.

### 7.3 AC-02B 고정 fixture

AC-02B runner는 build와 parser만으로 물리 PASS를 만들지 않는다. 두 probe UID, 두 COM port,
exact image hash와 실행 nonce를 모두 바인딩하며 `--acknowledge-wiring`이 없으면
`WIRING_REQUIRED`로 중지한다. 최종 fixture는 다음 8개 연결이다.

| 번호 | 연결 |
| --- | --- |
| 1 | 보드 A GND ↔ 보드 B GND |
| 2 | A P0.0 TX → B P0.1 RX |
| 3 | A P0.1 RX ← B P0.0 TX |
| 4 | A P1.2 SDA ↔ B P1.2 SDA |
| 5 | A P1.3 SCL ↔ B P1.3 SCL |
| 6 | A P1.10 PWM → B P1.14 capture |
| 7 | B P2.5 GPIO → A P1.12/A0 ADC |
| 8 | 보드 A 내부 loopback P2.2 MOSI ↔ P2.4 MISO |

I2C pull-up은 NU54DK board 회로의 pull-up을 사용한다. Peer는 direct Zephyr TWIS21 address `0x52`로
동작하며 Arduino Wire target 지원을 가장하지 않는다. PMIC `0x6a`를 AC-02B fixture target으로
접근하지 않는다. P2에는 CPUAPP GPIOTE가 없어 P2 edge interrupt를 시험하거나 지원으로 기록하지
않는다.

### 7.4 PMIC와 System OFF

- BQ25186 HIL은 허용된 address/register와 동작만 사용한다.
- 임의 scan, register write와 fallback을 protocol에 추가하지 않는다.
- 배터리가 없는 fixture에서 charge, rail, ship/shutdown 전기 HIL을 실행하지 않는다.
- System OFF는 image 기록과 UART 준비 뒤 SWD만 격리하고, 사용자 버튼과 debug-control switch를
  혼동하지 않는다.
- PMIC software semantic PASS를 배터리 전기 안전 PASS로 해석하지 않는다.

## 8. Upload와 debug

기본 upload는 CMSIS-DAP + pyOCD이며 J-Link는 외장 선택 경로다.

- single probe 자동 선택, explicit UID, zero/multiple probe 오류를 검사한다.
- J-Link serial을 명시하고 SEGGER software를 package에 재배포하지 않는다.
- 일반 upload와 destructive recovery를 분리한다.
- `zephyr.elf` source-level debug와 manifest artifact 경로를 보존한다.

Exact tool version, 반복 결과와 알려진 warning은
[M8 업로드와 디버그 기준선](<../04_검증 기록/08_M8_업로드와_디버그_기준선.md>)을 따른다.

## 9. Build/cache와 경로 회귀

- cold, no-change, source edit, conf/overlay 변경과 cache 손상 복구를 구분한다.
- 공백, 한글과 긴 경로를 검사한다.
- 동일 key 동시 접근과 서로 다른 Sketch의 병렬 build를 구분한다.
- 시간·용량 수치는 같은 tool identity에서만 회귀 비교한다.
- 설계 문서에 단일 PC의 측정값을 현재 성능 보장처럼 복제하지 않는다.

기준 수치는 [M9 증분 빌드·캐시·재현성 기준선](<../04_검증 기록/09_M9_증분_빌드_캐시와_재현성_기준선.md>)이
소유한다.

## 11. v0.3.0 현재 gate와 다음 단계

`v0.3.0`은 `AC-01 → AC-02 → AC-03` Arduino Compatibility 작업선과
`M19 → M20 → M21` BLE 작업선을 병렬로 검증한다. AC-01·AC-02A 자동 검증과 M19·M20·M21
구현·검증은 완료됐다. AC-02B는 자동 구현·host/target build PASS이며 물리 HIL 배선 대기다.
현재 source tree는 public library 6개·예제 27개다. 기존 19개는 Arduino CLI 19/19 compile을
통과했고 새 AC-02B 예제도 고정 source snapshot에서 8/8 compile을 통과했다. 설치 예제 discovery는
27/27이다. 27개 전체 clean package compile은 M22 gate로 남아 있으며 정식 `v0.2.0`의 library
4개·예제 14개 역사 계약을 변경하지 않는다.

M21은 Windows 11의 실제 OS HID pairing·키 입력과 재부팅 bond 복원까지 확인했다. 다음 순서는
AC-02B의 exact 8-wire physical HIL과 AC-03이다. M22는 AC-03까지 완료된 뒤에만
전체 예제·HIL·clean Windows package와 RC/stable gate를 시작한다.

- [AC-01 GPIO 호환성 검증](<../04_검증 기록/22_AC-01_GPIO_호환성_검증.md>)

- [AC-02B Peripheral/Analog runtime 기준선](<../04_검증 기록/27_AC-02B_Peripheral_Analog_runtime_기준선.md>)
- [M19 BLE Core/GAP 검증](<../04_검증 기록/23_M19_BLE_Core_GAP_검증.md>)
- [M20 범용 GATT 검증](<../04_검증 기록/24_M20_범용_GATT_검증.md>)

계획 또는 진행 중인 항목은 자동 계약, target build, 필요한 HIL과 예제 증거를 통과하기 전에는
현재 지원으로 표시하지 않는다.

## 12. 증거 보관

각 검증 기록에는 가능한 범위에서 다음 identity를 남긴다.

- Core, board package, NCS/Zephyr/toolchain revision
- OS, Python, Arduino CLI와 uploader version
- FQBN/profile/feature와 Sketch source identity
- build manifest와 artifact hash
- probe UID, UART와 fixture 조건
- 시작/종료 시각, exit code, 원본 log와 판정

설계 문서의 링크가 검증 기록을 대신하지 않으며, 검증 기록의 PASS도 명시한 fixture 범위를
넘어 일반화하지 않는다.
