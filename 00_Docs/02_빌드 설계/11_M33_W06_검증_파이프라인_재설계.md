# M33-W06 검증 파이프라인 재설계

상태: **W06 미완료·실패별 집중 검증으로 전환**, 2026-10-11 갱신.
R1·R2·R3 완료 이력과 첫 source의 전수조사는 보존한다. 후속 d909 조사는 일부 미실행 상태에서
중단했다. 현재 요청은 문서 정리·검사·commit/push이며, 코드·build·실기는 이 작업 중 보류한다.
이후에는 한 실패를 수정하고 로컬 해당 항목 PASS를 확인한 뒤 다음 실패로 이동한다.
전환 당시 사실은 [304번 기록](<../04_검증 기록/304_M33_W06_실행_정리와_문서_전수_검토.md>)이 소유하며,
현재 exact source·실행·결과는 [M33 인계](../M33_HANDOFF.md)와 후속 W06 실행 기록에 갱신한다.

## 1. 결정과 범위

**결함을 빨리 찾는 개발 시험과 완료를 증명하는 최종 시험을 분리한다.**
2026-10-11 사용자가 개발 운영을 변경했다. **실패 한 항목 선택 → 필요한 코드만 수정 →
로컬 단위 검사·필요 역할 build·해당 실기 재검증 → 실제 PASS → 다음 실패**로 진행한다.
실패하면 같은 항목에서 원인을 확인해 수정·재검증하며, 전수조사 완료나 대규모 일괄 패치 적용을
먼저 요구하지 않는다. 관련 없는 실패를 동시에 처리하거나 매 수정마다 전체 49개·Actions를 시작하지 않는다.

기존 조사와 실패 원본은 보존하고 미실행 범위는 명시한다. STOP·자원 반환·probe 상태가
확인되지 않으면 `SAFETY_HOLD`로 후속 실기를 막는다. 개발 PASS는 해당 변경·조건에 한정되며
새 source S의 최종 전체 PASS로 승계하지 않는다. 최종 완료 gate는 아래처럼 별도 유지한다.

재설계 대상은 W06의 계획·build/artifact 전달·보드 준비·실행·재개·증거 판정이다.
파일 분할 자체나 범용 framework 구축을 목표로 삼지 않는다. Arduino 공개 API, NCS 3.4.0,
board submodule, 기존 기능별 합격 조건은 보존한다. 생산 코드 수정은 재현된 결함에 한정한다.
이미 검증한 halt 복원·orphan GATT 정리·reboot handshake 수정을 폐기하지 않는다.

최종 W06 분모는 그대로다: **141 build slot, runtime 9, stage/validate 150,
33 기능 family + 8 자원 group + 8 자동 peer group, 3보드 1,800초 soak**.
최종 Host·SDK risk 7개·qualification 3개·지원표·strict closure도 필수다.
설계·도구 구현·짧은 smoke 통과는 이 분모의 완료가 아니다.

## 2. 기존 방식에서 줄일 비용

| 관측된 문제 | 새 구조의 대응 | 통과를 입증할 시험 |
| --- | --- | --- |
| 큰 build 후 경로·role·aggregate 결합 오류 발견 | 보드 없는 작은 실제 schema fixture로 생산자부터 최종 소비자까지 연결 | 누락·중복·이동 root·Windows LF/CRLF·잘못된 role 음성 시험 |
| 수정 때마다 긴 전체 campaign 재시작 | 개발 선택 실행과 최종 고정 campaign 분리 | 변경 영향 계획과 실제 실행 목록 비교; 최종 목록 누락 거부 |
| 많은 실패를 동시에 다루며 수정 범위 확대 | 한 실패에 필요한 수정·로컬 재검증을 완료한 뒤 다음 실패로 이동 | 현재 대상·변경 파일·직접 영향 검사·원본 FAIL/새 결과를 분리, 미실행 범위 유지 |
| 한 firmware의 NVM 상태가 다음 구성에 영향 | 그룹별 시작 상태 선언, 명시적 구성 전환 시험 | cache→signing, stale bond, reboot 복원·삭제 경계 |
| 양쪽 bond 상태가 달라 cleanup 인증이 교착 | 현재 peer 한정 stale bond 삭제·이전 link 격리·유한 1회 재연결; 늦은 event는 격리 link에서만 무시 | 비대칭 bond를 남긴 실패 attempt에서 fresh 재인증·양쪽 scoped 삭제·기존 bond 불변 확인 |
| UART reboot 경계에서 결과 수집 실패 | 원시 byte 보존과 명시적 readiness/nonce handshake | reset 경계 잡음 허용 한계·잘못된 nonce·일반 구간 잡음 거부 |
| 거대한 build 중간 파일을 매번 전달 | 실행·진단에 필요한 불변 bundle과 재생성 cache 분리 | 깨끗한 새 root에서 bundle만으로 모든 소비 경로 동작 |
| 실패 attempt가 앞선 PASS 재개를 방해 | append-only attempt와 검증된 checkpoint | 강제 중단·부분 JSON·손상·writer 충돌·재개 음성 시험 |

근거는 [303번 §6](<../04_검증 기록/303_M33_W06_재실행_최소화와_checkpoint_개선_계획.md>)이다.
SDK 위험 목록이나 timeout 하나만으로 원인을 단정하지 않는다. UART 경계 개선도 UART 드라이버의
전기적 결함을 입증한 결과가 아니다.

## 3. 실행 단계

```text
현재 문서 정리·검사·commit/push
  → P0 현재 실패 한 항목·환경·합격 기준 확인
  → P2 필요한 코드 수정 → 로컬 해당 항목 검증
       ↑ 실패: 같은 항목 원인 확인       ↓ 실제 PASS: 다음 실패
  → 안정화 후 별도 P3 clean source S 고정
  → 별도 P4 S의 필수 전체 검증·closure
```

### P0 — 비싼 작업 전에 실행기 자체를 검증

- registry에서 build·runtime·group·role·파일 소비 관계를 한 번 정의한다.
- 실제 parser/validator를 사용하는 작은 fake transport/board fixture로 plan부터 closure 거부/허용까지 검증한다.
- runner의 실제 인자, 필요 파일과 format, 모든 phase의 경로, APP/AUX, watcher/second peer를 전수 대조한다.
- 최종 fixture는 작아도 실제 schema를 충족해야 한다. 완료 검사를 monkeypatch하거나 합성 HIL PASS를
  제품 evidence로 내보내지 않는다. fake 결과는 production importer에서 명시적으로 거부한다.
- D 전용 output/temp/cache, 디스크 여유, SDK pin, Python/CLI, symlink, lock을 먼저 확인한다.
  symlink 권한이 없으면 사용자 조치를 요청한다. copy나 합성 record로 대체하지 않는다.
- 변경 분류를 실제 diff와 allowlist로 검사한다. 순수 문서 변경은 문서·참조·계약 gate만 실행하고
  큰 firmware build를 자동 시작하지 않게 한다. code/pin/schema/판정 변경이 섞이면 문서 전용으로 분류하지 않는다.
- 결과는 `DEVELOPMENT` 종류로만 저장한다. P0 실패 시 원격 전체 build를 시작하지 않는다.

### P1 — 별도 탐색 기능의 계약, 현재 자동 실행 대상 아님

49개 그룹마다 짧은 실행이 무엇을 확인하고 생략하는지 명시한다. 기본 연결·핵심 동작·negative 한 경로·
STOP/회수·재접속과 필요한 지속성 경계를 확인한다. 단순 boot/READY를 기능 smoke로 세지 않는다.

short mode가 없는 runner의 횟수를 밖에서 억지로 줄이거나 시간을 잘라 PASS로 만들지 않는다.
각 runner가 별도 smoke 계약과 판정기를 제공하게 하고, 제공되지 않은 그룹은 `NOT_RUN`으로 남긴다.
긴 필수 횟수는 P4에서 원래대로 수행한다. 재부팅·NVM 구성 전환·중단 복구처럼 위험한 경계를
긴 Audio/Profile/Mesh 부하보다 먼저 확인하되 의존성이 필요한 그룹의 순서는 지킨다.

첫 구현은 한 쌍의 보드로 build→전달→prepare→짧은 기능→STOP→재개를 끝까지 연결한다.
이 수직 경로가 통과하기 전에 49개 adapter를 동시에 바꾸지 않는다.

### P1F — 원본 조사 보존, 현재 재개하지 않음

- 기존 source·clean 상태·plan·artifact fingerprint·첫 raw 오류와 cleanup을 보존한다.
- 중단한 d909 조사의 나머지를 수정의 선행조건으로 실행하지 않는다. 미실행 그룹/하위 범위는
  [M33 인계](../M33_HANDOFF.md)에 남기고 새로운 개발 결과와 합산하지 않는다.
- 이후 별도 전수조사를 요청받으면 명시적 계획에 따라 실행하며 `SAFETY_HOLD`에서는 dispatch하지 않는다.

### P2 — 실패 하나가 통과할 때까지 해당 범위만 반복

- 이미 확보한 실패 중 한 항목을 고른다. P1F 전수 완료나 모든 후보 패치 적용을 선행조건으로 삼지 않는다.
- 실패를 재현하는 최소 입력, 첫 raw 오류, 분류, 수정 전 실패/수정 후 성공을 묶는다.
- 특정 group 선택과 해당 group의 prerequisite만 계획한다. 직전 group의 실행 여부를 초기 상태의 증거로 삼지 않는다.
- 관련 단위 검사·필요 역할 build·해당 실기를 로컬 실행한다. 공통 코드의 직접 영향 회귀만 추가한다.
  영향이 불명확하면 분석해 범위를 고정하며 임의로 전체 실행을 시작하지 않는다.
- 해당 항목이 실제 PASS하면 다음 실패로 이동한다. 기존 전체 판정 기준을 줄인 smoke는 진단일 뿐
  해당 항목의 완전한 PASS가 아니다. 최종 49-group/soak/Actions는 개별 수정 loop와 분리한다.
- 원인 없는 반복, timeout 상향, SDK 교체, 결과 parser 완화로 문제를 숨기지 않는다.
- 보안/NVM 복구는 전체 bond 삭제를 금지한다. 현재 연결 peer 한정 삭제와 나머지 startup bond의
  byte-equivalent 보존을 함께 입증하고, 복구 대상으로 격리한 이전 link의 지연 event만 판정에서 제외한다.
  재연결 횟수는 고정 상한을 두며 같은 peer의 무한 retry를 허용하지 않는다.
- 고정 SDK 결함이 공식 upstream 수정과 재현 증상으로 확정되면 설치 checkout을 임의 편집하지 않는다.
  patch byte·공식 upstream revision·적용 대상 SDK revision·변경 파일 집합을 저장소 lock에 고정하고,
  build 범위에서만 clean exact checkout에 적용한 뒤 내용 기준 clean 상태로 원상복구한다. build 계획·cache
  key·artifact provenance는 patch 집합을 입력으로 포함하며, 전체 SDK 전환은 배정된 별도 제품선에서 수행한다.

### P3/P4 — 안정화 후 최종 증거 생성

1. clean source **S**, board/SDK/toolchain, schema, runner와 전체 실행 계획을 고정한다.
2. S의 exact build/Host, 실제 inventory·runtime 9·stage 150을 검증한다.
3. S에서 49개 전체 group과 별도 3보드 1,800초 soak를 실행한다.
4. 최종 Host, risk·qualification, 지원표와 strict closure를 검사한다.
5. 허용된 기록 전용 후속 commit **C**로 완료 문서를 갱신한다. S→C 계약을 검증하고 push 결과를 확인한다.

P4 도중 같은 입력의 허용된 환경/전송 실패라면 검증된 checkpoint부터 재개한다.
제품·시험·판정 코드가 바뀌면 해당 실패의 P2로 돌아가고 안정화 후 새 S의 완료 계획을 만든다. 이전 S의 PASS를
새 S로 고쳐 쓰지 않는다. “전체 검증 한 번”은 안정화 목표이지 첫 시도 무조건 성공 보장이 아니다.

## 4. 책임과 데이터 계약

| 구성요소 | 소유하는 것 | 하지 않는 것 |
| --- | --- | --- |
| Registry/planner | group·role·의존성·mode·필수 파일·예산·선택 이유 | 장치 조작·PASS 판정 |
| Artifact store/importer | 불변 byte·manifest·hash·출처·위치 매핑 | 원본 record 수정·source 바꿔 붙이기 |
| Executor | DAG 순서·단일 writer·append-only attempt·취소·시간 측정 | 각 protocol 성공 조건 재구현 |
| Board adapter | probe lock·identity·sector program·readback·reset·안전 audit | feature PASS 추정·자동 mass erase |
| 기능 runner/oracle | 명령·nonce·raw·횟수·negative·STOP 의미 판정 | 앞 시험의 보드 상태 추정 |
| Evidence/closure | 입력·결과 결합, 원본 재검증, 최종 분모·비공개 경계 | 개발 smoke/가짜 fixture의 완료 승격 |

파일 수나 구체적인 package 이름은 구현 첫 단계에서 정한다. 같은 검사를 새 계층마다 중복 구현하지 않는다.
현행 registry·parser·안전 helper를 adapter로 재사용하고 순수 계획/판정과 부작용을 분리한다.

각 실행 record는 최소한 `kind`, mode, source revision/clean 여부, input fingerprint,
runner/oracle/schema fingerprint, group/role, attempt, parent/prerequisite, 시작·종료,
상태·오류 분류, raw/output hash, device 상태·cleanup 결과를 가진다. 이 필드는 **새 schema의 요구사항**이며
현재 JSON에 이미 모두 존재한다는 뜻이 아니다.

## 5. 재사용은 세 가지로 분리

| 대상 | 개발 중 | 최종 완료 |
| --- | --- | --- |
| compiler/build cache | 실제 의존 입력이 같고 도구가 검증할 때 계산 가속 | S의 provenance를 만족해야 하며 cache hit도 산출물 검증 필수 |
| firmware/artifact | 입력·설정·toolchain·embedded identity까지 동일할 때만 | S의 현재 exact 계약과 importer를 통과한 것만 |
| 실행 PASS/checkpoint | 같은 시험 입력·판정·mode·의존 결과를 재검증 | 같은 S·최종 mode의 유효 결과만, 생략 group 0 |

입력 fingerprint에는 실제 컴파일 source와 generated source, CMake/Kconfig/DTS, library/role 선택,
SDK/board/toolchain lock과 사용 byte, flags, builder 및 관련 의존성이 포함된다.
시험 재사용에는 runner·oracle·schema·환경 계약·fixture 준비·선행 결과도 포함한다.
경로는 위치 정보로 분리하되 컴파일 입력에 실제로 포함되는 경로·옵션의 영향은 무시하지 않는다.

**commit이 바뀌어도 무조건 artifact가 같다는 가정은 금지한다.** firmware에 full revision이
embedded되면 그 변경도 실제 build 입력이다. Git diff 파일명 목록만으로 안전한 의존성 분석을
완성했다고 주장하지 않는다. 의존성 추적이 불완전하거나 새 파일/미등록 경로가 나오면 재사용하지 않는다.
서로 다른 S의 HIL PASS 재사용은 이번 W06 최종 gate에 도입하지 않는다.

## 6. 보드 상태와 중단·복구

모든 group에 시작/종료 상태와 소유 자원·settings 영역을 명시한다. 프로그래밍은 필요한 exact
image에 한정하고 현재 readback으로 확인한다. HALTED는 firmware STOP 성공과 별도로 기록한다.
NVM 초기화로 migration 결함을 숨기지 않도록 fresh/restored/cross-configuration 시험을 구별한다.
시험 소유 정보만 지우며 사용자 정보·다른 identity는 보존한다.

중단 요청 시 새 단계 dispatch를 먼저 막고 실행 중 runner에 유한 cleanup 시간을 준다.

## 8. 병렬화와 시간·진행 보고

각 phase별 queue/setup/build/download/program/test/cleanup 시간을 분리한다. 같은 mode·조건의

`soak 미실행/실행/완료`, `closure 상태`를 따로 보고한다. 시간 목표는 측정 후 정하며 임의 완료 시각을 약속하지 않는다.
