# 업로드와 디버그 — v0.3.0 지원 경계

| 항목 | 현재 계약 |
| --- | --- |
| 일반 upload | Build Adapter `flash` |
| 기본 runner | pyOCD / 온보드 CMSIS-DAP V2 |
| 선택 runner | pyOCD UID, SEGGER J-Link |
| flash 입력 | 현재 build의 Full Zephyr image와 `.nu54-build.json` |
| flash log | `{build.path}/nu54-zephyr/logs/flash.log` |
| Arduino IDE Debug | v0.3.0 자동 통합 미지원 |

이 문서는 현재 구현된 upload와 수동 debug 경계만 설명한다. 실제 장비 UID, 실행 로그와
PASS/FAIL은 [M8 검증 기록](<../04_검증 기록/08_M8_업로드와_디버그_기준선.md>)과
[M18 검증 기록](<../04_검증 기록/20_M18_v0.2.0_rc1_공개_검증과_rc2_교정.md>)에 보존한다.

---

## 1. 일반 upload 흐름

1. `platform.txt`의 upload recipe가 `nu54-builder.cmd flash`를 호출한다.
2. Adapter가 현재 `{build.path}/<project>.nu54-build.json`만 허용한다.
3. FQBN, Zephyr board, non-sysbuild, profile, cache generation과 session context를 대조한다.
4. 공개 ELF/HEX의 크기·SHA-256을 manifest와 비교하고 native Zephyr artifact와도 대조한다.
5. 현재 NCS root, toolchain bundle과 compiler가 build 당시 identity와 같은지 확인한다.
6. `runners.yaml`에서 선택 runner의 안전한 설정을 확인하고 probe를 결정한다.
7. 같은 probe를 lock한 뒤 erase 없는 `west flash`를 실행한다.
8. console 결과와 실행 metadata를 `nu54-zephyr/logs/flash.log`에 추가한다.

실제 명령 형태는 다음과 같다.

~~~text
west -z <zephyr-base> flash -d <zephyr-build> -r <runner> \
  --no-rebuild --dev-id <probe-id>
~~~

pyOCD에는 `--tool-opt=-Osmart_flash=false`를 추가한다. 이 옵션은 nRF54L에서 부분 page
판단을 피하기 위한 write 정책이며 mass erase나 recover를 뜻하지 않는다.

## 2. Probe 선택

### pyOCD 자동 선택

`CMSIS-DAP (pyOCD)` 메뉴는 연결된 CMSIS-DAP probe가 정확히 하나일 때만 자동 선택한다.

- 0개: `E_PROBE_NOT_FOUND`
- 1개: 해당 UID 사용
- 2개 이상: `E_PROBE_AMBIGUOUS`; UID 지정 필요

### pyOCD UID

`CMSIS-DAP with UID (pyOCD)` 메뉴는 Arduino upload field로 받은 UID가 실제 열거 결과에
있는지 검사한다. 다른 UID로 자동 fallback하지 않는다.

### J-Link

`SEGGER J-Link` 메뉴는 명시적인 probe serial과 설치된 SEGGER software가 필요하다.
NU54DK board package의 runner metadata가 존재한다는 사실과 실제 J-Link hardware upload
검증은 구분한다. serial이 없으면 실행하지 않는다.

## 3. Arduino IDE와 CLI

IDE에서 `도구 → Upload probe`로 다음 중 하나를 선택한다.

- `CMSIS-DAP (pyOCD)`
- `CMSIS-DAP with UID (pyOCD)`
- `SEGGER J-Link`

CLI는 compile과 upload에서 같은 FQBN, board option과 build path를 사용한다.

~~~powershell
$BuildPath = Join-Path $PWD 'build\blink'

arduino-cli compile `
  --fqbn nucode:zephyr:nu54dk `
  --board-options feature_set=standard,upload_probe=pyocd `
  --build-path $BuildPath `
  .\libraries\NUCODE_NU54DK\examples\Blink

arduino-cli upload `
  --fqbn nucode:zephyr:nu54dk `
  --board-options feature_set=standard,upload_probe=pyocd `
  --build-path $BuildPath `
  .\libraries\NUCODE_NU54DK\examples\Blink
~~~

여러 CMSIS-DAP이 연결된 경우 `upload_probe=pyocd_uid`를 선택하고 Arduino CLI의 upload
field로 probe ID를 명시한다. 정확한 CLI field 문법은 설치한 Arduino CLI 버전의 help와
[v0.3.0 문제 해결](<../05_릴리스/v0.3.0/TROUBLESHOOTING.md>)을 따른다.

## 4. 안전 정책

일반 Upload는 다음 동작을 하지 않는다.

- `--erase`, `--recover`, mass erase
- 보호 상태 자동 해제
- 다른 runner나 probe로 자동 fallback
- manifest 검증 실패 시 HEX 직접 기록
- build tree 재구성 또는 암묵적 rebuild

현재 Build Adapter에는 별도 `recover` 명령이 없다. 보호 해제나 복구가 필요하면 사용자가
Nordic/runner 도구의 위험성을 확인한 뒤 일반 upload와 분리된 절차로 수행해야 한다.

같은 probe의 동시 flash는 직렬화하며 timeout이면 `E_PROBE_BUSY`로 종료한다. child process의
종료 코드는 보존하고, 오류가 나도 성공 marker를 출력하지 않는다.

## 5. Debug 경계

Build Adapter가 공개하는 명령은 `flash`까지이며 `debug`, `debugserver`, `attach` adapter
명령은 없다. `debug.*` property와 Arduino IDE 2.x Debug 버튼의 자동 설정도 v0.2.0 지원
범위가 아니다.

다만 유효한 Zephyr build tree와 runner가 있는 개발 환경에서는 다음 west-native 명령을
수동으로 사용할 수 있다.

~~~text
west debug -d <zephyr-build> -r <runner> --dev-id <probe-id>
west debugserver -d <zephyr-build> -r <runner> --dev-id <probe-id>
west attach -d <zephyr-build> -r <runner> --dev-id <probe-id>
~~~

이 경로는 cache 내부 `zephyr.elf`, 원래 source 경로와 설치된 runner/debugger를 사용한다.
Arduino build path의 ELF만 복사한 상태에서는 west runner context가 없으므로 같은 기능을
보장하지 않는다. J-Link metadata와 pyOCD flash 지원을 모든 debugger 조합의 실기 지원으로
확대 해석하지 않는다.

Serial/UART monitor도 SWD debug와 별도 채널이다. Upload 성공은 UART port 선택이나 monitor
연결 성공을 의미하지 않는다.
