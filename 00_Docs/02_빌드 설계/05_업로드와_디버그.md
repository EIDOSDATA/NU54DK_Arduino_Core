# 업로드와 디버그 설계

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | runner metadata 확인 — pyOCD 기본, J-Link 실기 검증 전 |
| 작성자 | Quantum / NUCODE |
| 기본 probe | NU54DK onboard CMSIS-DAP |
| 기본 runner | pyOCD |
| 선택 runner | SEGGER J-Link |
| 이미지 | Loader 없는 Native Full Zephyr |

---

## 1. 목적

이 문서는 Arduino IDE/CLI 및 west-native 개발에서 동일한 Full Zephyr firmware를 NU54DK에 안전하게 업로드하고 디버깅하기 위한 계약을 정의한다.

핵심 목표는 다음과 같다.

- onboard CMSIS-DAP를 pyOCD로 사용하는 기본 경로 제공
- 외장 SEGGER J-Link를 선택할 수 있는 대체 경로 제공
- Arduino Upload 버튼에서 전체 Zephyr image를 직접 플래시
- Loader, LLEXT 또는 bootloader update 단계 제거
- 일반 upload에서 mass erase 금지
- build 오류, runner 오류와 probe 오류 분리
- symbol이 포함된 Full Zephyr ELF를 이용한 source-level debug

CMSIS-DAP는 target에 SWD 명령을 전달하는 debug probe protocol이다. firmware loader가 아니므로 Loader 없는 설계와 충돌하지 않는다.

M3에서 확인한 runner 생성 결과와 실기 경계는
[M3 GPIO·시간·Scheduler 기준선](<../04_검증 기록/03_M3_GPIO_시간과_Scheduler_기준선.md>)에
기록한다. M3는 완료했으며, runner metadata 확인만으로 외장 J-Link 경로를 PASS로 올리지
않는다. 외장 J-Link 실기는 M8의 선택 경로에서 별도로 판정한다.

## 2. 범위

### 2.1 포함 범위

- west-native pyOCD flash
- Arduino Build Adapter의 pyOCD upload
- J-Link runner 등록 조건과 선택 upload
- 단일 probe와 다중 probe 선택
- 일반 reset-after-flash
- Full Zephyr ELF 기반 debug/debugserver/attach
- Arduino IDE Debug 통합을 위한 artifact 계약
- flash log와 오류 분류
- artifact hash 및 target 일치 검사
- 보호된 target의 별도 복구 경계

### 2.2 고정 조건

| 항목 | 값 |
| --- | --- |
| Board target | `nrf54l15dk/nrf54l15/cpuapp/nu54dk` |
| NCS | v3.4.0 |
| Zephyr | 4.4.0 |
| Sysbuild PoC | 사용하지 않음 |
| 기본 pyOCD target | board package가 지정한 `nrf54l` |
| J-Link CPUAPP device | NCS v3.4.0 Nordic 기준 `nRF54L15_M33` |
| J-Link 기본 speed 기준 | Nordic board 기준 `4000` kHz |
| 일반 erase | 사용하지 않음 |

### 2.3 현재 보드 패키지 상태

현재 `board_package/NU54DK_Zephyr_DTS/boards/nucode/nu54dk/board.cmake`는 다음을 수행한다.

- NU54DK CPUAPP qualifier에서 pyOCD target을 `nrf54l`로 지정
- flash/debug runner 기본값을 pyOCD로 설정
- `pyocd.board.cmake` 포함

NCS v3.4.0의 기본 nRF54L15 DK runner 설정과 NU54DK 보드 패키지를 함께 구성한 M3
build의 `runners.yaml`은 다음 결과를 생성했다.

| 항목 | 생성 결과 |
| --- | --- |
| available runners | `nrfutil`, `jlink`, `pyocd` |
| flash runner 기본값 | `pyocd` |
| debug runner 기본값 | `pyocd` |
| pyOCD target | `nrf54l` |
| J-Link device | `nRF54L15_M33` |
| J-Link speed | `4000` kHz |

따라서 J-Link runner 등록과 인자 **metadata 생성은 확인 완료**다. 다만 `runners.yaml`에
이름과 인자가 있다는 사실은 SEGGER 도구 설치, probe 연결, flash 또는 source debug가
동작한다는 증거가 아니다. 외장 J-Link HIL은 아직 실행하지 않았다.

J-Link 완료 조건은 다음과 같다.

1. configure 후 생성된 `runners.yaml`에 `jlink`가 available runner로 존재한다. **확인 완료**
2. NCS v3.4.0 CPUAPP 기준 device `nRF54L15_M33`와 speed `4000` metadata가 생성된다. **확인 완료**
3. pyOCD가 flash/debug 기본 runner로 유지된다. **확인 완료**
4. 설치한 SEGGER 도구가 runner metadata의 device를 실제로 지원한다. **미검증**
5. `west flash -r jlink`와 `west debug -r jlink`가 외장 probe 실기에서 성공한다. **미검증**

이 문서는 보드 패키지 파일을 직접 수정하지 않는다. 필요한 변경은 `NU54DK_Zephyr_DTS` 원본 저장소의 별도 변경으로 관리한다.

## 3. 업로드와 Loader의 관계

이 Core에서 Upload는 다음을 의미한다.

~~~text
Full Zephyr ELF/HEX 생성
  → SWD probe가 application flash에 기록
  → target reset
  → Zephyr kernel과 sketch가 직접 시작
~~~

다음 단계는 존재하지 않는다.

- Loader version 검사
- loader firmware 자동 갱신
- LLEXT sketch ELF 전송
- EDK symbol 검사
- sketch partition에 별도 동적 image 배치
- bootloader를 통한 serial upload

Upload 버튼은 SWD programmer 동작을 실행하지만 Arduino 사용자 관점에서는 일반 Upload action으로 제공할 수 있다.

---

## 4. 입력과 출력

### 4.1 입력

| 입력 | 설명 |
| --- | --- |
| Full Zephyr ELF | debug symbol과 load 정보를 가진 canonical image |
| Full Zephyr HEX | 일반 flash에 우선 사용하는 image |
| `runners.yaml` | build가 등록한 runner와 기본 인자 |
| artifact manifest | board, version, hash 및 cache build 경로 |
| runner | `pyocd` 또는 `jlink` |
| probe id | 다중 probe일 때 선택적으로 필요 |
| build directory | `west flash/debug`에 필요한 CMake cache root |

### 4.2 출력

성공한 upload 출력:

- 선택 probe와 runner
- target board
- 사용 artifact와 SHA-256
- flash 시작/종료 시각
- child command exit code 0
- reset 수행 여부
- mass erase가 요청되지 않았다는 기록

성공한 debug 출력:

- GDB server address/port
- symbol ELF 경로
- target device/core
- probe id
- server log 경로

### 4.3 로그

~~~text
<cache>/logs/flash.log
<cache>/logs/debugserver.log
<arduino-build>/<project>.nu54-build.json
~~~

로그에 보안 credential을 기록하지 않는다. probe serial number는 진단에 필요하지만 공개 CI artifact에 포함할 때 masking 정책을 적용할 수 있다.

## 5. 일반 업로드 처리 흐름

~~~text

   │
   ▼

   │
   ▼

   │
   ▼

   │
   ▼
probe 열거 및 단일 probe 결정
   │
   ▼
probe 전용 lock 획득
   │
   ▼

   │
   ▼

   ▼

~~~

flash 실패 시 recover 또는 다른 runner로 자동 전환하지 않는다.

## 6. pyOCD 기본 경로

### 6.1 Probe 확인

NCS v3.4.0 Toolchain 환경에서 다음 명령을 사용한다.

~~~powershell
pyocd list
~~~

Adapter가 machine-readable 출력을 사용하려면 설치된 pyOCD 버전의
`pyocd --help`에서 JSON 전용 하위 명령과 출력 계약을 먼저 확인해야 한다.
`list` 명령에 임의의 `--json` 옵션을 붙이는 것처럼 버전 간 지원 여부가
검증되지 않은 호출은 고정 계약으로 두지 않는다. PoC 단계에서는
`pyocd list`의 종료 코드와 사람이 읽을 수 있는
출력을 기준으로 probe를 확인한다.

확인할 항목:

- CMSIS-DAP probe가 한 개 이상 보이는지
- unique id가 안정적으로 제공되는지
- target voltage 또는 connection 정보가 정상인지
- `nrf54l` target을 pyOCD가 지원하는지

### 6.2 west-native flash

~~~powershell
$BuildDir = Join-Path (Resolve-Path '.').Path 'build/west-native-blink'
west flash -d $BuildDir -r pyocd
~~~

다중 probe일 때 NCS v3.4.0의 Zephyr runner 공통 option을 사용한다.

~~~powershell
west flash -d $BuildDir -r pyocd --dev-id '<CMSIS-DAP-UNIQUE-ID>'
~~~

Adapter는 `--dev-id`를 전달하기 전에 선택 runner가 이 capability를 지원하는지 확인한다.

### 6.3 Arduino Adapter flash 계약

~~~text
nu54-builder flash
  --manifest <project>.nu54-build.json
  --runner pyocd
  [--probe-id <id>]
~~~

첫 구현은 manifest에 기록된 Zephyr build directory를 사용해 `west flash -d`를 실행한다.

향후 `arduino-cli upload --input-dir`처럼 build cache가 없는 경우를 지원하려면 다음 중 하나를 별도로 구현하고 검증한다.

1. pyOCD에 export HEX를 직접 전달
2. upload 전용 최소 runner context 재생성

두 방식을 암묵적으로 섞지 않는다.

### 6.4 pyOCD debug

Full Zephyr GDB session:

~~~powershell
west debug -d $BuildDir -r pyocd
~~~

GDB client를 별도로 연결할 때:

~~~powershell
west debugserver -d $BuildDir -r pyocd
~~~

실행 중 target에 attach할 때 runner가 지원하면 다음을 사용한다.

~~~powershell
west attach -d $BuildDir -r pyocd
~~~

debug command는 `<build>/zephyr/zephyr.elf` 또는 export된 동일 Full Zephyr ELF의 symbol을 사용한다.

## 7. J-Link 선택 경로

### 7.1 사전 조건

- SEGGER J-Link Software가 지원 버전으로 설치돼 있어야 한다.
- 외장 J-Link의 SWDIO, SWDCLK, GND, VTref 및 필요 시 RESET 연결이 올바라야 한다.
- onboard CMSIS-DAP와 외장 J-Link가 동시에 target을 구동하지 않게 한다.
- generated `runners.yaml`에 `jlink`가 등록돼 있어야 한다.
- CPUAPP device가 `nRF54L15_M33`로 설정돼 있어야 한다.

### 7.2 Runner 등록 기준

NCS v3.4.0의 Nordic nRF54L15 DK CPUAPP 설정은 개념적으로 다음과 같다.

~~~cmake
board_runner_args(jlink "--device=nRF54L15_M33" "--speed=4000")
include(${ZEPHYR_BASE}/boards/common/jlink.board.cmake)
~~~

NU54DK board package에 적용할 때는 기존 pyOCD 기본값을 유지하고 J-Link를 추가 runner로 등록해야 한다. J-Link를 기본값으로 강제하지 않는다.

현재 M3 build의 `runners.yaml`은 위 J-Link device/speed 인자와 `jlink` runner를 생성하고,
flash/debug 기본값은 `pyocd`로 유지하므로 metadata 계약을 만족한다. 이 판정은 J-Link
실기 PASS를 의미하지 않는다.

### 7.3 등록 확인

~~~powershell
Select-String `
  -LiteralPath (Join-Path $BuildDir 'zephyr\runners.yaml') `
  -Pattern 'pyocd|jlink'
~~~

정확한 YAML 구조는 Zephyr version에 따라 달라질 수 있으므로 production Adapter는 text grep이 아니라 YAML parser를 사용한다.

### 7.4 west-native flash

~~~powershell
west flash -d $BuildDir -r jlink
~~~

다중 J-Link probe일 때:

~~~powershell
west flash -d $BuildDir -r jlink --dev-id '<JLINK-SERIAL-NUMBER>'
~~~

### 7.5 J-Link debug

~~~powershell
west debug -d $BuildDir -r jlink
~~~

또는:

~~~powershell
west debugserver -d $BuildDir -r jlink
~~~

J-Link path를 선택했는데 runner 또는 SEGGER tool이 없으면 `E_RUNNER_JLINK_UNAVAILABLE`로 실패한다. pyOCD로 자동 fallback하지 않는다.

## 8. Arduino platform 연결

### 8.1 Board menu

사용자 선택 예시:

~~~text
Tools
└─ Upload probe
   ├─ CMSIS-DAP (pyOCD)    # 기본
   └─ J-Link
~~~

`boards.txt` menu option은 각각 다른 `upload.tool` 또는 Adapter runner property를 설정한다.

### 8.2 Tool recipe 개념

pyOCD:

~~~ini
tools.nu54_pyocd.upload.pattern="{runtime.tools.nu54-builder.path}/nu54-builder" flash --manifest "{build.path}/{build.project_name}.nu54-build.json" --runner pyocd
~~~

J-Link:

~~~ini
tools.nu54_jlink.upload.pattern="{runtime.tools.nu54-builder.path}/nu54-builder" flash --manifest "{build.path}/{build.project_name}.nu54-build.json" --runner jlink
~~~

Arduino가 제공하는 port property가 SWD probe id와 동일하다고 가정하지 않는다. onboard CMSIS-DAP가 VCOM을 함께 제공하더라도 COM port와 CMSIS-DAP unique id는 별도 식별자다.

### 8.3 Probe 선택

첫 사용자 경험:

- probe 한 개: 자동 선택 가능
- 같은 유형 probe 여러 개: 명확한 오류와 발견된 id 목록 표시
- production 단계: custom discovery 또는 Adapter 설정으로 probe id 저장

임의의 첫 probe를 선택해 다른 보드를 덮어쓰지 않는다.

### 8.4 Upload 후 reset

- runner의 정상 reset-after-flash를 사용한다.
- reset 실패를 flash 성공과 구분해서 출력한다.
- 사용자가 debug attach 상태를 유지하려는 mode는 향후 별도 option이다.
- 1200 bps touch 또는 bootloader mode 진입은 사용하지 않는다.

## 9. Mass erase와 recover 정책

### 9.1 일반 Upload 금지

일반 Upload, Verify 후 Upload 및 IDE Upload 버튼에서 다음을 사용하지 않는다.

~~~text
west flash --erase
west flash --recover
pyocd erase --mass
nrfutil mass erase
J-Link 전체 칩 erase script
~~~

일반 flash가 실패했다는 이유만으로 자동 실행하지 않는다.

### 9.2 별도 복구 명령

복구 기능이 필요하면 명확한 별도 command로 설계한다.

~~~text
nu54-builder recover
  --runner <supported-runner>
  --probe-id <id>
  --confirm-device <expected-id>
  --yes-i-understand-this-erases-device
~~~

복구 전 확인 항목:

- 정확한 probe id
- 정확한 target family
- 사용자 데이터 및 provisioning 손실 경고
- 일반 upload 실패 log
- recover를 지원하는 runner인지

초기 Arduino platform에서는 Recover 메뉴를 제공하지 않아도 된다.

### 9.3 보호 상태

target protection, APPROTECT 또는 provisioning 상태가 의심되면 일반 flash 오류로 표시하고 별도 문서 절차를 안내한다. Adapter가 보안 상태를 임의로 해제하지 않는다.

## 10. Debug artifact와 symbol 계약

### 10.1 ELF

debugger가 사용할 ELF는 다음 정보를 포함한다.

- Zephyr kernel symbol
- Arduino Core symbol
- sketch와 library symbol
- DWARF debug information
- section/load address
- source path mapping

Arduino size/export용으로 ELF를 strip하더라도 debug ELF는 별도 보존한다.

### 10.2 Arduino debug property

향후 `platform.txt`에서 다음 방향을 사용한다.

~~~ini
debug.executable={build.path}/{build.project_name}.elf
debug.toolchain=gcc
debug.toolchain.path=<NCS toolchain gdb directory>
debug.toolchain.prefix=arm-zephyr-eabi
~~~

실제 GDB executable 이름과 Arduino IDE 2.x debug server 연동은 NCS v3.4.0 toolchain에서 검증 후 확정한다.

### 10.3 Source path

persistent cache와 Boards Manager 설치 경로가 DWARF에 포함될 수 있다. 다음을 검증한다.

- sketch source breakpoint가 원본 `.ino` 또는 생성 `.cpp`에 연결되는지
- Core source breakpoint가 설치된 Core source에 연결되는지
- cache 경로가 바뀐 export ELF를 다른 machine에서 사용할 때 source mapping이 필요한지
- Windows drive letter와 path case가 debugger에서 일치하는지

### 10.4 Debug 범위

Loader가 없으므로 debug session은 sketch thread만이 아니라 전체 Zephyr system을 대상으로 한다. 다음을 볼 수 있어야 한다.

- reset부터 `main()` 진입
- kernel thread와 scheduler
- Arduino `setup()`·`loop()`
- GPIO/UART/I2C/SPI driver stack
- fault handler와 stack trace

## 11. Serial과 SWD 구분

| 기능 | 채널 | 설명 |
| --- | --- | --- |
| Flash/Debug | SWD via CMSIS-DAP 또는 J-Link | firmware와 CPU 제어 |
| Serial Monitor | VCOM UART 또는 firmware USB CDC | 애플리케이션 입출력 |
| RTT | debug probe | 선택적 log/debug channel |

onboard CMSIS-DAP가 SWD와 VCOM을 함께 제공할 수 있지만 두 기능의 identifier와 failure mode는 다르다.

- COM port가 없어도 SWD flash는 가능할 수 있다.
- pyOCD probe가 보여도 firmware Serial이 활성화됐다는 의미는 아니다.
- Upload 성공을 Serial port 재열거에 의존시키지 않는다.
- RTT는 첫 upload PoC의 필수 조건이 아니다.

## 12. 오류 처리

| 오류 코드 | 상황 | 사용자 조치 |
| --- | --- | --- |
| `E_FLASH_ARTIFACT_MISSING` | HEX/ELF 또는 manifest 누락 | 먼저 Build 수행 |
| `E_FLASH_ARTIFACT_HASH` | artifact가 build 후 변경됨 | 다시 Build 후 Upload |
| `E_FLASH_BOARD_MISMATCH` | manifest board와 선택 board 불일치 | 올바른 FQBN으로 rebuild |
| `E_RUNNER_UNAVAILABLE` | `runners.yaml`에 선택 runner 없음 | board runner 설정 확인 |
| `E_RUNNER_JLINK_UNAVAILABLE` | J-Link runner/tool 미등록 | SEGGER 설치와 board CMake 확인 |
| `E_PROBE_NOT_FOUND` | probe 없음 | USB, cable, power, driver 확인 |
| `E_PROBE_AMBIGUOUS` | 여러 probe, id 미선택 | 표시된 probe id 지정 |
| `E_PROBE_BUSY` | 다른 debugger가 probe 사용 | 다른 session 종료 |
| `E_PYOCD_TARGET` | `nrf54l` target 미지원 | 고정 pyOCD version/pack 확인 |
| `E_TARGET_CONNECT` | SWD 연결 실패 | VTref, SWD 배선, reset 확인 |
| `E_TARGET_PROTECTED` | 보호 상태 의심 | 별도 recover/provisioning 절차 확인 |
| `E_FLASH_WRITE` | program/verify 실패 | log 보존, 자동 erase 금지 |
| `E_FLASH_RESET` | 기록 성공 후 reset 실패 | power/reset 상태 확인 |
| `E_DEBUG_SERVER` | GDB server 시작 실패 | port 충돌과 runner tool 확인 |

### 12.1 오류 출력 예시

~~~text
[NU54:E_RUNNER_JLINK_UNAVAILABLE]
선택한 Zephyr build에는 J-Link runner가 등록되어 있지 않습니다.
build: C:/.../zephyr-build
runner: jlink
available: pyocd
next: NU54DK board runner 설정과 runners.yaml을 확인하십시오.
자동으로 pyOCD로 전환하거나 target을 erase하지 않았습니다.
~~~

### 12.2 Child process

- west/pyOCD/J-Link의 원래 exit code를 보존한다.
- command와 stderr/stdout을 log에 저장한다.
- 사용자가 verbose를 선택하면 console에 전달한다.
- 일반 mode에서도 Adapter 오류 코드와 다음 조치를 표시한다.

## 13. 완료 기준

### 13.1 pyOCD

1. NU54DK onboard CMSIS-DAP가 pyOCD에서 열거된다.
2. board configure 후 `runners.yaml`에 pyOCD가 등록된다.
3. `west flash -r pyocd`가 erase 없이 성공한다.
4. 리셋 후 Full Zephyr Blink가 바로 실행된다.
5. Arduino IDE Upload 버튼이 같은 경로로 성공한다.
6. 다중 probe에서 id 선택이 안전하게 동작한다.
7. `west debug` 또는 `debugserver`가 Full ELF symbol을 사용한다.

### 13.2 J-Link

현재는 아래 1~2번에 해당하는 runner/argument metadata만 확인했다. 3~7번의 외장
J-Link 연결, flash, upload 및 debug는 아직 실행하지 않았으므로 J-Link 경로 전체는
완료 상태가 아니다.

1. NU54DK board 설정에 J-Link args와 common runner가 등록된다.
2. `runners.yaml`에 J-Link가 표시된다.
3. `nRF54L15_M33` CPUAPP device로 connect된다.
4. `west flash -r jlink`가 erase 없이 성공한다.
5. Arduino board menu에서 J-Link 선택 upload가 성공한다.
6. `west debug -r jlink`가 Full ELF symbol로 동작한다.
7. J-Link가 없는 경우 pyOCD fallback 없이 명확히 실패한다.

### 13.3 공통

1. Loader, bootloader 또는 LLEXT update가 없다.
2. upload artifact와 선택 board가 manifest로 검증된다.
3. 일반 upload log에 mass erase 요청이 없다.
4. flash failure가 이전 firmware를 지우는 자동 복구를 실행하지 않는다.
5. Serial port와 SWD probe 식별을 혼동하지 않는다.
