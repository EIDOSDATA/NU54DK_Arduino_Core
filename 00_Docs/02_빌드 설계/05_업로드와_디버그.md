# 업로드와 디버그 — stable v0.5.0 지원 경계

| 항목 | 현재 계약 |
| --- | --- |
| 일반 upload | Build Adapter `flash` |
| 기본 runner | pyOCD / 온보드 CMSIS-DAP V2 |
| 선택 runner | pyOCD exact UID 환경 변수, 외장 SEGGER J-Link |
| flash 입력 | 현재 build의 Full Zephyr image와 `.nu54-build.json` |
| flash log | `{build.path}/nu54-zephyr/logs/flash.log` |
| Arduino IDE Debug | 자동 통합 미지원 |

이 문서의 probe 메뉴·오류·환경 변수는 stable `v0.5.0` 구현 기준이다. 이전 stable `v0.4.1` 설치본의
기존 계약은 [v0.4.1 문제 해결](<../05_릴리스/v0.4.1/TROUBLESHOOTING.md>)에 보존한다.
RC2 exact package의 CMSIS-DAP/pyOCD Upload와 UART ready를 통과했고, 사용자는 Arduino IDE GUI에서
Blink 수정 뒤 연속 Verify·Upload 성공을 확인했다. 정식 v0.5.0은 같은 교정 경로를 포함한다.
Ubuntu/macOS는 버전 미정인 후속 제품선이며 [다중 Host 지원 계약](10_v0.5.0_다중_Host_지원_착수_계약.md)을 따른다.
실제 설치·USB upload·serial·debug·수명주기는 해당 OS를 추가할 릴리스의 최종 단계에서 사용자가
검증한다. 실물 증거 없이 해당 OS 지원 완료로 표시하지 않는다. J-Link는 설치·선택된 경우의
조건부 경로로 유지한다. HOST-W01~W03은 완료(3/8), HOST-W04~W08은 사용자 재개 지시까지 보류다.
Probe 원문 UID는 실행 시에만 필요한 값으로 취급하고 문서·로그·인계에는 SHA-256 identity만 남긴다.

이 문서는 현재 구현된 upload와 수동 debug 경계만 설명한다. 실제 장비 UID, 실행 로그와
PASS/FAIL은 [M8 검증 기록](<../04_검증 기록/08_M8_업로드와_디버그_기준선.md>)과
[M18 검증 기록](<../04_검증 기록/20_M18_v0.2.0_rc1_공개_검증과_rc2_교정.md>)에 보존한다.

## 1. 일반 upload 흐름

1. `platform.txt`의 upload recipe가 `nu54-builder.cmd flash`를 호출한다.
2. Adapter가 현재 `{build.path}/<project>.nu54-build.json`만 허용한다.
3. FQBN, Zephyr board, non-sysbuild, profile, cache generation과 session context를 대조한다.
4. 공개 ELF/HEX의 크기·SHA-256을 manifest와 비교하고 native Zephyr artifact와도 대조한다.
5. 현재 NCS root, toolchain bundle과 compiler가 build 당시 identity와 같은지 확인한다.
6. `runners.yaml`에서 선택 runner의 안전한 설정을 확인하고 probe를 결정한다.
7. 같은 probe를 lock한 뒤 mass erase 없는 `west flash`를 실행한다.
8. console 결과와 실행 metadata를 `nu54-zephyr/logs/flash.log`에 추가한다.

실제 명령 형태는 다음과 같다.

~~~text
west -z <zephyr-base> flash -d <zephyr-build> -r <runner> \
  --no-rebuild --dev-id <probe-id>
~~~

pyOCD에는 `--tool-opt=-Osmart_flash=false`를 추가한다. 이 옵션은 nRF54L에서 부분 page
판단을 피하기 위한 write 정책이며 mass erase나 recover를 뜻하지 않는다.

## 2. Probe 선택

### pyOCD 자동 선택

`CMSIS-DAP - one probe auto (multiple: CLI UID)` 메뉴는 연결된 CMSIS-DAP probe가 정확히
하나일 때만 자동 선택한다.

- 0개: `E_PROBE_NONE`
- 1개: 해당 UID 사용
- 2개 이상: `E_PROBE_AMBIGUOUS`; UID 지정 필요

### pyOCD UID

RC2는 Arduino IDE 2.x에서 임의 UID를 입력할 수 없는 `pyocd_uid` 메뉴를 제거했다.
여러 CMSIS-DAP을 연결하려면 CLI에서 `upload_probe=pyocd`를 유지하고 실행 환경의
`NUCODE_PROBE_UID`로 exact UID를 지정한다. 해당 UID가 실제 열거 결과에 있는지 검사하며
다른 UID로 자동 fallback하지 않는다. GUI 시험에서는 대상 CMSIS-DAP 한 대를 연결한다.

### J-Link

`SEGGER J-Link - external SWD/VTref/GND (CLI serial)` 메뉴는 명시적인 probe serial과 설치된
SEGGER software가 필요하다. Serial은 `NUCODE_PROBE_UID`로 전달한다.
NU54DK board package의 runner metadata가 존재한다는 사실과 실제 J-Link hardware upload
검증은 구분한다. serial이 없으면 실행하지 않는다.

## 3. Arduino IDE와 CLI

IDE에서 `도구 → Upload probe`로 다음 중 하나를 선택한다.

- `CMSIS-DAP - one probe auto (multiple: CLI UID)`
- `SEGGER J-Link - external SWD/VTref/GND (CLI serial)`

CLI는 compile과 upload에서 같은 FQBN, board option과 build path를 사용한다.

~~~powershell
$BuildPath = Join-Path $PWD 'build\blink'

arduino-cli compile `
  --fqbn nucode:zephyr:nu54dk `
  --board-options feature_set=standard,upload_probe=pyocd `
  --build-path $BuildPath `
  .\libraries\NUCODE_NU54DK\examples\Blink

arduino-cli upload `
  --fqbn nucode:zephyr:nu54dk `
  --board-options feature_set=standard,upload_probe=pyocd `
  --build-path $BuildPath `
  .\libraries\NUCODE_NU54DK\examples\Blink
~~~

여러 CMSIS-DAP이 연결된 경우 위 upload 전에 `$env:NUCODE_PROBE_UID = '<CMSIS-DAP-UID>'`를
설정한다. 값이 비거나 placeholder·형식 오류면 `E_PROBE_ID`, 지정 UID가 연결되지 않았으면
`E_PROBE_NOT_FOUND`로 flash 전에 실패한다. 원문 UID는 공개 로그·문서에 복사하지 않는다.
일반 console에는 끝 4자리만 표시하고 증거에는 SHA-256을 사용한다.

## 4. 안전 정책

일반 Upload는 다음 동작을 하지 않는다.

- `--erase`, `--recover`, mass erase
- 보호 상태 자동 해제
- 다른 runner나 probe로 자동 fallback
- manifest 검증 실패 시 HEX 직접 기록
- build tree 재구성 또는 암묵적 rebuild

현재 Build Adapter에는 별도 `recover` 명령이 없다. 보호 해제나 복구가 필요하면 사용자가
Nordic/runner 도구의 위험성을 확인한 뒤 일반 upload와 분리된 절차로 수행해야 한다.

같은 probe의 동시 flash는 직렬화하며 timeout이면 `E_PROBE_BUSY`로 종료한다. child process의
종료 코드는 보존하고, 오류가 나도 성공 marker를 출력하지 않는다.

RC2는 SWD No ACK, target 전원·응답, pyOCD/J-Link 실행 실패와 flash 쓰기 실패를 첫 원인
기준으로 구분한다. 비차단 Board ID 경고로 실제 실패 원인을 덮지 않으며, 전체 UTF-8 log 경로와
한국어 해결 안내를 남긴다. 저속 SWD는 명시적 비파괴 진단 옵션이다. 온보드 DAPLink에서
`under-reset`은 USB timeout과 probe 인터페이스 소실을 일으킨 현장 결과가 있으므로 자동 복구나
일반 해결책으로 실행하지 않는다.

Standard image는 runtime route가 실제로 사용하는 `PM_DEVICE_RUNTIME`을 유지하되
`CONFIG_PM_DEVICE_RUNTIME_DEFAULT_ENABLE=n`으로 전역 부팅 자동 suspend를 금지한다. 공개 RC2의
자동 enable 상태에서는 첫 Blink Upload 뒤 실행 중 target의 두 번째 SWD 접속이 No ACK로 실패했고,
이 설정을 끈 설치본은 USB 재연결 없는 250 ms → 100 ms 연속 Upload를 통과했다.

## 5. Debug 경계

Build Adapter가 공개하는 명령은 `flash`까지이며 `debug`, `debugserver`, `attach` adapter
명령은 없다. `debug.*` property와 Arduino IDE 2.x Debug 버튼의 자동 설정도 v0.4.1 지원
범위가 아니다.

다만 유효한 Zephyr build tree와 runner가 있는 개발 환경에서는 다음 west-native 명령을
수동으로 사용할 수 있다.

~~~text
west debug -d <zephyr-build> -r <runner> --dev-id <probe-id>
west debugserver -d <zephyr-build> -r <runner> --dev-id <probe-id>
west attach -d <zephyr-build> -r <runner> --dev-id <probe-id>
~~~

이 경로는 cache 내부 `zephyr.elf`, 원래 source 경로와 설치된 runner/debugger를 사용한다.
Arduino build path의 ELF만 복사한 상태에서는 west runner context가 없으므로 같은 기능을
보장하지 않는다. J-Link metadata와 pyOCD flash 지원을 모든 debugger 조합의 실기 지원으로
확대 해석하지 않는다.

Serial/UART monitor도 SWD debug와 별도 채널이다. Upload 성공은 UART port 선택이나 monitor
연결 성공을 의미하지 않는다.
