C11 macOS26·27 software CI는 PASS이며 실제 Mac USB·serial·debug·재연결·IDE는 NOT_RUN이다.
W06은 실제 PASS46 + 명시 수락3(#29·40·44)이며 기술49PASS가 아니다. #29 원인 분석은 유예한다.

최신 문서 checkout SHA와 제품 kit SHA를 구분하고 kit 안에 최신 파일을 덮어쓰지 마라.
board submodule은 fe65f2f0880bd05b32e562d9bf1ee59142b4f4d3,

NU54DK-Mac-handoff-20261116.zip의 SHA256SUMS·transfer-manifest.json과
windows-writer-release.json을 확인하라. 이전 Windows 실행·writer 해제와 최종 문서 CI를
실제 receipt로 확인한 뒤 Mac의 새 control/continuation.json과 단일 writer claim을 기록하라.
receipt의 최종 문서 SHA와 checkout HEAD·원격 branch를 대조하라. 다르면 변경 범위와 더 새 writer의
존재를 확인하기 전 옛 receipt로 현행 writer가 해제됐다고 간주하지 마라.
Windows의 D:/w06은 역사 보존 위치이며 Mac 재개에 그 드라이브를 요구하지 마라.
전달 자료가 없으면 MAC_HANDOFF의 원본 복구 절차를 따르되 artifact 보관 기한을 확인하고,
자료·소유권 확인에 의존하지 않는 읽기 전용 준비는 계속하라. 옛 Windows/WSL state.json·runtime·
절대경로 build manifest를 Mac 현재 실행 상태로 복사하지 마라.

실제 Mac의 sw_vers·uname -m과 OS major26 또는27, native Apple Silicon ARM64를 확인하라.
연결된 보드는 NU54DK이며 CMSIS-DAP USB와 실제 probe/serial/path hash를 새 inventory로 확인하라.
과거 COM 번호·UID/path hash를 재사용하지 마라. 단일 writer·단일 heavy job·기존 lock 정책을 지켜라.
작업/TMP/cache는 Mac의 쓰기 가능한 새 로컬 root를 사용하고 실제 여유 공간과 권한을 확인하라.
자동점검 w06은 PAUSED로 유지하고 새 예약작업이나 자동 재개 작업을 만들지 마라.

MAC_HANDOFF의 단계별 명령에 따라 kit hash→plan→필요한 SDK 설치/verify→lifecycle→대표 build→inventory를 진행하라.
새 Mac 실기에 필요한 로컬 설치본·manifest를 확보하되 --all-examples로 전체204를 반복하지 마라.
그다음 명시 probe로 Blink upload/runtime→debug→SerialEcho upload/nonce→물리 USB 재연결→Mac Arduino IDE 검증을 진행하라.
재연결 관찰 시작을 먼저 알리고 사용자가 케이블을 빼고10초 뒤 다시 연결하도록 안내하라.
첫 UART 응답을 기록하기 전에 재flash/reset하지 마라. open/close 성공을 물리 재연결 PASS로 세지 마라.
BLE 두 보드 검증은 배정 범위와 실제 준비 상태를 확인해 별도로 진행하고 한 보드 결과로 대신하지 마라.
Mac26/27 중 하나만 실제 실행하면 다른 행은 NOT_RUN으로 유지하라.
화면 제어가 불가능하거나 사용자 OS 승인이 필요하면 직접 해야 할 조작을 명확히 안내하면서 독립 작업을 계속하라.

정상 sector program·software reset·halt/resume·읽기 진단 범위로 진행하고
DAP/J-Link firmware 변경·자동 J-Link fallback·mass erase·unlock·recover·보안 보호 우회는 하지 마라.
새 FAIL은 원형을 보존해 원인을 구분하라. 제품 코드 수정은 새 source/kit/fresh attempt로 검증하고,
권한·경로 등 환경 준비만 보완하면 원본 kit를 유지한 fresh attempt에서 확인하라.
source별 PASS·FAIL·수락을 섞지 말고 SDK·firmware·compile 영향이 확인된 범위만 재검증하라.
STOP/cleanup·장치 소유권·raw log·exit code·hash·실제 OS/version을 남겨라.
